# 金樣零件（Phase 1 驗收 ①②）

三個夾治具零件，**只用 UI 建模**，存成 `.3dbx`。`golden.test.ts` 會開啟它們並重新計算，檢查：

- 體積等於手算值；
- 每個特徵都成功，沒有警告；每張草圖完全定義；
- 模型有效；面的名稱都是依「怎麼產生的」命名，沒有依位置編號的後備名稱；
- STEP 輸出再輸入，體積不變；
- 改變關鍵尺寸後，圓角、導角、孔、溝槽、削邊仍在原本的元素上（以只有在位置正確時才會對的體積檢查）。

| 檔案 | 零件 | 特徵 | 手算體積（mm³） |
|---|---|---|---|
| `locating-plate.3dbx` | 定位板 120×80×15 | 中心矩形 → 伸長 15 → 頂面草圖：4×Ø9（±50, ±30）、2×Ø8（±40, 0），以相等、水平與尺寸完全定義 → 除料 完全貫穿 → 圓角 R10（4 個外角）→ 導角 C1（頂面外緣 8 條邊） | 137197.0207 |

| `diamond-pin.3dbx` | 削邊銷 | 前基準面：中心線與半剖面（壓入段 Ø10×15、凸緣 Ø16×4、定位段 Ø8×12）→ 旋轉 360° → 旋轉除料：環溝 r4.5–5 × 1 → 導角 C0.5（壓入段底緣）→ 基準面1/2：右基準面偏移 ±3 → 各一矩形 → 除料 完全貫穿 → 定位段兩側削邊 | 2487.0292 |

## 怎麼做出來的

- 2026-09-28 在內建瀏覽器（1280×720）中建模，以 [`tests/e2e/phase1-demo-parts.js`](../e2e/phase1-demo-parts.js) 驅動：
  - 所有建模步驟都是 DOM、指標、滾輪、鍵盤事件，也就是滑鼠與鍵盤會產生的事件，而且都落在畫布上看得到的範圍；
  - 程式只讀取 store，用來知道東西在畫面上的哪裡、以及檢查結果。
- 系統的開檔與存檔對話框必須由真人點擊才會開啟，所以腳本以替身取代；真正的對話框已由使用者實機確認。
- 同一支腳本可以從頭重做三個零件，體積與這裡的檔案相同。
- 手算體積的算式寫在 `golden.test.ts`。

這些檔案不可修改。模型或命名規則改變、導致這裡的測試失敗時，先查明原因（見 `docs/phase1-verification.md` 的發現），不要直接更新檔案。

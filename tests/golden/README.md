# 金樣零件（Phase 1 驗收 ①②）

三個夾治具零件，**只用 UI 建模**，存成 `.3dbx`。`golden.test.ts` 會開啟它們並重新計算，檢查：

- 體積等於手算值；
- 每個特徵都成功，沒有警告；每張草圖完全定義；
- 模型有效；面的名稱都是依「怎麼產生的」命名，沒有依位置編號的後備名稱；
- STEP 輸出再輸入，體積不變；
- 改變關鍵尺寸後，圓角、導角、孔、溝槽、削邊仍在原本的元素上（以只有在位置正確時才會對的體積檢查）。

## 怎麼做出來的

- 2026-09-28 在內建瀏覽器（1280×720）中建模，以 [`tests/e2e/phase1-demo-parts.js`](../e2e/phase1-demo-parts.js) 驅動：
  - 所有建模步驟都是 DOM、指標、滾輪、鍵盤事件，也就是滑鼠與鍵盤會產生的事件，而且都落在畫布上看得到的範圍；
  - 程式只讀取 store，用來知道東西在畫面上的哪裡、以及檢查結果。
- 系統的開檔與存檔對話框必須由真人點擊才會開啟，所以腳本以替身取代；真正的對話框已由使用者實機確認。
- 同一支腳本可以從頭重做三個零件，體積與這裡的檔案相同。
- 手算體積的算式寫在 `golden.test.ts`。

## AI 照片建模樣本：SDS-plus 鎚鑽鑽頭 3/4"

`sds-plus-bit.3dbx` 不屬於上面的 Phase 1 驗收，也不是 UI 建模：2026-11-15 由 Claude Code 以 `/photo-to-cad`（[docs/photo-to-cad.md](../../docs/photo-to-cad.md)）從一張實物照片建模，經 MCP 工具逐批即時送進使用者開著的 App，再以 `part_save` 存檔。

- 照片比例：SDS-plus 柄 Ø10 = 40 px。使用者選定刀頭 Ø19.05（3/4"）、全長 210、雙溝、導程 39、溝長 115；柄上刻 3/4"。
- 照片看不出的尺寸是估計值，變數名稱以 `est_` 開頭、草圖名稱標「（估）」：溝深與溝寬、刀片厚 3、尖角 130°、後角 30°、刃帶 1.6、柄槽（開口槽寬 3 × 長 26、閉口槽寬 4 × 長 20、深 2）、刻字深 0.6。柄槽**未對照 SDS-plus 規格**，不可當作規格尺寸。
- 字型沒有英寸符號（"），以兩個小矩形刻出。
- 28 個特徵：旋轉本體 → 兩條螺旋掃出除料（第二條起始角 180°）→ 刀片伸長、導角作後角 → 四道柄槽（各自的除料，未用環狀陣列）→ 刻字。

`sds-plus-bit.test.ts`（獨立一檔，螺旋布林每次重建都佔 Heap，見 AGENTS.md §3.5）檢查：
- 每個特徵成功、每張草圖完全定義、模型有效、沒有依位置編號的名稱、STEP 來回體積不變；
- 旋轉本體等於圓錐與圓柱的手算值；每道柄槽移除的體積等於槽輪廓上 `√(R² − z²) − 槽底` 的積分（不經 kernel，柄端導角段以解析式）；兩條排屑溝移除相同體積（溝本身沒有封閉解，只驗相等）；
- 改變柄槽估計值與全長後，以上仍成立。

這些檔案不可修改。模型或命名規則改變、導致這裡的測試失敗時，先查明原因（見 `docs/phase1-verification.md` 的發現），不要直接更新檔案。

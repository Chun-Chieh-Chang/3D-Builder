# 組合件：爆炸線與動畫、多組爆炸、形成新次組合件（計畫）

- 日期：2026-10-07。來源：handoff §8 與手冊 K4（「組合件：爆炸線與動畫、爆炸視圖多組、形成新次組合件」）；使用者 2026-10-07 選了這一組。
- 狀態：**E-1、E-2、E-3 都已實作並驗證（2026-10-07，[ADR 0103](adr/0103-explode-lines-animation.md)、[ADR 0104](adr/0104-several-exploded-views.md)、[ADR 0105](adr/0105-form-sub-assembly.md)）**。實作時的差異：E-3 裡面沒有固定零組件時，第一個在次組合件裡固定；選項在「組合件」選單的「形成次組合件…」。

## 1. 現況

- 爆炸視圖（ADR 0050，組合件 Schema 5）：`AssemblyDoc.explosion?: ExplodeStep[]`（零組件、方向＝組合件的軸或零組件的元素、距離、反轉），只存意圖；`explosionOffsets` 算每個零組件的位移，`explodeLeaves` 把葉子移過去，`AssemblyStore.leaves()` 在 `exploded` 時用，「爆炸」「收合」是顯示開關，立刻切換；展開時不能移動零組件、不能編輯結合；STEP 輸出永遠是組裝位置。
- `Viewer.setInstances` 只更新矩陣（便宜），所以每個影格重算位置可行。
- 次組合件（ADR 0047）：`.3dba` 檔當零組件，父層視為剛體，`MateRef.path` 可以指到次組合件裡的零件。

## 2. E-1 爆炸線與動畫（不改檔案格式）

| # | 決定 | 理由 |
|---|---|---|
| 1 | **爆炸線**：每個被爆炸的零組件一條折線，從組裝位置的中心依序經過每個步驟之後的中心；中心＝它所有零件（含次組合件的零件、排列的實例）在組裝位置的包圍盒中心；虛線、深藍、不受深度遮擋；面板勾選「顯示爆炸線」（預設勾；顯示選項，不存進檔案） | SW 的爆炸線是「每個零組件走過的路」；包圍盒中心不依賴零件原點放在哪裡 |
| 2 | `explosionOffsets` 多回傳 `paths`（每個零組件每個步驟之後的累積位移），`explodeLeaves(leaves, offsets, t)` 多一個進度 t（0 到 1） | 純算術，好測 |
| 3 | **動畫**：「爆炸」「收合」與開啟面板時，進度 `explodeT` 在 0.5 秒內以緩入緩出走完（`requestAnimationFrame`；沒有 rAF 的環境，例如測試，直接跳到終點）；`exploded` 仍是目標狀態（展開中不能移動零組件的規則看目標，不看進度）；質量與干涉永遠用組裝位置（`assembledLeaves`） | 動畫只是顯示，不碰模型 |
| 4 | 需要組裝位置的操作（結合、移動、插入、排列）呼叫 `leaveExplode`，進度立刻歸 0（不播動畫） | 避免在位移中途操作 |

量化驗收：
- 手算：一個零組件先沿 Z 爆 50、再沿 X 爆 30：折線的相對點是 (0,0,0)→(0,0,50)→(30,0,50)；進度 0.5 時葉子的位置是組裝位置 + (15, 0, 25)（總位移 (30,0,50) 的一半）；進度 0 與 1 與原本一字不差。
- 中心：一個 10 × 10 × 10 的零件在原點、轉 90° 後的包圍盒中心 = 位置 + 轉過的局部中心（手算）。
- 次組合件與排列的實例跟著零組件、爆炸線一條。
- 瀏覽器：按「爆炸」，進度經過 0 與 1 之間的值、最後 1，「收合」後所有矩陣與組裝位置完全相同；爆炸線數 = 被爆炸的零組件數；取消勾選，線消失。

## 3. E-2 多組爆炸（組合件 Schema 7）

| # | 決定 | 理由 |
|---|---|---|
| 1 | `AssemblyDoc.explosions?: ExplodeView[]`（`{id, name, steps}`）與 `activeExplosion?: Id`；舊的 `explosion` 欄位在 Schema 6 → 7 遷移成第一組（名稱「爆炸視圖1」）；`explosion` 欄位移除 | 一組爆炸＝一個步驟清單；多組只是多幾份清單，單一來源 |
| 2 | 既有指令（加入、改、刪、搬步驟）作用在「使用中的那一組」，沒有時自動建一組；新指令：新增一組、重新命名、刪除、設為使用中 | 舊介面行為不變 |
| 3 | 面板最上方：下拉選「使用中的爆炸」，旁邊「新增」「重新命名」「刪除」；設計樹的爆炸資料夾寫使用中那組的名稱 | |
| 4 | 刪除零組件時，各組的步驟都清掉該零組件（空步驟刪除，空的一組保留） | 與現行一組的規則一致 |

量化驗收：舊的 Schema 6 檔讀進來，步驟一個不少、位移與以前相同（手算 50、30）；兩組爆炸各有不同步驟，切換後位移各自正確；刪除使用中的一組，另一組成為使用中；`id` 不重複不重用；存檔讀回一致；復原／重做。

## 4. E-3 形成新次組合件（組合件 Schema 不變）

「檔案」裡沒有，放在「組合件」→「形成次組合件…」：對話框列出組合件的零組件（勾選 ≥ 2 個）、新檔名（在專案資料夾內，預設「次組合件1.3dba」）。

| # | 決定 | 理由 |
|---|---|---|
| 1 | 新 `.3dba` 含被勾選的零組件（原樣：檔案參照、位置、固定、抑制、顯示旗標）與**兩端都在其中的結合**；父層移除這些零組件，換成一個零組件指向新檔，**位置＝單位位姿**（次組合件的座標就是父層的座標，所以每個零件的位置不變） | 位置完全不動，是最容易驗證的做法 |
| 2 | 一端在裡面、一端在外面的結合：改成指向次組合件零組件，並用 `path` 指到裡面的零件（既有機制，ADR 0047） | 保住外面的定位 |
| 3 | 裡面有固定的零組件時，新零組件在父層固定；否則浮動 | 固定是相對於父層座標，不能丟 |
| 4 | 爆炸步驟裡的零組件換成新零組件（同一步驟去重）；排列／鏡射的種子在裡面但複製品在外面（或相反）、種子與複製品被拆開：拒絕並說明 | 範圍：不拆開排列 |
| 5 | 只 ≥ 2 個、不含已被抑制後找不到的、新檔名不能已存在；寫檔失敗時父層不改 | 原子 |
| 6 | 一個復原步驟（父層的改動）；新檔寫在專案資料夾；已有的零組件 `id` 照舊（新檔裡的 id 沿用，父層的新零組件取新 id） | |

量化驗收：金樣夾具（15 個零組件、39 個結合）選一個工位的零件（1 定位板、2 銷、2 V 型塊）形成次組合件：每個零件的組裝位置誤差 < 1e-9（求解前後相同）、質量與零件表（攤平）數量不變、父層結合仍成立（自由度與衝突數不變）、新檔讀回再開能重新求解、復原後回到原樣；拒絕的情況各有訊息。

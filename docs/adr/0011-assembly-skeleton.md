# ADR 0011：組合件骨架（2A）

- 狀態：已採用（Phase 2A，2026-09-29）。
- 依據：藍圖附錄 C 的 B1.1、B1.2、C15.1、C15.2、A3.1、B9.4；handoff §10 的 2A。使用者決定：一次開一份文件，次組合件在 Phase 3b。

組合件是第一個跨檔案的文件：它不含幾何，只記錄用了哪些零件檔、每個零組件放在哪裡。這份 ADR 決定文件的形狀、檔案之間怎麼引用，以及瀏覽器怎麼找到這些檔案。

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **組合件文件有自己的版本線**，從 1 開始（`ASSEMBLY_SCHEMA_VERSION`），與零件的 Schema v6 分開：<br>• `files`：用到的檔案，每個一筆 `{ id, path }`<br>• `components`：`{ id, file, instance, fixed, placement }`，順序就是設計樹的順序<br>• 還沒有結合；2C 加入結合時升到版本 2 | 零件與組合件因不同理由改版，共用版本號會讓一方升版時另一方的舊程式無故拒開。結合要等升版才加：舊程式遇到不認得的結合應該拒開，而不是默默丟掉 |
| 2 | **檔案路徑只存一處**：同一個零件檔的所有實例都指向同一筆 `FileRef` | 路徑是一個事實（SSOT）。2D 的「重新指定遺失的零件檔」只改一處，所有實例一起跟著改，同 SW |
| 3 | **實例編號存在文件裡**（「削邊銷<2>」），新的實例取「目前最大值 + 1」；名稱本身不存，由檔名推得 | 同特徵名稱：刪掉 <1> 時 <2> 不會改名。零組件名稱 = 零件名稱，零件名稱 = 檔名（ADR 0010），所以只存編號 |
| 4 | **位姿 = 位置（mm）+ 單位四元數 `[x, y, z, w]`**：<br>• 對浮動的零組件，這是使用者擺放的位置，也是 2B 求解的起點；求解後的位置是衍生資料，不存<br>• 點選放置的位置取到 µm，檔案好讀 | 四元數沒有萬向鎖、只多一個自由度（長度 = 1，指令會檢查）；2E 的 STEP 輸出可直接轉成 `gp_Quaternion` |
| 5 | **參考 = 相對於組合件檔所在資料夾的路徑**，「/」分隔、最短形式（`../零件/銷.3dbx`）。**不存零件檔的雜湊值** | 相對路徑讓整個專案可以搬移或複製。藍圖寫的是「相對路徑 + 雜湊」，這裡刻意不存雜湊：雜湊是別的檔案的衍生資料，存了之後，要嘛每次存零件都讓組合件變成「已修改」，要嘛就過時。檔案遺失時（2D）依檔名在專案資料夾搜尋並讓使用者重新指定，同 SW |
| 6 | **專案資料夾**：瀏覽器只能讀使用者授權的檔案，所以組合件在一個「專案資料夾」內工作：<br>• 組合件和它用的零件都在這個資料夾之內（可以在子資料夾）<br>• 第一次需要時（插入零組件、存檔、開啟組合件）才詢問，本工作階段只問一次<br>• 資料夾選擇器必須由真人點擊觸發，所以用一個對話框承接這次點擊<br>• 開啟的組合件不在已授權的資料夾內時，再問一次；選到不包含它的資料夾會被拒絕並說明<br>• 組合件不能存到專案資料夾之外；零件也只能從專案資料夾插入<br>• 需要 File System Access API（Chrome、Edge）；其他瀏覽器可以用零件，不能用組合件 | 這是瀏覽器安全模型下，能用相對路徑找到檔案的唯一方式。授權跨工作階段保存（IndexedDB）排在 2D |
| 7 | **另存到別的資料夾時，改寫路徑並改寫復原記錄**：<br>• 未存檔的組合件視為在專案資料夾最上層<br>• 存到另一個資料夾時，每個路徑都改成從新位置到同一個檔案（`relocateAssembly`）<br>• `History.rebase(fn)` 把目前文件和復原/重做能到達的每個狀態都用同一個函數改寫，步驟變成整份文件的替換<br>• 寫檔失敗時改回原來的資料夾 | 文件內容必須與檔案一致（路徑相對於檔案位置）。只改目前文件的話，復原會帶回相對於舊位置的路徑，默默指到錯的檔案 |
| 8 | **`.3dba` 用與 `.3dbx` 相同的 ZIP 容器**，只有 `document.json`；`readDocumentFile` 依內容判斷是零件還是組合件 | 一種容器、一個讀取器；日後加縮圖或快取也不用換格式。依內容判斷，檔名被改過也能正確開啟 |
| 9 | **Worker 依內容快取零件**：<br>• 每個零件檔以 SHA-256 為鍵，重建一次，用它自己的 `Regenerator` 保留模型<br>• 沒改的零件永遠不再重建；改過的零件內容不同，就是新的一筆<br>• 組合件的檔案都讀完後，Worker 釋放不再使用的零件<br>• 「重新計算」在組合件中重新讀取所有零件檔 | 開組合件的成本 = 讀檔 + 只重建改過的零件。保留 B-Rep 是為了 2B/2C 從零件取出結合幾何 |
| 10 | **畫面：同一個零件的實例共用網格**，各自以矩陣定位；插入時零件的半透明預覽跟著游標，落在「通過原點、面向視線」的平面上 | 20 個零組件只需上傳每種零件一次。以矩陣定位，2D 拖曳時只要更新矩陣 |
| 11 | **一次開一份文件**：每開一份組合件就建立一個 `AssemblyStore`；App 依目前文件切換設計樹、圖面、指令分頁；檔案、復原/重做、重新計算依目前文件轉送 | 使用者決定（2026-09-28）。組合件的狀態自成一塊，零件的程式不必處處判斷文件類型 |
| 12 | **第一個零組件固定、其餘浮動**（C15.2）；設計樹以「(f)」「(-)」標示，右鍵可切換固定/浮動 | 同 SW。沒有結合時，浮動的零組件都是定義不足，所以是「(-)」 |
| 13 | **復原記錄泛化**：`History<D, C>` 接受任何文件與它的指令；`DocHistory`（零件）與 `AssemblyHistory` 是它的兩個特例 | 編輯會話、復原/重做只寫一次 |

## 相容性

- 零件的 Schema 不變（v6）。`.3dbx` 的讀取改用共用的容器程式；舊版樣本與既有測試都照舊通過。
- 組合件是新的檔案類型，沒有舊檔。

## 驗證

- **單元測試**：
  - 路徑：正規化、相對路徑、專案資料夾之外的路徑；
  - 位姿：矩陣、旋轉方向、無效的位姿被拒；
  - 指令：插入（新檔案、同一檔案的第二個實例）、各種無效插入被拒且文件不變、固定/浮動、移動、刪除（不再使用的檔案一起移除，ID 不重發）；
  - 搬移資料夾：路徑改寫、往返不變、復原/重做在改寫後仍正確；
  - 文字格式與 `.3dba`：往返、同一份文件寫出相同位元組、依內容判斷零件或組合件。
- **整合測試**（`tests/phase2/assembly.test.ts`）：磁碟上的專案資料夾放入金樣零件，組合件存到子資料夾後讀回，以相對路徑找到每個零件並重建，體積等於手算值，質心落在位姿指定的位置。
- **瀏覽器**（`tests/e2e/phase2-assembly.js`，專案資料夾用瀏覽器的私有檔案系統，檔案控制代碼是真的）：
  - 新組合件 → 插入零組件（詢問專案資料夾）→ 定位板按 ✓ 放在原點（固定）→ 削邊銷點選放置兩次（浮動，實例 1、2）→ 存到子資料夾（路徑改寫為 `../`）→ 換成新零件 → 開啟組合件：零組件與位置完全相同；
  - 開啟定位板，伸長深度 15 → 20 並存檔 → 開啟組合件：定位板變成 20 mm 厚，位置不變，只有定位板重建；
  - 復原/重做、「要儲存變更嗎？」、刪除零組件、零件檔遺失再補回、Esc 取消插入；
  - 新的工作階段開啟組合件：詢問專案資料夾，選錯資料夾被拒絕並說明，選對後開啟。
- 系統的資料夾與存檔對話框需由使用者實機確認（同 1E）。

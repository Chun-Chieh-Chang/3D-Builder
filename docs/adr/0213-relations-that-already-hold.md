# ADR 0213：已經成立的關係不再被要求一次；被拒絕時說清楚為什麼

日期：2026-10-28。狀態：已實作；本機閘門與完整 `verify:ui` 見 §4；遠端 CI 待推送後的結果。檔案格式不變（不升 Schema）。

## 1. 問題

使用者回報（附畫面）：草圖建構時，「同心同徑」限制失敗，底部訊息是「這個限制條件會使草圖過多定義，因此沒有加入」。畫面上是兩個同心的圓，兩個都被選取，草圖「定義不足（尚有 1 個自由度）」。

## 2. 根因（先重現，不猜）

用真實的 `SketchController` 與求解器重現：**第二個圓是從第一個圓的圓心畫的，圓心落在吸附範圍內，所以兩個圓共用同一個圓心點**（`ci1.center = ci2.center = p1`）。此時：

- 「同心」要求 `p2p_coincident(p1, p1)`：一個點與自己重合，永遠成立；求解器判為**多餘**（`redundant`，沒有 `conflicting`），草圖狀態變 `over`，被拒絕。
- 「同心同徑」＝同心＋相等半徑；其中同心那一半同樣多餘，整條關係被連帶拒絕，**連真正缺的「相等半徑」也沒加上**。
- 介面還在**提供**這兩個按鈕。提供清單只排除「完全相同的關係」，不排除「已經成立的關係」。
- 與 ADR 0211 無關：這個草圖沒有直線，守門不會執行。

「圓心由 `coincident` 關係接在一起（兩個點，不是同一個點）」也是同樣的情況。

## 3. 橫向檢查：不只這一個

隨機組合草圖（3 條線、3 個圓、6 個點，先隨機加入最多 5 個關係），對每一種選取組合的每一個「被提供的關係」逐一試算，數有多少**加入時被判為多餘**（只有新關係多餘、沒有衝突）：

| 關係 | 被提供 | 加入時是多餘 |
|---|---|---|
| 水平 | 310 | 109 |
| 垂直 | 323 | 106 |
| 相等 | 649 | 89 |
| 同心同徑 | 317 | 81 |
| 等曲率 | 322 | 77 |
| 端點相切 | 344 | 56 |
| 內相切 | 340 | 51 |
| 重合 | 322 | 40 |
| 共線 | 344 | 50 |
| 同心 | 270 | 10 |
| …（其餘見 DEV_LOG） | | |

（一次隨機掃描的計數，不是全部組合；掃描在 §4.1 的修正之後跑，所以同心與同心同徑列的是修正後**剩下的**：由相切、相等曲率等其他限制決定的。）所以這是一整類：關係已經被現有的限制條件（常是經過另一條鏈、另一種限制）決定了，按下去只會得到「過多定義」的誤導訊息。

## 4. 決策

1. **兩個圓或圓弧的「同心」「同心同徑」**：用既有的「最小森林」展開（原本只在選三個以上時用，`expandRelation`）：圓心已經是同一點或已由重合／同心連起來，就不再要求同心；半徑已由相等連起來，就不再要求相等。兩半都缺時仍是原來的單一「同心同徑」關係（儲存形式不變）。
   - 「同心」在圓心已經一致時**不再被提供**；「同心同徑」在兩半都成立時不被提供。
   - 兩個圓共用圓心時，按「同心同徑」只加一個「相等」，半徑相同。
2. **被拒絕時說清楚**：求解器回報「多餘、沒有衝突」時，訊息改為「這個限制條件已經由草圖現有的限制條件決定（加入只會重複），因此沒有加入」；真的矛盾或過度定義（有衝突）仍然是原本的「過多定義」訊息。判斷依據是求解器自己的 `conflicting` 與 `redundant` 診斷，不另外猜。
3. **不做的**：第 3 節表中其他關係（水平、垂直、相等、相切等）**仍會被提供**，只是被拒絕時訊息正確了。要不提供它們，必須為每個按鈕先試算一次（或為每種關係寫一套隱含判定），成本與複雜度都高；先記為已知限制，由使用者決定要不要做。

## 5. 紅隊四問

1. **輸入破壞**：沒有數值輸入；兩個圓共用圓心、圓心以 `coincident` 連接、半徑已相等、兩者皆成立、圓與圓弧混合、三個圓，都有案例；沒有 `Math.round`。
2. **幾何相交**：純草圖運算，沒有布林運算，不涉及 OCCT Heap。
3. **依賴鏈**：`interact.ts`（`expandRelation`、提供清單）→ `controller.ts`（`addRelation` 的訊息）→ 雙語字串（`sketch.relationImplied`）；不改 schema、命令、DAG、求解器。
4. **零 Mock**：真實的 `SketchController`、PlaneGCS、`DocHistory`；真值是手算的（共用圓心就只缺半徑，反之亦然），隨機測試的預期由建構方式決定，不呼叫被測的展開函式。瀏覽器端用真實滑鼠畫兩個圓。

## 7. 已知限制
- 第 3 節的其他關係仍會被提供；被拒絕時有正確的訊息，但按鈕還是在。
- 「已經成立」的判定對兩個圓只看圓心點與半徑的連結（相同的點、`coincident`、`concentric`、`coradial`、`equal`）；經由其他種類的限制（例如兩圓心都固定在同一座標）決定的，仍由求解器在加入時拒絕並說明。
- 求解器診斷的 `redundant` 與 `conflicting` 區別是 PlaneGCS 的；沒有另外證明。

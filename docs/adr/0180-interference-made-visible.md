# ADR 0180：看得見的干涉檢查（縮放到干涉、淡化其他零組件、紅圈、位置、忽略）

## 1. 背景

2026-10-21 使用者回報：組合件「干涉檢查」看不出干涉位置與干涉情形，要求比照 SolidWorks 的 Interference Detection。附圖是組合件4.3dba，剖面開著，面板列出「組合件3<1> × 零件1<1>，重疊體積 0.083 mm³」，畫面上只有兩小塊紅色。

**開工前讀碼的根因**：

1. **干涉體太小**：0.083 mm³ 大約是邊長 0.44 mm 的方塊，在幾十 mm 寬的畫面裡只有幾個像素；程式沒有縮放過去，也沒有不隨縮放變小的記號。
2. **選取一組什麼都沒變**：`AssemblyViewport` 只把兩個零組件塗成選取色，相機不動、其他零組件不淡化；干涉在零件裡面時只靠紅色的 `depthTest: false` 透出來，看不出在零件的哪裡。
3. **面板沒有位置**：worker 只回傳網格，面板只列名稱與體積。
4. **剖面**：紅色不受剖切，浮在剖面上；與切開的零件對不起來。

SolidWorks 的對照（說明網站以腳本產生，抓不到內文；以下依對 SW 的了解，**未逐條對照官方文件**）：結果清單、選取一組時紅色顯示並可縮放至選取、「非干涉零組件」線架構／隱藏／透明／使用目前、「使干涉零件透明」、忽略與顯示已忽略、「相符視為干涉」。

## 2. 決策（使用者 2026-10-21 確認：四個問題都照建議）

1. **位置是真值**：`Kernel.common` 由同一次 `VolumeProperties` 一併回傳質心（`CentreOfMass`），`findInterference` 每個重疊再取 `kernel.bounds`。worker 把 `center`／`min`／`max` 連同網格送出。不以網格包圍盒冒充質心（AGENTS §2.4）。
2. **以組為單位的純函式**（`apps/web/src/state/interferenceView.ts`）：`groupOverlaps`（體積加權的中心、包圍盒的聯集、依體積排序）、`shownPairs`、`stepPair`（↑／↓，頭尾相接，跳過忽略的）、`pairPlace`（兩位小數，無 −0.00）。
3. **選取一組 = 帶過去**（`store.selectInterference`）：
   - `focus` 序號加一 → `AssemblyViewport` 呼叫 `viewer.fitBox(min, max)`：視線方向不變，干涉包圍盒在畫面上的高與寬取較大者佔畫面的 `FIT_BOX_FRACTION = 0.3`（`viewNav.fitBoxView`，純函式），先 `rememberView`，所以「上一個視角」回得去。
   - `sectionRequest` → 剖面開著時，剖切面移到干涉中心（軸向不變，`ViewOptions` 處理）。
   - `viewer.setComponentFocus({ keys: [aTop, bTop], others })`：兩個干涉零件透明 0.45；其他依「非干涉零組件」為透明 0.12（邊線用另一個淡化材質）、線架構（`colorWrite: false`，保留邊線與輪廓線）、隱藏（`group.visible = false`，點選的射線也排除）、保持目前顯示。使用者自己設的透明另存於 `Instance.userTransparent`，取消聚焦時還原為 0.4。被淡化、線架構、隱藏的零組件不參與剖面填色與剖面邊線（`faded()`）。
4. **紅圈**（`viewer.setMarkers`）：HTML 元素放在標籤層，每次繪製時投影到干涉中心；固定 24 px（選取的 32 px），中間空心，編號在旁邊；點紅圈選取那一組。只有一組被選時只畫那一組的紅圈。
5. **紅色體積**：顏色改由主題變數 `--view-highlight`（`oklch(60% 0.22 27)`）與 `--view-highlight-edge` 提供，加畫深紅色的邊線；仍為 `depthTest: false`、不受剖切，在任何顯示類型下畫在最上層。
6. **忽略**：只在這個組合件開著時有效（`WeakMap<AssemblyStore, Set>`），重新檢查與關閉重開都保留，不寫入檔案（不升 Schema）。
7. **面板**：每列有編號、名稱、中心、範圍、「縮放」、「忽略／取消忽略」；「非干涉零組件」下拉、「顯示已忽略的干涉」；表格可取得焦點，↑／↓ 換組。

### 3.1 交付後的錯誤：紅圈不在紅色上（2026-10-21，同日修正）

- **現象**：使用者實際的組合件（組合件4.3dba）中，紅圈與「中心 (0.00, 0.37, 0.00)」落在圓柱中間的空處，兩塊紅色在左右兩側（範圍 8.88 × 3.77 × 9.20）。
- **根因**：以整組重疊的**質心**當作標示位置。環形或繞著軸分散的重疊，質心在中間的空處；這是正確的質心，卻是錯誤的標示。e2e 只用了 V 型塊角對角的方塊重疊（質心在材料裡），沒有涵蓋環形與多塊的情況。
- **修正**：
  - `Kernel.regions`：把重疊拆成分開的實體，每塊各有體積、質心、範圍與**錨點**；質心在實體內（`BRepClass3d_SolidClassifier`）時錨點就是質心，否則是實體邊界上離質心最近的點（`BRepExtrema_DistShapeShape`）。
  - 每一塊一個紅圈，放在錨點上，編號是組號；面板的「中心」改為「位置」（最大一塊的錨點），分成多塊時寫「共 N 處」；剖面改為穿過這個位置（穿過質心的剖切面可能從兩塊之間穿過、一塊都切不到）。
- **驗證**：
  - `tests/phase3/interference.test.ts`：r = 5 的桿穿過 r = 4 的孔，重疊是一圈；斷言質心被判定在外（分支確實被觸發），錨點在圈上（判定不在外、半徑 4–5）。橫跨孔的 1 mm 寬條，重疊兩塊：塊數 2，體積加總相對誤差 ≤ 1e-9，每塊錨點在自己的塊上。`liveShapes` 不變。
  - `manual-interference-view.js` 新增 `ring`：金樣夾具「也檢查子組合件裡面的零件」得 4 組環形重疊，錨點離質心 ≥ 3.9 mm；每個紅圈在錨點投影 ±2 px；逐一點選每一組，從畫布讀回紅圈中心那一點的像素為紅色（230, 44, 44）。

## 4. 已知限制

- **顯示類型是 4 種，不是 5 種**：組合件沒有「隱藏線可見」（`ASSEMBLY_DISPLAY_MODES`），所以驗收的「5 種 × 剖面開關 = 10 種」實際是 4 × 2 = 8 種。
- **「相符視為干涉」不做**（使用者裁決延後）：需要面接觸偵測，另立一項。
- **忽略不寫入檔案**（使用者裁決）：要保存須升 Schema。
- **縮放以整個畫布的中心為準**：面板蓋住畫布右側約 370 px；干涉在畫布中間，不會被面板蓋住，但可見區域的中心略偏左。
- **紅圈只有編號**：名稱在滑鼠停留的提示（`title`）與面板裡，不在 3D 畫面上，避免多組時文字重疊。

# ADR 0015：STEP 組合件輸出（2E）

- 狀態：已採用（Phase 2E，2026-09-30）。
- 依據：藍圖附錄 C 的 F1.2；handoff §10 的 2E；ADR 0009（STEP 輸入）、ADR 0011（組合件骨架）、ADR 0012（求解器）。

「輸出 STEP」原本只用於零件。2E 讓組合件也能輸出：結構、名稱、位置都寫進檔案，其他 CAD 系統開啟後看到的和圖面一樣。

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **XCAF 單層結構**：根是一個組合件（名稱 = 組合件檔名）；每個不同的零件檔一個原型（名稱 = 零件檔名，不含副檔名）；每個零組件一個帶位姿的實例（名稱 = 設計樹上的名稱，「削邊銷<2>」）。重複使用的零件只寫一份實體 | 與 SW 輸出的組合件同一種結構；檔案大小不隨實例數成長。次組合件在 Phase 3b |
| 2 | **寫出「圖面上的位姿」**：取 `poseOf`（拖曳中 > 求解結果 > 擺放位置），不是文件裡存的擺放位置 | 結合把零件從擺放位置移到別處；輸出必須和使用者看到的一致（ADR 0012 #14：位置是求解出的衍生資料） |
| 3 | **位姿用 `SetRotation(四元數)` + `SetTranslationPart(向量)` 組成 `gp_Trsf`**，不用 `SetTransformation(四元數, 向量)` | 後者與 `SetTransformation(gp_Ax3, gp_Ax3)` 同為兩個參數，libcascade 依參數個數分派（ADR 0003），無法確定會選哪個 |
| 4 | **不是單位四元數就拒絕**（誤差 > 1e-9，或含非有限數）：`位姿無效` | OCCT 會靜默地把非單位四元數轉成走樣的矩陣，輸出的位置錯了卻沒有任何提示。測試資料曾因此出錯（範數平方 0.9996，位置差 4.6e-4 mm） |
| 5 | **單位固定 mm**，同零件輸出 | 內部單位就是 mm；沿用 `write.step.unit` |
| 6 | **有零件檔讀不到就整個中止**，訊息列出檔名與原因（每個檔案只列一次，即使有多個零組件用它）；零件沒有本體同理。不會輸出缺了零件的組合件 | 靜默略過會產生看似完整、實際少了零組件的檔案，比報錯更糟 |
| 7 | **結合正在求解時拒絕**（「請稍後再輸出」），沒有 PropertyManager 在進行時才能按 | 求解中的位姿是舊的，會寫出過時的位置。求解約十幾毫秒，實際上很少遇到 |
| 8 | **檔名 = 組合件名**，`組合件1.step`；未存檔的組合件用暫名 | 同零件（`stepFileName`） |
| 9 | Worker 以內容雜湊取已重建的零件（`parts.get(key)`），不重建、不讀檔 | 輸出當下畫面上的就是這些零件；與求解共用同一份快取 |

## 驗證

- **Kernel**（`packages/kernel/test/assembly-export.test.ts`，6 項）：三個實例（其中一個零件用兩次、一個是斜的）輸出後以 `STEPCAFControl_Reader` 讀回：根名稱、原型數 2、實例名稱、產品名稱、體積（60000、720 mm³）；每個實例的平移與旋轉矩陣與輸入相差 < 1e-6；同一個零件只寫一個實體；單位；空組合件、不存在的零件、非單位四元數與 NaN 都被拒絕；不洩漏形狀控制代碼。
- **金樣夾具**（`tests/phase2/step-export.test.ts`，5 項）：定位板（固定）、兩支削邊銷（一支以同軸心與重合結合入孔、一支自由並傾斜）、V 型塊，求解後輸出並讀回：3 個原型、4 個實例、名稱等於檔名與設計樹；每個原型的體積與原零件相對誤差 < 1e-9；每個實例的位姿與求解結果相差 < 1e-6；被結合移動過的銷輸出的是求解位置，不是存下來的擺放位置（差 > 10 mm）；銷的凸緣中心用讀回的矩陣算出 = 孔軸上的 (−40, 15, 0)。
- **瀏覽器**（`tests/e2e/phase2-assembly.js` 的 `__asm.exportStep()`）：
  - 「輸出 STEP」在有零組件的組合件上可按，開著結合 PropertyManager 時不可按；
  - 下載的檔案有 3 個實體、4 個 `NEXT_ASSEMBLY_USAGE_OCCURRENCE`、產品名稱含三個零件與組合件，每個零組件在圖面上的位置都在檔案裡；
  - 刪掉削邊銷的檔案並重新讀取後再輸出：不下載，訊息「有 1 個零件檔無法讀取：零件/削邊銷.3dbx（…）」。
- 這台機器的 `F:` 磁碟不支援符號連結，工作區連結（`node_modules/@3db`）是空的，`npm run check` 與 `vite build` 無法直接執行。驗證時用暫存的 tsconfig、vitest 與 vite 設定加上路徑別名，執行了同樣的型別檢查、全部測試（`--maxWorkers=4`；並行 worker 太多會耗盡 WASM 記憶體）與建置，專案內沒有留下設定檔。
- **待使用者**：在 SW 開啟輸出的 `.step`，確認結構與位置（藍圖 §3 Phase 2 驗收 ③ 的一部分，屬 2F）。

# ADR 0013：結合的介面與管理（2C）

- 狀態：已採用（Phase 2C，2026-09-29）。
- 依據：藍圖附錄 C 的 C15.8、C15.12、A3.4、A5.1、D1.1、D7.1；handoff §10 的 2C；ADR 0012（求解器）。

2B 做好了求解器；2C 讓使用者在圖面與設計樹上建立、檢視、修改結合。

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **Worker 求解，主執行緒只顯示**：組合件每次改變（文件、零件讀完、結合草稿）都送出一次求解，一次只跑一個，等待中的只留最新的一個。圖面用解出的位置；還沒解出時用擺放位置 | 求解需要零件的 B-Rep 與持久名稱，它們留在 Worker（ADR 0011）；同一套 `solveAssembly` 也給測試用 |
| 2 | **零件的元素資料隨網格送到主執行緒**：每個面、邊、頂點的持久名稱、指紋與結合用的幾何，以及零件的基準面 | 點選到的索引要換成持久名稱（同零件模式的規則：只對照畫面上正在顯示的那份資料）；建議結合類型與對齊需要幾何 |
| 3 | **結合 PropertyManager 同 SW 的流程**：點「結合」→ 選兩個元素 → 自動選好 SW 會先給的類型（兩個圓的元素：同軸心；平面與圓柱或球：相切；其他：重合）、較接近目前位置的對齊方式、距離/角度填入目前的值 → 預覽 → ✓ 加入，PropertyManager 留著接著做下一個；什麼都沒選時 ✓ 關閉 | SW 的使用習慣：一次加好幾個結合。建議與預設讓零件移動最少 |
| 4 | **預覽**：未加入的結合（草稿）跟文件一起求解，但不寫進文件；PropertyManager 直接顯示「結合成立」或「與之前的結合矛盾」 | 文件只存使用者確認的設計意圖；SW 在加入前也會先顯示會不會過多定義 |
| 5 | **只提供這一對元素能用的類型**（其餘按鈕停用）；鎖住只在兩個都是零組件時提供 | 與求解器同一份規則（`supportedTypes` 用 `compileMate` 判斷），介面不會提供解不出的組合 |
| 6 | **選取元素**：結合時圖面改為拾取零組件上的頂點、邊線、面（同零件模式的優先順序：頂點 > 邊線 > 面，被擋住的不算）；基準面與原點在圖面左上的浮出樹中選（組合件自己的，以及每個零組件的預設與參考基準面） | SW 的做法；小孔的內壁要放大才點得到，與 SW 相同 |
| 7 | **同一個零組件上的兩個元素不能組成結合**（直接提示，不收下第二個） | 結合是兩個零組件之間的關係 |
| 8 | **設計樹**：零組件前加上求解出的狀態 (f)/(-)/(+)，完全定義時不加；結合資料夾列出每個結合與它連接的兩個零組件，有錯誤時標示；右鍵：編輯結合、抑制/恢復抑制、刪除、錯誤為何？；雙擊編輯 | C15.12、A3.4、D1.1 |
| 9 | **選取結合時，在圖面標示它的兩個元素**（面、邊、頂點以藍色；基準面以半透明方框） | C15.12「視覺化結合」 |
| 10 | **錯誤為何？與狀態列**：列出所有有錯誤的結合（矛盾、遺失參考、不支援）；狀態列顯示組合件「完全定義 / 定義不足 / 過多定義」 | D7.1；SW 狀態列的組合件狀態 |
| 11 | **編輯結合時改了類型，名稱跟著換**（「重合4」改成距離後叫「距離1」）；使用者自己改過的名稱保留 | SW 的命名習慣 |
| 12 | **距離接近 0 時不反轉**：兩個元素已經重合（解出的誤差約 10⁻⁹ mm）時，改成距離結合會落在第一個元素法向的一側 | 否則正負號由捨入誤差決定，零件會往任意一側跳 |
| 13 | **新組合件直接進入「開始組合件」**，任何新開或開啟的文件都顯示它的主分頁（組合件或特徵） | SW 的行為；使用者回報找不到「組合件」分頁後修正（ADR 0011 的操作因此少一步） |
| 14 | **STEP 檔可以直接當零組件插入**：清單列出專案資料夾中的 `.3dbx` 與 `.step/.stp`（標示 STEP）；零組件直接引用 STEP 檔，Worker 把它當成「只有一個輸入特徵的零件」重建，與「開啟舊檔」開 STEP 得到的零件完全相同（`blob1`、`import1`、「輸入1」）。不在資料夾裡另外寫出檔案 | 使用者回報：資料夾裡的 STEP 檔沒有出現（計畫本來就是把 SW 輸出的 STEP 當零件用）。同 SW 可直接插入 STEP；只需要讀取權限。持久名稱相同，日後把它存成 `.3dbx` 並改指向它（2D），結合仍然成立。要在 STEP 零組件上加特徵，須先開啟並存成零件 |
| 15 | **找零件時略過 `node_modules` 與隱藏資料夾，最多看 20000 個項目**，超過就提示「只列出一部分」 | 使用者可能直接選「下載」這類大資料夾（本專案本身就在下載資料夾裡，含數萬個檔案） |
| 16 | **選資料夾的對話框說明：下一個視窗只會顯示資料夾** | Windows 的資料夾選擇視窗看不到檔案，使用者以為檔案不見了（2026-09-29 回報） |

## 驗證

- **單元測試**（`packages/assembly/test/suggest.test.ts`）：各種元素組合提供的類型、預設類型、對齊、目前的距離與角度（含反轉與捨入誤差）。
- **瀏覽器驗收**（`tests/e2e/phase2-assembly.js`，`__asm.fixture()`、`__asm.mateExtras()`；所有操作都是 DOM 與指標事件，拾取方式同使用者：游標移到元素上、確認圖面認得是那個元素才按下）：
  - 三個金樣零件組成小夾具：定位板固定；兩支削邊銷各用同軸心（孔與柄）、重合（板面與凸緣底邊）、平行（削平面與板側面）；V 型塊用重合（底面貼板面）與兩個基準面重合（右、前基準面，從浮出樹選）。9 個結合全部成立，四個零組件完全定義，狀態列「完全定義」；銷在 (±40, 0, 0)，V 型塊在 (0, 15, 0)。
  - 故意加入矛盾的距離結合：預覽就顯示矛盾；加入後只有它被指名，V 型塊顯示 (+)，狀態列「錯誤為何？（1 個結合錯誤）」「過多定義」。
  - 從「錯誤為何？」選到矛盾的結合、Delete 刪除後恢復完全定義；選取結合標示它的兩個元素；把一個重合改成 10 mm 距離，V 型塊沿 +x 移 10 mm，復原後回到原位；抑制一個平行結合，銷變成 (-)，恢復後完全定義；存檔再開，位置與狀態相同。
- 畫面以讀回像素確認：零組件在解出的位置，選取結合時它的面以藍色標示。
- **STEP 零組件**（`packages/io/test/stepPart.test.ts`、`tests/phase2/mates.test.ts`、`__asm.step()`）：STEP 檔在清單中標示 STEP，`node_modules` 裡的不列出；STEP 板作為固定零組件，削邊銷以同軸心插入它的孔（依輸入面的名稱 `import1:f7`）、凸緣貼板面，剩 1 個自由度。

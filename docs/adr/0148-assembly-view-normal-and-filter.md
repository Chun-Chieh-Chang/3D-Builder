# ADR 0148：組合件的「正視於」與選擇濾器——兩者原本只限零件

- 狀態：**已完成（2026-10-15）**。不改檔案格式。
- 需求追溯：使用者回報「組合件頁面無法使用『正視於』」，並指出「選擇濾器的功能也是一樣應比照處理」。藍圖外的修正，比照慣例以 ADR 追溯（[ADR 0043](0043-selection.md) 的濾器、[ADR 0145](0145-selection-filter-sw-toolbar.md) 的工具列呈現；0145 與 0043 當時明訂「組合件無此列」，本 ADR 修訂這一點）。
- 使用者裁定：兩項皆要在組合件可用；未另問做法，採 SolidWorks 的做法（見下）。

## 背景（查明的原因）

| 項目 | 原因 |
|---|---|
| 「正視於」 | `view-normal` 的 `enabled` 是 `sketching(s) \|\| partIdle(s)`，而 `partIdle` 要求 `s.active === 'part'`——組合件裡永遠停用（工具列鈕與 Ctrl+8 皆無效）。就算啟用，`normalFrame()` 讀的是零件的 `selected`／`selectedFace`，組合件沒有這些 |
| 選擇濾器列 | `ViewOptions` 以 `!assembly &&` 隱藏濾器列；`filter-bar`（F5）、`clear-filters`（F6）的 `enabled` 是 `s.active === 'part'` |
| 濾器本身 | 組合件的 `AssemblyViewport` 從未呼叫 `viewer.setPickFilter`；且組合件挑元素走的是另一條路 `Viewer.pickElement`（`pickElements`，頂點→邊線→面），這條路完全沒讀 `filter`——就算把列顯示出來也不會有效果 |

## 決定

1. **「正視於」看最後挑的那個平面**（`AssemblyStore.normalFrame()`）：定義結合時是結合的第二個元素、沒有則第一個；不在結合中則 FeatureManager 挑的最後一個基準。元素的幾何取 `elementGeometry`（零件的面／基準面**已套用元件目前的姿態**，在組合件座標中），是平面就以 `planeFrame(origin, normal)` 成框；邊線、頂點、原點、曲面、什麼都沒挑則回等角視圖，與零件的行為一致。再按一次翻到另一面、斜視角時轉為正視，沿用零件的規則（`lookAtNormal` 不變）。
   - 啟用條件：組合件任何時候都可用（含定義結合與量測中——正好是挑面的時機）；工程圖仍不可用。
2. **選擇濾器在組合件**：濾器列與零件相同（四種、單選、F5 顯示／隱藏、F6 全開、記在選項），顯示於圖面左上、與「顯示類型」「剖面」同列。`AssemblyViewport` 把 store 的 `pickFilter` 交給 viewer；`Viewer.pickElement` 依 `filter.vertices`／`edges`／`faces` 略過濾掉的種類——**不會**在濾掉邊線時改回傳底下的面，物體仍遮擋其後的東西，與零件同一語意（只縮小、不放大）。濾器改變時清掉目前懸停的元素。
   - 整個零組件（點一下選元件）不是「元素」，不受濾器影響；FeatureManager 樹上挑基準面也不受影響（與零件相同：零件的樹也不經濾器）。
   - 「基準面」一種在組合件的圖面上沒有可挑的東西（基準面是在樹或結合浮出樹挑的），單選它時圖面上不會找到任何元素，這與零件單選「基準面」時一致。

## 驗收

| 標準 | 結果 |
|---|---|
| A1：組合件的「正視於」可用；FeatureManager 挑組合件基準面後 Ctrl+8 看向該面，再按翻面 | e2e `manual-asm-view-normal.js` 步驟 2、3（視線與 −法向 / +法向的內積 > 0.999） |
| A2：定義結合時挑的元件平面，正視於其目前的位置與方向 | e2e 步驟 4：視線 · `elementGeometry` 法向 < −0.999 |
| A3：沒有可看的平面（沒挑、邊線、頂點、原點）回等角視圖，不報錯 | e2e 步驟 1；單元「nothing picked」「the origin is a point」 |
| A4：結合中取最後一個挑的、不是樹上的挑選清單 | 單元「while a mate is defined」 |
| A5：F5 顯示濾器列、F6 全開 | e2e 步驟 5、8；單元：三個動作在組合件啟用、在工程圖停用 |
| A6：濾器真的篩掉元素：同一個螢幕點（板子最高的角）全開找到頂點；單選邊線找到邊線、單選面找到面、單選頂點找到頂點、單選基準面找不到元素 | e2e 步驟 6（以真實頂點投影到螢幕座標，非 mock） |
| A7：濾器改變時清掉懸停；整個零組件不受濾器影響 | e2e 步驟 7、8 |
| 反向對照 | 還原五個原始檔：e2e 步驟 1～3 失敗（「正視於」鈕停用，視線不動）；放回後全過 |
| typecheck 0、三項 lint、全量 vitest 0 失敗、相關 e2e | 見 DEV_LOG |

## 記憶體（AGENTS.md §3.1、§3.5）

不碰核心與 WASM；只改前端的啟用條件、濾器傳遞，以及 `Viewer.pickElement` 在 JS 端略過某些種類，沒有新增 OCCT 呼叫，不做 Heap 量測。

## 已知限制

- 組合件圖面上的元素挑選目前沒有「濾掉的面變半透明、邊線變淡」的視覺提示（零件有，見 ADR 0117）：該提示依賴零件模式的 `pickFaces`／`pickEdges` 旗標，組合件走另一條挑選路徑。濾器的行為（不懸停、不挑到）已生效，只缺這個視覺提示。
- 「正視於」只看挑的平面；選了整個零組件時回等角視圖（SolidWorks 會看向零組件的前基準面，這裡不做，需要時可挑其基準面）。

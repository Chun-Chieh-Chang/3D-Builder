# ADR 0179：組合件「以座標軸移動」（Move with Triad）

## 1. 背景

審查報告 `docs/ui-interaction-audit.md` §8 第 3 批（差距 #3，H）：組合件沒有 SolidWorks 的「以座標軸移動」（Triad）或 FreeCAD 的 Dragger，精確擺放零件只能自由拖曳或在「移動零組件」面板打數字。使用者於 2026-10-21 確認計畫、驗收標準與三個假設：座標軸對齊**組合件的 X/Y/Z**（不做對齊零組件）；放在零組件的**外框中心**（與右鍵拖曳旋轉的中心相同）；步進預設 **0**（不貼齊）。

## 2. 決策

### 2.1 顯示與操作

- 零組件右鍵選單（與設計樹同一份，ADR 0176）新增「以座標軸移動」（`move-with-triad`），座標軸放在該零組件的外框中心，直到 Esc 或再按一次指令；「移動零組件」開著時，選取的零組件也顯示。固定、被結合完全定義、抑制的零組件不顯示並說明原因（沿用拖曳的 `cannotMove`）。
- 把手：三支箭頭（X 紅、Y 綠、Z 藍）、三個平面方塊、三個圓環、中心灰球；畫在最上層、螢幕上大小固定（`overlayScene`，依 `pixelSize()` 縮放），滑過亮橘色。按下時以 capture 階段的 `pointerdown` 先於視角控制與零組件拖曳取得（比照剖面拖曳）。
- 圓環右鍵：繞該軸 90°、−90°、180°；任一把手右鍵：「移至 XYZ 座標…」打開「移動零組件」的「至 XYZ 位置」、「結束座標軸移動」。
- 「移動零組件」面板新增「座標軸的步進」：移動（mm）與旋轉（°），0 不貼齊；負數、空白、非有限數以 `triadStepsProblem` 拒絕並說明，步進不變（AGENTS.md §2.1）。

### 2.2 運動（`packages/assembly/src/triad.ts`，純函式）

- `triadMotion`：箭頭＝指標射線到軸線最近點的參數差；方塊＝射線與平面交點的差（法向分量為 0）；圓環＝平面上相對中心的有號角，跨過半圈仍連續。看向軸（或平面側視）時無法讀出，保留上一個值。步進以 `Math.round(v/step)*step` 貼齊（這是貼齊的定義，不是改寫輸入）。
- `triadTerms`：給求解器的目標項，依優先序（求解器逐項在前項允許的範圍內滿足）：
  - 箭頭：中心在軸線上（`pointOnLine`）→ 方向不變 → 中心到目標點。
  - 方塊：中心在平面上（新增的 `pointOnPlane`）→ 方向不變 → 中心到目標點。
  - 圓環：先轉到目標方向，再把中心拉回原處。不能把「中心不動」放第一：繞中心的轉動在求解器的變數中不是直線，每一步都會讓第一項多出二次方的誤差而被拒絕（開發中實測：圓環完全不動）。
- `triadHolds`：解出的位姿是否為把手提供的那種運動（箭頭：只沿軸、不轉；方塊：不離面、不轉；圓環：中心不動、軸向不變）。結合只允許「別種運動」時（例如同心於一條不過中心的軸，只能繞那條軸轉），求解器會給最接近的別種位姿；`pumpDrag` 不採用，零組件留在上一個成立的位置。圓環右鍵的 90°／180° 同樣經過此檢查。
- 拖曳沿用既有的 `startDrag` 機制（每次求解從上一個結果出發、碰撞偵測、放開時 `commitMove` 一個復原步驟、Esc 取消）。

### 2.3 求解器

`GoalTerm` 新增 `pointOnPlane`（一條方程式：點到平面的有號距離）。其餘不變。

## 4. 已知限制

- 座標軸只對齊組合件的軸（使用者確認）；不能對齊零組件、不能拖到邊或面上對齊（SW 的 Alt 拖曳）。
- 不做 SW 的「拖曳中心球自由移動」；中心球只有右鍵選單。
- 步進只在「移動零組件」面板設定；單獨用「以座標軸移動」時沿用上次的值。
- 子組合件內的零件不能單獨用（與既有拖曳相同，以頂層零組件為單位）。

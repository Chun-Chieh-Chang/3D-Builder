# ADR 0225: 草圖交叉/分岔子區域探針 (G11, D3)

- 日期：2026-11-02
- 狀態：探針報告（未進入正式實作）
- 相關：G11（plan.md）、D02（acceptance.md）、ADR 0025（輪廓與診斷歷史）

## 1. 探針目的

G11：相交／分岔輪廓不能直接形成 SW 式子區域；需獨立平面區域分割與持久子邊參照。本探針評估可行性（plan.md P5：每項探針 2–4 日）。

## 2. 現有基礎

- `profiles.ts` 已能列舉合法閉合輪廓（contours），含孔洞；G10 已支援畫布選區。
- OCCT 提供 `BRepAlgoAPI_Section`、`BRepAlgoAPI_Splitter` 等布林工具，可用於平面區域分割。
- 現有輪廓以 `contour IDs` 持久化，但子區域（交叉產生的子面）尚無持久參照。

## 3. 可行性分析

### 3.1 幾何分割

- 平面區域分割：給定一組曲線（線/弧/圓/樣條），計算其排列形成的最小區域（faces）。OCCT 的 `BRepBuilderAPI_MakeFace` + `BRepAlgoAPI_Section` 可從 2D 曲線建面並分割。
- 但曲線必須形成封閉環；交叉點需先計算並插入為頂點，否則 OCCT 無法正確分割。
- 本專案目前無「曲線求交插入頂點」的自動化流程；trim/extend 只處理單條曲線。

### 3.2 持久參照

- 子區域需持久 ID，以便模型特徵引用（如拉伸某子區域）。
- 現有 contour ID 方案可擴充，但子區域的邊界由多條原始曲線組成，需記錄「子邊」（sub-edge）參照。
- 當原始曲線被編輯（移動/刪除），子區域拓樸可能劇變，持久 참照需重新映射（類似 TNP）。

### 3.3 風險

1. **拓樸不穩定**：曲線微小變動可能改變子區域數量與邊界，持久參照頻繁失效。
2. **效能**：每次草圖求解後重新計算子區域（平面分割是 O(n²) 或更差）。
3. **使用者認知**：子區域數量可能爆炸（N 條線交叉產生 O(N²) 區域），需 UI 過濾。

## 4. 建議方案

1. **短期（本輪不做）**：G10 已支援合法閉合輪廓；交叉子區域列為候選。
2. **中期**：先做「平面區域列舉」純函式（不持久化），驗證 OCCT 分割能力與效能；估計 6–8 工作日。
3. **長期**：若可行，加入持久子邊 참照與 UI 選區；估計 10–15 工作日。

## 5. 探針結論

- **可行但高風險**：OCCT 能力存在，但拓樸穩定性與效能需驗證。
- **建議**：先做純函式探針（區域列舉），不持久化；證實後再核定範圍。

## 6. 驗收對應

- D02（acceptance.md）：探針報告已交付；子區域邊界/面積/持久참照的支援範圍已列。
- G11：探針完成；建議先做純函式探針。

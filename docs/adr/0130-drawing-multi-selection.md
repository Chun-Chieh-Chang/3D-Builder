# ADR 0130：工程圖的多重選取與一次修改（D-I1a）

- 狀態：**已完成（2026-10-13）**。
- 需求追溯：[ADR 0129](0129-drawing-interaction-roadmap.md) 的 D-I1a（使用者選了縮小範圍：只做多選、框選、批次修改與刪除）。

## 背景

工程圖原本一次只能選一個東西：`selected`、`dimension`、`finish` 是三個互斥的單一 id。所以不能一次把 5 個尺寸改成 ±0.05，也不能一次刪除多個尺寸。

## 決定

1. **選取集合** `DrawingState.selection: {kind: 'view'|'dimension'|'finish'|'table', id}[]`，依選取的先後排列。原本的 `selected`、`dimension`、`finish` 保留，改當「主要」選取，也就是面板顯示的那一個（最後選的），作法比照 SolidWorks 的 PropertyManager。這樣既有的面板與 e2e 腳本都不必改。
2. **一次修改的指令** `DrawingCommand` 新增 `{type: 'batch', commands}`：
   - 在同一個 immer recipe 裡依序執行，所以是**一個復原步驟**，而且**全做或全不做**：任何一個子指令被拒絕，整批都拒絕，文件不變。
   - 拒絕空的 batch 和巢狀的 batch，並明確說明原因。
   - 文件格式不變，batch 不會寫進檔案。
3. **圖紙上的操作**：
   - Ctrl（Mac 上是 ⌘）＋點選：加選或取消，不會開始拖曳。
   - 在圖紙空白處左鍵拖曳：框選。往右拖是窗選，要完全框住才選；往左拖是交叉選，碰到就選。這是 SolidWorks 的慣例。
   - 平移改為只用中鍵或右鍵拖曳（右鍵原本就能平移）。**行為變更**：以前左鍵拖曳空白處也是平移。
   - 框選**不選視圖**：框選常常是拖過視圖去選上面的尺寸，視圖若被框到，按 Delete 就會被誤刪。要選視圖，用點選或 Ctrl＋點選。
   - Delete 刪除全部所選；Esc 取消全部選取。
4. **刪除的順序**：先刪尺寸、表面粗糙度、表格，最後刪視圖。視圖刪除時會連同衍生視圖與上面的東西一起刪，所以已經會被帶走的東西就不再個別刪，避免同一個東西被要求刪兩次而整批被拒。
5. **面板**：
   - 頂部有「已選 N 項／刪除所選／取消選取」。
   - 選了多個尺寸時，尺寸群組改顯示批次區：參考尺寸、小數位數、公差類型與上下限、配合等級。各尺寸不同的值顯示「（各不相同）」，沒有改就保持原樣。
   - 上限和下限逐一套用，每個尺寸保留自己的另一個限值（`setDimensionsEach`）。
   - 所選尺寸裡有角度尺寸時，不提供「配合等級」，並說明原因：角度沒有尺寸大小，查不了 ISO 286 的表。

## 驗證

- `tests/phase5/drawing-selection.test.ts`（9 項）：
  - batch 是一個復原步驟；含一個非法子指令時整批拒絕、文件不變；後面的子指令看得到前面的結果；空的與巢狀的 batch 被拒絕。
  - 框選的幾何用「每條線段取 1000 點」的獨立判定法對照：線段與框各 200 組隨機、窗選與交叉選各 200 組隨機框，差異都是 0。測試也斷言「選中」與「沒選中」兩種結果都有出現，避免測試恆真。
  - 判定法的限制：線段只擦過框角、近到取樣分辨不出的情況，該組不計。文字只比對它的外框，判定方式與實作相同。
- 瀏覽器（定位板，13 個尺寸）：
  - 窗選整張圖頁：選到 13 個尺寸、0 個視圖。
  - Ctrl＋點選可加選和取消；往左拖的交叉選只框到半個尺寸也會選到。
  - 批次加公差後復原一次，文件與原本完全相同。
  - Delete 刪 3 個尺寸，復原一次全部回來。
  - 選一個視圖加上它的一個尺寸一起刪除，成功；復原一次全部回來。
  - Console 沒有錯誤。
- `verify:ui --only drawing|phase5|…`：14 支有 11 支通過。沒通過的 3 支（`manual-drawing-annotate` 的 `choose`、`manual-drawing-linked` 的步驟 2 與 7、`phase5-angle` 逾時）與 handoff 在 10-12 記載的既有失敗相同，不是這次造成的。

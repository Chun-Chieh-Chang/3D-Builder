# ADR 0042：顯示類型、視角選擇方塊、剖面視圖（Phase 3a-9c-1）

- 狀態：已實作（2026-10-01）。
- 對應：A4.3 顯示類型、D4.3 視角選擇方塊、D4.4 剖面視圖，見 [phase3-plan](../phase3-plan.md) §3 的 3a-9c。D4.5 透視／正交沒有做（見「還沒做」）。
- **Schema 不變**：顯示類型與剖面是檢視狀態，不存進文件（不變式 1：文件只放設計意圖）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **五種顯示類型**（`DisplayMode`）：帶邊線塗彩（預設）、塗彩（不畫邊線）、移除隱藏線（白色填滿加邊線）、顯示隱藏線（不填滿，被擋住的邊線用虛線）、線架構。全由材質設定達成，不重建幾何：實體的 `colorWrite`／`depthWrite`、自發光、被擋住的邊線是同一組邊線幾何的第二份，深度比較用 `GreaterDepth`。 | 切換顯示類型不應重算或重新三角化；邊線幾何已經有了。 |
| 2 | **選取在線架構與顯示隱藏線下可以點到背面的元素**；其他類型只有被實體擋住之前的元素才點得到（`firstBodyHit`）。「塗彩」沒有畫邊線，但邊線仍可懸停與點選（顏色和實體相同）。 | 看得到才點得到；線架構看得到的就是全部。 |
| 3 | **視角選擇方塊**（`ViewCube`）在圖面右上角，六個面各一個按鈕，轉到對應的標準視角；方塊跟著相機轉（`Viewer.cubeMatrix` 把相機旋轉換成 CSS `matrix3d`，`subscribeView` 在相機動時通知）。CSS 的座標 y 向下、相機的 y 向上，所以矩陣是 `S·R·S`（S 把 y 翻過來）。**2026-10-14 改為比照 FreeCAD 導覽方塊**：稜邊切 45°、頂角切成垂直於對角線，共 26 個面（6 個八角形、12 個矩形、8 個正六角形，`cubeFacets`，切角 0.24＝FreeCAD 的 0.12），各對應 `cubeDirection` 的一個方向；改用 SVG 依 `cubeMatrix` 正投影畫出朝向觀看者的面（凸多面體，不需排序），面上的字以同一個線性映射貼在面上；四周有旋轉與滾轉箭頭（`viewCubeStep`，預設 45°）。同一個 `ViewCube` 也放在組合件的圖面（`AssemblyViewport`；兩者都用 `store.viewer`）。 | D4.3；標準視角的按鈕（前視、上視…）仍在上方列。 |
| 4 | **剖面**是一個與座標軸垂直的平面（垂直於 X／Y／Z），位置用滑桿（範圍取顯示內容的邊界方塊 `contentBounds`），可以反向；用 three.js 的裁切平面（`clippingPlanes`）作用在實體與邊線，並且實體改成雙面，切開處看得到內側。選取（`kept`）也只認沒被切掉的那一側。 | 動態剖面不改模型、不做布林運算，拖滑桿順暢；只有軸向的平面，任意平面（以面或基準面當剖面）留到後面。 |
| 5 | **選項列**在圖面左上（標準視角列的下方）：顯示類型的下拉選單、「剖面」按鈕、剖面的方向、位置、反向。重算之後（`result` 改變）重新套用。 | 與標準視角列不重疊。 |

## 另外修好的

- **指令列在 1280 寬的視窗裡把整個畫面撐到 2349 寬**：3a-7、3a-8 加了許多指令，`.command-bar` 的最小寬度撐開了單欄的格線，圖面變寬，抬頭的按鈕列與視角方塊都跑到視窗外。`.app` 與 `.workspace` 的欄改成 `minmax(0, 1fr)`，`.tools` 可以縮小並橫向捲動，分頁與商標不換行。這是這次在瀏覽器裡看畫面才發現的。

## 驗證

- 渲染器要 WebGL，沒有單元測試；在無頭 Chromium（SwiftShader）看過：五種顯示類型各一張截圖、剖面把方塊切開、六個面的按鈕與用滑鼠點方塊上的面都把相機轉到對的視角（方塊矩陣：前＝單位矩陣、後＝轉 180° 等）、0 個頁面錯誤（唯一的主控台訊息是 favicon 的 404）。
- `npm run check` 全過（型別、分層、i18n 基準不增加、773 項測試）。

## 還沒做

- **D4.5 透視／正交**：檢視器整個是正交相機（`OrthographicCamera`），縮放、取景、拾取、草圖疊圖都依賴它；換成透視要同時改這些，另外做。
- 任意平面（基準面或模型的面）當剖面、剖面處的截面填色、多個剖面。
- 顯示類型與剖面不存進文件，重新載入會回到預設。

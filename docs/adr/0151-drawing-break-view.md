# ADR 0151：斷裂視圖（D-I6 第一部分）

- 狀態：**已完成（2026-10-19）**。**工程圖 Schema 21 → 22**（遷移空轉，舊程式拒開新檔）。
- 需求追溯：[ADR 0129](0129-drawing-interaction-roadmap.md) 的 D-I6（輔助／斷裂／裁剪視圖）。藍圖 `docs/blueprint.md` C16.3；規格 `docs/drawing-interaction-gap-plan.md`（輔助／斷裂／裁剪三節）。使用者 2026-10-19 決定：三種全做、逐一提交，並先升 Schema v21 → v22。本 ADR 只涵蓋**斷裂視圖**；裁剪與輔助視圖接續實作，另立 ADR。

## 背景

長軸零件（軸、樑、型鋼）在圖紙上若按全長繪製，比例會小到看不清楚。業界做法是**斷裂視圖**：把中段一段略去，兩半靠近並以斷裂線標示，圖上只畫縮短後的樣子。規格要求兩件事：尺寸數值必須仍是**模型的真實長度**（不能是圖上量到的長度），且剖面線不能穿出模型時要明確提示。

## 決定

1. **不是新的視圖種類，而是擺放方式的分段映射**（`break` 加在 `ViewCommon`，所有視圖都能用）：

   ```ts
   interface ViewBreak { axis: 'x' | 'y'; from: number; to: number; gap?: number }
   export const BREAK_GAP = 2; // 缺口預設 2 mm
   ```

   - `from`／`to` 是**模型座標**上要略去的帶狀區間（`to > from`），`gap` 是兩半在圖上被撐開的距離（預設 2 mm）。
   - 略去的帶長 `(to − from)`，圖上兩半之間出現 `gap`，因此**圖上長度 = 模型長度 − (to − from) + gap**。
   - `layout.ts` 提供純函式映射：`brokenAt(b, v)`（模型座標 → 繪製座標）、`unbrokenAt(b, v)`（反向，供指標換算），`toSheet`／`fromSheet` 一律經過它們。帶內的座標沒有東西可畫，映射到帶的近端。

2. **驗證（`checkView` → `checkBreak`）**：軸只能是 `x`／`y`；`from`／`to` 必須是有限數且 `to − from > 0`；`gap` 若給定必須是有限數且 ≥ 0。違反者**在命令層立即拋出顯式錯誤**（`drawing.badBreakAxis`、`drawing.badBreak`、`drawing.badBreakGap`），不默默四捨五入或夾取（AGENTS.md §2.1）。

3. **量測與擺放**（`layout.ts`）：`sizeOf` 以 `brokenAt` 把該軸的外框壓縮後才量大小，所以視圖在排列、堆疊、`at` 定位上就是用**縮短後**的尺寸（`PlacedView.w` 是畫出來的寬度）。`PlacedView.break` 帶著 `{ axis: 0|1, from, to, gap }` 隨視圖傳遞。

4. **繪製**（`scene.ts`）：每個視圖的每一條線都經過 `toSheet`，因此斷裂**自動**作用於可見線、隱藏線、中心線、切線、剖面線、尺寸、註記、表格與氣球——沒有第二套座標。跨越帶的線以新的 `clipToBand`（`geometry.ts`）在帶的兩端精確切斷，**不會橫跨缺口連成一條**。兩端各畫一條細的**斷裂線**（之字，ISO 128-30），跨過視圖在該軸的整個範圍並略微超出。

5. **區間不變式（紅隊防呆）**：尺寸的**數值**取自模型的元素事實（`evaluateDimension(d, elements, axes, own, …)`），`own` 只用來決定畫在哪；再加上 `fromSheet(toSheet(v)) = v`（帶外精確成立），因此「圖上量到的是縮短後的長度、標註的仍是模型長度」在結構上成立，並由測試直接鎖定（見驗收表）。

6. **已知限制（明確記載，非默默降級）**：斷裂的視圖**不塗彩**（`viewImage` 回 `null`）。塗彩是整張零件的一張圖，`SceneImage` 只有一個圓形裁切欄位，無法沿帶切開；若照舊以壓縮後的外框貼圖，會得到一張錯誤的圖。這是有意的選擇：寧可不畫，不畫錯。

## 驗收

| 標準 | 結果 |
|---|---|
| 圖上的長度確實縮短、且兩半之間有缺口 | `drawing-break-view.test.ts`：40 mm 零件、帶 (10, 20)、gap 2 → `PlacedView.w` 為 32；兩半之間為 2、兩半各為 10 與 20（皆以 `toSheet` 實測座標斷言） |
| **尺寸數值必須是模型長度，不能是圖上的長度（紅隊）** | 同一測試：`x(40) − x(0)` 為 32（圖上），而 `fromSheet` 反算為 **40**（模型）；帶外每一點的 `fromSheet(toSheet(v)) = v` 精確成立 |
| 線在帶的兩端被切斷，不橫跨缺口 | 同一測試：跨越帶的線得到兩段，繪製座標排序為 84 / 94 / 96 / 116，帶內（94–96 之間）沒有任何點 |
| 斷裂線畫在缺口的兩端 | 同一測試：兩條細線，平均落在 94 與 96，各跨 y = 0…20 並超出 3 mm |
| 沒有斷裂的視圖行為完全不變 | 同一測試：`viewItems` 一條可見線、零條細線；`toSheet` 距離仍為 40 |
| 非法輸入當場拒絕 | 軸非 x/y、`to ≤ from`、NaN／Infinity、`gap < 0` 四類皆拋出顯式錯誤（訊息含方向／兩個／缺口） |
| 存檔讀回與舊檔升級 | `parseDrawing(serializeDrawing(doc))` 保留 `break`；把版本改成 21 的檔案讀入後 `break` 缺席且視圖完整（走 `drawingMigrations[21]`） |
| 塗彩的降級是明示的 | 同一測試：未斷裂且塗彩 → `viewImage` 有值；斷裂且塗彩 → `null` |
| typecheck 0、lint 全過、全量 vitest 0 失敗 | typecheck 0；`lint:rules`／`lint:deps`／`lint:i18n` 全過；**233 檔通過、2942 過、25 略過、0 失敗** |
| `verify:ui` | **未執行**（本機 `verify:ui` 超過 25 分鐘逾時，與 B2.6 相同；斷裂的介面操作未經瀏覽器驗證，列為後續） |

## 已知限制

- 斷裂視圖不塗彩（見決定 6）。
- 每個視圖只有**一個**斷裂帶（`break` 單數）；兩個以上的帶（例如兩端各略一段）尚未支援。
- 帶內的座標映射到帶的近端，因此指標落在缺口上時會吸附到近端（沒有東西可指）。
- 尺寸的**繪製幾何**照樣經過映射：一個正好跨越帶的尺寸，其延伸線／尺寸線在缺口處會被切斷（線的切斷由 `clipToBand` 負責，數值不受影響）。
- 介面只在「視圖屬性」提供一組欄位（方向、從、到、缺口）與套用／取消兩個按鈕；未提供在圖上直接拖曳斷裂線。

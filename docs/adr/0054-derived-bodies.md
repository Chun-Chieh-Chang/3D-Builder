# ADR 0054：衍生本體與從本體產生組合件（Phase 4a-1，C7.5，零件 Schema 26）

- 狀態：已實作並驗證（2026-10-03）。限制見最後一節。
- 相關：[phase4a-plan](../phase4a-plan.md)（設計與取捨）、[ADR 0022](0022-multiple-bodies.md)（本體的身分是建立它的特徵的 id）、[ADR 0049](0049-step-assembly-import.md)（寫檔案的做法）、[ADR 0050](0050-parts-list-and-exploded-view.md)（零件表）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **新特徵 `derivedBody { source, body }`**（零件 Schema 26）：`source` 是主模型檔，相對於這個檔案（`/` 分隔，同組合件的檔案參考，`isFilePath` 檢查）；`body` 是主模型裡本體的 id。檔案裡**只存這兩個字串**，不存形狀、名稱、尺寸 | 一值一處（SSOT）；舊版程式不會跳過一個它不認得的特徵（版本號擋住）。v25 → v26 無需轉換，已補 v25 樣本 |
| 2 | **形狀來自重算主模型**：`Regenerator` 多一個 `SourceProvider`（`get(相對路徑) → { key, doc, blobs, sources? }`），衍生本體特徵重算時取得主模型、重算（以子 `Regenerator`）、依 id 取出本體、`kernel.clone`（不共用面）。每個檔案帶自己的提供者，所以主模型自己也衍生自別的檔案時，路徑是相對於它的 | 沿用既有重算，不另寫第二套形狀來源；衍生自衍生（鏈）自然成立 |
| 3 | **名稱沿用主模型**：面、邊、頂點的持久名稱照主模型本體的那一段原樣取用（`names` 切片；`clone` 後面序不變，已驗證）。所以組合件對衍生零件的面做的結合（用持久名稱），主模型改尺寸後照樣成立，不用重新指定 | 夾具的核心需求：改基板厚度，結合不壞 |
| 4 | **本體名稱與「參考本體」旗標沿用主模型**（`RebuildResult.bodies` 的 `name`、`reference` 先看零件自己的 `bodies`，再看沿用的）。零件自己改名有效；**參考旗標在衍生零件裡關不掉**（`setBody` 的 `reference: false` 是「取回選擇」，所以回到主模型的設定）：要讓一個衍生零件不是參考，得在主模型取消 | 參考旗標是主模型的設計意圖（工件只是依據） |
| 5 | **環與錯誤**：檔案的 `key`（專案路徑）沿著一條鏈累積，同一個 key 再出現就是環，報「主模型檔案直接或間接衍生自這個檔案」；沒有提供者、找不到檔案、找不到本體（列出主模型現有的本體 id）都各報一句話，特徵出錯、零件沒有本體 | 錯誤要說得出原因（ADR 0022 的前例） |
| 6 | **快取只在一個 `Regenerator` 之內**：同一份主模型文件（物件相同）在它的連續重算中只算一次，不再用到的主模型在重算結束時釋放，`dispose` 全放。**跨 `Regenerator` 不共用**，所以組合件有 N 個衍生零件就重算 N 次主模型 | 先求對；計畫的風險 2，量測後再決定要不要做跨零件快取 |
| 7 | **`derivedAssemblyFiles`**（`@3db/io`，純函式）：每個本體寫一個衍生零件檔（`零件/<本體名>.3dbx`，只含一個 `derivedBody`，`source` 是 `../<主模型檔名>`）加一個組合件 `<主模型名> 組合件.3dba`，每個零組件在原位（單位位姿）且固定、沒有結合。名稱撞到（含資料夾裡已有的）加序號，不覆寫 | 本體已在主模型的座標系，原位就是對的位置；固定是 SolidWorks 的做法 |
| 8 | **網頁版**：Worker 協定帶 `sources`（`SourceFileData`：`ref`、專案路徑 `path`、位元組、巢狀的 `sources`），`rebuild` 與 `buildPart` 都收；Worker 先把檔案讀成文件再交給 `Regenerator`（`SourceProvider.get` 是同步的）。App 端 `gatherSources` 沿著 `derivedBody` 讀專案資料夾，**零件的內容鍵 = 它自己的位元組加上每個主模型的內容鍵的雜湊**（沒有主模型時仍是檔案的雜湊），否則 Worker 以內容快取零件，主模型變了零件卻不重算。組合件記下每個衍生零件讀過的主模型的 `大小:修改時間`，視窗回來時 `refresh` 一併檢查，主模型變了就重讀該零件 | 內容鍵不含主模型，是這個設計最容易錯的地方 |
| 9 | **零件表排除只有參考本體的零件**：`PartBuildPayload.referenceOnly`、`BomInput.isReference`；只有參考本體的零件質量為 0（`combineMass` 對空的處理），所以物質特性不受影響；圖面照常畫、干涉檢查照常比 | 藍圖 C15.16 與 ADR 0022 決策 6 留下的債（參考本體不進零件表） |
| 10 | **介面**：「檔案」→「從本體產生組合件」（零件已儲存、沒有未存的變更、至少一個本體才可用）：問要寫入的資料夾（寫入權限，必須是直接放著主模型的那個資料夾），寫檔，該資料夾成為專案資料夾，開啟組合件。零件編輯時（`masterFiles`）若零件是專案資料夾裡的檔案，重算也帶上主模型 | 沿用 3b-3 輸入 STEP 組合件的流程與對話框 |

## 驗證（證據）

- **核心**（`tests/phase4/derived-body.test.ts`，10 項）：三個本體各自衍生，體積 120000／144000／6000（手算）、面數、面的種類／面積／中心逐面相同、面／邊／頂點名稱與主模型本體的那一段相同；名稱與參考旗標沿用、自己的名稱優先；基板改成 20 厚後，衍生零件與「從頭以 20 厚建」的對稱差 < 1e-6、面名稱不變；衍生零件上再加孔（主模型不受影響）；重算不洩漏形狀；沒有提供者／找不到檔案／找不到本體（列出 `ew, eb, ec`）／環／鏈的訊息與結果。
- **組合件層**（`tests/phase4/derived-assembly.test.ts`，6 項）：產生的檔案（3 個衍生零件 + 1 個組合件，零件檔只含 `derivedBody`、組合件 3 個固定在原位的零組件）、名稱已被佔用時加序號、開啟後各零件體積與參考旗標、**對衍生零件的面做重合結合，主模型基板由 15 改 20 後結合成立、壓板高度由 15 變 20**、本體從主模型消失時的訊息、零件表排除工件。
- **舊檔**：v25 樣本（`v25-notes.3dbx`）在 Schema 26 開啟、註解與標籤保留、可重算。
- **瀏覽器**（`tests/e2e/phase4-derived.js`，0 Console 錯誤）：開啟主模型（3 個本體、工件為參考）→「從本體產生組合件」→ 寫出 4 個檔案並開啟 → 3 個零件讀取並建好、3 個零組件固定、畫面 3 個實例、基板高 15 → 零件表只有 基板、ec → 把主模型存成 20 厚、`refresh` 後基板重新建好、高 20。
- `npm run check`：961 項通過。

## 限制與未做

- **同一個編輯階段內不即時更新**：改主模型後要存檔，組合件在重新載入或視窗回來時才更新。要即時更新需要跨文件的相依圖。
- **跨零件不共用主模型的重算**（決定 6）：N 個衍生零件重算 N 次主模型；大主模型會慢。
- **編輯衍生零件**需要它是專案資料夾裡的檔案（要找得到主模型）；否則特徵報「沒有提供讀取…」。
- **本體 id 變動就壞**：刪掉建立本體的特徵、或切開的碎塊 `#k` 重新編號（ADR 0022 決策 4 已固定規則），衍生零件報「主模型沒有本體 X」並列出現有的，不會自動改接；對它的結合也會遺失。
- **環的訊息**：App 端為了結束遞迴，會把成環的檔案當作沒有主模型，所以使用者看到的可能是「找不到主模型檔案」而不是「環」（核心層的環訊息有測）。
- **衍生零件不能取消參考旗標**（決定 4）。
- **主模型的「參考本體」改了**，已產生的零件表會跟著變（沿用，不是複製），但已存的 `PartBuildPayload` 要重建才會變——`refresh` 會處理。
- 沒有「更新衍生零件」或「重新產生組合件」的介面：新增的本體要再執行一次「從本體產生組合件」（會產生第二個組合件，不覆寫第一個）。

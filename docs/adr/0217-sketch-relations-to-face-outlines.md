# ADR 0217：草圖線與曲面輪廓的限制條件

日期：2026-10-27。狀態：已實作；遠端三平台 CI 待本次執行結果。

## 問題

使用者回報：在 右基準面 的草圖中，一條「水平」的線停在圓柱灰色輪廓上緣上方，無法與輪廓共線；PropertyManager 只有「垂直／固定」可加。

## 根因

1. **輪廓不是邊，而草圖只拿得到邊。** 草圖的模型抓取與選取（`modelSnapItems`，D5.3b／C1 2026-10-14）只列模型的邊、貫穿點與頂點。圓柱側看時，上緣是曲面的視輪廓（silhouette），拓樸上沒有邊；兩端圓邊側看成一條線而被略過，縫合邊也不列。所以游標在那裡抓不到東西，選取工具點下去也沒有物件，選取只有草圖線一個，只能提供單線的「水平／垂直／固定」。
2. **就算選得到，「共線」也會被拒絕。** 跟隨模型的圖元兩端是固定的；線本身已有「水平」，再加「共線」時「平行」部分與「水平」重複，求解器回報過多定義，而且它指出的多餘項是新加的「共線」。`addRelation` 因此以「會使草圖過多定義」拒絕，使用者無從得知是舊的「水平」該移除。

「輪廓」工具（`silhouetteProjector`、`ref.silhouette`）早已能把曲面輪廓轉成跟隨模型的圖元，只是要先切換工具；抓取與選取沒有用到它。

## 決策

- `ReferenceScope.outlines`：Worker 以同一個 `silhouetteProjector` 提供每個曲面的全部輪廓。`modelSnapItems` 在邊之後加入非平面面的輪廓，ref 為 `{ kind: 'face', name, fingerprint, silhouette }`，與「輪廓」工具做出的參照完全相同，因此重建、改尺寸後跟隨、存讀都沿用既有鏈路。
- 不重複：與邊看起來一樣的輪廓就是那條邊（邊優先，名稱較穩定）；看起來一樣的多個輪廓取面中心最近草圖面的一個。輪廓的端點不算「角點」，也排在頂點之後：圓錐側看時輪廓止於頂點，頂點仍保留並優先，點畫在那裡跟隨的是頂點，而不是輪廓的端點（第一版沒有這樣做，完整 `verify:ui` 的 `manual-sketch-vertex` 因此失敗而發現）。平面沒有自己的輪廓；圓柱／圓錐沿軸看（孔壁）沒有輪廓，直接略過不做 HLR。輪廓含橢圓（草圖無法保存）或核心做不出時，該面不提供抓取，不報錯——抓取只是輔助。
- 選取工具點在輪廓上：沿用 `anchorModelForSelection`，做出建構線並選取，於是「共線／平行／重合……」照一般兩線提供。
- 「共線」或「平行」過多定義時，逐一試著移除所選線本身的「水平」或「垂直」：移除後能解，**且該線求解後仍是水平（或垂直）**，才以一個 `editSketch` 同時移除舊的、加入新的（一次復原），並告知使用者。移除後能解但線被轉向的，是衝突而不是多餘，照舊拒絕。
- 成本：每個曲面一次 HLR，36 孔板約 3.4 ms／面。Worker 以「草圖之前的特徵與文件設定（不含 id 計數、顯示、外觀、屬性）、草圖 id、平面、顯示中的草圖」為鍵快取抓取項目；有主檔來源時不快取，因主檔可能在文件之外改變。

## 限制

- 側看的圓邊（端面圓）投影是一條線段，目前仍不提供抓取（既有行為，`modelSnapItems` 略過傾斜圓）。
- 輪廓為橢圓的曲面（斜看的圓柱端面以外，例如傾斜圓錐的部分情形）不提供抓取。
- 輪廓參照以 `silhouette` 序號跟隨，序號在幾何變化後改變時明示失效（既有「輪廓」工具的行為）。
- 既有行為、未在本次修改：「垂直」線與水平固定線「共線」時，求解器以把線縮成零長度滿足兩者，回報「定義不足」而被接受。

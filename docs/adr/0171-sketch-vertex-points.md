# ADR 0171：模型頂點投影成草圖點（G2）

## 1. 背景
這是 2026-10-19 草圖參照盤點的 G2。目前草圖要跟著一個模型頂點走，只有一個辦法：吸附「模型端點」。這會把整條邊轉成建構線，再讓新點與它的端點重合。這個做法有三個問題：
- **吸不到的頂點**：只有直線邊和平行圓會產生吸附項目。以下幾類頂點完全吸不到：
  - 只連著「與草圖平面垂直的邊」的頂點；
  - 只連著傾斜圓、雲形線、橢圓的頂點；
  - 錐頂。
- **轉換實體引用不收頂點**：`convertPicked` 只收邊和面。SolidWorks 轉換頂點會得到一個點；FreeCAD 的外部幾何也可以選頂點。
- **多餘的圖元**：只要一個點，卻得多一條建構線，以及跟著它的端點和關係。

## 2. 決策
1. **`SketchEntity` 的點新增 `ref?: Ref`，種類為 `vertex`**：
   - 點的位置是頂點沿草圖法向投影到草圖平面上的位置，跟著模型走。
   - 與 `pierce` 互斥：一個點最多跟著一個模型元素。
   - G3 的基準點會沿用這個欄位（屆時放寬為 `datum`）。
2. **Schema 69**，沒有資料要轉換。
3. **轉換實體引用**：工具開著時，圖形區也可以點頂點，結果是一個帶 `ref` 的點；同一個頂點已經有點時，不再重複加。
4. **吸附**：只**補上**目前吸不到的頂點，也就是投影位置不是任何吸附項目的端點、圓心或貫穿點的頂點。點下去得到一個帶 `ref` 的點。
   - 已經吸得到的「模型端點」仍照 ADR 0136 產生建構邊，不改既有行為，免得已經建好的草圖和腳本跟著變。
   - **只是 B-rep 封閉環起點的頂點不列入**：如果一個頂點除了接縫邊和退化邊之外，只連著起點和終點都在它身上的封閉邊（例如孔緣、錐底圓上的接縫頂點），它只是參數化的產物，不是設計上有意義的點。
     - 第一版沒有這條規則，既有的 `sketch-snap.test.ts` 有 2 項轉紅：板上的孔多出一個邊緣點。這是正確的紅燈，讓使用者吸到圓周上任意一點沒有意義。
     - 錐頂沒有封閉邊，照常列入。
5. 共用的 `modelRefOf(e)` 傳回一個圖元跟著的模型元素：點的 `pierce` 或 `ref`、曲線的 `ref`。原本散在 5 處、各自寫的判斷都改用它，避免漏接（AGENTS §2.1-3）。

## 3. 設計
- `references.ts`：
  - `vertexPoint(topology, index, frame)` 計算頂點的投影位置；
  - `followReferences` 把這種點放到投影位置並固定；
  - `convertEdges` 收到頂點時產生一個點；`pierce` 模式拒絕頂點；
  - `ConvertRequest.edges` 也可以放頂點，不另加欄位；
  - `modelSnapItems` 補上前述吸不到的頂點，以 `vertex` 項目表示，`off` 是頂點到草圖平面的距離；離平面近的排在前面，投影位置重疊時取較近的。
- `ops.ts`：
  - `ModelItem` 新增 `{ ref, vertex: P2, off? }`；
  - `anchorModel` 和 `anchorModelForSelection` 遇到這種項目時，沿用已有的點，或新建一個帶 `ref` 的點；
  - `referenceEntities` 以 `vertex:<name>` 去重。
- `interact.ts`：`snapModel` 把頂點和端點、圓心放在同一個優先層級，`part` 為 `'vertex'`。
- 介面：
  - `Viewport.picking` 在轉換實體引用工具下開放點選頂點；
  - `store.convertPicked` 接受頂點；
  - 推斷文字「模型頂點」；
  - 跟著模型走的點以參照色顯示。

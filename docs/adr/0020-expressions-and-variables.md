# ADR 0020：運算式、全域變數與檔案屬性（3a-1）

- 狀態：已採用（2026-09-30）。範圍：藍圖 B5.2 全域變數、B5.3 數學關係式、D2.4 數值框輸入運算式與單位、B8.3 檔案屬性；Schema 8。
- 依據：藍圖 §2.3 與附錄 C；phase3-plan §3 的 3a-1；ADR 0001（一值一處）、ADR 0019（訊息用 `t()`）。
- **假設**（使用者沒有指定，我依 SW 的習慣決定，寫在這裡讓你能推翻）：尺寸的引用寫法沿用 SW 的 `D1@草圖1`；沒有單位的數在長度裡是 mm、在角度裡是度；`sin(30)` 是 30 度；沒有做文字或陣列變數。

## 1. 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **文件只存運算式字串**，沒有第二份值。`Expr` 仍是 `string`：舊檔的 `"20"`、`"25.4mm"` 原樣有效。`PartDoc.variables`（`{id, name, expr}`）與 `properties` 早已在 Schema，這次開始使用。**Schema 升為 8**，遷移是空操作（同 v3–v6：純粹讓舊版程式不要打開它看不懂的檔案） | 不變式 1；值是重算的衍生資料 |
| 2 | **運算式語言**（`packages/model/src/expr/`，自寫解析器，不用 `eval`）：數字（含 `1e3`）與單位（`mm cm m in " deg ° rad`，緊接在數字後）、`+ - * / % ^`（`^` 右結合且高於一元負號）、括號、比較 `< > <= >= == !=`、`&& || !`、函數（`sin cos tan asin acos atan atan2 sqrt abs round floor ceil sign exp ln log log10 pow min max if property`）、常數 `pi`、`e` | 藍圖 B5.3：運算式、函數、單位、條件 |
| 3 | **值帶著量綱**：`{v, L, A}`（內部單位 mm 與 rad，加上長度與角度的次方）。`3mm*2` 是長度、`10mm/2mm` 是無單位的數、`3mm*3mm` 是長度² 並在需要長度的地方報錯。**沒有單位的數與有單位的數相加、相減、比較時，取對方的預設單位**（`3mm + 5` = 8 mm），同 SW；長度與角度相加是錯誤。最後依使用處收斂：長度處的裸數字是 mm、角度處是度 | 與 Phase 1 的行為完全相容，又能正確處理 `atan`、面積、角度運算。「單位不符」在算的時候就報，不是算出一個錯的數 |
| 4 | **名稱**：全域變數 `wall_t`（文字、數字、底線，可用中文，不能以數字開頭）；草圖的**驅動尺寸** `D3@草圖1`（SW 的寫法）；名稱含空白或符號時用雙引號 `"my dim@草圖 1"`。一個草圖內的尺寸可以直接寫 `D1`（不含 `@`）；**變數優先於同草圖的尺寸**。**參考尺寸（非驅動）不能被引用**（值來自求解結果，會循環）。特徵參數（伸長深度等）不能被引用，只有變數與草圖尺寸可以 | 與藍圖 B5.1 的 `D1@草圖1` 一致；只開放「輸入」性質的值，避免特徵參數與求解結果變成新的相依來源 |
| 5 | **尺寸的名稱** = 使用者給的 `label`，沒有就是 `D` 加上永久 ID 的數字（`d3` → `D3`）。ID 不重用（B1.3），所以名稱不會靜默指到別的尺寸。**不同於 SW**：SW 是每個草圖各自從 D1 起算；這裡是整份文件的序號，第二個草圖的第一個尺寸可能叫 `D4`。要好記的名字就改名（`setDimensionLabel`） | 不必新增儲存欄位與遷移；已有的 ID 政策就是穩定性的保證 |
| 6 | **檔案屬性**：`property('厚度')` 讀 `PartDoc.properties` 的文字並解析成數（可帶單位：`2.5mm`）；找不到或不是數值是錯誤。屬性名稱不會隨改名重寫（只有變數、草圖名稱、尺寸名稱會） | B8.3；屬性是自由文字（廠商、料號），只有數值的才能拿來算 |
| 7 | **求值順序不重要，循環會被指出來**：`Parameters`（`packages/model/src/params.ts`）依需要求值、每個節點只算一次；遇到正在求值的節點就是循環，訊息含完整路徑（`循環引用：a → b → a`）。指令在**套用之後**檢查（所以經過它的循環一定被看到），不合法就整個指令被拒絕 | 藍圖：循環相依檢查；不需要另外維護一張相依圖，也沒有「求值順序」這種隱含狀態 |
| 8 | **邊界：先解析成數字，再交給求解器與核心。** `resolveDoc`／`resolveSketch` 把每個運算式換成它的值（長度寫 mm 的數字，角度寫 `…rad`，精確往返），沒有名稱要查的原樣保留；`Regenerator.rebuild` 一開始就做，草圖求解前在主執行緒做。**PlaneGCS 與 OCCT 只看到數字，這次一行都沒改。** 算不出來的特徵回報原因（`status: 'error'`），其他照常建構 | 最小的改動面；失敗是明確的（沒解析的運算式進到求解器會因為沒有環境而報「找不到變數」，不會靜默算錯） |
| 9 | **值的範圍規則只有一套**（`roleProblem`）：尺寸、深度、半徑、距離要大於 0；旋轉 0–360°；導角角度 0–90° 等。指令（編輯當下）與重算共用它。**重算時也檢查**，因為改一個變數就能讓另一個尺寸變成 0，指令當下看不到（測試發現：原本這樣的尺寸會建出退化的草圖） | 一處定義 |
| 10 | **改名會一併改寫引用**：改變數名稱、改草圖名稱（`renameFeature`）、改尺寸名稱（`setDimensionLabel`）時，所有運算式裡的舊名稱（只換名稱那一段，其餘文字與空白照舊）改成新名稱。**刪除變數**若還有運算式在用會被拒絕並列出誰在用 | 同 SW；不做的話改名會讓模型靜默壞掉 |
| 11 | **父子關係由運算式推導**（`expressionParents`，接進 `regen/dag`）：一個特徵的運算式（含經過變數）用到哪個草圖的尺寸，它就是那個草圖的子特徵。刪除、抑制、「父子關係…」因此看得到 | 藍圖：由運算式推導父子關係 |
| 12 | **介面**：「工具」分頁的「方程式」與「檔案屬性」對話框（變數與草圖尺寸的名稱、運算式、值；屬性的名稱與值），改錯時輸入框變紅、滑鼠停上去看原因；屬性管理員的數值框（伸長、圓角、導角、基準面、旋轉）本來就接受文字，現在會在旁邊顯示運算式的值（`= 7.5 mm`）與錯誤；草圖裡由運算式驅動的尺寸標示 `Σ60`（SW 的記號），按兩下編輯看到的是運算式 | D2.4 |
| 13 | **所有新文字用 `t()`**（`zh-TW/expr.ts`、`equations.ts`、`model.ts`），`lint:i18n` 的基準只降不升（639 → 638） | ADR 0019 |

## 2. 與計畫不同的地方

phase3-plan §3 寫「用型別讓『沒有環境的求值』編譯不過」。**沒有照做**：`evalLength(expr, env = NO_ENV)` 的環境有預設值。理由是決策 8：求解器與核心只會看到已解析的數字，強制每個呼叫點傳環境要改 30 幾處（組合件的結合值、移動面板等根本沒有變數）。替代的保護是：忘了解析的運算式在沒有環境時會明確報錯（測試：`找不到變數「nope」`），不會算出一個錯的數。

## 4. 尚未做

- **文字與條件式以外的資料型別**：沒有字串運算、沒有陣列；`property()` 只讀數值。
- **屬性改名不會改寫引用**（只有變數、草圖、尺寸）。
- **特徵參數不能被引用**（例如 `深度@伸長1`）；SW 可以。要做時要決定它們在相依圖中的位置。
- **設計表格、組態**（藍圖進待辦池）。
- **組合件的結合值**（距離、角度）與移動面板仍然只能用數字與單位，沒有變數（組合件文件沒有變數）；運算式語言本身可用（`10*2`）。
- 尺寸旁沒有內嵌顯示名稱（`D3@草圖1`）；名稱在方程式對話框與提示裡。
- 沒有「連結數值」（SW 的多個尺寸共用一個值）；用變數取代，藍圖 B5.4 已併入 B5.2。
- 手寫的公式有語法錯誤時，位置是字元序號（第 n 個字元附近），沒有在輸入框裡標出來。

# ADR 0146：工程圖六項與 SolidWorks 對齊——回到零件、顯示樣式與塗彩、剖面解除對齊、尺寸樣式、斜角等角投影

- 狀態：**已完成（2026-10-15）**。**工程圖 Schema 18 → 19**（視圖 `hidden` 遷移為 `display`）。
- 需求追溯：使用者在「零件1」工程圖（A3 橫向、第三角、13:10；前視、B-B、A-A、下視、等角）回報的六個問題。藍圖外的修正，比照慣例以 ADR 追溯（工程圖互動路線圖見 [ADR 0129](0129-drawing-interaction-roadmap.md)；開啟零件見 [ADR 0140](0140-drawing-open-part.md)）。
- 使用者裁定（2026-10-15，選擇題）：新等角視圖預設「帶邊線塗彩」；剖面以「右鍵解除對齊」自由擺放；尺寸樣式做「整張圖＋單一尺寸覆寫」；斜角投影「依象限的等角投影，保留母子關係」。第 1 項未另問：瀏覽器保留 Ctrl+Tab，網頁收不到，因此不做快捷鍵。

## 背景（查明的現況）

| # | 回報 | 查到的原因 |
|---|---|---|
| 1 | 不知道怎麼從工程圖回到零件 | 只有視圖右鍵「開啟零件」（ADR 0140），畫面上沒有任何常駐入口 |
| 2 | 等角視圖不能塗彩 | 視圖只有 `hidden: boolean`；工程圖的場景只有線與字，沒有面 |
| 3 | 剖面視圖不能拖到任意位置 | 拖曳時預設只沿對齊線滑動；按住 Shift 才自由，但完全沒有提示，也沒有「解除對齊」 |
| 4、5 | 尺寸字高、線寬、箭頭樣式與大小不能改 | `DIM_TEXT = 3.5`、`ARROW = 3`、線寬 0.25 都是寫死的常數，文件沒有欄位 |
| 6 | 往斜角拖出的投影視圖方位不對 | 斜角一律放一個獨立的 `isometric` 模型視圖（固定從 +x+y+z 看），與拖往哪個角、母視圖朝哪都無關 |

## 決定

1. **回到零件**：工程圖設計樹最上方常駐「開啟零件：<檔名>」列（`data-action="openDrawingPart"`，樣式同零件樹的「返回工程圖」列）；「檔案」與「視圖配置」選單各有「開啟零件」。開的是選取視圖的零件，沒有選取就開第一個視圖的（`DrawingStore.partToOpen`），沿用 ADR 0140 的 `openPartOfDrawing`（未存檔先詢問、零件樹上「返回工程圖」）。
2. **顯示樣式**（`ViewCommon.display`）：`wireframe`（隱藏線畫成可見線）、`hiddenVisible`（虛線）、`hiddenRemoved`、`shadedEdges`、`shaded`（不畫可見線與隱藏線；中心線與剖面線照畫）。未設定時沿用原本預設（剖面「移除隱藏線」，其他「隱藏線可見」）。新放的等角視圖與斜角投影視圖預設 `shadedEdges`。展開圖沒有面可塗，介面不提供塗彩。
   - **塗彩做法**：`Kernel.projectView(..., { mesh: true })`（剖面的 `sectionView`／`sectionViewPath` 同樣傳下去，因此塗的是切過之後的形狀）另回傳**視圖座標**的網格（x、y 與線條相同，z 指向觀看者）。worker 以**深度緩衝**光柵化（`rasterizeShade`：每個像素取最靠近觀看者的面，不用三角形排序——大面旁邊有小的近面時排序會錯），再以 `CompressionStream` 編成 PNG 與 PDF 用的兩條 zlib 串流（RGB、alpha，每列前置 PNG 濾波位元組 0，PDF 以 `/Predictor 15` 解）。密度為圖紙每公釐 8 像素乘以視圖比例（細部放大圖的父視圖取較大者），單張上限 400 萬像素，超過就降密度而不是放大。光源固定（左上前方，雙面打光），顏色固定淺灰藍。
   - 場景新增 `scene.images`（在所有線之下）；SVG 以 `<image>`、細部放大圖以 `<clipPath>` 圓裁切；PDF 以影像 XObject＋`/SMask`、圓形以 `W n` 裁切；**DXF 不輸出影像**（工程圖的 DXF 是線，與 SolidWorks 相同）。塗彩失敗時線照畫並通知原因。
3. **剖面／投影視圖解除對齊**：右鍵選單「解除對齊」把視圖目前的位置寫入 `at`（`DrawingStore.breakAlignment`），之後可拖到任意位置；「預設對齊」清除 `at` 回到對齊。按住 Shift 拖曳仍可暫時自由移動，完成「解除對齊」時的提示會說明。斜角投影視圖本來就沒有對齊線，不顯示這兩項，「自動排版」也停用（拿掉位置會違反下面第 5 點）。
4. **尺寸樣式**（`DimStyle`：`text` 字高、`arrow` 箭頭長、`arrowStyle` 實心／空心／斜線／圓點／無、`line` 線寬）：`sheet.dimStyle` 是整張圖的，`dimension.style` 是單一尺寸的覆寫，`resolveDimStyle` 依「尺寸 → 圖面 → ISO 預設（3.5／3／實心／0.25）」合成。範圍：字高 1～20、箭頭 0.5～20、線寬 0.13～2 mm（ISO 3098、128-20）；超出、非數字、未知欄位或樣式一律 `CommandError` 拒絕並說明，**不四捨五入、不夾到範圍內**；空的樣式等於沒有。
   - 繪製：`evaluateDimension` 接受樣式，文字高度、箭頭幾何（實心／空心的半寬為長度的 1/6、斜線 45° 長度＝箭頭長、圓點半徑＝箭頭長的 1/5）、尺寸線寬都從樣式來；線寬等於預設時不寫 `width`，舊圖面畫出來完全不變。
   - 輸出：SVG／PDF 用 `width`；DXF 的 STANDARD 尺寸型式寫圖面的字高（140）與箭頭長（41），個別線寬以群組碼 370 寫最接近的標準線寬（DXF 只能表示標準值）。
   - 介面：圖頁屬性「尺寸樣式」群組；尺寸屬性「此尺寸自訂樣式」勾選後出現同樣的欄位（多選時一次套用）；「恢復預設」清除。
   - 範圍限定為尺寸（含座標尺寸）；註解、公差框、表格仍用原本的字高。
5. **斜角等角投影**（`ProjectedDrawingView.side` 可為 `upLeft`／`upRight`／`downLeft`／`downRight`）：觀看者在母視圖的前方，並依角落在右／左、上／下（第三角法為放置的那一角，第一角法為對角，與四個側邊的規則一致），三個方向等量，所以是真正的等角（與母視圖三軸的夾角餘弦皆為 1/√3）。從第三角法前視圖的右上角拖出，正好等於零件本身的等角視圖。它仍是母視圖的投影視圖：母視圖換方向會跟著轉。它不與任何視圖對齊，所以**必須有 `at`**（命令層強制）。屬性的「側邊」選單在斜角視圖上改列四個角。
6. **Schema 18 → 19**：遷移把 `hidden: true` 轉成 `display: 'hiddenVisible'`、`false` 轉成 `'hiddenRemoved'`，未設定的維持未設定；新增欄位都是選填。視圖再出現 `hidden` 欄位即拒絕（避免兩個欄位互相矛盾）。

## 記憶體（AGENTS.md §3.1、§3.5）

塗彩只多做一次 `BRepMesh`（不做布林）。以 `wasmMemory.buffer.byteLength`、每種情境各自一個全新 Heap、各 2000 次等角視圖（40×30×20 板）量測，先斷言基準 > 0：只做隱藏線 **+25.6 MiB**（零件事先網格化與否相同）、只做網格 **+0.0**、兩者一起 **+56.4 MiB**，即塗彩一張視圖比不塗彩多約 **0.015 MiB**；對照組 1000 次剖面（OCCT 布林）+366 MiB，證明量測看得到成長。**沒有**宣稱 0 洩漏。塗彩每次視圖變更只算一次並快取；新路徑建立的形狀以 `liveShapes` 驗證全數釋放（`drawing-shade-memory.test.ts`）。剖面塗彩沿用既有的剖面布林（§3.5 已記載的 OCCT 布林成長），產品側由 worker 高水位重啟（ADR 0126）限制。

## 已知限制

- 塗彩顏色固定，不讀零件的外觀顏色；光源固定。
- 塗彩是點陣影像（圖紙每公釐 8 像素）：放大檢視會看到像素；PDF 也是影像。
- 斜角投影視圖再往側邊投影，是從等角方向往側邊轉，結果不是標準視圖（與 SolidWorks 相同，不建議）。
- 尺寸樣式不含註解、幾何公差框、表格的字高；DXF 的個別線寬取最接近的標準值。

## 7. 修正（2026-10-20）：塗彩視圖上出現被遮蔽的相切邊

- **回報**：使用者「工程圖中的圖彩部份會出現突兀的線條，可能是原本應該被遮蔽的輪廓線」。
- **重現與量測**：定位板（四角圓角）的等角視圖「帶邊線塗彩」：後方角落圓角的兩條相切邊畫在頂面上。以零件網格的 3D 邊對照塗彩的深度緩衝：核心給的 12 條相切邊中，前 8 條（`Rg1LineVCompound`）被遮比例 0.00，後 4 條（`Rg1LineHCompound`，邊 0、3、23、42）為 1.00／1.00／1.00／0.50——在零件面的後方。削邊銷沒有相切邊（0 條），其可見線也都通過檢查，因此不是網格接縫、側影線或 z-fighting。
- **根因**：B2.3（相切邊，2026-10-19）讓核心把「看得到」與「被遮住」的相切邊合在同一個 `tangent`（註解寫明「hidden ones are among them」），繪圖層卻在「線架構」以外的所有樣式都把整個 `tangent` 畫成細實線；塗彩只是讓它特別明顯（「移除隱藏線」也有同樣的錯）。
- **修法**：核心分成 `tangent`（看得到）與 `tangentHidden`（被遮住，落在可見線上的不重複給）；繪圖層只在「隱藏線可見」以虛線、「線架構」以細線畫被遮住的相切邊，其餘樣式不畫；「相切邊」關閉時兩者都不畫；細部放大圖與裁剪視圖同樣裁切 `tangentHidden`。檔案格式不變（線條每次重算）。
- **驗收**：
  | 標準 | 結果 |
  |---|---|
  | 每條看得到的相切邊在畫的位置是最近的東西（深度差 < 0.2 mm）；每條被遮住的在零件面後方（> 0.2 mm），且兩類各 ≥ 3 條 | `drawing-tangent-hidden.test.ts`（定位板等角視圖，深度緩衝 20 px/mm） |
  | 「帶邊線塗彩」畫的線與「移除隱藏線」完全相同；「塗彩」不畫線；「隱藏線可見」虛線多出被遮住的相切邊；「線架構」細線；關閉相切邊時都不畫 | 同上，逐樣式數量與集合比對 |
  | e2e：實際 App 中被遮住的相切邊 0 條、看得到的 8／8、頁面上的線與「移除隱藏線」相同、「隱藏線可見」4／4 為虛線 | `manual-drawing-shade-tangent.js` 5 步 PASS |
  | 反向對照 | 繪圖層把被遮住的相切邊畫回細線：單元 2 項、e2e 3 步失敗；核心改回合併：單元 3 項失敗；還原後全過 |
- **未處理（既有）**：B2.2「隱藏個別的邊」（`withoutHiddenEdges`）不作用在相切邊上。

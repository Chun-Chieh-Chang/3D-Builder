# ADR 0039：輸出 — STL、STEP 選項（AP242、座標系統）、影像（Phase 3a-8c）

- 狀態：已實作（2026-10-01）。**3a-8（材質、屬性與輸出）到此完成**（8a ADR 0037、8b ADR 0038）。
- 對應：F4.1 STL 輸出、F1.3 STEP AP242 與輸出選項、F3.3 影像輸出、C3.4 座標系統當輸出座標系，見 [phase3-plan](../phase3-plan.md) §3 的 3a-8。Schema 不變（輸出不寫進文件）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **STL 是自寫的二進位 STL**（`@3db/io` 的 `binaryStl`）：把核心的網格（頂點、三角形，缺陷是面朝外的逆時針繞向，與畫面相同）寫成 80 位元組標頭、三角形數、每個三角形的法向（由三個角點算）、三個角點、2 位元組屬性。網格細緻度用文件設定的「顯示與輸出品質」（ADR 0037），輸出的是算數的本體（不含參考本體，併成一個複合形狀）。檔案是毫米。 | 不依賴 OCCT 的 STL 綁定；用的就是畫面的網格，所以所見即所得。讀回（`readBinaryStl`、`stlMeasure`）也在 `@3db/io`，測試用它量體積與面積。 |
| 2 | **STEP 輸出先問選項**（「檔案」→「輸出 STEP」，零件才有；組合件照舊直接輸出）：格式 AP214（預設）或 AP242、是否帶顏色（預設帶）、座標系統（預設零件原點）。選項是 `PartExportOptions`，不存進文件。 | 其他軟體幾乎都讀 AP214；AP242 是較新的。 |
| 3 | **AP242 的做法**：輸出前設 `write.step.schema` 為 `AP242DIS`，輸出後設回 `AP214IS`。**陷阱**：這個設定是整個函式庫共用的，而且要等第一個 `STEPCAFControl_Writer` 做出來它才存在，在那之前設是沒有作用的（瀏覽器第一次輸出 AP242 照樣寫出 AP214，單元測試因為前面已經輸出過而沒發現）。所以寫入器先做，再設格式；每次輸出都明確設，並在 `finally` 設回預設，一次 AP242 不會讓下一個輸出變成 AP242。 | 瀏覽器實測找到的。 |
| 4 | **座標系統當輸出座標系（C3.4）**：選了一個座標系統，零件在寫進檔案之前被移動，使那個座標系統的原點在 (0,0,0)、軸向沿 X、Y、Z（`intoFrame`：三個軸當矩陣的列，平移是 −R·原點）。座標系統永遠是右手系，所以是剛體運動，面的順序與名稱不變，顏色也跟著。STL 同樣可用同一個選項，目前介面只在 STEP 提供。 | 夾治具與量測要在工件的基準座標裡。 |
| 5 | **影像輸出**（「檔案」→「輸出影像」）：把圖面目前畫的樣子存成 PNG（`Viewer.snapshot`：畫一次再 `toBlob`，因為畫布不保留畫過的內容），大小是畫面的大小；零件與組合件都可用。 | 最簡單而足夠；高解析度與透明背景留給之後。 |

## 驗證

- `tests/phase3/export.test.ts`（9 項，真的 OCCT）：**STL**：板 12 個三角形、檔案大小 84 + 50 × 12，體積 6000、面積 3200；帶柱的板，細網格的 STL 圍起來的體積與面積和核心量到的相差不到 1e-4，**網格是封閉的**（每個有向邊都有另一個方向的鄰居）；品質越細三角形越多；兩個網格併一個檔案；不是二進位 STL 的檔案被拒絕。**STEP**：座標系統在 (10,0,0)、X 沿 y、Y 沿 −x 時，板寫出後讀回的範圍是 x 0..20、y −50..10、z 0..5（手算），體積不變；與零件自己的座標系統相同時不變；AP242 的檔頭、讀回同一個實體、下一個 AP214 的檔案不是 AP242；多個本體併成一個檔案並整個移動。
- `packages/kernel/test/transform.test.ts`：一個新的核心第一次輸出就是 AP242。
- **瀏覽器**（`tests/e2e/phase3-output.js`，Chromium，0 個特徵失敗）：圖面的 PNG（28 KB、檔頭是 PNG）、STL（12 個三角形、684 位元組）、STEP 在對話框選 AP242 且帶 `COLOUR_RGB`。同一個頁面還量到：材質選碳鋼，狀態列與對話框都是 47.10 g（手算 6000 mm³ × 7.85 / 1000）；「外觀」對話框列出整個零件與選取的特徵，套用後 6 個面都有顏色。找到並修了兩個只有瀏覽器才看得到的問題：外觀對話框用 `useStore((s) => … ?? [])` 每次都拿到新陣列而無限重繪（整個畫面當掉）；AP242 的第一次輸出（上面的第 3 點）。
- `npm run check` 全過。

## 還沒做

- 影像輸出的解析度與透明背景；STL 的 ASCII 格式與「以座標系統輸出」的介面；輸出設定的記憶。
- AP242 的特有內容（PMI、材質）：現在只是格式不同。

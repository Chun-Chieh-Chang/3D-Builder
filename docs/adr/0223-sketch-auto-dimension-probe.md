# ADR 0223: 草圖自動尺寸配置探針 (G19, D5)

- 日期：2026-11-02
- 狀態：探針報告（未進入正式實作）
- 相關：G19（plan.md）、D08（acceptance.md）、ADR 0195（草圖拘束擴充）

## 1. 探針目的

G19：無完整自動尺寸配置工作流；自動定義必須讓使用者指定基準與偏好並預覽，不能以 Fix 全圖冒充。本探針先證實精確幾何／參照／求解可行，再核定範圍（plan.md P5：每項探針 2–4 日）。

## 2. 現有基礎

- `smartDimension(geometry, picks, place)` 已能從點選產生單一尺寸提案（距離 X/Y/斜、角度、半徑/直徑），含 placement 象限。
- PlaneGCS 求解器提供 `entityFreedom`（每實體的自由點與半徑自由度）與整體 `dof`。
- `fix` / `block` 關係已存在，但 G19 明確禁止以 Fix 全圖代替設計拘束。
- 試解管線 (`controller.trial`、worker solve) 可在提交前驗證候選尺寸是否真的減少 DOF 且不衝突。
- 既有 `autoDimensions`（drawing 套件）是工程圖層的自動標註，與草圖層的驅動尺寸不同，不應混用（plan.md：不混用工程圖尺寸模型）。

## 3. 可行性分析

### 3.1 基本策略（探針結論）

自動尺寸 = 用驅動尺寸（distance/angle/radius/diameter）取代 Fix，使幾何仍可編輯（尺寸值可改）：

1. 使用者指定 **基準**（原點或某條基準線/軸）與 **偏好**（水平/垂直/平行/角度/半徑）。
2. 對每個 under-defined 實體，利用 `entityFreedom` 找出自由點/半徑。
3. 為每個自由度產生候選尺寸（復用 `smartDimension` 的提案邏輯），基準為使用者指定的參考。
4. 每個候選以 trial solve 驗證：總 DOF 必須減少、不產生 conflicting/redundant；接受才納入。
5. 預覽（虛線）顯示將加入的尺寸；確認才提交，取消零變更。

### 3.2 可行部分

- 單一自由度 → 單一尺寸的映射在大多數情況下成立（水平/垂直距離、半徑）。
- `smartDimension` 已處理 placement 象限與 X/Y 分解，可直接復用。
- trial solve 可避免過約束與冗餘。

### 3.3 風險與困難

1. **尺寸選擇順序**：自動尺寸必須先鎖「基準」再鎖「相對」；順序錯誤會產生冗餘或過約束。需使用者指定基準（G19 要求）。
2. **冗餘偵測**：PlaneGCS 的 redundant 報告可用，但 trial solve 每候選一次求解成本高；大草圖可能慢。需批次驗證與預算守衛（C2）。
3. **角度尺寸的象限**：自動選象限可能與使用者意圖不符；需預覽 + 可調整。
4. **圓/弧半徑**：radius 尺寸驅動半徑，可行；但若半徑已被 concentric/equal 約束，自動加 radius 會冗餘 → trial solve 過濾。
5. **3D 草圖**：不在平面控制器範圍；G19 明確另立專案。
6. **完全定義的判定**：DOF=0 且無衝突/冗餘；但「完全定義」不等於「設計意圖正確」；自動尺寸只能保證幾何固定，不能保證設計合理性。

## 4. 與 Fix 的差異（G19 硬性要求）

- Fix = 把點/曲線鎖死在當前位置，不可編輯、不可參數化。
- 自動尺寸 = 用驅動尺寸鎖定，值可改、可參數化、可表达式。
- 探針結論：兩者可共存——自動尺寸優先，Fix 作為最後手段（使用者明示）。

## 5. 建議的最小可行範圍（MVP）

1. **基準選擇**：使用者點選原點或一條水平/垂直基準線。
2. **偏好設定**：勾選「水平距離」「垂直距離」「半徑/直徑」「角度」。
3. **候選產生**：對每個 under-defined 實體，依偏好產生候選尺寸（復用 smartDimension），基準為所選參考。
4. **預覽**：虛線顯示候選尺寸，衝突者標紅；使用者可個別取消。
5. **確認提交**：trial solve 全通過才提交；一次 Undo。
6. **範圍限制**：僅平面草圖；不含 3D；不含樣條（G17 相關）。

## 6. 開放問題

1. 候選尺寸的放置位置（labelPosition）自動排版，避免重疊（G12/G14 相關）。
2. 大草圖效能：trial solve 批次化與預算守衛。
3. 使用者偏好持久化（是否存入文件或僅 session）。
4. 與既有手動尺寸的整合（不重複、不衝突）。

## 7. 探針結論

- **可行**：在現有基礎（smartDimension + entityFreedom + trial solve）上可實作 MVP，估計 5–8 工作日。
- **不可行／延後**：3D 草圖；樣條自動尺寸；完全自動（無使用者基準）。
- **建議**：進入正式實作時，先做 MVP（基準 + 偏好 + 預覽 + 確認），附上本 ADR 的策略與 i18n 訊息。

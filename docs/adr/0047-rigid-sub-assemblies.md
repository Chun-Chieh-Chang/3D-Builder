# ADR 0047：剛性次組合件與零組件的隱藏、抑制、透明（Phase 3b-1，**組合件 Schema 3**）

- 狀態：1a（資料格式與循環偵測）已實作（2026-10-02）；1b 以後（求解、介面、旗標、STEP 輸出）進行中，完成後在此補寫。
- 對應：[phase3-plan](../phase3-plan.md) §4 的 3b-1（C15.4、C15.5）。使用者 2026-10-02 確認：只做「插入現有 `.3dba`」（不做「形成新次組合件」）；父層的結合可以選次組合件內零件的面與邊。

## 決定

1. **次組合件就是一個零組件，它的檔案是 `.3dba`。** `Component.file` 指向 `FileRef`，路徑的規則與零件檔完全相同（相對於這個組合件所在的資料夾）。模型層不分辨檔案種類：哪些檔案是組合件由讀檔的地方知道，所以不用新欄位。
2. **每個檔案只記相對於自己資料夾的路徑，所以搬動不需要遞迴改寫。** 整個專案資料夾搬到別處，所有檔案原封不動；一個組合件另存到別的資料夾，只有它自己的路徑被改寫（`relocateAssembly`，ADR 0011），次組合件的 `.3dba` 位元組不變（`tests/phase3/subassembly-files.test.ts` 逐位元組比對）。
3. **結合的參考帶路徑。** `MateRef.path`：在 `component`（次組合件）裡要穿過的零組件 ID，最外層在前，最後一個是零件本身。ID 屬於次組合件自己的檔案，與父層的 ID 各自編號，所以必須帶路徑才不會混淆。沒有 `path` 的參考是次組合件自己的預設基準面或原點。模型層只檢查形狀（非空、無空字串、組合件本身不能有路徑）；路徑通不通是求解器的事，因為模型層不讀檔。
4. **次組合件在父層是一個剛體。** 同一個零組件的兩個元素不能互相結合，不論路徑。內部的結合在它自己的檔案裡求解，不進父層的結合清單。
5. **零組件的旗標都是可省略的欄位**：`hidden`（不畫、不能點，仍求解）、`suppressed`（不求解、不輸出、它的結合顯示為抑制）、`transparent`（只改顯示）。沒有旗標的零組件寫出的檔案不含這些鍵，所以 v2 的檔案原封不動，遷移 2→3 是恆等函數。
6. **循環引用在讀檔的地方偵測，不靠名稱。** `findReferenceCycle(root, refsOf)`：`refsOf` 給一個組合件檔使用的檔案（專案相對路徑，`usedFiles` 把「相對於該檔資料夾」換成「相對於專案」，不同資料夾寫法不同的同一個檔案會是同一個字串），零件、STEP 與讀不到的檔案回傳 null（底下沒有東西可追）。找到就回傳從根開始的路徑鏈，`cycleMessage` 說「這樣組合件會包含它自己：a → b → a」，自己用自己說「組合件不能把自己當成零組件」。用已走完的集合避免菱形（同一個次組合件用兩次）被重複走，用鏈避免在 500 層深的樹上遞迴失控。

7. **不合併幾何，沿路徑走過去（1b）。** 原本想把次組合件的所有零件拓撲與名稱合成一份「合成零件」，改成不合併：`SubAssemblyPart`（`@3db/regen`）只有「每個零組件在次組合件座標裡的位姿」與「每個零組件是什麼」，所以一個元素的幾何是 `mateGeometryIn(ref, path, source)` 沿 `path` 一層層走到葉零件、在葉零件自己的座標裡解析（持久名稱與指紋照舊），再用路上的位姿 `placed(...)` 帶出來。好處：名稱不用加前綴、不用複製拓撲、巢狀幾層都是同一個遞迴。`solveSubAssembly(doc, partOf)` 先在它自己的檔案裡求解（與一般組合件同一個 `solveAssembly`），結果交給上一層；每個零組件的來源只問一次，次組合件自己的零件由 `partOf` 在被問到時建。上一層的求解器把次組合件當一個剛體，轉動中心與大小由所有葉零件的球算出（`extentOfSource`，遞迴）。
8. **「組合件本身」與「沒載入」是兩件事。** `component: null` 是這個組合件的預設基準面與原點，直接走 `mateGeometry(ref, null)`；`mateGeometryIn` 的 `source` 為 null 才是「零件沒有載入」（1b 的測試抓到我一開始把兩者混為一談）。

9. **Worker 拿到的是「來源樹」，畫面拿到的是「葉子」（1c）。** `SourceTree`（`@3db/model`）：零件是 `{part, key}`，次組合件是 `{assembly, doc, children}`；`Worker.solveAssembly(doc, trees, options)` 用 `solveAssemblyTree`（`@3db/regen`）解，回傳的 `AssemblyResult.inner` 是每個次組合件裡各零組件的位姿（`InnerPoses`，只有位姿，不傳拓撲）。主執行緒用 `leavesOf`（純函式，在 `@3db/model`，因為主執行緒不能在執行期匯入 regen）把「頂層位姿 ∘ 內部位姿」算成每個要畫的零件：葉子 ID 是 `top` 或 `top/子/孫`，`leafAt(leaves, top, path)` 把結合參考的 `component` 與 `path` 對回葉子。
10. **檢視器按「所屬零組件」操作。** `ViewInstance.owner`：次組合件的每個零件各是一個實例，但懸停、選取、拖曳都以 `owner`（頂層零組件）為單位，事件回報的也是 `owner`；元素事件仍回報葉子的 key，`refOf` 用 `leaves()` 換成 `{component, path, ref}`。次組合件裡的零件在父層不能單獨移動。
11. **讀檔是遞迴的，每個路徑一個狀態。** `FileStatus` 的 `ok` 多了 `assembly?: AssemblyDoc`；讀到 `.3dba` 後逐一讀它用的檔案（路徑相對於那個檔案）。讀到的次組合件立刻用 `findReferenceCycle` 檢查，會包含自己的標為錯誤（訊息是路徑鏈）；插入時另外檢查「它的下面會不會回到這個組合件」（還有檔案在載入時不讓放，預覽的灰色零件也不畫：次組合件沒有單一網格可以跟著游標，所以按一下放置、✓ 放在原點）。`pointOutNestedProblems`：次組合件用到的檔案不見或壞掉時說一次檔名，要修復請開啟那個次組合件（它自己的「找不到參考的檔案」），**這與驗收標準 9 的「重新指定」有出入：頂層直接用的檔案有重新指定對話框，次組合件內部的檔案沒有**。
12. **開啟次組合件與返回沿用開啟零件的機制。** 設計樹右鍵「開啟次組合件」→ 次組合件成為目前文件，左上有「返回組合件「X」」；返回時重新讀整個組合件，所以次組合件改過存檔的內容會顯示。

13. **三個旗標（1d）。** `setComponentState`（零組件 ID 們、`hidden`／`suppressed`／`transparent`、真假）：一個指令、一個復原步驟，全部成功或都不變；關掉就刪掉那個鍵，所以沒有旗標的零組件寫出的檔案沒有它們。**抑制**：`solveAssembly` 不向 `partOf` 要它的零件、不放進求解、沒有位姿與自由度；它的結合，以及經過它的帶路徑結合（次組合件裡被抑制的零件：`SubAssemblyPart.leftOut`），狀態是 `suppressed`，不是「遺失」；STEP 輸出略過它；不能移動，會說明；結合的飛出樹不列它。**隱藏**：仍求解，不畫、點不到（`leavesOf` 的葉子帶 `hidden`，視圖不收這個實例）；次組合件裡被隱藏的零件只隱藏那個零件，隱藏次組合件則整個隱藏。**透明**：只改視圖的材質（不透明度 0.4、不寫深度），次組合件的旗標會傳給它所有的零件。三個都在設計樹的右鍵選單；被抑制的列劃掉、被隱藏的列斜體。

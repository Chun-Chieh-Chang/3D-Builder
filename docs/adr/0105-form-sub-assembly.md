# ADR 0105：形成次組合件（E-3，檔案格式不變）

- 狀態：**已實作並驗證（2026-10-07）**。計畫：[assembly-explode-plan](../assembly-explode-plan.md) §4。
- 組合件 Schema 不變（用的都是既有的欄位：次組合件的檔案、零組件、`MateRef.path`）。

## 決定與做法

1. **純函式 `formSubAssembly(doc, ids, {file, componentId, placements})`**（`packages/model/src/subAssembly.ts`）回傳 `{ parent, sub }`：
   - **次組合件**：選的零組件（照原樣：檔案參照、固定、抑制、顯示旗標，位置取 `placements`＝它們現在被結合擺到的位置，所以裡面的結合立刻成立、沒有東西移動）、它們用到的檔案、**兩端都在它們之間的結合**；裡面沒有固定的零組件時，第一個（沒被抑制的）在裡面固定，讓次組合件有個基準。
   - **組合件**：選的零組件拿掉，在第一個的位置放一個代表新檔案的零組件，位置＝單位位姿（次組合件的座標就是組合件的座標，所以每個零件不動），選的裡面有固定的就固定；沒人用的檔案拿掉；**只要有一端在外面的結合都留著**，裡面那一端改成通過次組合件（`component` 是新零組件、`path` 是 `[原零組件 id, …原來的 path]`，既有機制，ADR 0047）；爆炸視圖各組的步驟裡這些零組件換成新零組件（一個步驟內去重）、方向的參照同樣改成通過次組合件。
2. **拒絕**（`formSubAssemblyProblem`）：少於兩個、找不到的零組件、排列或鏡射用到它們（種子或方向的參照；它們的複製品是在組合件裡算出來的，不在次組合件裡算）。id 已被使用也拒絕。
3. **指令 `formSubAssembly`**（一個復原步驟）：用同一個函式算出 `parent` 取代整份文件；`AssemblyStore.applyFormSub()` 先算 `sub`、寫成新的 `.3dba`（在組合件旁邊，`writeFilesInto`，名稱已有就拒絕）、再執行指令；寫檔失敗時組合件不變。復原不刪寫出去的檔案（寫在說明裡）。
4. **介面**：「組合件」→「形成次組合件…」（`form-sub-assembly`）開 `FormSubPanel`：零組件的勾選清單、檔名（預設「次組合件N」）、問題的文字、✔／✕；Esc 取消。

## 驗證

- `tests/phase3/subassembly-form.test.ts`（11 項，金樣夾具手算）：15 個零組件、39 個結合（11 + 14 + 14）；中間一站的 5 個零組件形成次組合件：組合件 11 個零組件、新的排第五、在原點、不固定；次組合件 5 個零組件（第一個固定、位置等於解出來的位置）、3 種檔案、11 個結合；組合件留下 28 個結合，6 個端點通過次組合件且 `path` 是板的 id，其餘結合原樣；**每個零件的位置誤差 < 1e-6**（完全定義的零件對照平的解、次組合件裡的對照 `composePose`），組合件與次組合件所有結合都成立；第一站（含固定的板）形成後新零組件固定；爆炸步驟改名與方向通過次組合件；拒絕的情況（少於兩個、沒有的 id、id 已用、排列的種子與方向的參照）；指令與函式結果相同、復原回到原文件、寫出再讀回相同。（還有自由度的零件，例如只有同軸與重合的銷，從不同起點解會轉得不同，不在比較之列。）
- 瀏覽器（`tests/e2e/phase3-form-sub.js`）：夾具（兩個定位組）形成一個次組合件：面板在選一個時說至少要選兩個、✔ 不能按；形成後組合件一個零組件、3 個結合進了裡面、新檔寫在旁邊（661 位元組）、讀回是 2 個零組件 3 個結合、6 個零件的位置都沒變；一次復原回到兩個；檔名已有時被拒、面板留著。

## 限制

- 排列、鏡射用到的零組件不能形成（要先刪排列）。
- 新檔寫在組合件旁邊，不能選資料夾；結合的零件參照仍是同一個資料夾的相對路徑。
- 外面的結合若原本靠裡面兩個零件之間還有自由度來成立（兩端都接到外面、裡面的零件彼此原本可以相對移動），形成後次組合件是剛性的，那些結合以目前位置為準；沒有為這種情況另外檢查。
- 沒有「解散次組合件」。

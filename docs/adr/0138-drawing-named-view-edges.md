# ADR 0138：視圖的邊與頂點有名字，尺寸可以標在頂點與邊上，等角視圖也行（D-I2，第一部分）

- 狀態：**第一部分已完成（2026-10-14）；第二部分的前三項（細部放大圖的點選、垂直距離、圓柱輪廓線，工程圖 Schema 12 → 13）已完成（2026-10-15）**。**第二部分（二）組合件視圖的尺寸（Schema 13 → 14）已完成（2026-10-15）**。註記綁定模型邊仍待做。
- 需求追溯：[ADR 0129](0129-drawing-interaction-roadmap.md) 的 D-I2；技術驗證見 [docs/drawing-interaction-gap-plan.md](../drawing-interaction-gap-plan.md) §10。

## 背景

原本能掛尺寸的只有「側看成線的平面、斜面、看成圓的圓柱、圓角」（`ViewFeature`），因為 HLR 畫出來的線沒有名字。所以不能標頂點、不能標一般的邊（例如倒角邊的長度），等角視圖也完全不能標。技術驗證確認了兩件事：本專案用的 OCCT 建置不能直接追溯每條線來自哪條邊；但用幾何回推可行。

## 決定

1. **worker 依名字投影所有邊與頂點**（`viewEdges`，`@3db/regen`）：
   - 用零件網格的邊折線（它和 topology 的邊同序），投影成視圖座標，並附上每一點離觀看者多近（depth）。
   - 每條邊附上兩端頂點的持久名稱；直線標記是否位於圖紙平面上（`inPlane`）；端面看到的圓附上圓心和半徑。
   - 參考用工件的面不納入。
   - 網格每個零件只算一次，跟著建好的零件存在 worker（WeakMap）。
   - 隨 `drawingFeatures` 回傳（`edges?: ViewEdgeSet`）。
2. **哪些看得見，由視圖自己的線決定**（`visibleElements`，`@3db/drawing`，純函數）：
   - 邊的取樣點有 ≥ 25% 落在可見線上（容差 0.08 mm），就算看得見；頂點要落在可見線上。用空間格點加速。
   - 在圖上重合的幾條（方塊的前緣與後緣）只留一條，取離觀看者最近的那條。
   - 邊的端點換成畫出來的那個頂點。
   - 端面看到的圓邊若和既有的圓柱面重合，就不另外列出，讓孔仍然透過它的面來標，帶著孔標註。
   - **隱藏線仍然是唯一的裁判**：不做其他的可見性判斷。
3. **點選**（`featureAt`）：
   - 頂點優先，比照 SW 會先抓到端點。
   - 直線邊和平面平手時，平面勝（面積），所以既有的行為完全不變。
4. **標註規劃**（`planDimension`）：
   - 單選一條直線邊：它的長度（兩端頂點之間）；在圖上是水平的就標水平，垂直的就標垂直，其他標對齊。
   - 兩個點（頂點與頂點，或頂點與圓心）：游標在上下方標水平，在左右方標垂直，在斜角或視圖內標對齊（真實距離）。
   - 邊和其他元素一起選時，水平或垂直的邊當作側看成線的平面，斜的邊當作斜面。
   - **角度只能量位於圖紙平面上的邊**：在等角視圖裡，邊被投影縮短，角度不真實，因此拒絕並說明，不給一個假的數字。
5. **接縫不提供點選**：封閉曲面（圓柱、圓錐）自己接合處的接縫邊，以及整圓起點和終點的頂點，是 B-rep 的產物，不是看得見的角；SW 也不會吸附到它們。這類邊只連到一個非平面的面；這類頂點只連到接縫或封閉的邊。兩者都不納入。若沒有這條規則，指向孔輪廓的最右點時，會選到圓的起點頂點而不是孔（全量 `verify:ui` 的 `manual-drawing-annotate` 步驟 3、4 就是這樣抓到的）。
6. **修正一個既有的座標錯誤**（`sheetUp`）：
   - HLR 畫的 y 是 (−視線方向) × x。原本的程式把視圖的 `up` 直接當成 y。
   - 在 6 個正視圖裡兩者相同；**在等角視圖裡不同**，因為 `up` = (0,1,0) 和 (−1,−1,−1) 不垂直。
   - 以前等角視圖不能標尺寸，所以沒有被發現；但組合件等角視圖的號球引線起點（`drawingAnchors`）也用了這個錯誤的 y。
   - 現在所有放進視圖座標的點都改用 `sheetUp`：`inView`、`squareTo`、`seenAsLine`、`circleCentre`、`factsOf`、`viewFeatures`、`viewEdges`、`drawingAnchors`。

## 限制與下一步（D-I2 第二部分）

- **組合件視圖**：還不能標尺寸，因為尺寸的 `Ref` 需要加上零組件路徑。
- **註記綁定模型邊**（ADR 0132 的限制）：還沒做；目前註記仍記在視圖座標。
- **細部放大圖**：沒有開放點選邊和頂點（原本就不能在細部視圖上點選標註）。
- **曲面的輪廓線**（例如圓柱的側面輪廓）：不是模型的邊，目前不能點；要對應到面，還沒做。
- **斜線之間的垂直距離、點到斜邊的距離**：還不支援（對齊尺寸目前只做「兩點之間」）。

## 第二部分（一）：細部放大圖的點選、垂直距離、圓柱輪廓線（2026-10-15）

1. **細部放大圖可以點選**：點選和可見性判斷都改用 `resolveLines`（細部圓裁切後的母視圖線條），特徵和邊沿用母視圖的；尺寸畫在細部視圖上，用它自己的比例。
2. **垂直距離**（SW 的「點到線」與「兩條平行線之間」）：
   - 「對齊」尺寸的一端是線（直線邊，或側看成線的平面）時，量點到線的垂足（`alignedEnds`）。
   - 兩端都是線時，必須平行，量兩線之間的垂直距離；不平行就拒絕並說明（`drawing.dimNotParallel`）。
   - `planDimension`：點（頂點、圓心）加斜線、兩條平行斜線，都給對齊尺寸，不再回報錯誤。
   - **語意修正**：面板的「對齊」原本在兩個平面之間量的是兩平面原點的距離，對平行平面沒有意義；現在是垂直距離。
3. **圓柱輪廓線**（SW：點側看圓柱的輪廓線）：
   - 側看的整圓柱（`axis` 特徵）提供兩條可點選的輪廓線（`OutlinePick`，軸線兩側各一個半徑）。
   - 單選一條輪廓線：兩條輪廓線之間的線性尺寸，**自動加上 Ø 前綴**（ISO 129-1：側看的直徑也寫 Ø），可以修改。
   - 輪廓線和其他元素一起選：從那條輪廓線量起。
   - **工程圖 Schema 12 → 13**：`LinearDimension.aSide`／`bSide`（±1，左或右的輪廓線）。舊程式會量到軸線而算錯，所以升版擋住舊程式。命令層拒絕：側別不是 ±1、側別用在頂點或邊上、同一個面量自己卻不是兩側。
   - 端面看成圓的圓柱沒有輪廓線，從側面標的尺寸會說明原因（`drawing.dimNoOutline`）。
   - 輪廓線和端面在角落重合時，平面優先（既有的優先序）。

## 第二部分（二）：組合件視圖的尺寸（2026-10-15，工程圖 Schema 13 → 14）

1. **元素參照**：`DrawingRef = Ref & { in?: string }`。在組合件視圖裡，`in` 是葉節點的 id（「comp2」、「comp2/pa」），指出元素是哪一個零件實例的。命令層拒絕空字串的 `in`。舊程式會到錯的零件裡找元素，所以升版擋住舊程式。
2. **worker 的 `drawingAssemblyEdges`**：
   - 對每個零件實例，沿用該零件快取的網格。
   - `viewEdges` 新增 `place` 參數：用 `placementRows(pose, mirrored)` 移動點、轉動圓的法線與直線方向。
   - 參照帶上 `in`；參考用工件照樣排除。
3. **元素事實**：主執行緒依 `in` 找到葉節點，向 worker 要零件自己的事實，再用 `placeElementFacts`（`@3db/model`，純函數）放到組合件座標：點移動、方向轉動、鏡射也一併處理，尺寸大小不變。找不到葉節點（零件已被移除或隱藏）時會說明（`drawing.dimNoPart`）。
4. 點選、標註規劃、計算數值的程式都不必改：參照帶著 `in` 一路傳下去，事實已經在組合件座標裡。

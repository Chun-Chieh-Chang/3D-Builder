# ADR 0212：兩條線的交點可作為智慧型尺寸的參考點

日期：2026-10-28。狀態：已實作；本機全閘門與完整 `verify:ui` 見 §4；遠端 CI 待推送後的結果。檔案格式不變（不升 Schema）。

## 1. 需求與取捨

使用者：兩條線的交點本身是重要的特徵點，標註時應能把它當磁吸參考點。

先查了別人怎麼做（讀原始碼；SolidWorks 沒查證，下表是記憶）：

| 軟體 | 做法 |
|---|---|
| FreeCAD | 自動拘束只認頂點與曲線，沒有交點吸附。 |
| SolidCraft | 畫圖時才吸附，且只吸附兩條有限線段真的交叉的點；平行與延長線的交點忽略；交點上已有點就不再建。 |
| SolidWorks | 「虛擬交點」是獨立功能（記憶，**未查證**）。 |

使用者裁示（照建議）：**只做線與線的實際交叉，不做延長線交點；圓與圓弧的交點延後。**

## 2. 決策

1. **智慧型尺寸工具**多一種可點選的東西：兩條線（兩條都畫到那裡）的交叉點。優先順序：草圖的點（含原點）→ 線與線的交叉 → 其他曲線與軸。所以游標在交叉處 7 px 內，點到的是交叉點，不是其中一條線；要點線，點離交叉處遠一點。
2. **點選時不建立任何東西**。被點選的交叉只存在控制器裡（`crossings`），以一個暫時的 id（`@x:<線a>:<線b>`）代表，畫面上以一個標記顯示（`ControllerView.pickedCrossings`），尺寸預覽與 `smartDimension` 把它當一個點。Esc 或點到不能標註的組合就清掉，**什麼都不留下**。
3. **尺寸放下的那一刻**，用同一個指令（`addSketchItems`，一個復原步驟）建立：一個點（座標是交叉點本身，不是滑鼠點的位置）、一個 `intersection` 關係（既有的關係種類，點在兩條線上）、以及尺寸。先用 `trial` 求解：失敗就一樣都不建（顯示原因）；過度定義就和其他尺寸一樣變成從動尺寸，點與關係照建。
4. **交叉處本來就有點**（例如已經標過一次）：點到的就是那個點（第一優先），不會再建第二個。
5. **只認線**（`intersectionSnap(..., linesOnly)`）。線與圓、圓與圓的交叉有兩個位置與相切要處理，不在這次。畫圖工具的交點吸附不變（仍含圓與圓弧）。
6. **修了一個因此浮現的介面問題**（`Viewport.tsx`）：修改尺寸的輸入框讀的是「渲染之後才重建」的覆蓋層參照，所以框總是慢一次；一般尺寸碰巧不受影響，但新尺寸帶著新點時，標籤要等求解器回應有了那個點才有，框就永遠不出現（尺寸建立了，卻無法輸入數值）。改成把覆蓋層放進狀態、框顯示出來的那一刻才聚焦。

## 3. 紅隊四問

1. **輸入破壞**：平行線沒有交點、重疊的共線不會被當成交叉（沿用 `crossings`）；兩條線只在端點相接時，點到的是那個端點（草圖的點優先），不會多建一個。點在線的延長線上不算交叉，只會點到線本身。不使用 `Math.round`。
2. **幾何相交**：純草圖運算，沒有布林運算，不涉及 OCCT Heap。
3. **依賴鏈**：`snaps.ts`（`linesOnly`）→ `controller.ts`（`dimensionPick`／`dimensionGeometry`／`placeDimension`）→ `overlay.ts`（標記）→ `Viewport.tsx`（框）→ 說明（雙語 `help.toolDimension.body`）。不新增 schema 欄位、不新增命令；使用既有的 `intersection` 關係，所以 DAG、重建與輸出都不需要動。
4. **零 Mock**：真實的 `SketchController`、真實的 PlaneGCS 求解器、真實的 `DocHistory`；真值是手算的交點（y = x/2 與 y = 10 − x/2 交於 (10, 5)）與獨立的參數式代數，不用被測的吸附判定。瀏覽器端用真實滑鼠點選。

## 5. 已知限制

- **延長線的交點不吸附**，圓與圓弧的交點不吸附（使用者裁示）。
- 只在智慧型尺寸工具；其他選取工具、關係按鈕不能點交叉。
- 交叉點的優先序高於線：在交叉處 7 px 內，不能直接點其中一條線。
- 點建立為一般點（與「點」工具畫的相同），不是構造點。
- 與 SolidWorks 的對應沒有查證（沒有該軟體）。

# ADR 0010：Phase 1 驗收發現的修正（1G）

- 狀態：已採用（Phase 1G，2026-09-28）。使用者已確認 Phase 1 閘門通過。
- 依據：[phase1-verification.md](../phase1-verification.md) 的發現 1–3；藍圖附錄 C 的 B4.1、C1.28、F1.1、F7.1

只用 UI 建三個示範零件時，發現了三個問題。

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **整圈旋轉產生的每個面，都以掃出它的輪廓線命名**：<br>• 除了 `BRepPrimAPI_MakeRevol.Generated(edge)`，也查掃掠本身的紀錄 `Revol().Shape(edge)`，兩者合併、去除重複<br>• 輪廓線落在軸上時什麼也掃不出，照舊略過 | OCCT 在整圈旋轉時，對與軸垂直的輪廓線，`Generated()` 回傳空集合，這些平面只能依位置編號（`revolve1:face#2`）。輪廓增減台階時，參考可能默默跳到別的面，正是持久命名要防止的情形 |
| 2 | **角度尺寸量的是放置那一側的角度**（同 SW）：<br>• 放置點以兩線交點為原點，分解成 α·a + β·b；α、β 的正負決定夾出那個扇形的兩條射線<br>• 尺寸記下哪條線的射線反向（`flip: 'a' \| 'b' \| 'both'`），順序排成「b 的射線在 a 的逆時針方向」<br>• 只有一條反向時，求解器用 值 − 180° 轉動兩線；兩條都反向或都不反向時，直接用值<br>• Schema v6：沒有 `flip` 的角度（舊檔）意義不變 | 原本量的是兩條線「畫的方向」之間的角度。V 型塊的 90° 看不出差別；改成 100 時，V 反而變窄成 80°。記下放置的扇形，數值就是使用者看到並想改的那個角；升版讓舊程式拒絕開啟，而不是把 `flip` 忽略後算錯 |
| 3 | **零件名稱就是檔名**（同 SW）：<br>• 存檔或開檔之後：檔名去掉副檔名<br>• 從未存檔：先用零件名稱屬性（示範件），否則用本次工作階段的「零件1、零件2 …」<br>• 同一個名稱用在設計樹頂端、標題、STEP 產品名稱與檔名、另存新檔的建議檔名<br>• 「新零件」不再把「零件1」寫進文件 | 原本名稱來自零件屬性，三個示範件輸出的 STEP 都叫「零件1」。名稱只有一個來源（檔名），就不會與檔案不一致 |
| 4 | **補齊 v4、v5 的舊版樣本**，由那兩版的程式自己寫出（`tests/fixtures/old-versions/`） | ADR 0008 的規則是每次升版都新增樣本；1C（v4）、1F（v5）時漏了，v6 升版前補上 |

## 相容性

- **修正 1**：修正前存檔、且參考了整圈旋轉平面的零件（例如旋轉件端面邊線上的導角），開啟後該參考會顯示「遺失參考」，需要重新選擇。這種參考不會默默綁到別的面。
- **修正 2**：舊檔的角度尺寸沒有 `flip`，意義維持原樣；只有新標註的角度尺寸量放置的那一側。
- **修正 3**：只影響顯示與輸出的名稱，文件內容不變。

## 驗證

- 修正 1：
  - 核心測試：整圈旋轉的每個面都只有一個來源，平面也有；
  - 零件測試：面名都是 `r1:side:s1.alN`，導角參考在輪廓變高後仍在原邊；
  - 金樣削邊銷沒有依位置編號的名稱。
- 修正 2：
  - 智慧型尺寸：夾角內、旁邊、對面、V 槽內、V 底下方，量到的角度與記錄的反向都正確；
  - 求解器：V 槽內標註改為 100 時開口為 100°，沒有 `flip` 的舊尺寸為 80°；
  - 瀏覽器中用 PropertyManager 把 V 型塊的角度改成 100：體積等於開口 100° 的手算值。
- 修正 3：
  - 名稱規則的單元測試；
  - 瀏覽器中存成「定位板.3dbx」後，設計樹頂端為「定位板」，輸出的 STEP 檔名為「定位板.step」、產品名稱為「定位板」。
- 三個金樣零件都以修正後的 UI 重做，金樣測試全綠；`npm run check` 195/195。

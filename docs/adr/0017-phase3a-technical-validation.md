## 1. 薄殼、拔模、掃出、疊層拉伸：演化歷史夠不夠命名

判定標準：每個輸入面都有去處（`Modified`、`Generated`、原封不動、或被刪除），每個結果面都有來源；體積與手算或解析解相同；結果有效。

| 案例 | 結果 |
|---|---|
| 方塊薄殼（開頂面，壁厚 2） | 通過：體積 7152 = 手算。5 個面原封不動（用「同一個面」認出，`Modified` 為空）、內側 5 個面由原面 `Generated`、頂面 `Modified` 成開口的環 |
| 方塊拔模（四個側面 3°） | 通過：體積 = 手算積分（22561.879） |
| 圓角＋通孔的板（11 面）薄殼 | 通過：11 → 22 面，全部對得上，有效 |
| 同一塊板，外壁（4 平面＋4 圓角，切線連續）拔模 2° | 通過：加入 4 個面、0 失敗，切線的圓角面隨之傳遞，11 → 11 面，全部對得上 |
| 通孔圓柱面拔模 → 圓錐面 | 通過：結果出現 `Cone`，全部對得上 |
| 掃出：圓形輪廓沿「直線＋四分之一圓弧」 | 通過：體積 = Pappus（574.3832）；輪廓邊 `Generated` 得到每段脊線各一個面；起點、終點各一個平面蓋（`FirstShape`/`LastShape`） |
| 疊層拉伸：兩個矩形（直紋） | 通過：體積 3000 = 手算；起始截面每條邊各產生 1 個面；首尾蓋可辨識 |

**結論**：這四個特徵的歷史足以命名，沒有需要靜默猜測的地方。命名規則的具體形式（例如掃出的側面 = 輪廓邊名 × 脊線邊序）留給 3a-5、3a-6 的 ADR。

**兩個陷阱**（會讓人誤以為「歷史不完整」）：

- **未被修改的面**：`Modified()` 對它回傳空集合，它在結果裡就是原來那個面。命名程式要先查「結果裡有沒有同一個面」。
- **`BRepBuilderAPI_MakeWire.Add(edge)` 之後，wire 裡的邊不是傳進去的那個邊**（會重新定位）。用傳進去的邊查 `Generated` 只有第一條有結果（疊層拉伸得到 1,0,0,0），從 wire 用 `TopExp` 取出的邊才是完整的（1,1,1,1）。產品程式碼一律從 wire 取邊（既有的 `mw.Edge()` 用法就是這個原因）。

**沒有驗證的**（不要當作已解決）：有曲面輪廓的掃出（脊線為 B 樣條、有引導線）、多個輪廓的疊層拉伸（3 個以上截面、曲線截面）、薄殼在多個開口面或壁厚大於最小曲率半徑時的失敗行為、拔模在非切線相連的面組上。這些要用真實零件（樣本到手後）再驗證。

## 2. C10.1 移動面（沒有 `BRepOffset_MakeOffset`）

**做法：延伸板（extended slab）。** 移動平面 F、距離 d（沿外法向）：

1. 在 F 的平面上做一塊夠大的面，沿法向掃出 d，得到板；
2. 對 F 的每一個鄰接面 g，取它的整個曲面（`BRep_Tool.Surface` ＋ `MakeFace`），做「F 所在那一側」的半空間，板與它取交集；
3. d > 0：本體 ∪ 板；d < 0：本體 − 板；再合併共面。

半空間必須取「F 所在的那一側」，不是「材料所在的那一側」：凸邊上兩者相同；凹邊上 F 在鄰接面的材料另一側，取材料側會得到錯的結果（實測體積 77100，正確為 18900）。

| 案例 | 結果 |
|---|---|
| 方塊頂面 +5／−5 | 通過：體積 = 手算，6 面 |
| 拔模方塊（斜壁 3°）頂面 +5／−5 | 通過：斜壁保持斜度，體積 = 手算積分，6 面 |
| L 形塊的內側立面 +3（凹角） | 通過：體積 18900 = 手算，8 面 |

**限制（未驗證，實作時要偵測並拒絕，不要靜默產生錯的形狀）**：

- 只做平面。圓柱面（孔徑）不用它：改用刪除面（`BRepAlgoAPI_Defeaturing`，ADR 0003 G3 已驗證）加上新的除料。
- **與 F 相切的鄰接面（例如頂面旁的圓角）**：半空間規則對它不成立，這種情形沒有測試。要偵測邊上的連續性（G1），是的話拒絕並說明「請先移動連同的圓角」，或改為連同一起移動。
- 半空間用的「F 所在那一側」以 F 的質心判斷；質心與鄰接面的曲面重合（極細的面）時會失敗。
- 命名：結果經過布林與 `UnifySameDomain`，沿用 ADR 0005 的「目標在前、工具在後」規則。這次沒有驗證移動面前後的持久名稱。

**建議**：C10.1 只支援平面，用上面的做法。不需要為它重建 libcascade。

## 3. 重算時間（B3.x 要做多少）

一個 400×300×20 的板加上 n 個「在頂面畫圓、深 10 的除料」（每個孔 2 個特徵：草圖＋除料）；Node，全部重算，每個特徵都成功：

| 特徵數 | 全部重算 |
|---|---|
| 12 | 約 50–100 ms |
| 26 | 約 135 ms |
| 52 | 約 385 ms |
| 100 | 約 1.2 s |

- 最慢的單一特徵隨面數成長：第 5 個除料 12 ms → 第 49 個 47 ms。整體約為 O(n²)。
- 瀏覽器約為 Node 的 2.5–3 倍（ADR 0016），所以 52 個特徵約 1 s，100 個約 3.5 s。
- 藍圖 §4 預算「50 個特徵 < 2 s」：**簡單特徵（孔）達成，且有約 5 倍的餘裕**。
- **沒有量的**：圓角、薄殼、掃出、疊層拉伸、STEP 輸入本體。它們單一特徵的成本比一個孔高很多，50 個特徵的零件如果含很多圓角，可能超過預算。

**結論**：3a-9 的 B3.x（特徵結果快取）**不是先決條件**，先不做。在 3a-5、3a-6 完成後，用含這些特徵的 50 特徵零件再量一次，再決定。

## 5. 「成形至下一面」

長棱柱（輪廓沿方向掃很長）與本體取交集，`Modified()` 有結果的本體面之中，離草圖平面最近的就是目標面；再用「成形至面」（Phase 1B 已有）的做法。測試：草圖在 z=0，板底面在 z=10，更遠處還有一個凸台：找到的是板底面，結果體積 4000 = 手算。**特徵只存「下一面」這個意圖**，目標面每次重算時從幾何決定；結果的終止面用特徵自己的名稱（`<id>:cap:end`）。只驗證了平面的目標面與單一區段；輪廓跨越多個高度的面（半個輪廓碰到近的面、半個碰到遠的面）要決定是取哪一個，實作時再議。

「成形至頂點」「從曲面偏移」「成形至本體」沒有驗證，範圍與清單仍待使用者對照 SW 2010 說明確認（plan §6 決定 3）。

# ADR 0147：新工程圖的「最適比例」與存檔——存檔等它、它併入放視圖那一步

- 狀態：**已完成（2026-10-15）**。不改檔案格式（工程圖 Schema 仍為 19）。
- 需求追溯：[ADR 0146](0146-drawing-sw-parity-six.md) 確效時發現（DEV_LOG 2026-10-15（晚二）§5 第三點）：在不含 0146 的 origin/main 上同樣重現，屬既有行為。藍圖外的修正，比照慣例以 ADR 追溯；最適比例等待視圖特徵的由來見 DEV_LOG 2026-10-13 審查第 7 項（`autoScaleWhenReady`）。
- 使用者裁定（2026-10-15，選擇題，採建議選項）：「等候＋併入同一步」——存檔對話框照常立即開啟，選好檔案後先等最適比例完成再寫入；最適比例併入「放視圖／新工程圖」那一步，不再是可單獨 Ctrl+Z 的步驟。未採：「等候但復原不變」、「存檔即取消自動比例」（可能存下未置中或超出圖框的版面）。

## 背景（查明的現況）

新工程圖（或在空白圖頁按「標準三視圖」）的比例與置中由 `autoScaleWhenReady` 決定：等**所有視圖的線條**與**可標註特徵**（孔的中心線由此畫出，會佔位置）都到齊才執行 `autoScale()`，後者走 `execute(setSheet)` 成為一個可復原的步驟。特徵比線條晚到；核心載入慢時（e2e 批次中 5.4 s，對單獨跑 1.4 s）差距更大。

在兩者之間按「儲存檔案」：

1. 寫入檔案的是**未置中**的版面（重現：存檔 `shift: null`，之後才變成 `[0, 3]`）；
2. 最適比例接著發生，文件與存檔內容不同，標題出現 `*`；
3. 接著「開啟零件」被「要儲存變更嗎？」擋住；
4. 按一次 Ctrl+Z 退回的是未置中的版面——一個使用者從沒做過的步驟。

ADR 0146 在 `manual-drawing-open-part.js`、`manual-drawing-sw-parity.js` 以「存檔前等 features」繞過，產品行為未改。

## 決定

1. **最適比例不是自己的一步**：`History.amend(cmd)`（`packages/model/src/history.ts`）把命令併入**最後一步**——復原那一步時兩者一起退；沒有可復原的步驟時（從零件建立、視圖隨新工程圖一起來）成為文件起始狀態的一部分，不能復原。命令不合法時拋 `CommandError`、文件不變；同時清掉重做堆疊（那些步驟是在沒有這個變更的文件上記錄的），與 `execute` 一致。編輯工作階段中則併入該工作階段的最後一步。
   - 自動的最適比例改呼叫 `amend`；使用者按的「最適比例」按鈕仍是 `execute`，照舊是一步。共用的計算抽成 `fitSheet()`。
   - 比照 SolidWorks：放第一個視圖時就決定圖頁比例，不會多出一個「改比例」的復原步驟。
2. **存檔等最適比例**：`write()` 寫入前 `await fitSettled()`。對話框在等候**之前**開啟（`showSaveFilePicker` 需要使用者那一下點擊的啟用狀態），所以操作感覺不變，只是寫入延後到最適比例完成。
3. **不等不會來的東西**：`fitSettled()` 在下列任一成立時即完成——最適比例已發生、工程圖已關閉、圖頁沒有視圖、或**沒有任何可能帶來它的工作在進行**（沒有零件正在讀取與建構 `loadingSources`、沒有線條請求 `computing`、沒有特徵請求 `featuring`）。核心失敗時線條永遠不會來，存檔就以當下的樣子寫入，不會卡住；不以逾時判斷（逾時是猜測，慢的機器會被誤判）。
   - 為此 `loadSources` 計數進行中的讀取（`finally` 遞減，失敗也算結束）；`computeLines`、`computeDimensionData` 的 `finally`、`close()`、最適比例完成時都會喚醒等候者。

## 記憶體（AGENTS.md §3.1、§3.5）

不碰核心與 WASM：只改主執行緒的復原歷史與存檔順序，沒有新增任何 OCCT 呼叫，因此不做 Heap 量測（也不宣稱任何 Heap 數字）。

## 已知限制

- 最適比例到來前若使用者又做了別的改動（例如拖動視圖），最適比例會併入**那一步**而不是放視圖那一步；復原那一步時比例也一起退。這種情況下比例仍是自動決定的、不是使用者的操作，以此為可接受。
- 核心失敗時存檔寫入未置中的版面；之後若重新計算成功，最適比例仍會發生並使工程圖變成未存檔——那時版面確實改變了，提示是正確的。
- 等候期間沒有額外的進度提示（工程圖本身的「計算中」狀態照常顯示）。

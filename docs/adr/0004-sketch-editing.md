# ADR 0004：草圖編輯（Phase 1A）

- 狀態：已採用（Phase 1A，2026-09-27）
- 依據：藍圖附錄 C 的 C1、A2.6、D5.3、D6；[handoff.md](../../handoff.md) 的里程碑 1A

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **ID 可讀且永不重用**（例 `sketch2`、`l5`），取代藍圖原寫的 ULID。文件以 `idCounters` 記錄每個前綴已發出的最大編號，新增與刪除都會更新 | 持久名稱內含 ID（`extrude1:side:sketch1.l2`），可讀的名稱讓 JSON 容易比對、錯誤訊息看得懂（B9.6）。刪除後不重用，舊參考才不會悄悄綁到新圖元（B1.3） |
| 2 | ID 由 UI 產生並放進指令 | `mutate` 維持純函數，復原/重做與測試都是確定的 |
| 3 | **Schema v2**（附遷移）：`pointOnLine` 一般化為 `pointOnCurve`（直線、圓、圓弧）；`horizontal`/`vertical` 改為 `a` + 選用的 `b`（一條線，或兩個點）；新增 `idCounters` | SW 的「重合」適用點與任何曲線；水平/垂直也適用兩點。一種關係只用一個型別表達（MECE） |
| 4 | **草圖內只解草圖，不重建 3D**。Worker 的 `solveSketch` 負責求解；離開草圖才重建。編輯草圖時，模型回溯到草圖之前 | 與 SW 相同；大模型時，草圖內的每次操作不必付重建成本 |
| 5 | **拖曳**（A2.6）：被拖曳的點用 PlaneGCS 暫時限制條件（軟約束）拉向游標，並以上一格的解為初值；放開時把整個解存回文件 | 其他幾何做最小擾動；放開後停在使用者看到的位置。實測 104 個圖元，每格 1.6 ms（預算 16 ms） |
| 6 | **點座標 = 擺放意圖**：只在畫圖與拖曳時改變。求解結果是衍生資料，不會在每次求解後寫回 | 同一份文件永遠解出同一個結果（B3.1），不必處理非同步寫回與復原的交互 |
| 7 | **逐圖元定義狀態**（C1.31）：把某個點固定後重算 DOF，DOF 不變 ⇔ 該點已被決定。直線、圓弧看端點與圓心，圓另外檢查半徑 | PlaneGCS 包裝層沒有提供相依參數；這個方法是秩的精確計算，不是猜測。只在編輯後計算（104 個圖元約 66 ms），拖曳時沿用上次結果 |
| 8 | **共用端點的相切**對應為 `angle_via_point`：法向夾角 0 或 π，依目前幾何選較接近的一個。PlaneGCS 的法向慣例：直線是方向逆時針轉 90°，圓是指向圓心 | 原本的「圓心到直線距離 = r」，在相切點與「端點在圓上」一階相依，求解器會把正常的長槽判為過多定義 |
| 9 | **加入尺寸或限制條件前先試算**，會過多定義就不加入並提示 | SW 會提示改為從動尺寸；從動尺寸（C1.29）排在 P1 |
| 10 | **工作階段內可以復原**：`DocHistory` 在交易中有自己的復原堆疊，✔ 時合併成一步。新建特徵的插入指令屬於「工作階段起點」：✖ 會移除它，草圖內的復原不會 | 與 SW 草圖內的 Ctrl+Z 相同，又不會把正在編輯的草圖本身復原掉 |

## 程式碼分工（依 ADR 0001 的擁有關係）

| 位置 | 內容 |
|---|---|
| `@3db/model` | 草圖指令、ID 發放、結構規則（`sketch-rules.ts`：參考種類、刪除連帶） |
| `@3db/sketch` | 求解、拖曳、逐圖元分析（只在 Worker 執行） |
| `@3db/sketch/interact` | 拾取、吸附、推斷、智慧型尺寸、可加入的限制條件、尺寸配置。純 TS，主執行緒可用 |
| `@3db/render` | 通用 2D 疊加層（曲線、點、DOM 標籤）、螢幕↔平面換算、正視於 |
| `apps/web/src/sketcher` | 工具狀態機 `SketchController`（經 `SketchHost` 介面與 store 溝通，可以脫離 DOM 做單元測試）、疊加層組裝 |

## 推斷與吸附規則（C1.25、D5.3）

- **吸附優先序**：
  1. 點（含原點；同距離時草圖點優先）；
  2. 中點；
  3. 曲線上；
  4. 自由位置。
- **吸附的效果**：
  - 吸附到點 = 合併，重用既有點的 ID；
  - 吸附到原點 = 新點 + 重合；
  - 吸附到中點 = 中點關係；
  - 吸附到曲線上 = 重合（點在曲線上）。
- **直線方向**：從圓弧端點出發且方向在 6° 內，推斷為相切，且優先於水平/垂直，兩者不會同時加入；否則在 3° 內推斷為水平或垂直。
- **智慧型尺寸**：依選取的圖元與放置位置，決定距離、水平、垂直、角度、半徑或直徑，行為與 SW 相同。

## 過程中發現並修正的問題

- **相機矩陣過時**：three.js 只在繪製時更新相機矩陣。縮放或正視於之後立刻點擊，螢幕↔平面換算會用到過時的矩陣。現在換算前會先同步矩陣，並一律以畫布尺寸為準。
- **點與原點重合時選到原點**：現在改為草圖點優先。

## 範圍外

- 在模型平面上繪製草圖：排在 1B。
- 草圖圓角、修剪、偏移、狹槽、多邊形、從動尺寸：屬於 P1。
- 由使用者擺放尺寸位置：目前是自動配置。

## 驗證

- **自動化**：91 個測試。新增的測試涵蓋指令、遷移、交易內復原、拖曳、逐圖元狀態、端點相切、互動幾何、控制器流程。
- **瀏覽器實測，只用 UI 操作**：
  - 上基準面：長槽 + 同心孔，完全定義（全黑）。伸長後體積 2659.734 mm³，等於解析值。
  - 前基準面：矩形 + 圓孔。伸長後體積 14214.602 mm³，等於解析值。

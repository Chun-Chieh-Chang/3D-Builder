# ADR 0236：「設計配合件…」入口——以匯入的實體為參考，在同一零件檔建模並拆成組合件

日期：2026-11-04。狀態：**已實作並通過全部驗收（AC1–AC13）**，Schema 90。

使用者裁決（2026-11-04）：**Q1 = A2**（新增 `locked` 屬性）；**Q2 = 只放右鍵**；**Q3 = 第一個配合件本體命名「配合件1」**（之後依序「配合件2」…）；**Q4 = 提供「產生組合件」按鈕**，由使用者決定何時產生；**驗收標準 AC1–AC13 照原文**。

## 背景

使用者以 SolidWorks 轉出的 STEP（`3D_MT17203_CIV0000467_Porduct`，340 面）匯入後，想做「與之配合的零件或組件」。STEP 只帶幾何、沒有特徵，這是任何 CAD 的共同限制；本系統既有流程（同一零件檔建多本體 → 產生組合件）能做到，但使用者必須自己記住約六個步驟（先存檔、取消合併、轉換實體引用、組合相減、產生組合件…）。使用者要求「不必閱讀步驟也能完成」。

同日的實測與修正：「轉換實體引用」點含圓弧的面原本一律被判過多定義，已在 `eb1646cd` 修正；該 STEP 的頂面現在一次轉入 14 條、完全定義、伸長面積吻合。這是本入口的前提，已滿足。

## 現況盤點（2026-11-04，`7be46fe2`）

| 需要的能力 | 現況 | 位置 |
|---|---|---|
| 把匯入件標成參考 | **有**：「設為參考本體」——不計質量、不輸出到零件 STEP、不進零件表 | `BodyProps.reference`（`packages/model/src/schema.ts` 1306–1310）；命令 `setBody`（`commands.ts` 188）；設計樹右鍵 `tree.makeReference` |
| 從匯入件的面取輪廓 | **有**：「轉換實體引用」點面取外框與孔；含圓弧已修 | `convertReferences`（`apps/web/src/worker/kernel.worker.ts`）；`heldArcs`（`packages/sketch/src/planegcs.ts`） |
| 新特徵長成另一個本體 | **有**：特徵的 `merge?: boolean`，預設合併 | `engine.ts` 各特徵 `f.merge !== false` |
| 拆成組合件 | **有**：「產生組合件」，每個本體一個衍生零件檔；要求已存檔且無未存變更 | `generateAssembly`（`apps/web/src/state/store.ts` 3674–）；`packages/io/src/derivedAssembly.ts` |
| **保護參考件不被改到** | **沒有**。凸台合併時與**任何**相接的實體融合（只跳過曲面本體，不看 `reference`）；除料作用於所有本體 | `apply()`（`engine.ts` 2653–2683）；特徵範圍 C7.4 未做（`docs/blueprint.md` 604，P2） |

結論：入口本身只是把既有功能串起來；**真正缺的是第 5 列**——在參考件旁邊做凸台會被併進參考件、除料會把參考件也切掉。不先解決，一鍵入口只會讓錯誤更快發生。

## 決定（提議）

1. **入口**：在設計樹與 3D 視窗的右鍵選單，對「實體本體」顯示「設計配合件…」；曲面、曲線本體與輸入的網格不顯示。組合件與工程圖中不顯示。
2. **開始時**（一個可復原的步驟）：
   - 零件從未存檔或有未存變更 → 先走「另存新檔」；使用者取消則整個入口不做任何事。
   - 把所選本體標為**參考且鎖定**（見第 3 點）。
   - 提示下一步：「點參考件的面開始畫配合件」，並把草圖工具切到「轉換實體引用」可用的狀態。
3. **保護：新增本體屬性「鎖定」**（`BodyProps.locked?: boolean`，建議方案 A2，見「待決問題 Q1」）。鎖定的本體：
   - 不是凸台合併的對象（`apply()` 跳過它，如同曲面本體），所以第一個凸台自然長成新本體，之後的凸台併進這個新本體；不需要改特徵的 `merge` 預設值。
   - 不被除料、薄殼、圓角等修改特徵改變；「組合」時不能當主要本體，**可以**當相減的工具本體（做凹槽座用），且本身保留。
   - 仍可被選取作參考：轉換實體引用、量測、干涉檢查、組合件結合。
   - 舊檔沒有這個欄位，行為完全不變（`reference` 的既有語意不動）。
4. **完成**：面板「完成 → 產生組合件」直接呼叫既有「產生組合件」；鎖定的參考件成為組合件裡的參考零組件（不進零件表）。
5. **不在本 ADR 範圍**：點面一次套用間隙偏移、截面取輪廓（handoff §1b #4）、一鍵凹槽座（#5）、組合件中關聯編輯。

## 紅隊四問

1. **輸入破壞**：對不存在的本體 id、曲面本體、已鎖定的本體執行入口 → 命令層明確報錯並說原因；不默默略過。
2. **相交破壞**：配合件與參考件重疊（干涉）時，鎖定保證不會被融合或切除；以體積前後比對驗證，而不是只看本體數。
3. **依賴鏈**：`locked` 必須走完 `schema.ts` → `commands.ts`（`setBody`）→ `serialize.ts`（舊檔遷移）→ `engine.ts`（合併、除料、組合）→ 設計樹顯示與右鍵 → `help.*` 與 `docs/help-links.json`。
4. **零 Mock**：驗收用使用者的 SW STEP 與 golden 零件，體積由 kernel 實量；不 hardcode 結果。

## 待決問題（請使用者裁決）

- **Q1 保護的做法**：
  - **A2（建議）**：新增 `locked` 屬性，只有經此入口（或右鍵「鎖定」）標記的本體受保護；舊檔不受影響。
  - A1：直接改 `reference` 的語意，讓所有參考本體都不被合併、不被除料。較少概念，但會改變既有夾具主模型的重建結果（AC9 會失敗），需要遷移。
  - B：先做特徵範圍（C7.4）——每個特徵選要作用的本體。最通用，但工作量大、屬 P2。
- **Q2 入口位置**：只放右鍵，還是「工具」選單也放？
- **Q3 新本體名稱**：第一個配合件本體自動命名為「配合件1」，或沿用預設的特徵名？
- **Q4 完成時**：直接產生組合件，還是只提供按鈕、由使用者決定何時產生？

## 實作與驗收結果（2026-11-04）

- **模型**：`BodyProps.locked`（`schema.ts`）、`setBody.locked`（`commands.ts`）、Schema 90 恆等遷移（`serialize.ts`）。
- **引擎**（`packages/regen/src/engine.ts`）：`apply()` 合併與 `boolBodies()` 除料／交集略過鎖定本體；`advance()` 為通用守門——鎖定本體的形狀被改或被移除，該特徵以 `body.lockedChanged` 失敗並釋放它做出的形狀；`combineBodies()` 拒絕鎖定的主要本體與「加入」的鎖定工具，相減／交集保留鎖定工具；鎖定件之後的特徵做出、未命名的實體命名為「配合件N」。
- **介面**：設計樹本體右鍵「設計配合件…」／「解除鎖定」與「（鎖定）」標示；3D 視窗實體面右鍵（`partMenu` 以 `matingBody()` 判斷）；`store.designMatingPart()`（先存檔、一個復原步驟）；3D 視窗提示列與「產生組合件」按鈕（`generateMatingAssembly()`）；action `design-mating` 不放頁籤、圖示對應 `body`；中英說明主題 `help.designMating.*`。

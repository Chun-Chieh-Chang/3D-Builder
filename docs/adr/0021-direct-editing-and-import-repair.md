# ADR 0021：直接編輯與輸入修復（Phase 3a-2：刪除面、移動面、STEP 診斷與縫合）

- 狀態：已採用（2026-10-01）。使用者決定：「置換面」先不做（見「未做」）；樣本中沒有真實的壞檔，缺陷樣本由程式製造。
- 依據：藍圖 C10.1（移動面）、C10.2（刪除面、刪除鑽孔）、F2.2（輸入診斷與修復）、A1.7（檢查與修復）；[phase3-plan](../phase3-plan.md) 的 3a-2；[ADR 0017](0017-phase3a-technical-validation.md) §2（移動面用延伸板）；[ADR 0009](0009-step-import.md)（輸入）；[ADR 0005](0005-features-and-booleans.md)（命名繼承）。
- **Schema 升為 9**：新增兩種特徵 `deleteFace`、`moveFace`，`importedBody` 多一個選填的 `sewTolerance`。v8 → v9 不需轉換內容；版本號讓舊程式拒絕開它不認得的特徵。

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **兩個新特徵，都以持久名稱引用面。**<br>`deleteFace { faces: Ref[], hole?: true }`、`moveFace { face: Ref, distance: Expr }`。命令：`setFaces`、`setMoveFace`、`setImportOptions`。距離是運算式（`nonZero`：不能是 0，可以是負的）。父子關係由引用的面名稱導出（`dag.ts`），不另存 | 與圓角、導角同一套：引用 = 持久名稱 + 指紋，遺失時有「改用這個」（ADR 0018） |
| 2 | **刪除面用 `BRepAlgoAPI_Defeaturing`（ADR 0003 G3），周圍的面延伸補合缺口。** 每個要刪的面都必須真的不見（`IsDeleted`）：有任何一個留下就是特徵的錯誤，說「有 n 個面無法移除」，不回傳半成品。鄰面的來源記為 `modified`，所以名稱照舊；沒有新面 | 刪除鑽孔與圓角是修改輸入件最常做的事（藍圖 D.2：輸入的品質比多做幾種特徵重要）。靜默的半成品比明確的失敗糟 |
| 3 | **「刪除鑽孔」存成意圖 `hole: true`，不存孔有哪些面。** 重算時由模型算出（`holeFaces`）：① 鄰面的所有鄰面都已在內的面（盲孔孔底）；② 同軸、同半徑的凹圓柱（CAD 把孔壁切成兩半）；③ 與孔壁同軸、相鄰的錐面或環面（孔口的倒角或圓角，只加不再往外長，所以孔口外面的面不會被吃掉）。別的特徵改了孔的樣子，孔仍然是孔 | 實際的夾具檔（2004 個面）的孔是兩個半圓柱加孔口圓角；只選一個面做不到「刪孔」 |
| 4 | **移動面有兩種做法，依鄰面與面的關係選。** 先在每條共用邊上取三個點（中間與近兩端）比對鄰面的法向：<br>• 與移動面**相切**（點積 ≈ ±1，例如邊緣有圓角）：拒絕，說明「請先移動連同的圓角，或先刪除圓角」——沒有「在哪一側」可言，不猜；<br>• 全部**垂直**且鄰面都是平面：把這個面本身沿法向掃出去（**掃出**）；鄰面是曲面（孔壁）時先試延伸板，失敗再掃出；<br>• 其他（斜面）：**延伸板**——整張平板被每個鄰面「在這個面那一側」的曲面逐一切下（ADR 0017 §2），所以斜壁維持原本的斜度。切完後板貼在這個面所在平面的那一面必須仍等於這個面（面積相同），否則這個面不是凸的、被別處的邊切掉了，**拒絕**並說明 | 延伸板的半空間是整個平面，凹形的面（L 形、環）會被另一邊的曲面切掉遠端；掃出對任何形狀的面都對，但鄰面不垂直時側面會歪。兩種做法各有不能做的情形，每個不能做的情形都有訊息，不產生錯的形狀 |
| 5 | **移動面的命名**：被移動的面留著原名（`modified` 自己）；板的側面取它所靠的鄰面的名字（延伸板：切它的那個曲面；掃出：掃出那條邊對面的面），合併共面後與鄰面同名。**只允許重新分組移動面的鄰面**：不相干的面之間的邊用 `UnifySameDomain.KeepShape` 保護起來，否則在 2004 個面的檔案移動一個 3.9 mm² 的面，會把 48 個不相干的共面合在一起、別人用的名稱跟著改（實測）。往材料內移動超過後面的厚度（掃出穿到另一側）時檢查體積少掉的量是否小於面積 × 距離，是則拒絕 | 名稱是別的特徵的參考；體積的比對容許 1e-6 倍整體體積（2000 面的本體，體積積分的精度） |
| 6 | **輸入診斷是一份數字**（`ImportDiagnostics`：實體數、面數、不屬於實體的面、讀入時是否通過檢查、是否修復過、是否縫合與容差、縫合後沒接上的邊數、現在是否通過），由核心產生、經 `FeatureResult.diagnostics` 到介面，介面用 `t()` 說成文字。`importStep` = 讀檔 + `repairImport`；`repairImport` 公開，讓 STEP 讀入器自己會修好的小缺陷可以在記憶體裡做出來測 | 數字可以測；文字隨語言 |
| 7 | **只有曲面、沒有實體的檔案：縫合成實體**（`BRepBuilderAPI_Sewing` + `ShapeFix_Solid`），預設容差 0.01 mm。縫合後還有自由邊（曲面沒圍成封閉的體積）時是特徵的錯誤，說「仍有 n 條邊沒有接上」並建議加大容差，不從開放的殼猜一個實體。**容差存在特徵上**（`sewTolerance`，運算式，屬性管理員的「縫合容差」），因為它決定了結果；匯入結果的快取改以「資料雜湊 + 容差」為鍵（容差改變就是另一次縫合，舊的釋放）。曲面縫合後的面序由 Sewing 決定，同樣的檔案與容差永遠相同，所以 `imp:f<k>` 的名稱照舊成立 | F2.2。有真實 SW 輸出的缺陷檔之前，行為以製造出來的樣本證明 |
| 8 | **介面**：「特徵」分頁多了「刪除面」「移動面」；在圖面點面加入或移除（刪除面）、點平面（移動面），選取中的面會高亮；已選取的面會成為起點。「刪除面」有「刪除鑽孔」勾選。輸入本體的屬性管理員多了診斷報告與縫合容差。編輯時顯示這個特徵之前的模型（同圓角） | 同 SW 的流程；沿用現有的選取與遺失參考機制 |
| 9 | **重算有時間上限：超過就換掉 Worker。** OCCT 不能中斷，而實測有一個操作永遠不回來：產品件（340 面）上刪除最小的圓柱面（`import1:f254`，2.2 mm²）的 Defeaturing 跑了十分鐘以上仍未結束（周圍是 B 樣條面）。核心的 `Message_ProgressIndicator` 沒有綁定可中斷的子類，所以改在介面端：`store.ts` 的重算超過 60 秒（不含載入核心的時間）就 `terminate()` 那個 Worker、重開一個、重送語言與輸入資料，並說「這次的內容讓 OCCT 卡住了；可以復原最後一個動作」；文件在主執行緒，所以只損失時間，也不自動復原。另外：重算已經超過 15 秒、文件又改了（例如使用者按了復原），就不等它，立刻換 Worker 跑新的。`api` 改成一個轉給「目前的 Worker」的代理，草圖求解佇列也丟掉舊的（`LatestRunner.abandon`），舊 Worker 的回覆（世代號不同）一律不採用 | 一個卡住的操作不能讓整個程式卡死；這個保護對之後所有進階特徵（薄殼、拔模、掃出）也有用。限制：之後的 Worker 要重新載入 OCCT（約 3 秒，瀏覽器已快取）與重建；組合件載入零件不在這個保護範圍內 |

## 已知限制與未做

- **置換面（C10.2 的一部分）：使用者決定先不做**，沒有驗證過，ADR 0017 也沒有涵蓋。
- **移動面只做平面**，只沿外法向偏移；SW 的「平移 XYZ」「旋轉」沒有做。一次只動一個面（動兩個共面的面要做兩個特徵）。
- **移動面的做法有兩個不能做的情形**：與它相切的鄰面（先刪圓角）；非凸的面而且鄰面不都垂直（例如 L 形斜壁的頂面）。兩者都拒絕並說明，不產生錯的形狀。
- **刪除面不保證每個面都能刪**：周圍的面延伸後必須能接上。實際檔案中，192 個一對一對的凸圓柱面（滑槽、銷的兩半）單獨刪會失敗；孔與孔口的圓角則可以。失敗的特徵說明原因，本體保持刪除前的樣子。
- **編輯中沒有預覽**：屬性管理員顯示這個特徵之前的模型（同圓角、導角），按 ✔ 後才看到結果。
- **輸入修復的真實缺陷檔**：目前只有製造的樣本；使用者之後拿到真實的壞檔，要補一個。縫合的預設容差 0.01 mm 是依一般 CAD 輸出的縫隙選的，沒有真實資料佐證。
- 效能：2004 個面的檔案，刪一個孔約 3 秒、移動一個面約 3.5–5.5 秒（含重建全部的名稱與拓撲），主要是 Defeaturing 與布林，與面數成正比。不在 3a-2 優化；3a-9 量過之後再決定（ADR 0017 §3）。

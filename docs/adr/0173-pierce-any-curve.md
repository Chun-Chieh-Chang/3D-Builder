# ADR 0173：任意曲線的貫穿點（G4）

## 1. 背景
這是 2026-10-19 草圖參照盤點的 G4。

**現況**：「貫穿」（C1.26）和吸附的貫穿點只支援直線邊（`pierceEdge` 要求 `curve === 'line'`；ADR 0136 §限制）。

**缺口**：圓弧、橢圓、雲形線、螺旋（ADR 0168）穿過草圖平面的位置，草圖都跟不到。SolidWorks 的貫穿可以用在任何曲線上，掃出和導引曲線常靠它定位輪廓。

## 2. 決策
1. **在 kernel 對曲線求值，不做布林運算**：
   - `Kernel.edgePlaneCrossings(shape, edge, plane)` 對 `BRepAdaptor_Curve` 求帶號距離；
   - 參數範圍以約 0.5 mm 一步切成 64 到 4096 段；
   - 有變號的段落用 Newton 法求根，落在段外時改用二分法，收斂到 1e-12 mm；
   - 端點在平面上（1e-9 內）也算一個交點，並標記為 `end`。

   沒有使用 `BRepAlgoAPI_Section`：它是布林運算，對 B-spline 運算元會永久佔用 Emscripten Heap（AGENTS §3.5）。綁定裡也沒有 `GeomAPI_IntCS`。
2. **精度要分兩件事驗證**：
   - 交點落在平面上：1e-12，這驗證的是求根；
   - 與理想螺旋公式的差距：受 kernel 螺旋本身的近似誤差限制。它由 `BuildCurves3d` 建出，OCCT 容許的誤差是 Precision::Confusion = 1e-7；實測約 4e-9。

   測試以 1e-7 比較公式，並寫明理由，而不是用 1e-9 去假設一個不存在的精確螺旋。
3. **一條曲線多次穿過平面時**，取最接近該點目前儲存位置的那個交點。草圖點的儲存座標本來就是「初始猜測與意圖」（schema 註解），所以結果仍然是決定性的。SolidWorks 也取最近的那一個。
4. **吸附**：曲線邊在草圖平面上的內部交點列為貫穿吸附項目。端點在平面上的交點不列，因為它已經是頂點或端點（ADR 0171）。
5. **範圍**：只處理模型邊。其他草圖的曲線要靠跨草圖參照，屬於第二批 G6。

## 3. 設計
- `references.ts`：`ReferenceScope` 新增可選的 `curves.crossings(index)`，由 engine 和 worker 用 kernel 提供：
  - `pierceEdge` 是直線時照舊走解析解；不是直線時用 `curves`；
  - 沒有 `curves` 時，仍回報「只支援直線」。
- `followReferences`：曲線的貫穿點取最接近儲存位置的交點；完全沒有交點時報錯。
- `modelSnapItems`：加入曲線邊的內部交點。

**反向對照**（皆已還原）：
- engine 不提供 `curves` → 跟隨相關 2 項轉紅；
- 拿掉曲線的吸附交點 → 1 項轉紅；
- 不取最近交點 → 1 項轉紅。

## 5. 已知限制
- 同一個 0.5 mm 步長內穿過兩次，或只是擦過平面，不會被找到。
- 不支援其他草圖的曲線（G6）。

# ADR 0254：特徵名稱唯一、估計值標記與特徵樹的整理

日期：2026-11-15。狀態：已實作。

## 背景

使用者看了 Agent 依照片建好的 SDS-plus 鑽頭（`tests/golden/sds-plus-bit.3dbx`）的特徵管理員，要求對照 SolidWorks、FreeCAD 與 [SolidCraft](https://github.com/tangency-labs/solidcraft)，找出不合理的地方。對照結果：

1. **名稱可重複**。樹上「開口槽平面」「開口槽」「開口槽（估）」各出現兩次。`renameFeature` 只檢查空白，`insertFeature` 完全不檢查。運算式以草圖名稱找尺寸（`D1@草圖1`），同名時 `Parameters` 會報「名稱不明確」；Agent 與使用者也只能靠名稱分辨特徵。SolidWorks 新增時自動編號、改名時拒絕重名；FreeCAD 的內部名稱一定唯一。
2. **曲線算進「實體(3)」**。兩條螺旋線列在實體資料夾，數字 3 只有 1 個是實體。SolidWorks 與 FreeCAD 都不把曲線當實體。
3. **同一個東西出現兩次**。掃出的「吸收清單」含路徑，路徑是螺旋特徵；樹只在頂層略過被吸收的草圖，所以螺旋同時列在頂層與掃出底下。特徵右側的「↳ 父特徵」標籤也和展開在下方的草圖重複。
4. **估計值寫進名稱**。Agent 用「（估）」與 `est_` 字首標出估計值：改成實測值後要改名，而名稱又被尺寸引用。
5. **參數看不到**。Agent 已把尺寸寫成 28 個變數，樹上沒有地方顯示；SolidWorks 在樹中有「方程式」資料夾，SolidCraft 有 Parameters 面板。
6. 每列都顯示劃掉的眼睛，畫面雜。
7. 重複的特徵（兩條排屑溝、兩組開口槽）各建一次，而不是建一個再陣列；也沒有用資料夾分區。這是 Agent 的建法，不是介面。

使用者另指「顯示隱藏實體」按鈕被頁籤蓋住。核對 CSS：頁籤列是 `position: sticky`，截圖時樹已捲動，按鈕只是捲到頁籤下方，不是版面錯誤，不改。

## 決定

使用者於 2026-11-15 選定全部做、估計值做成正式標記、通過檢查後提交並推送。

1. **名稱唯一，重名拒絕而不自動改名**。`insertFeature` 與 `renameFeature` 遇到其他特徵已用的名稱（去掉前後空白比較）拋出 `cmd.featureNameTaken`，錯誤訊息附上可用的名稱（`freeFeatureName`：「開口槽」→「開口槽2」、「Cut3」→「Cut4」）。不採「新增時自動改名」：同一批命令裡，後面的運算式若寫的是原名，會默默綁到另一個特徵。`insertFeature` 也拒絕空白名稱。舊檔中已重名的特徵照樣開啟，不在背後改名。
   - 會自己產生名稱的地方改用 `freeFeatureName`：特徵辨識用編號找可用名稱，MCP 的 `create_primitive` 從 `<名稱>:profile` 尋找可用的輪廓草圖名稱。數字尾碼以整數精確遞增，超過 JavaScript 安全整數範圍時仍能建議下一個名稱。App 的新特徵本來就用 `nextName` 編號。
2. **估計值標記**（schema v96）。特徵與變數各加 `estimate?: true`，只存 `true`。設定方式：`setFeatureNote { estimate }`、`addVariable`／`setVariable { estimate }`；不是布林值就拒絕，不猜。舊版程式拒開 v96 檔，不會丟掉標記讓估計值看起來像實測值。
3. **特徵樹**（`FeatureTree.tsx`）：
   - 特徵底下只放草圖；螺旋等曲線特徵留在歷程原位，只出現一次。
   - 實體資料夾只數實體與曲面；曲線另列「曲線(n)」。
   - 頂端加「參數(n)」節點，預設收合；展開列出 `名稱 = 值`，按兩下開啟方程式。過濾文字也套用到參數。
   - 有估計值的特徵與變數顯示「估」徽章；右鍵選單「標為估計值／取消估計值標記」；有估計值時過濾列出現「估計值 n」按鈕，按下只列含估計值的特徵與參數。方程式對話框加「估計值」勾選欄。
   - 「↳ 父特徵」標籤在父特徵就是展開於下方的草圖時不顯示（滑鼠提示仍列出全部父特徵）。
   - 隱藏項目的眼睛平時不顯示，滑鼠指到該列、選取該列或以鍵盤聚焦時才出現。
4. **Agent 指引**：`apps/mcp/src/reference.ts` 的連線說明與 [照片建模流程](../photo-to-cad.md) 加上：主要尺寸寫成變數、估計值用標記不寫進名稱、相同特徵建一個再陣列或鏡射、名稱不可重複、依區域分資料夾。

## 紅隊四問

1. **輸入破壞**：空白或只有空白的名稱、前後空白造成的「看起來一樣」、`estimate` 給字串／數字／null／`false`（新增時），都明確拒絕；不自動修正。名稱尾端是數字時從該數字往後編（`x9` → `x10`）。
2. **拓樸與幾何相交**：不涉及幾何。
3. **依賴鏈**：名稱是運算式找草圖尺寸的鍵；唯一後 `D1@P` 不再可能不明確。改名的既有流程（`rewriteNames` 更新引用）不變。辨識流程裡沒有用名稱引用草圖的運算式，改名安全。標記的完整路徑：`schema.ts` → `commands.ts` → `serialize.ts`（v96）→ 樹與方程式對話框 → MCP 說明。
4. **零 Mock**：單元測試以文件本身為真值（存了什麼、檔案讀回、運算式讀到的值）；介面以真瀏覽器操作鑽頭檔驗收。

## 驗證結果（2026-11-15）

- 單元測試 `packages/model/test/feature-names.test.ts` 10 項。突變 5 項：新增不檢查、改名不檢查、比較不去空白、標記不驗型別各使 1～2 項轉紅；「編號從原數字開始」是等價突變（該數字必已被占用，迴圈會跳過），存活屬預期。
- 真瀏覽器 `tests/e2e/manual-feature-tree-0254.js` 8 步全過：曲線資料夾與實體數、螺旋只一列、↳ 不重複、參數節點與值、標記／徽章／快速過濾／取消、重名被拒且文件不變、隱藏眼睛不顯示、方程式勾選估計值後樹與過濾列出該變數。
- 既有測試被新規則抓到的同名固定資料：`tests/phase3/direct-edit.test.ts` 的 `target` 參考面複製了 `p` 的名稱，改為 `target`；`tests/phase7/sheet-unfold-refold.test.ts` 的巢狀展開與錯誤的反折各自複製了 `u`／`f` 的名稱，改用自己的名稱，讓它們仍因原本要測的理由被拒（否則會因重名先被拒，測試照樣變綠卻沒測到）。
- 本機（雲端 Linux 工作副本）的 `verify:ui` 以瀏覽器私有檔案系統建專案時，既有腳本（例如 `manual-action-icons.js`）同樣在建專案這步失敗（`TypeMismatchError`）；新腳本因此直接讀檔交給 store，不經專案資料夾。此環境問題與本次改動無關（改動前的提交也一樣），未在此處追查。

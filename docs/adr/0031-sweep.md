# ADR 0031：掃出（Phase 3a-6b）

- 狀態：已實作（2026-10-01）。
- 對應：C4.4 掃出（輪廓＋路徑；導引曲線、扭轉是 P2），見 [phase3-plan](../phase3-plan.md) §3 的 3a-6；演化歷史夠命名已在 [ADR 0017](0017-phase3a-technical-validation.md) §1 驗證過。
- **Schema 升為 18**：新的特徵種類 `sweep`（輪廓草圖 `sketch`、路徑草圖 `path`、`op`、`merge`、`contours`）。舊檔不需轉換；已補 v17 樣本 `tests/fixtures/old-versions/v17-hole.3dbx`（由 `8f3948c` 寫出）。
- 證據腳本（不進 `npm test`）：`spikes/occt-gaps/phase3-sweep.mjs`、`phase3-sweep-closed.mjs`（`node` 直接執行）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **兩張草圖：輪廓（要掃的封閉輪廓）與路徑（一條連在一起的開放線）**。路徑只有直線與圓弧（草圖本來就只有這些），要剛好一條；沒有線、有分開的好幾條、有分岔、是封閉的，各有一則說明的錯誤。輪廓的選取、`contours`、「合併結果」、填料／除料與伸長相同。 | 使用者選的範圍（2026-10-01）：輪廓＋路徑，不做導引曲線與扭轉。路徑做成草圖，才有尺寸、限制條件與運算式可以用。 |
| 2 | **掃出從路徑落在輪廓平面上的那一端開始**。輪廓的位置可以離路徑的端點很遠，掃過去時維持它對路徑的相對位置（輪廓偏離路徑多少，掃出的體積就偏離多少）。兩端都不在輪廓的平面上（容差 1e-6 倍路徑尺寸）是錯誤，訊息說兩端各離平面多遠；路徑在那一端沿著輪廓的平面走（切線與平面法向的夾角餘弦 < 1e-3）也是錯誤。路徑畫反了（起點在遠端）就把整條路徑反過來走，結果相同。 | 不猜：沒有端點在平面上時，要從路徑中間穿過平面的掃出要不要往兩邊走，是另一個決定。 |
| 3 | **輪廓跟隨路徑**（「隨路徑變化」）：用 `BRepOffsetAPI_MakePipeShell`，`SetMode(false)`（修正過的 Frenet 標架）。輪廓與路徑的夾角維持不變，輪廓不必垂直於路徑（傾斜 30° 的方形，體積 = 垂直投影面積 × 長度）。直線接圓弧、**反向的兩段圓弧（S 形）**、輪廓偏離路徑，體積都與帕普斯定理一致；修正的 Frenet 在直線與反曲處沒有扭轉。 | 平面路徑，標架的二法向量就是路徑草圖的法向，沒有扭轉的自由度可以選；固定方向與扭轉隨 C4.4 的 P2 一起做。 |
| 4 | **封閉的路徑還不支援**：`MakePipeShell` 對封閉的脊線回報有效的實體，但**體積為 0**（Frenet、修正的 Frenet、不設模式、輪廓反向、`ShapeFix_Solid.SolidFromShell` 都試過，`phase3-sweep-closed.mjs`）。所以報錯「封閉的路徑還不支援」，不產生一個體積為 0 的實體。路徑要通過輪廓平面的點也限制在線的端點上，所以圓（整圈的路徑）同樣不收。 | 沒有辦法確認那個形狀是對的。 |
| 5 | **面的命名**：側面 `<掃出>:side:<輪廓草圖>.<輪廓圖元>@<路徑圖元>`，端蓋 `<掃出>:cap:start`（路徑的起點端）與 `<掃出>:cap:end`。一個側面由「輪廓的一條邊」與「路徑的一條邊」交叉產生，所以名字就是這一對。對應用**兩個產生清單的交集**：輪廓邊 `Generated` 的面 ∩ 路徑邊 `Generated` 的面（用面的身分比，不靠順序）。沒有路徑邊認領的面（不應該發生）只以輪廓邊命名，不會沒有名字。 | 實測：每條輪廓邊在每段路徑上各產生一個面，順序也和路徑一致，但名字不靠順序（ADR 0017 的陷阱一樣：從 wire 取邊）。路徑加了一段或拆了一段，名字會變，這是預期的；改長度、改半徑、改輪廓尺寸，名字不變。 |
| 6 | **有洞的輪廓**（例如管子）：外輪廓掃出，減去每個洞各自掃出的形狀；面的來源經布林的歷史（`faceSources`）傳到結果，洞的內壁是 `<輪廓草圖>.<洞的圖元>@<路徑圖元>`。**多個輪廓**各自掃出，放進同一個複合體，每個面保留自己那次掃出的來源。 | 管子是最常見的掃出之一；`MakePipeShell` 只收線框，不收有洞的面。 |
| 7 | **結果要是有效的實體**（`BRepCheck_Analyzer`，且體積 > 0），否則錯誤「掃出的結果不是有效的實體（路徑轉彎的半徑比輪廓小，輪廓掃過去自己疊在一起時常見）」。實測：30 寬的輪廓繞半徑 3 的彎，OCCT 給出的實體不是無效就是體積 ≤ 0，被這一關擋下（兩個條件沒有分開量）。 | 自己疊在一起的掃出沒有意義，也會讓之後的布林出錯；擋在這裡，訊息才說得清楚。 |
| 8 | **介面**：「特徵」分頁的「掃出填料/基材」「掃出除料」，先選輪廓草圖；路徑預設是最近畫了線或圓弧的另一張草圖，屬性管理員的清單可以換成它之前的任何草圖（`setSweepPath`，路徑與輪廓不能是同一張）。掃出用過的輪廓與路徑兩張草圖，預設隱藏（同伸長）。刪除、抑制、父子關係都由 `parentsOf` 的 `[輪廓, 路徑]` 推出。 | 與其他特徵一致。 |

## 驗證

- **手算**（`tests/phase3/sweep.test.ts`，13 項，真的 OCCT）：直線 6×4×40（體積、六個面的名字）；直線＋R10 四分之一圓弧＋直線，帕普斯 24×(30+5π+20)，14 個面名字都不重複；S 形（兩段反向圓弧）、輪廓偏離路徑 1：16×(π/2·9+π/2·11)；管子（外徑 3、內徑 2）π×5×路徑長，內外壁各有名字；路徑畫反、路徑背著輪廓法向走；除料（Ø4 的溝，路徑在底面、輪廓圓心在 z = 5）18000 − π·4·25；填料與本體接觸時合併、`merge: false` 時成為第二個本體；兩個輪廓；含圓角與孔的零件加進除料後，之前的參考找得到、板加寬後 0 失敗；在掃出的端蓋上畫草圖再伸長。
- **錯誤**（各有可讀訊息的測試）：沒有線、封閉的一圈、兩條分開的線、兩端都不在輪廓的平面上、沿著輪廓的平面走、路徑草圖被抑制、輪廓掃進自己、路徑與輪廓同一張／不是草圖／不是掃出特徵的指令。
- **舊檔**：v17 樣本（示範件加柱孔）開啟、遷移到 18，孔照常重算（體積 = 示範件 − π(3.25²·3.4 + 1.7²·0.6)）。
- **瀏覽器**（`tests/e2e/phase3-sweep.js`）：兩條路徑（40、60）與右基準面上的 6×4 矩形，用 UI 做掃出：路徑預設為最近一張（體積 1440），屬性管理員的清單換成另一張 → 960，✔ 之後設計樹有「掃出1」、6 個面的名字、0 個 Console 錯誤。
- **擴充檢查**：`npm run check` 全過（型別、分層、i18n 基準不增加、全部測試）。

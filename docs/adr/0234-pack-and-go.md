# ADR 0234：單一打包檔（.3dbp，Pack and Go）與解開時更新既有檔案

日期：2026-11-03。狀態：已實作。

## 問題

組合件只記著零件的相對路徑（B9.4），工程圖只記著視圖模型的路徑，零件的衍生本體只記著母零件的路徑。所以只把組合件或工程圖檔交給別人，對方打不開。使用者要一個「單一打包檔」：一個檔帶著走；解開到一個已有部分檔案的專案資料夾時，要能更新既有的版本。

使用者選定（以白話說明三個問題後回覆「照建議」）：

1. 只裝**用得到的**檔（不是整個資料夾）。
2. 解開時資料夾已有同名檔：內容相同的略過；內容不同的**列出來逐一勾選**，預設取代。
3. 新的檔案類型 `.3dbp`，「開啟舊檔」可直接開。

## 決定

### 格式（`packages/io/src/package.ts`）

- zip：檔案放在它在專案資料夾中的路徑，加上 `3dbp.json`（`format`、`version`、`main`、`files`）。改副檔名成 .zip 就能用一般工具解開成同樣的資料夾。
- `isPackageData` 以「zip 且有 `3dbp.json`」辨認，不看副檔名；零件檔也是 zip，但沒有這個項目。

### 打包（`collectPackage`）

- 從主檔開始，逐檔讀取並找出它引用的檔（`referencesOf`）：組合件的 `files`（零件、STEP、次組合件），工程圖每一頁的模型視圖 `source`（衍生視圖沿用母視圖，不重複），零件的 `derivedBody.source`。路徑轉成相對於專案資料夾，一路找到底，每個檔只讀一次（循環會結束）。STEP、IGES、STL 不再往下找。
- **缺檔就拒絕**並列出缺的檔：不在專案資料夾、或路徑跑到資料夾外（含 `..`）。缺檔的打包檔在另一台電腦一樣打不開，正是它要解決的問題，所以不做「缺了也照打」。
- 打包的是**存好的檔案**：目前文件有未存的修改時拒絕並說明。零件沒有在專案資料夾中開啟時，只打包它自己；它有衍生本體時，母零件會被列為缺檔。

### 解開（`readPackage`、`compareWithFolder`、`AppStore.unpackPackage`）

- 讀取時整包驗證，任一不合格就**整個拒絕，什麼都不寫**：
  - 格式名稱不符；
  - 版本比程式新；
  - `main` 不在清單中；
  - 任一路徑含 `..`、`.`、空段，或以 `/`、磁碟代號開頭，或含 `\`；
  - zip 裡的檔與清單不一致（多了或少了）。
- 選要解開到哪個專案資料夾：電腦上的資料夾，或瀏覽器內專案（ADR 0233），所以 Firefox、Safari 也能解開。
- 逐檔比對**位元組內容**：
  - 資料夾沒有 → 新增；
  - 相同 → 略過；
  - 不同 → 列進 `UnpackDialog`，預設勾選「換成打包檔裡的版本」。
- 按「解開並開啟」才寫入；「取消」什麼都不改。新增的檔經 `writeFilesInto`，其中一個失敗時，這次新增的會撤回；取代的檔各自經 `writeFile`，瀏覽器先寫暫存再換上，寫入失敗時原檔不受影響。
- 寫完把該資料夾設為專案，並從那裡開啟主檔：組合件或工程圖的零件就在旁邊。
- 比對用位元組而不用修改時間：我們的 zip 寫入固定的時間戳記，兩台電腦的時鐘也未必一致。

## 驗證

- `packages/io/test/package.test.ts` 12 項：
  - 三種引用各自的找法，含子資料夾與 `..`。
  - 次組合件與衍生母零件一路找到底；不相干的檔不裝。
  - 循環會結束。
  - 缺檔與資料夾外的檔列名拒絕；讀不出的檔拒絕。
  - 往返後內容相同。
  - 跳出資料夾的路徑、清單不符、非本格式或較新版本，都拒絕。
  - 新增／相同／不同的分類正確。
- 突變測試：
  - 拿掉路徑安全檢查 → 「跳出資料夾」那一項轉紅。
  - 拿掉缺檔拒絕 → 「缺檔列名」那一項轉紅。
- 瀏覽器 `tests/e2e/manual-pack-and-go.js`：
  - **打包**：以 UI 建立組合件與工程圖並存檔，對工程圖打包，得到 4 個檔，不相干的零件不在其中，位元組與存檔相同。
  - **改動資料夾**：一個零件換成別的版本、一個零件刪掉，然後解開三次：
    - 取消勾選 → 保留資料夾原檔，新增 1、略過 3。
    - 保持勾選 → 換成打包檔的版本。
    - 取消 → 什麼都沒寫。
  - **缺檔拒絕**：零件不見時打包被拒絕、列出檔名、沒有下載。
  - 比對清單有截圖確認。

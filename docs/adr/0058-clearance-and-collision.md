# ADR 0058：餘隙確認、取放空間與拖曳時的碰撞偵測（Phase 4a-5，E2.2、A3.6，Schema 不變）

- 狀態：已實作並驗證（2026-10-03）。限制見最後一節。
- 相關：[phase4a-plan](../phase4a-plan.md)、[ADR 0051](0051-evaluation-tools.md)（干涉檢查：零組件的分法、`common` 的最小體積）、[ADR 0014](0014-moving-and-reference-files.md)（拖曳）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **餘隙確認**（`findClearance`，`@3db/regen`）：每兩個零組件，用核心的精確最短距離（`kernel.distance`）量它們的零件，**小於「最小餘隙」的才列出**，最近的排最前，附最近點；先以兩個零件的外框相距超過最小餘隙者略過（不量）。同一個零組件的零件不互比（同干涉檢查）；距離 0 時再用 `common` 分「接觸」與「共用體積（干涉）」。`only` 只量含某些零組件的組 | 精確值，不用網格；用干涉檢查同一套零組件分法，結果可以對照 |
| 2 | **取放空間**（`sweepClearance`）：把一個零組件沿一個方向移，算它**最多能移多遠才碰到別的零組件**（最長 `length`）。以「到別的零件的距離」為步長前進（短於這個距離的移動不可能碰到），步長至少 `length/200`；一步若進入別的零件（`common` 體積超過最小值），在那一步之內二分找接觸，到 1e-4 mm。**貼著面滑過去不算碰到**（接觸沒有體積），離開接觸面也是通的，往接觸面裡面走在第一步就停；一開始就已經重疊則回報「已經重疊」 | 沒有掃掠實體也能得到精確的「距離」；保守前進不會漏掉薄的障礙，直到接觸滑動時才靠最小步長 |
| 3 | **拖曳碰撞偵測**（A3.6）：移動零組件的屬性管理員多「碰撞偵測（停在接觸前）」（預設關，同 SolidWorks）。每次拖曳求解的結果先問 Worker（`collisions`：含移動中零組件的組，共用體積者），沒有就照顯示；有就在「拖曳上一刻的位姿」與「求解器給的位姿」之間找一個比例（位置線性、旋轉取正規化線性內插，**二分十次**），取最大且不碰的，再讓結合從那裡回到成立（沒有目標的求解），仍不碰就用它，不然用內插的位姿；停下時碰到的零組件顯示紅色，屬性管理員寫出它們的名稱。**拖曳開始前就已經重疊的組不算**（`baseline`） | 零組件停在接觸前、結合仍成立；一次拖曳不會因為本來就重疊而動不了 |
| 4 | **Worker 三個新呼叫**：`clearance`、`sweep`、`collisions`（用 `shapesOf` 取各零件建好的形狀）；`findInterference` 多一個選用的 `involving`（只比含這些零組件的組）。`lerpPose`（`@3db/model`）是位姿內插 | 重算與求解已在 Worker，核心呼叫也在那裡 |
| 5 | **「餘隙確認」視窗**（組合件分頁，與干涉檢查同一種浮動面板）：最小餘隙（mm，預設 1）、檢查、配對清單（距離；0 寫「接觸」或「干涉」；點一列選取兩個零組件，游標停在名稱上看最近點的座標）、組合件改過之後註明結果過時；下面「取放空間」：選取的零組件、方向（±X ±Y ±Z）、長度、結果一句話（能移多遠、會碰到誰，或沒有阻礙） | 兩個問題放在同一個地方 |
| 6 | `Viewer.setCollidedComponents`：紅色（優先於選取與懸停） | 拖曳時要立刻看出碰到誰 |

## 驗證（證據）

- **核心**（`tests/phase4/clearance.test.ts`，15 項，邊長 10 的方塊與 100×100×5 的板，間隙手算）：兩個方塊相距 5 → 5，最近點在面對面的 x = 10 與 15；最小餘隙 4 時沒有；斜著錯開 → √(5²+5²)，最近點在角；接觸 → 0 非干涉、重疊 → 0 是干涉；最近的排最前、`only`；同一零組件的零件不互比；比最小餘隙遠的不量（`checked` 為 0）。**取放空間**：朝牆最多 20（面 x = 10 到牆 x = 30，差在 1e-3 以內）；方向 (1, 0.2, 0) 為 20.396；遠離、向上、向下錯開都是整段通；比間隙短的長度通；在板上（貼著它）沿板滑 50 通、離板 50 通、往板裡 < 0.01 就停；一開始重疊回報 `startsInside`；貼著一塊、離另一塊 0.5 mm 的走道通過 60，第二塊往內 0.5 mm 時停在 20。位姿內插與 `involving` 篩選也各有測試。
- **瀏覽器**（`tests/e2e/phase4-clearance.js`，0 Console 錯誤；定位板固定、V 型塊在它上面 5 mm）：「餘隙確認」最小餘隙 1 時沒有、改 10 時剛好一組距離 5、點那一列選取；取放空間：往 −y 只能移動 5 mm、+y 與 +x 沒有阻礙；移動零組件：**沒開碰撞偵測時**往下拖 10 進到板裡（y = 10）、**開了之後**停在板頂（y 在 15 到 15.01）並說碰到定位板、該零組件紅色。
- **效能**（瀏覽器內量，20 個零組件）：碰撞查詢 4–7 ms（含 Worker 往返），餘隙檢查 23 ms；拖曳一步在沒有碰撞時是一次求解加一次查詢，停下時最多再加十一次查詢，都在 100 ms 的預算內。
- `npm run check`：1057 項通過。

## 限制與未做

- **取放空間不是掃掠實體**：用步進與二分算接觸；零組件一直貼著別的零件滑動時，比 `length/200` 薄的障礙可能被越過。要算旋轉出來的軌跡（夾鉗的開合）不在範圍內（沒有繞軸的取放）。
- **餘隙以零件為單位**：同一個零組件裡的零件不互比；兩個零組件中有參考本體（工件）也照量，要排除要自己看清單。
- **拖曳碰撞偵測在沿路徑的中間會用內插近似**：一步之內的路徑當作直線（位置）與正規化線性（旋轉），所以一步很大的彎路可能在內插點不是結合的解；已用「讓結合回到成立」修正，仍碰就退回內插值。
- **只在拖曳時**：用數字移動（Delta XYZ、至 XYZ）與用結合求出的位置不檢查碰撞；干涉檢查才是檢查整個組合件。
- 開關預設關、不存檔；沒有「只標示不停下」的選項。
- 餘隙的最近點只在提示文字裡，圖面上沒有畫兩點之間的線。

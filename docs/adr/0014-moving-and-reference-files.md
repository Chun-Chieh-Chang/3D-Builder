# ADR 0014：移動零組件與參考檔（2D）

- 狀態：已採用（Phase 2D，2026-09-29）。
- 依據：藍圖附錄 C 的 C15.3、A3.5（2026-09-28 使用者決定提前到 Phase 2）、B9.4；handoff §10 的 2D；ADR 0011（組合件骨架、一次開一份文件）、ADR 0012（求解器）、ADR 0013（結合介面）。

2C 之後，零組件只能靠結合或插入時的位置擺放。2D 讓使用者拖曳、以數值移動零組件（只沿結合留下的自由度），並處理零件檔改名、搬移、修改。

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **移動 = 求解器的「移動目標」**：對一個零組件提出幾項要求（某點落在游標下的直線上、某點到某位置、轉到某方向），依重要性排列。每一步只在結合允許的方向上走（結合 Jacobian 的零空間）：先滿足第一項，在它留下的自由中再滿足下一項，且步長最小；走完再解一次結合，所以繞孔轉動這類曲線路徑也跟得上；沒有更接近目標就把步長減半 | A3.5 要的正是「只沿剩餘自由度移動」。同一套機制給拖曳與數值移動用，也能用純 TS 測試（`packages/assembly/test/move.test.ts`）。完全定義或固定的零組件自然不動 |
| 2 | **拖曳時優先平移；旋轉時保持中心**：左鍵拖曳的要求是〔抓住的點在游標線上、方向不變〕；旋轉是〔轉到軌跡球給的方向、零件中心不動〕 | SW 的自由拖曳只平移不轉；但只能轉的零件（入孔的銷）拖它的凸緣就會繞孔轉，同 SW |
| 3 | **拖曳從目前的位置接著解**：每次滑鼠移動送一次求解，從上一次的結果開始；同時只跑一個，等待中的只留最新的 | 連續、不會跳到另一組解；Worker 忙時不堆積 |
| 4 | **放開時才寫入文件**：與它一起求解的浮動零組件（同一組）凡是位置改變的，擺放位置改為目前位置，一個指令 `setPlacements`、一個復原步驟；Esc 取消，什麼都不寫 | 文件只存使用者的擺放（ADR 0011 #4）。整組寫入，是因為組內其他零件的舊擺放位置若不在結合上，重新求解時會把剛拖好的零件拉走 |
| 5 | **固定與完全定義的零組件不能拖**，狀態列說明原因（右鍵→浮動） | SW 的行為；避免使用者以為沒反應 |
| 6 | **左鍵移動、右鍵旋轉**（不用開任何工具）；「組合件」分頁的「移動零組件」「旋轉零組件」開啟同一個 PropertyManager：<br>• 拖曳時移動或旋轉（左鍵）<br>• 移動：自由拖曳、依據 Delta XYZ、至 XYZ 位置（零件原點）<br>• 旋轉：自由拖曳、依據 Delta XYZ（依序繞組合件 X、Y、Z 軸，轉軸通過零件中心）<br>• 每次「套用」是一個復原步驟；被結合擋住時提示 | SW 2010 的兩個指令與選項。未做：沿著組合件 XYZ、沿著圖元、對於圖元（可以用結合達成），碰撞偵測排在 Phase 4a（A3.6） |
| 7 | **重新指定零件檔**（指令 `relinkFile`）：改變 `FileRef` 的路徑，這個檔案的所有零組件跟著改。指到組合件已經在用的檔案時，零組件併入那一筆，已被佔用的實例編號改為最大值 + 1 | 路徑只存一處（ADR 0011 #2）。結合以持久名稱引用，新檔有相同的面（改名、複本、從 STEP 存成的零件）就照樣成立 |
| 8 | **開啟時找不到的檔案**：讀完所有零件檔後自動顯示「找不到參考的檔案」，列出使用它的零組件、專案資料夾中同名的檔案（被搬到別的資料夾）與「瀏覽…」；略過則零組件標示錯誤、存檔保留原路徑；狀態列的「N 個零件檔無法載入」與設計樹的「重新指定零件檔…」可以再開 | 同 SW 開啟時詢問。不存雜湊（ADR 0011 #5），所以改了名的檔案只能由使用者指出 |
| 9 | **零件改過後自動更新**：開啟組合件時一律重新讀取（2A 起如此）；另外在視窗重新取得焦點時，比對每個零件檔的修改時間與大小，有變才重讀，內容雜湊不同才重建 | 使用者可以在另一個分頁或視窗改零件再回來。瀏覽器的檔案監看 API（FileSystemObserver）尚未普及 |
| 10 | **開啟零件**（設計樹右鍵）：一次開一份文件（2026-09-28 使用者決定）。組合件有未存變更先問「要儲存變更嗎？」；零件以它的檔案開啟、存回原檔；「返回組合件」（「檔案」分頁與零件設計樹上方）重新開啟組合件，改過的零件因此更新。STEP 零組件依「開啟舊檔」開 STEP 的方式開成新零件 | 使用者選定的做法；不做多文件視窗 |
| 11 | **專案資料夾跨工作階段保存**：資料夾的控制代碼存在 IndexedDB。需要資料夾時，若瀏覽器已允許（使用者選了「每次造訪都允許」）就直接使用；否則資料夾對話框多一個「使用「X」」按鈕，按下後瀏覽器再詢問一次 | 瀏覽器規定：讀取權限要由點擊觸發才能再要一次。比每次重選資料夾少一個系統對話框 |

## 驗證

- **求解器**（`packages/assembly/test/move.test.ts`）：自由零件隨游標平移、不轉；貼在面上的方塊沿面滑到游標所指之處（從任何方向看）；入孔的銷被拖著繞孔轉 60°（游標在圓周上或更外面都一樣）；拖完從新位置重解不再移動；完全定義或固定的不動；鎖在滑塊上的蓋子拖動時帶著滑塊走；旋轉：自由零件繞中心、入孔的銷只繞孔；數值移動：被結合擋住的方向不動、允許的方向到位；19 支銷串成一組，拖最上面那支約 19 ms（預算 50 ms）。
- **文件指令**（`packages/model/test/assembly.test.ts`）：一次設定多個擺放位置（全部有效才生效）；重新指定路徑、所有實例跟著改；指到已使用的檔案時併入並重新編號、舊檔案 ID 不再發放。
- **真實零件**（`tests/phase2/mates.test.ts`）：金樣削邊銷入定位板的孔後，拖它的凸緣 1/4 圈，繞孔轉 90°，仍在孔中、凸緣貼板面；往孔外移動則不動。
- **瀏覽器驗收**（`tests/e2e/phase2-assembly.js`，全部以指標與鍵盤事件操作）：
  - `__asm.move()`：自由的 V 型塊隨游標平移（螢幕上正好移動 90、50 px）、方向不變、擺放位置寫入、復原回原位；拖曳中 Esc 取消、文件不變；固定的定位板不動並提示；入孔的銷從上方拖 1/4 圈轉了 90.3°，仍在孔中；右鍵在前視圖拖曳只繞孔轉；加上平行結合完全定義後不能拖；「移動零組件」至 XYZ 位置 (10, 20, 30)、依據 Delta XYZ、「旋轉零組件」繞 Z 轉 90° 且中心不動；被結合擋住的銷不動並提示。
  - `__asm.files()`：組合件有未存變更時「開啟零件」先詢問；開啟削邊銷、在草圖的修改框把柄長 15 改成 13、存檔；「返回組合件」後銷升高 2 mm、結合全部成立；在「別處」把零件檔改回原樣，視窗取得焦點時組合件跟著更新；零件檔改名後開啟組合件，對話框列出它、以「瀏覽…」重新指定、結合成立；檔案搬到另一個資料夾時，對話框列出同名檔，一鍵重新指定。
  - `__asm.remembered()`（重新載入頁面後）：資料夾對話框提供「使用「3db-e2e」」，瀏覽器再問一次讀取權限、不必再開資料夾選擇視窗；瀏覽器已允許時直接使用，不顯示對話框。清除記憶後（`__asm.forget()`）原本的 `__asm.openFresh()` 照舊通過。

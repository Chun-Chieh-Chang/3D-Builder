# ADR 0266：角度尺寸的引線畫法——小角度斜面不再被自動標註丟掉

日期：2026-11-26。狀態：**已採用**。工程圖格式 v44 → v45。

## 1. 問題

- 自動標註為斜面標角度時，以斜面和一個基準面的兩條線之夾角標註，圓弧畫在兩線的交點。
- 1°～8° 的斜面（拔模牆），兩線幾乎平行，交點遠在視圖外：R1-10226 量到 12～279 mm（handoff 2026-11-22）。
- `dimensionAll` 的防護（圓弧中心離視圖框超過 8 mm × 比例，或夾角 ≥ 87°）於是把這個角度刪掉，斜面就成了缺標。ADR 0262 之後改選「交點較近」的基準面，R1-10226 由缺 7 面降為 5 面；剩下這 5 面，不論選哪個基準面，交點都很遠。
- R1-10226 原圖（`R1-10226-MC_04_mdx.pdf`）在這類地方，正是從斜面拉一條引線寫上角度（第 3 頁「(.5°)」）。

## 2. 決定

角度尺寸多一種畫法：**以引線標註**。

- **資料**：`AngleDimension` 新增兩個選填欄位，必須同時出現或同時省略：
  - `leader`：引線長度（圖紙上的 mm），必須是有限的正數；
  - `angle`：引線方向（度，由圖紙 x 軸逆時針量）。
  - 這兩個欄位的名稱與倒角尺寸相同，所以拖曳的引線把手可以直接沿用（`dragDimension` 的 `round` 把手會修改 `angle` 與 `leader`）。
- **畫法**（`packages/drawing/src/dimension.ts` 的 `angle()`）：不畫圓弧和延長線，從第一個元素（斜面）的中點拉一條帶箭頭的引線，在末端寫上數值。數值與圓弧畫法完全相同，由同一段計算求得。把手為 `round`；DXF 比照倒角，寫成徑向的 DIMENSION，以角度值為文字。
- **它仍是一個尺寸**：數值由幾何算出、隨零件更新，自我檢查（`dimensionCoverage`）照樣算這個斜面「已標註」。不採用自由文字的引線註記，原因是那樣零件改了數值不會跟著變，覆蓋率也認不得。
- **自動標註**（`apps/mcp/src/drawingSession.ts` 的 `dimensionAll`）：
  - 交點太遠時，不再刪除，改成引線畫法（長度 8）。
  - 引線方向取離視圖中心最近的對角方向，讓文字落在零件外；之後的排開重疊步驟會像處理倒角一樣，調整引線的方向和長度。
  - 夾角 ≥ 87° 的照舊刪除：那是基準面選錯，不是小角度。
- **修改指令**（`setDimension`）：`leader: null` 回到圓弧畫法，連同 `angle` 一起拿掉；只給 `leader` 時，方向預設 45°；在圓弧畫法上只給 `angle`，則拒絕。
- **面板**（`DimensionPanel.tsx`）：角度尺寸多一個「以引線標註」的勾選框；勾選後顯示引線長度，不再顯示圓弧半徑。
- **格式版本**：v45，沒有需要轉換的資料。升版是為了讓舊版程式拒絕開啟新檔，而不是把它畫成一條交點遠在視圖外的圓弧。

## 3. 驗證（2026-11-26）

- **合成零件**（`apps/mcp/test/drawing-angle-leader.test.ts`）：
  - 零件是一塊料，右邊的斜面偏離垂直 θ，與左邊的垂直面交於約 40/tan θ mm 之外（θ = 3° 時約 764 mm）；左上角另有一個 45° 的角作為對照。
  - θ = 1°、3°、5°、8°：自動標註後，斜面都以引線標註，覆蓋率 2/2。
  - **對照**：用修改前的 `drawingSession.ts` 跑同一批零件，四件的斜面都列為缺標（1/2）。
  - 引線畫法與圓弧畫法的值差 < 1e-9，與 θ 差 < 1e-6。
  - 45° 的角照舊畫圓弧。
- **拒絕**：引線長度 0、−1、NaN、∞，以及方向為 NaN、∞，都明確拒絕；兩個欄位缺一也拒絕（新訊息 `drawing.dimLeaderPair`）。
- **檔案**：存檔再讀回，兩個欄位都保留；v44 的舊檔可以讀入，內容不變；版本只斷言等於 `DRAWING_SCHEMA_VERSION` 且 ≥ 45。
- **輸出**：圖面上有箭頭與數值；SVG 含「3°」；DXF 有一個徑向 DIMENSION（群組碼 70 = 164），文字為「3°」。
- **網頁**（`tests/e2e/phase5-angle.js` 新增的段落）：
  - 勾選後引線長度 8、方向 45°，數值不變，面板不再顯示圓弧半徑；
  - 改長度為 14；
  - 以真實的指標事件拖曳數值，引線轉向、伸長，數值不變；
  - 取消勾選後回到圓弧，`angle` 一併拿掉。
- **突變**（`spikes/0266-angle-leader/mutate.mjs`，6 項全部轉紅）：
  - 自動標註仍然刪除；
  - 引線畫法的數值算錯；
  - 不檢查引線長度；
  - 不檢查兩個欄位是否成對；
  - 讀檔時丟掉引線欄位；
  - 缺少 v44 → v45 的升級步驟。
- **完整 `verify:ui`**：**276/281，未全過**。5 支失敗，經對照都與本次修改無關：`phase3-component-pattern`、`phase3-step-import`、`phase3-worker-crash` 在不含本次修改的 `4d31b21f`、核心換回 ADR 0265 前（`464366fa`），以及 11-24 曾 281/281 的 `ec0cb5e9` 上都一樣失敗；`phase5-assembly`（本次修改 5/5 失敗，`4d31b21f` 1/4 通過，`ec0cb5e9` 通過）與 `phase3-explode`（整輪失敗、單獨通過）時好時壞，失敗都在開啟組合件那一步。推測是這台電腦的環境問題（未查明）。**使用者 2026-11-26 同意延後**（AGENTS §3.6），先提交推送，再另查。本次的 e2e `phase5-angle`（含真實指標拖曳）通過。
- 工程圖相關的單元測試（`apps/mcp/test`、`tests/phase5`、`packages/drawing`、`packages/model`、`apps/web/test`、`packages/i18n`）共 156 個檔，全部通過。

## 4. 已知限制

- **R1-10226 實件沒有驗證**：當時的工程圖與 3D 檔（`out/approved-20261122/…`）不在這台電腦，所以「實件上 5 個斜面從缺標變成有標」只以合成零件代證。原圖 PDF 可以拿來核對數值，但核對需要 R1-10226 的 3D 檔。
- 在合成零件上，右側已經有「30」的尺寸線，排開重疊時把引線轉向零件內側，數值因此落在輪廓內。數值可讀、不和其他東西重疊，但不是最理想的位置。

# ADR 0118：開發伺服器隨最後一個分頁關閉而自己結束（Schema 不變）

- 狀態：**已實作並驗證（2026-10-07）**。來源：使用者問「關掉頁面後伺服器會不會自動關閉」；原本不會，Vite 開發伺服器會一直開著，直到終端機關掉或行程被結束。

## 做法

1. 新增 `npm run dev:auto`（根目錄與 `apps/web` 都有），等於 `npm run dev` 加上 `--mode autoclose`；`npm run dev` 完全不變。
2. `apps/web/dev/autoClose.ts` 是只在 `autoclose` 模式、只在開發伺服器載入的 Vite 外掛：每秒看一次 `server.ws.clients`（Vite 為每個開著的頁面留一條熱更新用的 WebSocket）。**沒有任何頁面連著**滿 30 秒，就關閉伺服器並結束行程，日誌寫出原因。
3. 決定的部分是純函式 `idleWatcher`（時鐘由呼叫端給），可以單元測試。
4. 兩個寬限時間：最後一個頁面斷線後 **30 秒**（重新整理或電腦短暫睡眠會讓連線斷幾秒，不能立刻關；環境變數 `DEV_AUTO_CLOSE_SECONDS` 可改）；**從來沒有頁面連上過**時等 **120 秒**（瀏覽器啟動可能很慢）。

## 驗證

- 單元測試 `tests/phase8/auto-close.test.ts`（5 項）：斷線後差 1 毫秒不關、滿 30 秒關；寬限內重新連上不關，之後重新計時；從未連線等 120 秒；一直有頁面連著一整天不關；環境變數不是正數就用 30。
- 真的啟動：用 6 秒的寬限在另一個埠啟動，用瀏覽器開頁面並等過寬限，伺服器仍回 200；關掉分頁，約 6 秒後伺服器結束，日誌寫「No page has been connected for 6 seconds…」。

## 限制

- 伺服器結束後還開著的分頁是死的，要重新執行 `npm run dev:auto`。
- 計的是連線，不是「看得見的分頁」：背景分頁、最小化的視窗仍算有頁面。
- 同一個埠被別的行程佔用時（`strictPort`）根本啟動不了，與這個外掛無關。
- 只管 Vite 開發伺服器；桌面版（Tauri）自帶畫面，不用伺服器。

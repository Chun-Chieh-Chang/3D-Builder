# ADR 0092：併面時舊面保留原名（鞏固 H-1，持久命名）

- 狀態：已實作並驗證（2026-10-04）。修的是 [ADR 0085](0085-edge-flange.md) 記下的缺口。
- 相關：[hardening-plan](../hardening-plan.md)、藍圖風險表第 1 列（持久命名）。

## 問題

一個填料（凸緣、摺邊、任何拉伸）接到本體上，工具的一個面與本體的一個面共面時，融合把它們併成一個面。併起來的面叫什麼，原本取決於核心列出來源的順序：凸緣的情形是**叫了後來加上去的工具的名字**（`flange.s1`），於是板的那條側面不再叫 `bf:side:sk.rl1`，所有以它為邊界的邊（`{bf:cap:end|bf:side:sk.rl1}`）也跟著改名。後果：事先在板上點的邊，在別的凸緣把側面併進去之後找不到（指紋也因長度變了對不上）；重排特徵、在前面插入特徵會讓凸緣失敗，「遺失參考」。

## 決定

**一個面有幾個來源時，同一種來源裡編號小的贏**（`faceBaseName` 的排序多一個鍵：`index`）。融合的兩個運算元是本體在前、工具在後（`concatNames`），所以併起來的面保留本體原來的名字；名字不再取決於核心列出來源的順序（那不是名字可以依賴的東西）。對只有一個來源的面、對圓角等「由邊產生」的面（種類排在前面）沒有影響。

## 驗證（證據）

- **新測試**（`tests/phase8/naming-merge.test.ts`，9 項）：全寬的摺邊之後板的側面仍叫 `bf:side:sk.rl1`、`bf:side:sk.rl3`（沒有 `hm:side:flange.bend.s…`）；三個凸緣（金樣支架的 90°、135°、摺邊）**以三種順序**做，每個都找得到在板上點的邊、都成功；塊上兩個與兩邊共面的凸台：塊的四個側面名字保留、兩種順序名字集合相同；在最前面插入一個基準面，塊與支架的名字不變；壓抑一個凸緣再恢復，名字回到原來、後面的凸緣仍找得到邊。修之前這些中有五項失敗（遺失參考、側面被改名）。
- **順序與體積**：凸緣取「做的時候邊剩下的部分」：摺邊先做時，90° 凸緣的邊少了 2（摺邊切掉了角落），所以那個凸緣窄 2；測試用手算的 `2 × (折彎 + 平直段 − 切掉)` 驗證體積差，三種順序中另外兩種體積相同。這是設計（凸緣長在剩下的邊上），不是命名問題。
- 全部測試（含 Phase 1 的持久命名回歸、金樣）通過；Phase 7 的角落測試的期望改了（併面後板的側面叫板的名字，凸緣的側面叫彎的名字）。
- `npm run check`：1503 項通過、21 項略過。

## 限制與未做

- **規則是「本體優先」**：對於兩個運算元都是新工具的融合（圖樣的實例互相併面等）以索引小的為準，是確定的但不一定是使用者想的那個；沒有針對圖樣、鏡射的併面另外測。
- 邊在**被切短之後**（長度變了）仍然用名字找；名字與指紋都對不上時還是會「遺失參考」（本來就該這樣說）。

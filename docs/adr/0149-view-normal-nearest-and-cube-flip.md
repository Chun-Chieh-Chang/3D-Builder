# ADR 0149：「正視於」沒有可看的平面時轉到最近的標準視角、視角方塊加翻面鈕

- 狀態：**已完成（2026-10-15）**。純介面，檔案格式不變。
- 需求追溯：使用者在「專案待決定事項」選擇題頁（2026-10-15）的裁定。本 ADR 同時記下那一頁的六個裁定，方便之後查。

## 決定

1. **「正視於」沒有可看的平面時**（什麼都沒選、選的是曲面／邊線／頂點／原點）：
   - 轉到目前攝影機**最接近的標準視角**（前、後、上、下、左、右；Viewer 的 `nearestPrincipalView()`）。
   - 已經正對某個標準視角（夾角內積 > 0.999）時再按，轉到**另一側**（前↔後、上↔下、左↔右）。
   - 從等角視角看，三個軸同樣近：依固定順序（前、右、上、後、左、下）取前視，結果不受浮點誤差影響。
   - 取代 ADR 0148 的 A3 和 2026-10-14 B2 決定裡「沒有平面就回等角視圖」；有平面時的行為（正對、再按翻面）不變。
   - 草圖內、零件、組合件都走同一條路（`lookAtNormal`）。
2. **視角方塊右下角加「⇄」翻面鈕**：把模型繞螢幕的垂直軸轉 180°（`orbit('horizontal', 180)`）。攝影機位置永遠和螢幕的上方垂直，所以結果一定是**正好相反的一側**（從上方看會變成從下方看），螢幕的上方不變，連按兩次回到原狀。
3. **視角方塊在窄視窗下的位置**（順手修正的既有問題）：窄視窗時方塊要放在 heads-up 工具列下面，原本寫死 `top: 100px`；工具列隨著指令變多已經長到 124 px，方塊蓋在工具列上，`manual-c20.js` 的窄視窗步驟在 pull 進來的 `main` 上就是紅的（我用 `git stash` 還原所有修改後重跑，同樣失敗）。改成由 `ResizeObserver` 量工具列的實際底部，寫進 `--heads-up-bottom`，CSS 用它。測試原本斷言 `top === 100`（寫死的數字），改為「方塊在工具列底部之下、比寬視窗時更低、且沒有任何部分被工具列蓋住」；沒有被蓋住的斷言（`covered === 0`）沒有放寬。

## 驗證

- 單元：`nearestView` 純函數 4 項（軸上、斜視、等角平手、200 組隨機方向對暴力法、非有限／零向量／無候選的拒絕）；翻面 180°（正面變背面、傾斜時是正好相反的一側、連做兩次回原位）；指令對 Viewer 的使用（右↔左、上↔下、前↔後）。phase8 共 651 項通過。
- 真實攝影機：`manual-c20.js` 步驟 9b（等角視角按「正視於」→ 前視，再按 → 後視；從上方傾斜 20° 按 → 上視，再按 → 下視）、新步驟 13c（翻面鈕：前→後→前；傾斜 30° 時翻到正好相反）、窄視窗步驟；`manual-asm-view-normal.js` 步驟 1（組合件從上視按 → 下視）。
- 反向檢查：把 9b 和 13c 的預期故意改錯，兩步都判定失敗，並回報實際量到的方向（前視 `[0,0,1]`、背面 `[0,0,-1]`、傾斜翻面 `[0,0.5,-0.866]`）。
- 說明文字（中、英）同步更新；help 測試 42 項通過。

## 限制

- 翻面是「轉到正好相反的一側」，不是 FreeCAD 的「旋轉 180° 並保持世界的上方」；攝影機沒有固定的世界上方，所以兩者不同。
- 選整個零組件按「正視於」仍然沒有平面可看（SolidWorks 會看向它的前基準面），現在轉到最近的標準視角。

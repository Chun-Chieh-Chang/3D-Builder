# ADR 0008：零件檔 `.3dbx` 與本機檔案（Phase 1E）

- 狀態：已採用（Phase 1E，2026-09-28）
- 依據：藍圖 §2.1「檔案」「本機存取」、附錄 C 的 B9.1、B9.2、F7.1；[handoff.md](../../handoff.md) 的里程碑 1E

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **`.3dbx` 是 ZIP**，內容只有：<br>• `document.json`：`serializePart` 寫出的標準文字（鍵排序、固定縮排）<br>• `blobs/<sha256>.step`：文件輸入的資料（1F 起）<br>不存任何衍生資料（B-Rep、網格、名稱、結果）。藍圖允許的 `cache/` 暫不做 | SSOT：開檔一律重新計算，檔案不可能與自己的設計意圖不一致。解壓後的 `document.json` 可以直接比對差異（B9.6） |
| 2 | **自己寫 ZIP 讀寫（約 200 行），不加套件**：<br>• 支援 stored 與 DEFLATE、UTF-8 檔名<br>• 壓縮使用平台內建的 `CompressionStream('deflate-raw')`，瀏覽器與 Node 都有<br>• 讀取時檢查每個項目的 CRC-32<br>• 不支援 ZIP64、加密、分割壓縮檔，遇到時明確報錯 | 需求很窄，不值得引入相依套件；新增相依也需要另外下載與審查 |
| 3 | **同一份文件永遠寫出相同的位元組**：時間戳固定為 1980-01-01（DOS 日期的起點），項目順序固定（先 `document.json`，再依路徑排序的 blobs） | 測試可以直接比對整個檔案；「內容有沒有變」一眼可知。代價：用解壓工具看時，日期顯示 1980 年 |
| 4 | **輸入的資料以 SHA-256 命名**：<br>• 內容相同的輸入只存一份<br>• 存檔時捨棄文件已不再參考的資料<br>• 開檔時，缺少或雜湊不符的資料列為警告、不使用；檔案照樣開啟 | 內容定址天然去重，也能驗證完整性。缺資料時比照 SW 的遺失參考：先開起來，由用到它的特徵回報（1F） |
| 5 | **舊版 `.3db.json` 照樣開啟**。第一次儲存時要求另存為 `.3dbx`，絕不把 ZIP 寫進原本的 `.json` 檔 | 不破壞使用者的舊檔；副檔名與內容永遠一致 |
| 6 | **「舊檔可開啟」的證據是舊版程式自己寫出的檔案**：以 `git archive` 取出當時的模型套件，用 `rolldown` 打包執行後產生。測試會開啟、遷移、重新計算，並與手算的體積比對。樣本不可修改；每次升版都新增該版本的樣本 | 手寫的舊檔只能證明「我以為的舊格式」可以開 |
| 7 | **本機檔案（F7.1）使用 File System Access API**（Chrome、Edge）：<br>• 開檔與存檔都在原檔上進行，像桌面程式一樣<br>• 檔案對話框會記住上次的資料夾<br>• 寫入先寫到暫存檔，關閉串流時才替換原檔，存檔失敗時舊檔不受影響<br>其他瀏覽器改用選檔欄位與下載 | 藍圖 §2.1 的決定。這也是 Phase 3b 改用 Tauri 原生檔案系統之前的做法 |
| 8 | **「已修改」的判斷**：把目前文件的標準文字，與上次開檔或存檔時的文字比較。<br>• 復原回到存檔時的狀態，就不算已修改<br>• 標題列與 CommandManager 右側顯示檔名，已修改時加「*」<br>• 要被新零件或開啟的檔案取代時，先問「要儲存變更嗎？」（儲存／不儲存／取消），同 SW<br>• 關閉分頁前也會詢問 | 比較文字不必另外維護旗標，也不會出現「改回去了卻仍顯示已修改」的情形。資料遺失是藍圖風險 #11 |
| 9 | **開檔或新零件後，模型出現時自動全部顯示** | 修正舊的行為：原本會對「上一個模型」做全部顯示 |

## 驗證

- ZIP 讀寫（`packages/io/test/zip.test.ts`，9 項）：
  - CRC-32 標準檢查值；
  - 往返一致，同樣輸入寫出相同位元組；
  - 讀取 CPython `zipfile` 寫的檔案：封存註解、資料夾項目、stored、中文檔名、只在資料描述區記錄大小的串流項目；
  - 損毀（CRC 不符、截斷）、加密、不支援的壓縮方式都會報錯。
- 反向驗證：本程式寫出的 `.3dbx` 可由 CPython `zipfile`（`testzip` 通過、SHA-256 相符）與 Windows 內建的 `tar`（libarchive）正確列出並解壓。
- 零件檔（`tests/phase1/files.test.ts`，9 項，1E 的完成條件）：
  - v1、v2、v3 舊檔（示範件與「板、孔、導角、凸台」）開啟後遷移到 v4，重新計算的體積與手算值一致；
  - 存檔再開檔，文件完全相同，`document.json` 與 `serializePart` 逐字相同，重建後的名稱與體積也相同；
  - 輸入資料只存一份；缺少或被竄改時發出警告；
  - 不是零件檔、版本較新、ZIP 損毀時，拒絕開啟並說明原因。
- 瀏覽器實測：
  - 系統的開檔與存檔對話框必須由真人點擊才能開啟，所以改用替身；其餘都是真實程式。
  - 驗證的流程：
    - 已修改標記：修改、復原、重做；
    - 另存新檔，以及之後原地儲存（不再詢問）；
    - 未儲存提示的取消、不儲存、儲存三種結果；
    - 開啟 v1 舊檔（體積 991.416 mm³，與手算值相同），儲存時另存為 `.3dbx`，原 `.json` 不變；
    - 沒有檔案存取 API 時改為下載；
    - 開檔後自動全部顯示。
  - **待使用者實機確認**：在 Chrome 或 Edge 用真正的系統對話框存檔與開檔。

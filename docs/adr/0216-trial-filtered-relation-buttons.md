# ADR 0216：不會被接受的限制條件按鈕不顯示（試算後過濾）

日期：2026-10-28。狀態：已實作；本機閘門與完整 `verify:ui` 見 §5；遠端 CI 待推送。檔案格式不變。

## 1. 問題
PropertyManager 的「加入限制條件」按鈕由 `applicableRelations` 依幾何同步決定，它只排除「相同的限制條件已存在」（`sameRelation`）。已被其他條件隱含的（兩條水平線再要求平行）或必然衝突的（要求垂直）仍然顯示，按下去才被拒絕（ADR 0213 的訊息）。要準確知道，只能問求解器。

## 2. 決策
- 按鈕**先全部顯示**，不等待。`SketchController.refusedRelations(offered)` 對每個按鈕以 `host.trial` 加上它實際會加入的限制條件（與 `addRelation` 共用 `relationsFor`）試算一次；結果為 `over` 或 `failed` 者回報為「會被拒絕」，PropertyManager 隨後把它們移除。
- 唯讀：不改文件。試算期間文件變了就回傳 `null`，按鈕全數保留（不用過期的結果）。結果綁定該草圖物件，草圖一變即作廢。
- 上限：提供的按鈕超過 12 個、或草圖超過 400 個圖元時不試算（`null`），按鈕全留，按下才看到拒絕訊息。
- 右鍵選單**沒有改**：它在點擊當下同步建立，無法等待試算；那裡仍可能出現這類按鈕，按下得到相同訊息。

## 3. 紅隊四問
1. **輸入破壞**：不改任何數值；試算與按下按鈕走同一個 `relationsFor`，不會「試算 A、實際加 B」。
2. **相交**：不適用（草圖限制條件）。
3. **依賴鏈**：`controller.ts`（`relationsFor`、`refusedRelations`）→ `PropertyManager.tsx`；不動 schema、命令、DAG、i18n。
4. **零 Mock**：真實的 `SketchController`、真實 PlaneGCS 求解器；真值是手算（兩條水平線：平行已隱含、垂直衝突、等長可行）。

## 4. 測試
`apps/web/test/sketch-offered-trial.test.ts`（5 項）：手算案例；唯讀；**與實際按下按鈕一致**（對每個按鈕，在新的工作階段呼叫 `addRelation`，拒絕集合必須等於被拒者，且兩側各至少一個，避免單邊假綠）；文件中途改變回傳 `null`；無按鈕回傳 `null`。反向對照：把拒絕判斷停用，2 項轉紅。

## 5. 驗證
`npm test`：3749 通過、5 失敗（與 ADR 0211 在乾淨 HEAD 重現的同一 5 項）。完整 `verify:ui`：239 個腳本 224 通過、15 失敗，**失敗名單與上一輪（ADR 0214）完全相同**。

## 6. 已知限制
- 每個按鈕一次求解，大型草圖每次選取多 N 次求解的成本（上限以外的情況未量測延遲，上限 12／400 是保守值，不是量測所得）。
- 沒有 e2e 腳本直接斷言「按鈕消失」；覆蓋在單元測試（控制器層），畫面層（PropertyManager 的 effect）未被自動化檢查。
- 右鍵選單未過濾（見 §2）。

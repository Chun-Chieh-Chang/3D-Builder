# ADR 0045：3a 驗收——不需要樣本的部分與驗收工具（Phase 3a-10）

- 狀態：工具與不需樣本的項目已完成（2026-10-01）。**需要使用者真實零件的項目還沒做**，見最後一節。
- 對應：[phase3-plan](../phase3-plan.md) §5 的 3a 表（①②與兩個「新增」列）。

## 做了什麼

`tests/support/acceptance.ts`：驗收用的工具，使用者的三個零件之後用同一套。

| 工具 | 做什麼 | 對應 §5 |
|---|---|---|
| `symmetricDifference(kernel, a, b)` | \|A∖B\| + \|B∖A\| 的體積 | ① |
| `compareToReference(kernel, built, reference)` | 對稱差 ÷ 參考體積、體積差、表面積差、質心差；`REFERENCE_LIMITS` 是 1e-6、1e-4、1e-4、0.01 mm | ① ② |
| `sweepKeyDimensions(kernel, solver, doc, dimensions)` | 每個關鍵尺寸取名義值的 50%、75%、125%、150%、200%（`SWEEP_FACTORS`）；**在一個編輯過程裡**依序改（同一份文件、一個長壽的 `Regenerator`），每個結果再和「只改這一個尺寸、從頭重算」（新的 `Regenerator`）比對稱差 | ② |
| `expectSweepPasses(rows)` | 每一列：0 個錯誤／警告／遺失參考、`isValid`、和從頭重算的對稱差 < 1e-6、有手算體積時差 < 1e-9（相對） | ② |

`tests/phase3/acceptance.test.ts`（8 項）：

- **工具本身**：零件對自己輸出再輸入的 STEP，對稱差、體積、面積、質心都在限度內；兩個只差孔徑的零件，對稱差等於手算的孔體積差，兩個方向都一樣。
- **§5 ② 在三個金樣上**（9 個關鍵尺寸 × 5 個值 = 45 個結果）：定位板（厚度、圓角半徑、Ø8 孔徑）、V 型塊（V 底圓角、孔徑、孔深）、削邊銷（銷長、凸緣厚度、柄長）。全部 0 錯誤、有效、和從頭重算相同、和手算體積差 < 1e-9。
- **另外兩類零件**（用 builders 做）：薄殼的盒子（塑膠件型：壁厚、高、寬）、板加線性複製排列的柱（夾治具型：間距、柱半徑、柱高）。同樣的檢查，同樣全過。

手算公式中有兩處是掃描時才發現公式要加條件，不是程式的錯：削邊銷的凸緣厚度超過 5 時，削邊會切到凸緣，而且切削的矩形只有 12 寬，比凸緣在削邊處的寬度窄，凸緣上超出的那塊留著（公式用 `∫` 的閉式解）。

## §5 逐項狀態

| §5 項目 | 狀態 |
|---|---|
| ① 與參考 STEP 的對稱差、體積、面積、質心、特徵清單、只用 UI、eDrawings | **等樣本**：需要使用者的 3 個零件（SW 輸出 STEP、特徵清單）。工具已備，`compareToReference` 直接用 |
| ② 關鍵尺寸 50%–200% 不壞，且和從頭重算相同 | **工具與金樣已過**；使用者的 3 個零件要由使用者指定每個零件至少 3 個關鍵尺寸，再用 `sweepKeyDimensions` 跑 |
| 3 個零件存成金樣（`tests/golden/`）、v1–v7 舊版樣本都能開、`npm run check` 全綠 | v1–v24 舊版樣本都能開（`tests/phase1/files.test.ts`）；`npm run check` 全綠；**使用者零件的金樣等樣本**（現有 3 個金樣是 Phase 1 的） |
| 效能：50 個特徵 < 2 s、100 個圖元草圖拖曳 < 16 ms | 已有測試（`rebuild-speed.test.ts`：53 個特徵含 17 個圓角；`packages/sketch/test/perf.test.ts`）；測試門檻放寬到 3 s（整個測試一起跑） |

# ADR 0006：設計樹操作（Phase 1D）

- 狀態：已採用（Phase 1D，2026-09-27）
- 依據：藍圖附錄 C 的 B2.4、B2.6、B2.8、D1.2、D1.3、D1.6、D7.1；[handoff.md](../../handoff.md) 的里程碑 1D

## 決策

| # | 決策 | 理由 |
|---|---|---|
| 1 | **哪些特徵受影響由父子關係推導**：`@3db/regen/dag` 的 `suppressionTargets`、`deletion` 是純函式。模型只提供批次指令 `setSuppressed { featureIds }`、`deleteFeatures { featureIds }` | 父子關係屬於 regen（B2.2），模型不依賴它。一個動作只是一個指令，也就是一個復原步驟 |
| 2 | **抑制語意比照 SW**：<br>• 抑制：這個特徵及所有子孫<br>• 恢復抑制：這個特徵及它需要的祖先，子特徵維持抑制<br>• 恢復抑制（含相依特徵）：再加上子孫 | 被抑制的父特徵不會讓子特徵變成錯誤，只會一起被抑制 |
| 3 | **刪除時跳出確認對話框**，列出相依的子特徵與「被吸收的特徵」（只有被刪除的特徵在用的草圖）。兩個勾選預設都不勾 | 破壞最小；刪錯可以復原。保留下來的子特徵會以遺失參考報錯，而不是被悄悄改綁到別的地方 |
| 4 | **刪除後，所有 ID 仍算已發出**（包括草圖內的圖元與限制條件）。回溯控制棒保持在原本的相對位置 | 延續 ADR 0004：ID 永不重用 |
| 5 | **靠幾何指紋找回的參考要發出警告**：`FeatureResult.warnings`。設計樹顯示黃色三角形，「錯誤為何？」也會列出 | 同名的元素有好幾個、只能靠幾何判斷時，就是一次猜測，必須讓使用者看見。去掉 `#k` 後唯一的基底名稱是確定的，不發警告 |
| 6 | **「錯誤為何？」（D7.1）**：列出所有錯誤與警告，包括訊息、找不到的名稱與最接近的候選。點一列會在設計樹中選取該特徵。入口在狀態列按鈕與右鍵選單 | 對應 SW 的「What's Wrong」 |
| 7 | **雙向選取同步（D1.2）**：<br>• 在設計樹選取特徵，圖面高亮它產生的面（以持久名稱判斷擁有者）<br>• 在圖面選取面，設計樹標出建立這個面的特徵 | 名稱本身就記錄了擁有者，不需要另外存一份對應表 |
| 8 | **右鍵選單的回溯**：<br>• 「回溯（到此特徵之前）」把控制棒放在該特徵之前<br>• 「推進至最後」讓所有特徵重新生效 | 選單文字直接說明控制棒會停在哪裡 |

## 驗證

- 行為測試（`tests/phase1/tree.test.ts`，1D 的完成條件）：
  - 連帶抑制、恢復抑制、含相依特徵恢復；
  - 刪除時保留或一併刪除子特徵與被吸收的草圖；
  - 刪除後 ID 不重用、控制棒維持原位；
  - 不存在的特徵不能刪除；
  - 靠指紋解析時發出警告，完全無法分辨時回報模稜兩可；
  - 在回溯位置插入特徵。
- 瀏覽器實測（只用 UI 建立「板 → 凸台 → 貫穿孔 → 圓角」）：右鍵抑制/恢復、刪除對話框、錯誤為何、Delete 鍵、回溯/推進、雙向選取同步都符合預期，體積與解析值一致。

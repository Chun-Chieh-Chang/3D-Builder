# ADR 0024：草圖的 P1 限制條件與從動尺寸（Phase 3a-4b）

- 狀態：已實作（2026-10-01）。
- 對應：C1.26 加入限制條件（P1：同心同徑、交錯、合併）、C1.28 弧長、C1.29 從動（參考）尺寸，見 [phase3-plan](../phase3-plan.md) §3 的 3a-4。「貫穿」（Pierce，點在模型的邊穿過草圖面的位置）要引用模型的邊，留給 4d 的參考圖元。
- **Schema 升為 11**：新的限制條件種類 `coradial`、`intersection` 與新的尺寸 `arcLength`。舊檔不需轉換（`migrations[10]` 什麼都不做），舊版程式不能開 v11 的檔（它們不認得這些限制條件）。已補 v10 樣本 `tests/fixtures/old-versions/v10-bodies.3dbx`（由 `027a70d` 寫出，兩個本體，第二個叫「工件」）與測試。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **同心同徑（`coradial`）是一個限制條件，不是「同心」加「相等」兩個**；求解時展開成圓心重合加半徑相等（兩個 PlaneGCS 式子）。 | 使用者看到、刪除的是一個；與 SolidWorks 相同；舊版程式因為版本號而不會把它誤讀成別的。 |
| 2 | **交錯（`intersection`）是一個限制條件**：`point` 在兩條曲線 `a`、`b` 上（直線、圓、圓弧），展開成兩個「點在曲線上」。要選一個點加兩條曲線。 | 同上；點在直線上是在無限長的直線上，與「點在曲線上」一致。 |
| 3 | **合併不是限制條件而是一個操作**（`mergePoints`）：第二個點被第一個取代，原來用它的圖元與限制條件改用第一個，兩點之間的「重合」刪掉，其他在兩點之間的關係刪掉，**兩點之間有尺寸就拒絕**，同一個圖元的兩端、原點則拒絕（原點請用「重合」）。一次 `editSketch`＝一次復原。 | 合併要的是「只剩一個點」，用重合限制條件做不到；刪尺寸會改變設計，所以拒絕比默默刪除好。 |
| 4 | **弧長（`arcLength`）是尺寸**，用既有的 `circle` 欄位指向圓弧（規則只允許圓弧），PlaneGCS 的 `arc_length`；用屬性管理員裡選取一條圓弧時的「標註弧長」按鈕建立（智慧型尺寸的選取流程只有兩個選取＋放置，加第三種選法不值得）。 | 不增加新的參照欄位；工具列的流程不變。 |
| 5 | **從動尺寸用既有的 `driving: false`**（欄位本來就在 Schema、求解器本來就略過它，只是沒有人能建立）。新指令 `setDimensionDriving`：改成從動時，**若有運算式還在引用它就拒絕並說是哪個尺寸**（Parameters 重算前後的問題清單比較）；改回驅動時帶入「現在量到的值」（SolidWorks 也是），並先試算，過多定義就拒絕。 | 從動尺寸沒有自己的值，引用它的運算式不能默默變成錯誤。 |
| 6 | **會讓草圖過多定義的尺寸，改成加為從動尺寸**（並提示），不再單純拒絕（ADR 0004 決定 9 預告過）。求解失敗（不是過多定義）仍然拒絕。關係（限制條件）仍然是拒絕，因為它們沒有「從動」。 | SolidWorks 的行為；使用者要的往往只是看到那個值。 |
| 7 | **從動尺寸顯示「現在量到的值」，加括號、灰色斜體**；`measure()`（`@3db/sketch/interact`）從求解後的幾何量出每一種尺寸的值（含弧長、角度），與求解器量的方式相同（線到線是從 `a` 的第一點到 `b`）。存在文件裡的 `value` 只是建立當時的值，不會用來求解或顯示。 | 值要隨幾何走，而不是存下來就過期。 |
| 8 | **求解器：把「點在曲線上」與「半徑相等」抽成函式**（交錯與同心同徑用得到），行為不變。 | 避免三處重複同樣的對應。 |

## 驗證

- **單元測試**（`packages/sketch/test/relations.test.ts`，12 項，用真的 PlaneGCS）：同心同徑完全定義且沒有冗餘、圓與圓弧；交錯的點在兩條直線上（手算的方程式）、與圓；弧長 10π/2 在半徑 10 上是 90°、10π 是 180°；`measure` 每一種尺寸與手算值；從動尺寸不參與求解（同一個草圖，驅動時是「過多定義」，從動時是「完全定義」且量到 30）；`setDimensionDriving` 兩個方向、被運算式引用時拒絕；合併的各種情形。
- **控制器測試**（`apps/web/test/sketcher.test.ts`）：合併一次復原；弧長在已定義的圓弧上成為從動；過多定義的尺寸成為從動；從動改回驅動被過多定義拒絕；驅動改為從動後草圖變欠定義。
- **舊檔**（`tests/phase1/files.test.ts`）：v10 樣本開啟、遷移到 11、重算，兩個本體的體積與名稱不變。
- **瀏覽器**（`tests/e2e/phase3-sketch-relations.js`，每個一次頁面載入）：同心同徑、交錯、合併（點 4→3，兩條線共用一個點）、弧長（15.708，標籤「⌒15.708」）、第三個尺寸成為「(30)」且草圖維持完全定義。
- `npm run check`、i18n 的基準降為 627 行。

## 還沒做

- 「貫穿」（4d，要引用模型的邊）。
- 弧長以外的 C1.28 尺寸（例如點到圓的距離、弦長）。
- 一次選多個尺寸改成從動／驅動；從動尺寸不能被運算式引用，沒有「引用它就自動改成它的值」的選項。

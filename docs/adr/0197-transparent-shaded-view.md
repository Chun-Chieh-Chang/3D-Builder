# ADR 0197：模型透明塗彩

2026-10-25。使用者回報模型缺少透明塗彩。以已恢復文字工具名稱的版本為基底；不重做已撤回的 ADR 0196 圖示工具列。Schema 不變。

## 功能與使用

圖形區左上「顯示類型」新增 **透明塗彩**，零件與組合件均可選。保留原有面色、光照與邊線，並顯示 **不透明度 10–90%** 滑桿，預設 35%；較低值較透明。滑桿放在顯示類型與剖面控制下方，避免覆蓋視圖工具。原本的文字工具名稱保留。

切回「帶邊線塗彩」恢復一般顯示。這是目前視窗的狀態，不寫入模型／工程圖，不新增透明材料或更動實體幾何。PNG 擷取仍是目前畫面。

## 渲染規則

- 新 `DisplayMode = transparent`；材質保留 `colorWrite` 與 vertex colors，啟用 alpha blending、關閉 `depthWrite`，不是把塗彩關掉變線架構。
- `setTransparencyOpacity` 僅接受有限的 0.1–0.9，超界顯式拒絕，不靜默 clamp。UI 滑桿每次 5%。
- 零件的透明度與選擇濾器暫時淡化共用 `styleBodyOpacity`；取較透明者。切換選取工具／面濾器或重建網格，不可把透明模式重設成不透明。順帶保留線架構的 `depthWrite=false`，避免濾器刷新覆寫。
- 組合件的全局透明度與使用者個別透明、干涉聚焦淡化依原優先序組合，再取較透明者。離開全局透明模式後，原有個別透明旗標仍生效。
- 透明模式省略不透明剖面填蓋，保留切面邊界；恢復普通模式時可恢復填蓋。組合件隱藏／線架構聚焦角色仍照原規則處理。
- 可見的背後邊線可被選取；面仍以原有最近面與「選擇其他」機制選取。沒有改變 CAD 拓樸或命名。

## 驗證與紅隊四問

`manual-transparent-shading.js` 三個新案例各有通過紀錄；執行分為 part／assembly 兩項及新增 layout 一項的分項驗證，不是完整 UI 套件。證據：`out/transparent-shading-ui.json`、`out/transparent-layout-ui.json` 及對應截圖資料夾，截圖已實際檢視。

1. **零件**：UI 建立真實齒輪，賦予實際面的塗彩；讀取 renderer PNG 像素，確認透明與不透明、10% 與 90% 的畫面各有超過 1000 個像素確實改變。確認保留原面色、可選到先前被遮擋的真實邊線、濾器淡化組合、拒絕 NaN／Infinity／負值／零／超界值、透明剖面邊界及無不透明填蓋。顯示操作前後文件與實際體積不變；修改真實齒輪齒寬重建後仍透明，復原再恢復原體積；切回一般塗彩與線架構也驗證深度政策。
2. **組合件渲染**：進入真實組合件畫面，透過公開 renderer API 放入兩個由原生齒輪網格建立的實例（不是假網格）。確認全局透明、個別透明與聚焦淡化、剖面，以及恢復普通模式後仍保留個別透明。這是渲染整合測試，不宣稱驗證了組合件檔案的匯入／重建。
3. **配置**：實際不透明度列與視圖工具列不重疊、預設值可見，原有文字工具名稱保留。

紅隊：① 有限與上下界明確驗證、先驗證再賦值；② 無新增布林或幾何參數化核心，用原生幾何的畫面／邊線／體積驗證，不用假幾何代替；③ DisplayMode → Viewer 的零件／實例材質 → ViewOptions → 雙語字典／說明完整接線，網格重建、濾器、聚焦、剖面與模式恢復有覆蓋；④ 實際 WebGL PNG 像素而非只看 UI 文案或材質設定，無放寬門檻與期限。沒有進行 heap 量測，不宣稱無洩漏。

# ADR 0065：DXF 與 PDF 輸出（Phase 5-5，F3.1、F3.2）

- 狀態：已實作並以自寫的讀取器驗證（2026-10-03）。**尚未在真實的 CAD 與 PDF 檢視器開啟**（使用者待辦，見最後一節）。
- 相關：[phase5-plan](../phase5-plan.md)（預設假設：DXF 用 `\U+XXXX`、PDF 中文要內嵌字型）、[ADR 0060](0060-drawing-document-and-views.md)（場景是唯一的輸出來源）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **三種輸出都從同一個場景寫出**（`buildScene`：圖紙座標 mm、y 向上的折線與文字）：SVG、DXF、PDF 不可能彼此不一致。純 TypeScript，在 `@3db/drawing`，不用核心 | 驗收要求兩種輸出的座標差 < 0.01 mm |
| 2 | **DXF**（`toDxf`）：ASCII、**AC1015（2000 版）**、毫米（`$INSUNITS 4`）、模型空間。完整的 2000 版結構：HEADER（含範圍與下一個控制碼）、CLASSES、TABLES（VPORT、LTYPE、LAYER、STYLE、VIEW、UCS、APPID、DIMSTYLE、BLOCK_RECORD）、BLOCKS（模型與圖紙空間）、ENTITIES、OBJECTS（根字典），每個物件有控制碼（5）與擁有者（330）。**每種線型是一個圖層**（VISIBLE、HIDDEN、CENTER、THIN、FRAME、DIMENSION＋TEXT），圖層帶 ISO 128 的線型（CONTINUOUS、DASHED 3/1、CENTER 12/2/2/2）與線寬（0.5、0.25、0.7 mm）；折線是 LWPOLYLINE，實心多邊形（箭頭）是 SOLID 三角扇，文字是 TEXT（高度＝大寫字高、旋轉、靠左／中／右） | 夾具圖交給別人用 CAD 開 |
| 3 | **DXF 的文字**：ASCII 以外的字元（中文、Ø、×、±）寫成 **`\U+XXXX`**，反斜線寫成 `\\`；整個檔案都是 ASCII，任何 CAD 都讀得到（字樣式是 STANDARD，要有支援中文的字型才顯示） | 計畫的決定 |
| 4 | **PDF**（`toPdf`）：PDF 1.4、一頁（圖頁大小，點）、線條是向量路徑（`m l h S`／`f`，線寬與虛線依 ISO 128，圓頭）、文字用 **Helvetica**（標準字型，不內嵌；WinAnsi：ASCII 與 Ø × ± ° µ · ² ³，寬度表是標準 AFM，用來算置中與靠右）。XRef 表、trailer、Info 都有；不壓縮，所以每個位元組都可以驗證 | 沒有外部函式庫；可自動測試 |
| 5 | **中文：內嵌使用者給的 TrueType 字型**（`readTrueType`、`subsetTrueType`）：讀 .ttf 與 .ttc（取第一個字型）；**子集化**（字符編號不變，沒用到的字符清空，複合字符保留它用到的字符，只留 PDF 需要的表，檢查碼正確）；寫成 Type0／CIDFontType2／Identity-H 加 **ToUnicode**（所以文字可以搜尋與複製）、`/W` 寬度與 FontDescriptor／FontFile2。**Helvetica 寫得出的文字照用 Helvetica，只有含它寫不出的字元的文字用內嵌字型**（整段，包括其中的數字）。字型沒有的字元寫成 `?` 並說出是哪些；沒指定字型時中文都是 `?`，說明要指定字型檔。OTTO（CFF）的字型不支援（說明原因）；`OS/2 fsType` 是「受限」的字型拒絕內嵌 | 不隨程式附中文字型（授權與大小）；字型檔由使用者選（例如微軟正黑體） |
| 6 | **自寫的讀取器與檢查**（證據）：`readDxf`／`checkDxf`（版本、區段順序、成對的群組碼、EOF、每個控制碼一次、每個擁有者存在、表格項數、線型與圖層與文字樣式存在、多段線頂點數）；`readPdf`／`checkPdf`（標頭、startxref、**xref 的每個位置都在它說的物件上**、trailer 的 Size、頁面樹與 Count、MediaBox、串流長度、內容串流的路徑與文字運算、字型：標準字型與內嵌字型的描述、W、ToUnicode、字型檔的表與檢查碼 0xB1B0AFBA）；`readToUnicode` | 沒有真實的 CAD／PDF 檢視器可以對照（風險 6） |
| 7 | **介面**：工程圖面板「輸出 SVG」「輸出 DXF」「輸出 PDF」；「PDF 字型…」選字型檔（.ttf、.ttc；選的當下就讀，讀不了或不允許內嵌馬上說明），旁邊顯示字型名稱與取消；輸出 PDF 時沒寫出的字元會以通知說明 | |

## 驗證（證據）

- **場景**（`tests/phase5/drawing-output.test.ts`，用 `tests/support/outputScene.ts`）：金樣定位板的上視與前視，A3 第一角，總長寬、孔徑與孔標註、孔位置共 12 個尺寸（其中一個有 H11）、中心記號與中心線、孔表（Ø8 H7）、標題圖塊有「定位板」「S45C」；一百多條線、實心箭頭、含中文、Ø、×、±、括號的文字。
- **DXF**：`Ø9` ＝ `\U+00D89`、`孔` ＝ `\U+5B54`、反斜線、超出基本多文種平面的字元（代理對），全部讀回相同；整個檔案都是 ASCII；AC1015、區段順序、檢查沒有問題、`$EXTMIN／$EXTMAX` ＝ 圖頁、下一個控制碼大於所有控制碼；每種線型的圖層帶正確的線型與線寬、DASHED ＝ [3, −1]、CENTER ＝ [12, −2, 2, −2]；**場景的每條折線都是同一圖層的 LWPOLYLINE，點相同（< 1e-6）、封閉相同**；實心多邊形＝SOLID 扇（數量 ＝ Σ(頂點數 − 2)），三角形的第四點重複第三點；**每個文字都是 TEXT，位置、高度、角度、對齊、字串都相同**（中文與 Ø 讀回一樣）；壞的檔案被找出來：沒有 EOF、奇數行、控制碼重複（BLOCK 與 ENDBLK 也算）、圖層不存在、頂點數不符、別的版本、擁有者不存在。
- **TrueType**：用測試自製的字型（每個字元一個方塊、最後一個是複合字符、1000 單位/em、大寫 700）：字元→字符、寬度（600 與 1000）、上升下降、大寫高度、名稱、授權、外框；短 loca 與 TrueType Collection 也讀得到；不是字型、CFF、截斷、缺表各有說明；受限授權；子集化：保留的字符有輪廓、其餘清空、複合字符的元件保留、hmtx 全留、檢查碼 0xB1B0AFBA。
- **PDF**：沒有字型時：1.4、讀回沒有問題、一頁、MediaBox ＝ 420×297 mm（點）、**每條線都是一條路徑，點與場景相同（< 0.001 mm）**、封閉與填滿相同、線寬 ＝ 樣式寬度、虛線相同；文字：每個能用 Helvetica 寫的文字原樣寫出、位置、大小（大寫高度）、旋轉、置中與靠右依 Helvetica 寬度，中文成 `?` 且警告一次；有字型時：沒有警告、每個文字（含 `4×Ø9 H11 (+0.09/0) 貫穿`）經 ToUnicode 讀回與場景相同、含中文的用 F2 其餘用 F1、字符編號是字型的、字型檔裡用到的字有輪廓沒用到的是空的、`/W` 有 600；字型沒有的字元成 `?` 並說明；不可內嵌的字型被拒；損壞的 PDF 被找出來（不是 PDF、沒有 startxref、物件不在 xref 說的位置、串流長度不對、標頭壞了）。
- **兩種輸出互相比對**：DXF 與 PDF 的折線是**同樣的點（差 < 0.01 mm）**、同樣的文字同樣的順序。
- **真實字型**（本機有就跑）：標楷體 kaiu.ttf 與微軟正黑體 msjh.ttc 讀得進（`中` 有字符、可內嵌）、PDF 小於字型檔的 1/4（只有用到的字）、檢查沒有問題、「定位板」讀回。
- **瀏覽器**（`tests/e2e/phase5-output.js`，0 Console 錯誤）：新工程圖加自動尺寸（含孔位置與孔標註）與孔表；輸出 DXF：檔名、AC1015、檢查沒有問題、每條線與每個文字都在、讀回含「定位板」與孔標註；輸出 PDF（沒有字型）：A3、每條線一條路徑、`4×R10` 照寫、中文是 `?`、有通知；面板選字型（寫在專案資料夾的測試字型）：每個文字讀回相同、中文在內嵌字型裡、檔案 < 200 KB；DXF 與 PDF 的線相同；取消字型。
- `npm run check`：1191 項通過。

## 限制與未做（與使用者的待辦）

- **沒有在真實的程式裡開過**：DXF 沒有用 AutoCAD、DraftSight 等開過，PDF 沒有用 Chrome、Acrobat 開過；格式依我對規格的理解寫成，自寫讀取器證明檔案的內容與結構自洽，**不能代替真實檢視器**。請用 Chrome（PDF）與你的 CAD（DXF）各開一張夾具圖：看線寬、虛線、箭頭、中文、尺寸文字的位置。這是 Phase 5 驗收②的 B 段。
- **DXF 的文字樣式是 STANDARD（字型檔 txt）**：中文要在 CAD 裡把樣式換成有中文的字型才顯示；沒有輸出尺寸（DIMENSION 圖元）：尺寸是線與文字，在 CAD 裡不能用「編輯尺寸」改數值。
- **PDF 的字型**：只支援 TrueType 輪廓（.ttf、.ttc 的第一個字型；沒有 CFF 的 .otf）；沒有記住上次選的字型檔（每次開啟圖面要重選）；Helvetica 的寬度表只有 ASCII 與八個 Latin-1 字元（置中與靠右的估算，其餘字元用內嵌字型時用字型的寬度）；不壓縮（簡單且可驗證；大圖的檔案較大）；沒有書籤、圖層（PDF 的 OCG）與多頁。
- **字型授權**：只檢查字型自己宣告的內嵌權限（OS/2 fsType）；微軟正黑體等是否可內嵌於你的文件，請看字型的授權。
- DXF 的線寬只在圖層上（實體用「依圖層」）；沒有列印樣式（CTB）。

# ADR 0032：疊層拉伸（Phase 3a-6c）

- 狀態：已實作（2026-10-01）。
- 對應：C4.5 疊層拉伸（2 個以上截面、閉合輪廓；導引曲線是 P2），見 [phase3-plan](../phase3-plan.md) §3 的 3a-6；演化歷史夠命名已在 [ADR 0017](0017-phase3a-technical-validation.md) §1 驗證過（兩個矩形）。
- **Schema 升為 19**：新的特徵種類 `loft`（`sections`：截面草圖的 ID 依序、`op`、`merge`）。舊檔不需轉換；已補 v18 樣本 `tests/fixtures/old-versions/v18-sweep.3dbx`（由 `221a0f6` 寫出）。
- 證據腳本（不進 `npm test`）：`spikes/occt-gaps/phase3-loft.mjs`（`node` 直接執行）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **截面是草圖，每張草圖一個封閉輪廓、沒有洞**，依 `sections` 的順序（第一個到最後一個）。草圖裡有兩個以上輪廓、輪廓有洞、沒有封閉輪廓，各有說明的錯誤（訊息帶草圖名稱）；少於兩個截面是錯誤；同一張草圖不能當兩個截面（指令擋下）；所有截面都要在特徵之前。 | 使用者選的範圍（2026-10-01）：2 個以上截面草圖、閉合輪廓、不做導引曲線。截面做成草圖才有尺寸與限制條件。有洞的截面與選輪廓留給之後。 |
| 2 | **面順著所有截面平滑通過**（`BRepOffsetAPI_ThruSections`，非直紋；只有兩個截面時 OCCT 給的就是直紋）。**不提供「直紋」選項**。 | 實測：三個以上截面用直紋時，每條截面邊在每個截面上都「產生」兩個面（`Generated` 回報的不是各段的面），分不出哪個面屬於哪一段，只能靠幾何猜；平滑的做法每條邊只有一個面，名稱乾淨。兩個截面時直紋與平滑相同，所以直紋的需求只剩三個以上截面要折角的情形，那不在這次範圍。 |
| 3 | **截面不必對齊**：從哪個角開始、繞哪個方向、邊數不同，都交給 OCCT（`CheckCompatibility` 預設開）。實測：第二個截面從別的角開始、反方向繞，體積與柱體完全相同；方形對圓形（4 邊對 1 邊）OCCT 把方形的一條邊拆成兩條、圓拆成 5 段，結果有效。 | 自己重排會多一層出錯的機會；OCCT 的做法已被驗證。 |
| 4 | **面的命名**：側面用**第一個截面**的邊命名，`<疊層拉伸>:side:<第一張草圖>.<圖元>`，端蓋 `cap:start`（第一個截面）與 `cap:end`（最後一個截面）。一個圖元產生幾個面（方形對圓形時，圓的一條邊產生 5 個面）就靠既有的 `#k` 依幾何順序分開。 | 實測：第一個截面的每條邊 `Generated` 剛好涵蓋所有側面（方形對圓形：[1,2,1,1] 共 5 個、圓形對方形：[5]），不會有沒名字的面；測試檢查每個名字不重複、沒有 `:face`。第一個截面的圖元改了，名字才變；改尺寸、改別的截面，名字不變。 |
| 5 | **結果要是有效的實體**（`BRepCheck_Analyzer`，且體積 > 0），否則錯誤「疊層拉伸的結果不是有效的實體（截面的順序不對、截面互相穿過，或兩個截面在同一個位置）」。兩個截面在同一個位置（同一張平面）會被這一關擋下。 | 與掃出相同：自己疊在一起的結果沒有意義。 |
| 6 | 填料／除料、「合併結果」與伸長、掃出相同。 | 一致。 |
| 7 | **介面**：「特徵」分頁的「疊層拉伸填料/基材」「疊層拉伸除料」，先選一張草圖；屬性管理員是一個有順序的截面清單（上移、下移、移除）加一個「加入截面…」清單。新建時截面是選取的草圖與**最近畫了圓、線或圓弧的另一張草圖**，順序要在清單裡調。用過的截面草圖預設隱藏。 | 設計樹一次只能選一個項目，沒有 SW 的「在圖面依序點選」；清單是最少的做法。 |

## 驗證

- **手算**（`tests/phase3/loft.test.ts`，11 項，真的 OCCT）：兩個相同矩形 = 柱體 1200，六個面的名字；20×10 到 10×10 = 楔形 3000；20×20 到 10×10 = 角錐台 h/3·(A1 + √(A1A2) + A2) = 4666.67（反過來相同）；圓到圓 = 圓錐台 π·h/3·(R² + Rr + r²)，三個面；方形對圓形（兩個方向）有效、介於圓柱與方柱之間、每個名字都不重複；三個截面：相同的矩形 = 2400，10→20→10 的鼓形有效、網格寬度達到中間截面的 20；核心對齊（起點的角、反向繞）全部是 1200；除料（圓錐台從方塊取出，18000 − 錐台）；填料接觸本體時合併、`merge: false` 時第二個本體；之後的圓角找得到邊線、第一個截面加寬後 0 失敗、在端蓋上畫草圖再伸長。
- **錯誤**：一個截面、兩個輪廓、有洞、不封閉、兩個截面在同一個位置、截面草圖被抑制；指令：同一張草圖兩次、不存在的草圖、不是疊層拉伸的特徵。
- **舊檔**：v18 樣本（示範件加掃出）開啟、遷移到 19，掃出照常重算（兩個本體，總體積 = 示範件 + 16×30）。
- **瀏覽器**（`tests/e2e/phase3-loft.js`）：三張草圖（前基準面 10×6、偏移 10 的平面上 5×3、偏移 20 的平面上 10×6），用 UI 做疊層拉伸：兩個截面 350（角錐台公式），清單把第一個截面下移後仍是 350，從清單加入第三個截面後是有效實體，✔ 之後設計樹有「疊層拉伸1」、cap:start／cap:end 與側面的名字、0 個特徵失敗。
- `npm run check` 全過（型別、分層、i18n 基準不增加、全部測試）。

## 觀察（不改，但要知道）

- `Kernel.bounds` 用 `BRepBndLib.Add(shape, box, false)`，平滑曲面的盒子是**控制點的盒子**，比實際大（10→20→10 的鼓形算出寬 30，網格量出約 20）。目前只用在「貫穿」要延伸多長，偏大無妨；要用在別處（例如對齊、干涉的粗篩）時要注意。
- 三個截面的順序不是依序往前（z = 10、20、0）時 OCCT 仍給出有效的實體；順序是否合理由使用者負責，我們只擋無效的結果。

## 還沒做

- 導引曲線、起點／終點相切、直紋選項、有洞的截面、一張草圖的多個輪廓之中選一個、點選圖面上的草圖當截面（C4.5 的 P2 與介面）。
- 曲面的截面（ADR 0017 沒驗證的）、三個以上截面的非平行平面組合（核心對齊只驗了平行的與同一組標準）。

## 2026-10-24：平行基準面的圓形截面與操作入口

使用者欲在兩個平行基準面上畫異徑圓並生成錐體；既有核心已有圓錐台能力，入口原本因沒有預選草圖而停用。現在有兩張可用輪廓草圖時可直接啟動填料或（有本體時）除料疊層拉伸，預設最近兩張；有預選則保留其作最後截面的舊規則。預設排除抑制、純建構、空白、回溯桿後的草圖。閉合與單輪廓等真實幾何有效性仍由既有再生驗證，不把 UI 候選誤稱為已驗證的封閉截面。面板開啟後可直接點設計樹中的草圖加入截面，已有截面不重複；前後依賴由既有 setLoftSections 命令檢查，Schema 不變。

驗證：新增候選／預設截面 3 項測試，新增兩個獨立平行基準面異徑圓的真實再生案例（原生實體有效、三個面、體積符合 πh(R²+Rr+r²)/3，半徑及基準面距離修改後跟隨），原有圓錐台案例亦通過；共 5 項相關測試。新瀏覽器 manual-loft-circles.js 通過：實際 UI 畫圓、基準面偏移、無預選啟動、面板移除／設計樹加入與去重、尺寸對話框改直徑、一次復原及實際體積（out/loft-circles-ui.json）。核心幾何演算法未修改，不宣稱新增導引線、孔洞輪廓或點截面。

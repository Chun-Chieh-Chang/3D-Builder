# ADR 0183：圓弧條件，最近與最遠距離（G8b）

## 1. 背景
2026-10-19 草圖參照盤點的 G8，第二批的後半。2026-10-22 使用者裁決：圓弧條件用屬性管理員的下拉選單（不加 Shift／Ctrl 點選）；點對圓、線對圓的最近／最遠一起做。前半（固定整個圖元）是 ADR 0182。

**現況**：圓或圓弧與別的圖元之間的距離，一律從圓心量（`distance` 對圓取 `anchor`，即圓心）。要量兩個圓「之間的間隙」，只能自己加輔助線。

**別的軟體**：SolidWorks 的距離標註對圓或圓弧有「圓弧條件」：圓心、最小（最近）、最大（最遠）。

## 2. 決策（使用者已定）
1. **`distance` 新增選填欄位 `condition`**（`min`／`max`；沒有就是圓心），Schema 75。沒有這個欄位的舊檔行為完全不變。
2. **適用範圍**：圓或圓弧，與點、直線、另一個圓或圓弧之間的距離。不適用：兩個點、兩條線、單一直線的長度、草圖軸。這由規則表（`sketchError`）與新命令共同把關。
3. **圓弧量到它所在的整個圓**，不限於弧段內（限制在弧段內要判斷最近點是否落在掃過範圍，結果會因拖曳而跳變；不做）。
4. **選法只在屬性管理員的尺寸列**：下拉選單「圓弧條件」（圓心／最近／最遠），只在可適用時出現；新命令 `setDistanceCondition`。
5. **切換時數值換成現在量得的值**：幾何不跳動（SolidWorks 同）。從動（參考）尺寸只換條件，不寫值。
6. **明確拒絕**，不做近似：
   - 兩個圖元相交（圓與直線相交也一樣）→ 沒有「最近」，說明原因，不切換；
   - 圓心與另一端重合 → 沒有「最遠」（每個方向都一樣遠）：介面拒絕切換，求解器也明確回報失敗，不隨便挑一個方向。
7. **標註線**畫在量測的兩個端點之間（圓與點、圓與圓沿著圓心連線；圓與直線畫到垂足），顯示的數值就是它的長度。

## 3. 設計
| 層級 | 檔案 | 改動 |
|---|---|---|
| 模型 | `schema.ts`、`serialize.ts`、`sketch-rules.ts`、`commands.ts` | `distance.condition`、v75；規則（適用的圖元種類）；新命令 `setDistanceCondition`（條件加上數值，並重新檢查整張草圖） |
| 求解器 | `planegcs.ts` | `conditioned()`：最近用求解器**原生**的 `c2cdistance`（圓對圓）、`p2cdistance`（點對圓）、`c2ldistance`（圓對線）；最遠沒有原生版本，用輔助點 |
| 幾何 | `interact.ts` | `conditionEnds`：量測的兩個端點與長度，或不能量的原因；`measure` 與標註的畫法都用它 |
| 介面 | `controller.ts`、`PropertyManager.tsx`、i18n、說明 | 下拉選單；切換時取量得的值；被拒絕時顯示原因 |

**最近用原生關係的理由（實測，不猜）**：PlaneGCS 的 `c2cdistance` 量的是兩圓周之間的間隙，分離的圓與一個在另一個裡面的圓都正確（半徑 10 與 5、間隙 5 → 圓心距 20；半徑 20 與 5、間隙 3 → 圓心距 12），半徑是求解變數，編輯半徑後間隙仍是間隙，不會用到過期的半徑。

**最遠的做法**：沒有原生關係，所以在圓上放一個輔助點，起點取圓目前離對方最遠的一側：
- 圓對圓：兩個圓各一個輔助點，都與兩個圓心共線，再對這兩點做距離；
- 點對圓：輔助點在圓上，與圓心和那個點共線，再量到那個點；
- 圓對線：輔助點在圓上，圓心到它垂直於那條線，再量它到線的距離。

每個輔助點的兩個關係剛好拿掉它的兩個自由度，所以**不會增加自由度**。輔助點只是求解器裡的暫時物件，不在文件裡，也不會出現在幾何結果中；從動尺寸整個跳過，不會建立。

**反向對照**（皆已還原）：
- 求解器：最遠的輔助點放在近側，5 項轉紅；點對圓的最近改成圓心距，2 項；圓對線的最遠放在近側，2 項；`measure` 忽略條件，1 項（隨機測試的第三項）；相交的圓不被分辨，1 項；規則拿掉，2 項。
- 瀏覽器：切換時不帶值，e2e 轉紅，而且看得到圓心跳到 y = 57.66；不拒絕不能量的條件，e2e 轉紅；下拉選單不顯示，e2e 轉紅。

**測試第一版的錯，都在測試這邊**：
- `t` 要從 `@3db/i18n` 匯入；
- 圓弧的起點 id 取 `s1`，與草圖特徵的 id 撞名；
- 直線對圓的手算案例把圓心 x 設成 0，但距離值必須大於 0；
- 我把「最遠 = 35」誤寫成 30（20 + 10 + 5 = 35）；
- 固定的圓弧用三個 `fix`，會多出 1 個重複限制，改用上一項的 `block`；
- **隨機測試要求了沒有解的值**：一個圓在另一個裡面時，間隙最大只到 |R₂ − R₁|（同心時），我把值放大到超過它，求解器回報 `failed` 是對的。已把新值限制在有解的範圍；
- 直線對圓的圓心 y 沒有相對於直線的位置，造成負的距離值。

## 5. 已知限制
- 圓弧量到完整的圓，不限弧段（§2.3）；
- 草圖軸不適用；兩條線、兩個點之間沒有「圓弧條件」；
- 最近的求解結果在「分離」與「一個在另一個裡面」之間不會跳邊：求解器從目前的配置開始，值不能把配置推過相切點（例如在內部的配置，最近的間隙最大只到 |R₂ − R₁|，要求更大的值會求解失敗，並由求解器回報）；
- 最遠的輔助點依賴起點取在遠側：極端的拖曳若把兩個圓心拖到重合，求解失敗並說明。

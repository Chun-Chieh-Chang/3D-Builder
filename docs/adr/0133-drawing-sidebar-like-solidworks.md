# ADR 0133：工程圖側邊欄比照 SolidWorks 的結構（D-I1b 提前）

- 狀態：**已完成（2026-10-13）**。
- 需求追溯：使用者在 2026-10-13 提出：「側邊欄的設計太不高級，必須對照 SW 優化」。對應 [ADR 0129](0129-drawing-interaction-roadmap.md) 的 D-I1b（工具列、工程圖樹），提前到現在做。

## 背景與根因

這不只是樣式問題，而是結構問題：工程圖的左側面板把圖頁、標題欄、調色盤、視圖、尺寸、註記、衍生視圖、輸出全部攤成一條長清單。SolidWorks 的組織方式是：

- 左側上方分頁：FeatureManager（工程圖樹）和 PropertyManager（屬性）。
- PropertyManager 依選取的東西切換內容：標題列寫出正在編輯什麼，內容是可以收合的群組框。
- 指令放在 CommandManager。
- 視圖調色盤放在右側的工作窗格。

## 決定

1. **兩個分頁**：
   - **工程圖樹**：文件 → 圖頁（尺寸、比例）→ 圖頁格式 → 視圖。衍生視圖巢狀放在母視圖下面，可以收合。每列有依視圖種類的圖示、尺寸與註記數量、錯誤提示；滑鼠移上去才出現刪除鈕。
   - **屬性**：在圖紙上選了東西，會自動切到屬性分頁（比照 SW 在繪圖區點選物件）；在樹上點選則留在樹上。
2. **PropertyManager 依內容切換**：
   - 標題列有圖示、種類（圖頁、工程視圖、尺寸、註記、表面粗糙度、表格、圖頁格式）、名稱，以及 ✓（完成並取消選取）。
   - **不做 ✗（取消）**：這裡的修改都是即時寫入的指令，沒有可以取消的編輯階段，假的取消按鈕會誤導人。
   - 群組框依內容決定預設展開哪些（圖頁：圖頁、輸出；視圖：視圖屬性、衍生視圖；尺寸：尺寸；註記、表面粗糙度、表格：註記）。手動展開或收合的狀態會保留，直到內容換成別的東西。
3. **常駐的指令列**（等同 SW 的 CommandManager）：投影、剖面、細部、尺寸、註解、基準、幾何公差、中心符號、中心線、粗糙度，共 10 個圖示指令。按鈕用 `data-command` 標示，和群組裡原本的 `data-action` 分開，避免影響既有的腳本。
4. **視圖調色盤移到右側工作窗格**，可以收合成一條直式分頁；收合狀態只記在這個瀏覽器（localStorage，失敗時不影響使用）。
5. **群組收合和分頁切換都只用 `hidden` 隱藏，不卸載元件**：所有欄位一直留在頁面上，既有 e2e 腳本用的 `data-field`、`data-action`、`data-view` 都找得到。CSS 用 `.sw-panel [hidden] { display: none !important }` 確保 `hidden` 優先（第一版的 `display:flex` 蓋過了它，截圖時抓到）。
6. **多選列**只在選了 2 個以上時出現。
7. 新增 21 個 16 px 線條圖示（圖頁、視圖、投影、剖面、細部、尺寸、註解、基準、幾何公差等），和既有圖示的筆畫風格一致。

## 限制

- 只改了工程圖。零件和組合件的 FeatureManager、PropertyManager 還是原本的樣式，要等使用者確認方向後再比照。
- 指令列放在側邊欄頂部；SW 的 CommandManager 是在視窗頂端的頁籤。日後頂端的 `CommandBar` 若加入工程圖頁籤，指令應該移過去。
- 工程圖樹還沒有右鍵選單（D-I1b 剩下的部分）。

## 驗證

- 瀏覽器（定位板）：
  - 沒有選取時，屬性分頁顯示「圖頁 A3 · 1:1」，展開圖頁、輸出，收合圖頁格式。
  - 在樹上點上視圖：停在樹，該列高亮。切到屬性：標題「工程視圖／上視」，展開視圖屬性、衍生視圖。
  - 在圖紙上選一個尺寸：自動切到屬性，展開尺寸群組。
  - 收合中的欄位（`size`、`auto-overall`、`centreMarks`、`sectionAxis`、`newDirection`）都還在 DOM 裡。
  - 截圖確認：分頁、指令列、PM 標題、群組框、右側調色盤都正常顯示。
- `verify:ui` 的工程圖腳本（含 `manual-measure-view`）：15 支有 12 支通過，3 支是既有失敗。

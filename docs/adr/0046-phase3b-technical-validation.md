# ADR 0046：Phase 3b-0 技術驗證——鏡射零組件、干涉檢查效能、STEP 組合件結構、桌面版

- 狀態：② ③ ④ 已量測並有決定（2026-10-02）；**① 桌面版（Tauri）只做了不需要安裝的調查**，要安裝 Rust 與 MSVC 才能繼續，等使用者決定（見 §4）。
- 對應：[phase3-plan](../phase3-plan.md) §4 的 3b-0。證據是 `spikes/occt-gaps/phase3b-validation.test.ts`（8 項，不屬於 `npm test`）：

```bash
npx vitest run --config spikes/occt-gaps/vitest.config.ts spikes/occt-gaps/phase3b-validation.test.ts --reporter=verbose
```

## 1. 鏡射零組件的表示法（②）

決定 4（2026-09-30）已定：鏡射時產生一個「鏡射零件」檔，內容是原件的鏡射，是衍生資料。這裡驗證它站得住腳。

實測（定位板，24 個面）：

| 項目 | 結果 |
|---|---|
| `Kernel.transformed(形狀, 鏡射矩陣)` 後 `isValid` | 有效 |
| 體積、表面積 | 與原件相同（137197.0207 mm³） |
| 面的順序 | 第 i 個面就是原件的第 i 個面：曲面種類相同、面積相同、中心的 X 變號、平面外法向的 X 變號且仍朝外 |
| 質心 | X 變號 |
| 鏡射零件放進 STEP 組合件（原件一個實例、鏡射件一個實例，位姿都是剛體） | 往返成立，兩個原型，體積相同 |

**面的順序不變**是關鍵：原件的持久名稱可以用「同一個序號」對到鏡射件，所以鏡射零件的面名稱可以是「`<鏡射>:mirror:<原名>`」（與 3a-7c 的特徵鏡射同一個文法），結合可以用它。

另量了「把鏡射直接放在零組件的位置上」會怎樣：OCCT 寫得出來，用 `CARTESIAN_TRANSFORMATION_OPERATOR_3D`（包在 `MAPPED_ITEM` 裡）表示，OCCT 讀回行列式 −1。**但那是 OCCT 讀 OCCT 自己的檔**，不能證明別的讀取器（eDrawings、SW）處理得對；使用者手上只有 eDrawings，沒有第二個可信的讀取器。所以決定不變：鏡射在零件裡，位姿永遠是剛體，與 ADR 0015 的「非單位四元數一律拒絕」一致。

**決定：** 沿用決定 4。鏡射零件檔由原件加鏡射面（或鏡射矩陣）重新產生，改原件時重新產生；組合件的零組件參考這個鏡射零件檔。`Kernel.transformed` 已能做，3b-2 不需要新的核心功能。

## 2. 干涉檢查的效能（③）

做法：每對零組件做 `BRepAlgoAPI_Common`，體積 > 1e-6 mm³ 才算干涉；先用包圍盒濾掉不可能相交的配對。

正確性（尺寸與重疊量都已知）：

| 配置 | 預期 | 結果 |
|---|---|---|
| 兩個 10×10×5，Z 方向重疊 2 | 200 mm³ | 200（誤差 < 1e-6） |
| 兩個 10×10×5，面接觸 | 0 | 0（接觸不算干涉） |
| 兩個 10×10×5，分開 | 0 | 0 |
| 兩個 10×10×5，偏移 (4, 3, 1) | 6×7×4 = 168 | 168 |
| 削邊銷放進板的 R4 孔（柄 R5，有槽與倒角） | 手算 405.40 mm³ | 405.396（相對 < 1e-6） |
| 銷抬高到柄剛好站在板上／抬到空中 | 0 | 0 |

效能（20 個零組件：定位板、削邊銷、V 型塊輪流，格子間距是尺寸的 85%，所以相鄰的都重疊；22 對有干涉）：

| 做法 | 配對數 | 時間 |
|---|---|---|
| 190 對全部做 Common | 190 | **約 1.0 s** |
| 先用包圍盒濾掉 | 26 | **約 0.5 s**（同樣找到 22 對） |

這些零件各只有 15–24 個面；真實的零件面數多得多（治具 2004 個面，產品件 340 個面），單對的時間會大很多，**這個預算只對面數少的零件成立**。

**決定：**
1. 干涉檢查在 Worker 做，按下「干涉檢查」才算，不在每次結合求解時算。
2. 先用包圍盒（`Kernel.bounds`）濾掉，再對剩下的配對做 `Common`；結果列出配對、體積、重疊區的位置，可以逐對點選。
3. 預算：**20 個每個 ≤ 50 面的零組件 < 2 s**（量到約 0.5 s，有餘裕）。面數大的零件（輸入的 STEP）要有進度與取消（Worker 換掉，同 ADR 0021 的重算時間上限），不承諾時間。
4. 之後若 3b-5 用真實零件量到太慢，備案是按零組件各用一個 Worker 平行；這會多佔記憶體（WASM 約 42.7 MB 每個），所以現在不做。

## 3. STEP 組合件輸入的結構對應（④）

在 XCAF 建一個兩層的組合件（`Fixture` 內有 1 塊板與兩個 `PinPair` 次組合件，每個 `PinPair` 有 2 支銷；銷與板各是一個原型），寫成 STEP 再用 `STEPCAFControl_Reader` 讀回，遞迴走訪、累計位姿：

| 項目 | 結果 |
|---|---|
| 檔案裡的 `NEXT_ASSEMBLY_USAGE_OCCURRENCE` | 5 個（頂層 3 個：1 板、2 個 `PinPair`；`PinPair` 的定義裡 2 個：2 支銷，次組合件的定義只存一份），`PRODUCT`：`Fixture`、`plate`、`PinPair`、`pin` |
| 階層 | 讀回的樹與寫入的一致：`Fixture/plate<1>`、`Fixture/PinPair<1>/pin<1>` 等，次組合件用 `IsAssembly` 判斷 |
| 名稱 | 零組件名稱（`pin<1>`）與產品名稱（`pin`）分開保存，都讀得回來 |
| 位姿 | 遞迴累計後，4 支銷分別在 (−40, 0, 5)、(40, 0, 5)、(−40, 100, 5)、(40, 100, 5)，與預期完全相同 |
| 原型共用 | 兩個原型（`plate`、`pin`）；4 支銷共用一個原型 |

對應到我們的檔案：

- 每個原型（`GetReferredShape` 取得、非組合件的標籤）→ 一個零件檔（輸入特徵，用現有的 `importStep` 路徑，檔名取產品名稱，同名時加序號）；
- 每個組合件原型 → 一個 `.3dba`（次組合件，3b-1 之後才能存）；頂層組合件 → 組合件檔；
- 每個零組件 → 一個零組件（名稱取組合件內的名稱，位姿取 `GetLocation`，**只取該層的相對位姿**，不要累計）；
- 位置只能是剛體：行列式 −1 的位置要拒絕並說明（見 §1，不要靜默接受）。

**決定：** 3b-3 照這個對應做。名稱衝突、AP203 把組合件併成單一實體（現有的兩個 STEP 就是）、顏色（`XCAFDoc_ColorTool`）留到 3b-3 實作時處理；顏色是原型的還是實例的，要在 3b-3 先用金樣夾具輸出檔量過。

## 4. 桌面版（①）——只做了調查，沒有安裝

這台機器（2026-10-02）：

| 項目 | 狀態 |
|---|---|
| WebView2 Runtime | 已安裝，版本 154.0.4258.48 |
| Rust（`rustc`、`cargo`、`rustup`） | **沒有** |
| MSVC 建置工具（`vswhere`） | **沒有** |
| `winget` | 有 |

Tauri 2 在 Windows 上需要 Rust 與 MSVC 建置工具（含 Windows SDK），安裝量是幾個 GB，屬於系統層級變更。**沒有使用者許可不安裝。**

不需安裝就能確認的：**檔案存取集中在 `apps/web/src/files.ts` 一個模組**（`showOpenFilePicker`／`showSaveFilePicker`／`showDirectoryPicker`／`createWritable`／IndexedDB 記住的資料夾控制代碼）。`store.ts`、`assembly.ts`、`PropertyManager.tsx` 只透過它的函式取檔。所以「`FileStore` 抽象」的範圍已經縮小為「替換 `files.ts`」，不是改所有呼叫處。

還沒驗證（需要先安裝才能做）：
1. WebView2 內 `showOpenFilePicker`／`showSaveFilePicker`／`showDirectoryPicker` 是否可用（Chromium 154 應有，但 Tauri 的 WebView2 設定可能關掉）；
2. 不可用時，改用 Tauri 的 dialog 與 fs 外掛（原生對話框、真實路徑）；
3. WASM（42.7 MB）改為本機資源載入的啟動時間與離線啟動；
4. 安裝檔大小、解除安裝是否乾淨。

**決定：** 待使用者決定是否安裝 Rust 與 MSVC 建置工具；備案（phase3-plan 風險 7）是保留網頁版，只用原生殼做檔案存取。

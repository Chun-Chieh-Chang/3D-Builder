# ADR 0047：剛性次組合件的模型層（Phase 3b-1，第一段）

- 狀態：模型層已做（2026-10-02）。**介面、解算、存檔的整合還沒做**。

## 決定

- 次組合件不新增資料：零組件的檔案若是 `.3dba`，它就是次組合件（`isSubAssemblyPath`）。Schema 不變，舊檔照開。
- 遞迴解析是衍生資料：`resolveTree(頂層路徑, 載入函式)` 走完整棵樹，回傳每個零件在頂層座標的位姿（`composePoses`）、從頂層到零件的零組件 id 鏈、各自的檔案路徑（路徑相對各自組合件所在資料夾，結果統一成相對專案資料夾）。
- 次組合件內的結合不外洩：每個組合件各自解算，上一層只看到整個次組合件的 placement；移動次組合件，裡面每個零件移動同一個量（測試）。
- 循環引用：`resolveTree` 回報 `cycle`（含檔案鏈）而不展開，其他零件照常回傳；`wouldCycle(頂層, 候選, 載入函式)` 在插入前問，插入指令不必接受開不了的文件。
- 檔案遺失回報 `missing`（含零組件鏈）。

## 還沒做

1. 把 `resolveTree` 接進網頁版：載入次組合件檔案、顯示、設計樹階層、插入零組件時選 `.3dba`。
2. 解算：每個組合件各自 `solveAssembly`，把解出的位姿寫回該層再 `resolveTree`。
3. 路徑改寫（ADR 0011）遞迴：組合件另存新資料夾時，次組合件的檔案要連同相對路徑一起處理。
4. 隱藏／抑制／透明（C15.5）。

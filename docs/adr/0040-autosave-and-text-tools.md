# ADR 0040：自動存檔與當機復原、文字化格式的工具（Phase 3a-9a）

- 狀態：已實作（2026-10-01）。
- 對應：B9.3 自動存檔與當機復原、B9.6 文字化可比對格式（phase3-plan §6 決定 5）、B3.2／B3.4／B3.7 的量測，見 [phase3-plan](../phase3-plan.md) §3 的 3a-9。3a-9 分三段：9a 這份、9b 設計樹與範本與快速鍵（ADR 0041）、9c 檢視與選取（ADR 0042）。Schema 不變。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **自動存檔存的是「零件檔的位元組」**（`writePartFile`，與存檔同一條路，所以含輸入的 STEP 資料），放在瀏覽器的 IndexedDB（與資料夾控制代碼同一個資料庫，鍵 `recovery`），**只有一份**；附檔名（或「零件1」）與時間。只有零件，組合件不做。 | 復原回來的就是一個合法的零件檔，不用另一種格式；一份就夠，因為一次只開一份文件。 |
| 2 | **時機**（`Autosaver`，`apps/web/src/autosave.ts`，邏輯與儲存地點分開，單元測試用假計時器與記憶體盒子）：有未存檔的變更時，**最後一次變更後 5 秒**存一份（連續編輯不會每次都存）；頁面被藏起來（`visibilitychange` 為 hidden，關分頁、切換、手機）立刻存；存檔、新零件、開啟別的檔、變更回到與檔案相同時，丟掉那一份。丟掉會等正在做的那一份寫完才執行，所以不會有「刪掉之後又冒出來」。做不出副本（記憶體、被拒絕）不中斷工作，下一次變更再試。 | 5 秒是不拖慢編輯又不丟太多工作的折衷；一個大零件的 `writePartFile` 要壓縮，不能每次變更都做。 |
| 3 | **下次開啟時問一次**（「找到沒有儲存的零件」，復原／捨棄，不能按外面取消）：復原 ＝ 開成一份**尚未儲存的零件**（沒有檔案控制代碼，第一次存檔會問名稱，標題有「*」），瀏覽器裡的副本留著直到新的一份取代它（復原後立刻當機也不會丟）；捨棄 ＝ 丟掉。答之前不存新的副本（否則空白的新零件會把舊的蓋掉）。多個分頁共用同一份：後存的蓋過先存的（已知限制）。 | SW 也是復原成一份要另存的文件；不自動覆蓋原檔，因為使用者可能已經在別處改過它。 |
| 4 | **文字化格式（B9.6，phase3-plan 決定 5：先當作已滿足）**：`.3dbx` 裡的 `document.json` 本來就是排好序、每次相同的 JSON 文字，缺的是看它的工具：<br>• `scripts/3dbx.mjs`（只用 Node，不用建置）：`cat <檔>` 印出 `document.json`；`unpack <檔> [資料夾]` 展開成 `document.json` 加 `blobs/`；`pack <資料夾> <檔>` 打包回去（`document.json` 在前、其餘依名稱排序，同一個資料夾永遠同樣的位元組；沒有 `document.json` 或沒有 `schemaVersion` 就拒絕）。<br>• `.gitattributes` 的 `*.3dbx diff=3dbx` 與 `npm run setup:git`（`git config diff.3dbx.textconv "node scripts/3dbx.mjs cat"`），`git diff` 就看得到零件檔裡改了什麼。這個設定是 Git 的限制：每個 clone 要各自跑一次，沒跑時 `git diff` 還是顯示 Binary files。 | 腳本與 AI 能讀寫檔案內容；金樣與樣本檔的變更看得懂。什麼情況要重新考慮：想用文字編輯器直接改檔案、或需要 Git 合併兩份修改（那時才需要另一種存檔格式）。 |
| 5 | **B3.2 增量重算、B3.4 特徵快取不做**：ADR 0017 說等 3a-5、3a-6 的特徵都有了再量一次。量了：53 個特徵的零件（17 個伸長加 17 個圓角，其餘為草圖）從頭重算 **約 0.85 秒**（預算 2 秒），最慢的特徵是第一個伸長（約 90 毫秒）。有餘裕，所以不加快取；`tests/phase3/rebuild-speed.test.ts` 守著這個數字（上限 3 秒，因為整套測試同時跑）。B3.5 背景重算（Worker）與 B3.7 中止（重算時間上限，ADR 0021）早就有了。 | 沒有量到問題就不加複雜度（快取要處理失效的正確性）。 |
| 6 | **匯入結果快取（handoff §10）這次不做**：大 STEP 的匯入時間花在 OCCT 讀檔與命名，要快取得把形狀序列化（`BRepTools` 寫出）進 IndexedDB，是另一個工程；現在有進度提示，且同一個工作階段內已有記憶體快取。留給後面（3b 的 STEP 組合件輸入會乘上零件數，那時再做）。 | |

## 驗證

- `apps/web/test/autosave.test.ts`（6 項，假計時器）：連續變更只存一次且在最後一次之後 5 秒；變更回到與檔案相同就丟掉副本；頁面要走時立刻存、沒有新變更不重存；丟掉之後排定的存檔不會發生；正在做副本時丟掉，副本不會留下；做不出副本不影響下一次。
- `tests/phase3/textual.test.ts`（5 項，真的執行 `scripts/3dbx.mjs` 與 `git`）：`cat` 印出的就是檔案裡的文字；`unpack` 的 `document.json` 與 `blobs/` 與 `pack` 回去的檔案程式讀得懂，同一個資料夾兩次打包位元組相同；手改 `document.json` 裡的尺寸，打包後程式讀到新的值；壞檔、缺 `document.json`、不是 3D-Builder 的文件各有錯誤；**在暫時的 Git 倉庫裡，沒設定時 `git diff` 說 Binary files，設定之後看到 `-"value": "20"` 與 `+"value": "35"`**。
- `tests/phase3/rebuild-speed.test.ts`：53 個特徵 0.85 秒，全部成功。
- **瀏覽器**（Chromium，兩個分頁）：畫一個板、等 6.5 秒，關掉頁面、開新頁：出現「找到沒有儲存的零件」，按「復原」後回來的是 草圖＋伸長、體積 6000、標題有「*」，沒有主控台錯誤。（`tests/e2e/phase3-recovery.js`）
- `npm run check` 全過。

## 還沒做

- 組合件的自動存檔；多個分頁各一份；自動存檔間隔的設定（3a-9c 的系統選項）。
- 匯入結果快取；真正的文字編輯器可合併的格式。

# ADR 0140：從工程圖的視圖開啟零件，返回後自動更新（D-I7(a)）

- 狀態：**已完成（2026-10-15）**。工程圖檔案格式不變。
- 需求追溯：[ADR 0129](0129-drawing-interaction-roadmap.md) 的 D-I7(a)。使用者決定 Q3：右鍵「開啟零件」，回到工程圖時自動重新整理；不做多文件同時開啟（R4-b）。

## 背景

SolidWorks 在視圖上按右鍵就能「開啟零件」，改完存檔後回到工程圖，視圖會跟著更新。本專案一次只開一份文件（2026-09-28 的決定）。組合件已經有「開啟零件 → 返回組合件」的流程，工程圖卻沒有：要改零件，只能自己去開檔，再自己開回工程圖。

## 決定

1. **右鍵選單**（`DrawingViewMenu`）：
   - 在圖紙上，右鍵**在原處放開**就會打開游標下視圖的選單，並選取那個視圖。右鍵拖曳仍然是平移，判斷門檻是移動不到 4 px。
   - 工程圖樹的視圖列按右鍵，會出現相同的選單。
   - 選單項目：
     - 「開啟零件（檔名）」：視圖來源是組合件時，改為「開啟組合件（檔名）」。剖面、細部等衍生視圖，開啟的是它們上層視圖的來源。
     - 組合件視圖裡，游標下若點得到某個零件的元素，就多一項「開啟這個零件（檔名）」。依據是該元素參照帶的葉節點 id（`in`，ADR 0138），再用 `leafPath` 找出檔案。
   - Esc 或在其他地方按一下，選單就會關閉。
2. **開啟與返回**（`store.openPartOfDrawing`，和組合件共用 `openPartFile`）：
   - 工程圖有未存的變更時，先問「要儲存變更嗎？」。
   - 來源檔不見時，說明原因，不開啟任何東西。
   - 開啟後，零件（或組合件）的特徵樹上方出現「返回工程圖「名稱」」。
   - `returnTo` 改成 `{ name, kind: 'assembly' | 'drawing' }`，同一個返回列可以回到組合件或工程圖。
   - 工程圖從沒存過檔時，沒有檔案可以返回：照樣開啟零件，並在通知裡說明沒有「返回工程圖」。
3. **自動更新**：「返回工程圖」會重新讀取工程圖檔，各視圖的來源依內容重新建立。存過檔的零件變更因此會出現在視圖上，尺寸和註記也照常依名稱重新解析。視窗切回來時，原本就會重新讀取有變更的來源（`refresh`），這部分不變。

## 驗證

- `tests/e2e/manual-drawing-open-part.js` 共 8 步，全部通過：
  1. 定位板加三視圖存成工程圖，前視圖寬 120。
  2. 右鍵拖曳會平移，不出現選單。
  3. 右鍵在原處放開，出現「開啟零件（定位板.3dbx）」，且選取了該視圖；按 Esc 關閉。
  4. 工程圖樹按右鍵，出現同樣的選單。
  5. 工程圖有變更時，先詢問是否儲存；按取消就留在工程圖。
  6. 開啟零件後出現「返回工程圖」。
  7. 把寬度改成 150 並存檔。
  8. 返回後，前視圖寬 150。
- 反向檢查：把第 8 步的預期故意改錯，腳本確實判定失敗，並回報實際量到的 `w: 150`。
- `phase5-assembly.js`：
  - 組合件視圖的選單是「開啟組合件（夾具.3dba）」。
  - `leafPath` 依葉節點找到 `定位板.3dbx`、`削邊銷.3dbx`、`削邊銷.3dbx`。

## 後果與限制

- 回到工程圖是重新開檔，所以沒有存檔的工程圖狀態（平移、縮放）不會保留，和「返回組合件」相同。
- 「開啟這個零件」只出現在游標下點得到元素的時候（邊、頂點、平面），點在面的空白處不會出現。這一項的 e2e 只驗證了 `leafPath` 對應正確；實際在組合件視圖上右鍵點到零件元素再開啟，還沒有 e2e 腳本覆蓋。
- 從工程圖開啟子組合件，再從子組合件開啟零件時，返回只回到上一層，不會一路回到工程圖。這和原本子組合件的行為一致。

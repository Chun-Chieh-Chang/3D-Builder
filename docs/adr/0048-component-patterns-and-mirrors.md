# ADR 0048：零組件的複製排列與鏡射（Phase 3b-2，**組合件 Schema 4**）

- 狀態：2a–2d 都已實作並推送（2026-10-02）。
- 對應：[phase3-plan](../phase3-plan.md) §4 的 3b-2（C15.13）。使用者 2026-10-02 確認：實例是衍生位姿、跟著種子（不另存、不能再加結合）；鏡射零件在載入時由原件算出、**不另存檔**（取代 2026-09-30 的決定 4「產生一個鏡射零件檔」，理由：沒有第二份要同步的檔案，永遠跟著原件）；驗收標準 1–9。

## 決定

1. **只存定義。** `AssemblyDoc.patterns?: ComponentPattern[]`（可省略，沒有排列的檔案沒有這個鍵，所以舊檔原封不動，遷移 3→4 是恆等）。`ComponentPattern`：`kind`（`linear`／`circular`／`mirror`）、`seed`（零組件 ID）、`axis1`／`count1`／`spacing1`／`flip1`、`axis2`／`count2`／`spacing2`／`flip2`（線性的第二方向，格子）、`equal`（環狀：`spacing1` 是總角度）、`plane`（鏡射面：前、上、右基準面）、`skip`（要跳過的實例，標籤 "2" 或 "2x1"）。間距是運算式（長度或角度），實例數是整數。
2. **方向與軸**是組合件的 X／Y／Z 軸，或某個零組件的一個元素（`MateRef`，同結合，可帶次組合件內的路徑）：直線邊線、圓柱或圓錐的軸、平面的法向。
3. **實例的位姿是種子位姿的一個剛體運動**：線性是沿軸平移、環狀是繞軸（通過給定的點）轉動，`componentPatternInstances` 回傳每個實例的運動（`Pose`，用在種子位姿之前：`composePose(運動, 種子位姿)`）。環狀的「等間距」：總角度 ≥ 360° 時除以 n，否則除以 n − 1。標籤 "1"／"1x1" 是種子，不能跳過。上限 500 個實例。
4. **鏡射件仍用剛體位姿。** 鏡射件的零件是原件在**零件自己的 x = 0 平面**的鏡射（零件座標 x → −x，面的順序不變），位姿是 `R · 位姿 · M`（`mirroredPose`：R 是組合件基準面的反射，M 是零件座標的反射，兩個反射成一個旋轉，行列式 +1），所以 STEP 不必有行列式 −1 的位姿（ADR 0046）。次組合件的鏡射逐個葉零件做同樣的事，次組合件內部各零件的位姿是 `M · I · M`（`mirroredInside`），用於 STEP 輸出的鏡射次組合件產品。
5. **種子被刪或被抑制：** 刪除種子，或刪除提供軸的零組件，排列一起刪（同結合隨零組件刪除）；種子被抑制，實例也不存在（2b）。
6. **命名：** `componentPattern*` 與零件的 `patterns`／`patternInstances` 分開（兩者都從 `@3db/model` 匯出）。
7. **實例是葉子（2b）。** `patternLeavesOf`（`@3db/model`，純函式）由種子的葉子（`leavesOf` 的結果）算出每個實例要畫的零件：線性與環狀是「運動 ∘ 種子葉子的位姿」，鏡射是「鏡射零件（`mirrorKey(key)` = `key:mx`）加 `mirroredPose`」。實例葉子的 `top` 是種子，所以懸停、選取、拖曳都落在種子上，旗標（隱藏、透明）與抑制自然跟著；`instanceOf` 說是哪個排列做的。方向或軸找不到、定義讀不通時，排列沒有實例並在設計樹上標錯誤與原因（`patternProblems`）。
8. **鏡射零件由 Worker 建（2b）。** `buildMirrorPart(partKey)`：把已建好的零件形狀以零件自己的 x → −x 鏡射後切網格（面、邊、頂點的順序不變），只回網格，不回名稱與幾何，所以實例不能被拾取成結合元素：視圖在拾取到實例上的元素時說明（`pattern.derivedNoMate`），不會悄悄綁到種子的同名元素。每個 key 只建一次，零件建好後才建它的鏡射。
9. **預覽（2c）。** `AssemblyState.pattern`（`PatternDraft`：定義、編輯中的 ID、正在圖面上選哪個軸）；屬性管理員開著時，草稿以 `pattern-preview` 這個 ID 加進文件裡算實例，所以改數量、間距、跳過、反轉、軸都即時看到；✓ 才寫進文件（一個復原步驟），✗ 或 Esc 丟掉。方向與軸可以在圖面點直線邊線、圓柱或圓錐面、圓形邊線、平面（沿用結合的元素拾取，帶次組合件內的路徑）。設計樹有排列列（雙按編輯、右鍵編輯或刪除、Delete 鍵刪除）。
10. **STEP（2d）。** 實例是種子產品的更多使用（位姿 `運動 ∘ 種子位姿`，名稱 `定位組<1> 〔線性複製排列1：2〕`）；鏡射是產品的鏡射版本：零件的鏡射是另一個零件（`<名稱>（鏡射）`，Worker 輸出時才鏡射形狀），次組合件的鏡射是另一個次組合件，裡面每個零件是鏡射零件、位姿是 `M · I · M`（`mirroredInside`）；頂層位姿是 `R · 位姿 · M`，所以檔案裡沒有任何行列式 −1 的位姿。軸找不到的排列在檔案裡也沒有實例（與畫面一致）。
11. **限制（記下來）：** ① 次組合件**自己的檔案裡**的排列，在上一層不會出現（只有目前文件的排列做成實例），要看請開啟那個次組合件；② 實例不能被結合、不能單獨移動，要動就動種子；③ 鏡射面只有組合件的前、上、右基準面（不含自訂基準面）；④ 驗收標準 5 的「可被結合選取」改成「鏡射件的面與原件逐面對得上」（鏡射零件的面順序不變）。

## 2a 的驗證

- `packages/model/test/componentPatterns.test.ts`（14 項）：線性（間距、反轉、跳過、格子、任意直線）、環狀（點繞軸轉到手算的位置、等間距 360° 與 180°、跳過、反轉）、定義的 12 種拒絕理由；鏡射：三個平面 × 四個姿態 × 三個點，鏡射件的點（x 取負）經 `R · 位姿 · M` 與「原件的點對基準面反射」相差 < 1e-9、行列式 +1；次組合件內部的位姿；矩陣轉四元數（含 180° 的邊界）；指令（新增、修改、刪除、各一個復原步驟、ID 不重用、拒絕不合法的定義而不改變文件、刪種子與刪提供軸的零組件）；序列化往返、Schema 3 的文字原樣讀入、計數器涵蓋排列的 ID。
- `tests/fixtures/old-versions/v3-assembly.3dba`：次組合件用兩次、帶路徑的結合、透明旗標；**不是 Schema 3 的程式寫的**（Schema 4 的程式寫出再把版本設成 3，理由見該目錄 README）。

## 2b–2d 的驗證

- `packages/model/test/componentPatterns.test.ts` 再加 4 項（`patternLeavesOf`：每個實例每個零件一個葉子、屬於種子、旗標跟著、鏡射的鍵與位姿、種子被抑制沒有實例、軸找不到或定義讀不通時說明）。
- `tests/phase3/component-pattern-step.test.ts`（5 項）：夾具（一個傾斜的定位組、一個自己的零件、線性排列跳過一個、環狀排列、鏡射）輸出後，產品是 定位組、定位組（鏡射）、定位板、削邊銷、各自的鏡射；頂層 6 個零組件、檔案裡 10 個 `NEXT_ASSEMBLY_USAGE_OCCURRENCE`；**檔案裡每個零件的世界位姿與視圖畫的葉子位姿相差 < 1e-6**（全部零件，含鏡射）；每個位姿的行列式 +1；鏡射件的體積相同、質心 x 取負；**鏡射件放在鏡射位姿，與「原件對基準面反射」的對稱差體積 < 1e-6**（三個基準面 × 兩個姿態）；種子被抑制時沒有實例、軸找不到時線性與環狀沒有實例而鏡射還在。
- 瀏覽器（`tests/e2e/phase3-component-pattern.js`：`__pat.linear()`／`circular()`／`mirror()`／`follow()`／`edit()`／`saveReopen()`／`step()`）：命令列的三個按鈕開屬性管理員、種子預設是選取的零組件；數量改了預覽立刻變、跳過一個；加入後設計樹有排列列；環狀 90° 的位置是 (x, y) → (−y, x)；鏡射的零件在右基準面對面、視圖的實例矩陣行列式 +1；移動種子 25，種子與所有實例一起動；隱藏、抑制種子實例跟著不見、復原回來；編輯改數量；軸用一條零組件的直線邊線；Delete 鍵刪排列；另存、重開：排列與同樣數量的零件都在、沒有問題；Worker 輸出的 STEP 有鏡射產品與全部實例。Console 沒有應用程式的錯誤。
- **沒有直接測的：** 改種子的零件檔後實例更新（實例葉子與種子用同一個 key，所以重畫時一起換，機制與次組合件相同，但沒有單獨的測試）。

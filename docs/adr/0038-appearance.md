# ADR 0038：外觀與顏色（Phase 3a-8b）

- 狀態：已實作（2026-10-01）。
- 對應：C14.2 色彩及外觀（單一覆寫優先序；STEP 可帶顏色）、F1.3 的顏色部分，見 [phase3-plan](../phase3-plan.md) §3 的 3a-8。
- Schema 仍是 24（與 ADR 0037 同一版）：`AppearanceOverride.target` 從「面的參考或整個零件」改成四種對象。以前沒有任何版本能存下外觀（沒有介面也沒有指令），所以不需轉換。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **四種對象**（`AppearanceTarget`）：整個零件、一個本體（本體 ID）、一個特徵（特徵 ID，它做出的面）、一個面（參考）。顏色是 `#rrggbb`，同一個對象只存一筆（再設就取代，設成 `null` 就拿掉）。 | 藍圖 C14.2。 |
| 2 | **優先序：面 ＞ 特徵 ＞ 本體 ＞ 零件**（窄的蓋過寬的）。特徵的面是名稱第一段是那個特徵的面，所以排列與鏡射做出的面屬於排列或鏡射特徵（對它上色，實例都變色）；圓角後面積變了的面仍叫原來的名字，顏色跟著。面的參考照一般參考的規則找（名稱，其次幾何指紋）；本體或特徵不在了，那一筆不作用，不是錯誤。 | 與 SW 的「面蓋過特徵蓋過本體蓋過零件」一致。`faceColors`（`@3db/regen`）是唯一算顏色的地方，畫面與 STEP 共用。 |
| 3 | **畫面**：Worker 每次重算回傳每個面的顏色（`faceColors`），`Viewer.setFaceColors` 用頂點色畫（沒顏色的面維持本體色）；面的選取與滑過高亮照舊疊在上面。 | 顏色是衍生資料：文件只存選擇。 |
| 4 | **STEP**：輸出時每個有顏色的面是一個子形狀，設成面色（XCAF `ColorSurf`）；顏色以 sRGB 寫入（`Quantity_TOC_sRGB`，用另一種會把 `#808080` 當線性光而變亮，量到 `0x80` 變成 0.7367）；有 STEP 名字的顏色（純紅）OCCT 會用名字（`DRAUGHTING_PRE_DEFINED_COLOUR('red')`），其他寫 `COLOUR_RGB`。參考本體連同它的顏色不輸出；多個本體併成一個複合形狀，顏色依本體順序接起來（`exportFaces`）。 | 讀回去的實體不變（體積一致）；別的軟體看到的顏色就是畫面上的。 |
| 5 | **介面**：「工具」分頁的「外觀」：對象清單是目前選取的東西（零件一定有、選了本體列有本體、選了特徵有特徵、點了面有面），顏色輸入、套用、移除，下面列出所有上過色的（可個別移除）。 | 不另外開特徵：外觀不是歷史的一部分。 |

## 驗證

- `tests/phase3/appearance.test.ts`（7 項，真的 OCCT）：沒選時沒有顏色；零件紅、本體綠、特徵藍、面黃一起設，板是紅、柱壁是藍、柱頂是黃、獨立的方塊是綠；同對象取代（大小寫統一）、移除、不存在的本體不作用；排列特徵的顏色到它的實例面（種子本身沒有）；指令拒絕非 `#rrggbb`、不存在的特徵、不是面的參考；STEP：只有一個本體算數時 `COLOUR_RGB` 恰一筆且值 ＝ `#3366cc`、參考本體的綠色沒進檔案、不給顏色的檔案沒有顏色、讀回體積一致；兩個本體算數時顏色依序接起來。
- `packages/kernel/test/transform.test.ts`：面色、`AP214` 與 `AP242` 的檔頭、一次輸出的設定不影響下一次、`#rrggbb` 以外的色被拒絕。
- `npm run check` 全過。

## 還沒做

- 材質或特徵層級以外的外觀屬性（透明、反光）；圖面上點選面後直接上色的快捷。
- 面的外觀參考遺失時的「改用這個」修復（`mapRefs` 還沒收外觀的面參考）。
- STEP 組合件輸出帶顏色（3b）。

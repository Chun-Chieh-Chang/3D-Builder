# ADR 0198：剖面線區域與紙面樣式

2026-10-25。使用者回報工程圖剖面線位置錯誤，要求一般、階梯／對正、局部及衍生視圖全部檢查，並能調整密度與角度。圖紙 Schema 29；零件82與組合件7不變。

## 操作

選取剖面視圖，開啟「屬性」，設定「剖面線距（mm）」與「剖面線角度（°）」。線距越小越密；0.5–20 mm，以紙面毫米計算，不受視圖比例改變。角度從紙面水平線逆時針算，範圍 -180–180°。預設3 mm、45°；按 Enter 或離開輸入框套用，非法或空白值拒絕並保留待修正文字。

裁剪、局部放大繼承母剖面的樣式，也可獨立覆寫。「恢復預設／繼承」移除覆寫；一般剖面恢復3／45，衍生視圖恢復母視圖樣式。每次修改可復原／重做，寫入3dbd；舊圖紙升級保留既有預設。沒有新增全圖預設、材料自動樣式或任意視圖裁剪功能；既有crop仍只從局部剖面建立。

## 區域真值

舊實作依最終面的平面位置識別剖切面。若未被切的原面與工具共面，OCCT可能把它與真正新切面合併，導致原面被塗剖面線。只改法向或面中心不可靠。

- `Kernel.boolean` 增加可選 `mergeFaces:false`，預設不變。只有工程圖剖面選擇保留raw切割面及history，不影響模型特徵既有合面、持久命名語意。
- 新剖面必須含工具面來源，且沒有任何模型面來源；共面原面在raw history也可能同時具有兩種來源，故不能僅以工具來源判別。
- 一般／局部再核對切割／深度平面。階梯核對有效切段平面；對正保留原始cap集合，在既有common/cut分割中繼承，再以剛體turn的拓樸順序取出實際cap。100組原生旋轉切面面積驗證此對齊。
- 邊的相鄰面恰有一個cap才畫入輪廓，避免共享內部邊重複切線。

原生L形回歸：XY輪廓(0,0),(40,0),(40,5),(20,5),(20,30),(0,30)，沿Z拉伸12，體積8400。Y=5的真正切面只有X0..20，應有面積240；X20..40原本就是外表面，不可填線。一般、階梯、對正、局部四種均驗證。

## 衍生視圖與輸出

裁剪前保留完整cut邊界。若把逐邊cut先裁切，輪廓可能開放，even-odd掃線會錯配。`ViewLines.hatchClip`記錄累積裁切條件：先掃完整閉合切域（含孔洞），再裁生成的線段。detail保留母剖面cut，加圓形裁切；連續detail優先取已解出的父視圖。斷裂帶先切斷線段再轉換壓縮座標，不跨空隙畫線。

半格掃描起點為 `(ceil(lo/spacing - .5)+.5)*spacing`，避免漏掉窄域的第一列。scene以`spacing/scale`生成，角度轉弧度；SVG／PDF／DXF共用同一批向量線，不用各自的填紋解譯。

## 驗證與邊界

10個新核心案例各有通過結果；100組樣式、兩種比例，使用真實原生環形實體（含16×14孔）的section/local切面，檢查線段探針不入孔、方向及紙面行相位、巢狀裁剪／detail與斷裂；命令拒絕、原子性、繼承／覆寫／重設、復原／重做、舊版升級及存讀；輸出SVG／DXF／PDF線段數與DXF座標。既有相關65項各有通過紀錄，包含200組原生階梯／對正組態；最終來源判別再次通過這200組。

`manual-drawing-hatch-style.js`兩項瀏覽器案例各有通過紀錄，驗證定位板的真實剖面與實際SVG線條、面板、非法值修正、比例、復原／重做、重設、detail繼承／獨立樣式與存讀。截圖已檢視。存檔測試初輪用JSON欄位順序比較誤判，stable比較後只重試該失敗案例。證據含原始失敗在`out/section-hatch/`（git忽略）。

型別、反模式、分層、i18n及build通過；遵照使用者只跑相關與失敗案例，不聲稱全套通過。未新增實體建構核心，不承諾任意退化／自交切面可接受；本輪未量測heap，也不宣稱原生布林零洩漏，記憶體限制與Worker高水位回收依AGENTS.md §3.5。

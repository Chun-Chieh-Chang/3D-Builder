# ADR 0034：參考幾何（Phase 3a-7a）

- 狀態：已實作（2026-10-01）。
- 對應：C3.2 基準面的 P1（平行、垂直、中間、相切）、C3.3 基準軸、C3.4 座標系統、C3.5 參考點，見 [phase3-plan](../phase3-plan.md) §3 的 3a-7。7b 複製排列、7c 鏡射接在後面。
- **Schema 升為 21**：基準面多了四種定義（`parallel`、`perpendicular`、`midplane`、`tangent`），新的特徵種類 `refAxis`、`refPoint`、`coordSys`。舊檔不需轉換；已補 v20 樣本 `tests/fixtures/old-versions/v20-rib.3dbx`（由 `bde58f8` 寫出）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **基準面的新類型**（`PlaneDefinition`，每種一個型別，同 ADR 0007）：<br>• `parallel`：通過一個點、與參考面平行；<br>• `perpendicular`：通過一個點、垂直於一條直線邊線或基準軸；<br>• `midplane`：兩個互相平行的面的正中間；<br>• `tangent`：與一個圓柱面相切、與參考面平行（參考面的法向要垂直於圓柱的軸），`reverse` 換到圓柱的另一側。<br>框架一律走 `planeFrame`（原點是零件原點在平面上的投影、軸向依規則），所以平行於預設基準面的面拿到那個基準面的軸向。 | 草圖放在哪個平面上都得到同樣的 X/Y 方向（ADR 0007 決定 5）。相切只做「平行於參考面」這一種，因為過一點的相切有兩個解要選，SW 也是另外給選項；先做不需要猜的。 |
| 2 | **不平行的兩個面做中間面是錯誤**（說明夾角），不做角平分面；兩面重合也是錯誤。 | 角平分面是另一個意思（SW 的中間面對不平行的面給角平分面），要做時另外加一個類型，不要讓同一個名字有兩種結果。 |
| 3 | **基準軸**（`refAxis`，`AxisDefinition`）：直線邊線（經過邊線中點）；兩點（頂點或參考點，從第一點指向第二點）；圓柱面或圓錐面的軸；兩個平面的交線（平行就說沒有交線）。 | C3.3 的常用做法；沒做「垂直於平面過點」的軸，那個用兩點或垂直基準面就能表達。 |
| 4 | **參考點**（`refPoint`，`PointDefinition`）：座標（三個運算式，從零件原點量起）；邊線或面的中心（圓形邊線取圓心、直線邊線取中點；球面取球心、其他面取面的中心）；基準軸與平面的交點（平行就說沒有交點）。 | 座標可以用變數驅動，所以參考點也是有參數的特徵（`mapExprs` 認得它）。 |
| 5 | **座標系統**（`coordSys`）：原點（頂點或參考點，不選＝零件原點）、X 方向與 Y 方向各取一條直線邊線、基準軸或平面（平面取它的外法向）、`flipX`、`flipY`。X ＝所選的 X 方向；Z ＝ X × Y；Y 重新取 Z × X，所以兩個方向不必互相垂直；兩個方向平行就說無法決定 Z。**永遠是右手系**，所以沒有 `flipZ`。 | 反轉 Z 會做出左手系；要反轉 Z 就反轉 X 或 Y 其中一個。 |
| 6 | **參考幾何的參考還是 `Ref`**：`kind: 'datum'`，`name` 是特徵 ID（基準面、基準軸、參考點都一樣）；它是什麼，由文件裡那個特徵的種類決定。頂點與直線邊線仍是 `kind: 'vertex'`／`'edge'`。`angle` 基準面的 `axis`、`threePoint` 的 `points` 也可以用基準軸與參考點。父子關係用同一個 `defRefs`（`packages/model/src/refs.ts`）從定義裡的所有 `Ref` 推出，改參考（B4.3 的「改用這個」）用同一個 `mapDefRefs`，新的類型不必再改這兩處。 | 一個參考一種寫法；抑制、刪除、相依警告（ADR 0006）自動適用：抑制基準軸會連帶抑制用它的基準面與座標系統（測試）。 |
| 7 | **衍生資料**：`RebuildResult.axes`、`points`、`systems`（特徵 ID → 軸、點、座標系統），與 `frames` 一樣只在重算時算出，不寫回文件。基準軸（`Axis3`）與座標系統（`CoordSystem`）的型別在 `@3db/model`。 | 不變式 1。 |
| 8 | **選取方塊是一張表**（`apps/web/src/state/datumSlots.ts`）：每種定義有哪些方塊（參考面、旋轉軸、通過的點、圓柱面…）、各自接受什麼（平面、直線邊線或基準軸、頂點或參考點、圓柱面…），圖面上點到的、屬性管理員裡按到的元素，都放進「第一個接受它而且還空著的方塊」；方塊都滿了就換掉最後一個接受它的；清單型的方塊（三點、兩點）再點一次已選的就移除。屬性管理員、圖面的拾取（哪些元素可點、哪些要標示為已選、提示文字）、指令都讀這一張表，不會不一致。 | 取代 1C 的 `setPlaneRef` 那串 if；新增一種定義只改這張表。 |
| 9 | **屬性管理員裡有基準的按鈕**（`DatumPicker`）：預設基準面、以及這個特徵之前的基準面／基準軸／參考點，只列接受它們的方塊還需要的種類，按一下放進去。**發現**：開著屬性管理員時設計樹被它蓋住（`App.tsx`），ADR 0007 決定 8 說的「在設計樹點選基準面」其實點不到；這些按鈕就是 SW 的快顯設計樹。`treeClick` 的路徑保留（程式碼呼叫仍有效），但使用者走按鈕。 | 沒有按鈕就沒辦法選基準軸與參考點（它們不能在圖面上點）。 |
| 10 | **圖面顯示**：基準軸是穿過模型範圍再多一點的線；參考點是點；座標系統是三支固定螢幕長度的箭頭（X 紅、Y 綠、Z 藍）。選取、編輯中、被正在定義的特徵用到時高亮（橘色），其餘用紫色。都能用眼睛圖示顯示／隱藏（D4.6，`isHideable`）。圖面上**點不到**它們，用設計樹或屬性管理員選。 | 在圖面上點到線／點要處理與模型邊線的優先順序，這次不做。 |

## 驗證

- **手算**（`tests/phase3/datums.test.ts`，30 項，真的 OCCT，板 40×30×10 加半徑 5 的圓柱）：平行（通過 (40,30,10) 的上基準面平行面 y = 30，反轉後法向 −Y）、垂直（z = 10）、中間面（板的上下面 z = 5；前基準面與偏移 25 的面 z = 12.5）、相切（x = 25，反轉 x = 15 且法向 −X）；邊線軸、兩點軸 (0.8, 0.6, 0)、圓柱軸 (20, 15)、兩平面交線（前＋右 ＝ y 軸；偏移 25 的面＋右 ＝ (0,0,25)；斜面與前基準面的交線在兩面內）；座標、圓邊中心、直線邊中點、面中心、軸與面的交點；座標系統 X／Y 取方向後 Y 被壓成垂直、反轉 X 之後 X 與 Z 反向、不選原點在零件原點；三個參考點做的基準面與兩點軸；柱子移動後軸與點跟著移動。
- **錯誤**：不平行／重合的中間面、不平行於軸的相切、相切的不是圓柱、兩點重合、少一點、不是圓柱的軸、平行的兩面沒有交線、平行的軸與面沒有交點、平行的座標方向。
- **相依**：基準軸、參考點、基準面、座標系統的父子關係；抑制軸連帶基準面與座標系統；基準面不能參考它之後的軸（種類不對、順序不對各一項）；`setRefAxis`／`setRefPoint`／`setCoordSys` 與種類不符；`mapRefs` 在每一種裡改參考。
- **舊檔**：v20 樣本（板加肋材）開啟、遷移到 21，肋材照常重算（體積 = 16000 ＋ 15×20×4，面名稱不變）。
- **瀏覽器**（`tests/e2e/phase3-datums.js`，Chromium，0 個特徵失敗，唯一的主控台訊息是 favicon 的 404）：板 40×30×10，在圖面上點垂直邊線做基準軸 (20, 5, 15)；參考點選「邊線或面的中心」點上面 → (0, 10, 0)；基準面選「垂直」，用按鈕選軸與點 → y = 10，反轉；中間面（先清空預填的參考面，按「上基準面」再點上面）→ y = 5；相切沒選圓柱時屬性管理員說「請選擇圓柱面」；座標系統原點選點、清空 X 後選軸、Y 換成右基準面 → X = (0,1,0)、Y = (1,0,0)、Z = (0,0,−1)，反轉 X 之後 X 與 Z 反向。
- `npm run check` 全過（型別、分層、i18n 基準不增加、全部測試）。

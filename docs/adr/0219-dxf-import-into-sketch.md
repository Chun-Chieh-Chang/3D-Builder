# ADR 0219：匯入 DXF 到草圖（F2.6）

- 狀態：**已實作並驗證（2026-10-29）**：程式產生與手寫的 DXF、真實求解器與核心、瀏覽器，以及其他 CAD 存出的 67 個公開 DXF（R12 到 2018；AutoCAD 格式、LibreCAD、QCAD）都驗過，其中 11 個納入版本庫做固定測試（見「外部檔案」）。
- 來源：藍圖 F2.6「DXF/DWG 輸入為草圖」（P2）。使用者在討論 DXF 輸出時問「用本系統開啟呢」，當時程式只會輸出 DXF。範圍由使用者在四個選項中選定：匯入到草圖；只合併端點；文字轉草圖文字、尺寸略過；匯入前選圖層。
- 零件 Schema 不變：匯入的是既有的草圖圖元（點、直線、圓、圓弧、橢圓、貝茲樣條、文字），由一個 `addSketchItems` 指令加入。

## 決定與做法

1. **讀取**沿用 `readDxf`（新增記錄每個圖塊的基準點 `blockBases`；略過 999 註解與用不到的區段，見「外部檔案」），檔案結構錯誤（行數奇數、沒有 EOF、群組碼不是數字、區段沒有 ENDSEC）整個拒絕。位元組先解碼：UTF-8（2007 以後），不是合法 UTF-8 時依 `$DWGCODEPAGE`（ANSI_950 → Big5 等）；二進位 DXF 以文字拒絕。
2. **展開**（`packages/drawing/src/dxfImport.ts`）：只讀模型空間（群組 67 = 1 的圖紙空間略過）。INSERT 依「基準點移到原點 → 縮放 → 旋轉 → 移到插入點，再加陣列格的偏移（沿旋轉後的軸）」展開，可巢狀；圖塊內在圖層 0 的圖元取 INSERT 的圖層（DXF 的規則）。OCS 圖元（CIRCLE、ARC、LWPOLYLINE、POLYLINE、TEXT、INSERT）的擠出方向為 (0,0,−1) 時 x 鏡射；其他不在 XY 平面的方向不匯入並說明。
3. **單位**：`$INSUNITS` 換算成 mm（in 25.4、cm 10、m 1000 等）；沒有標單位時以 mm 匯入，對話框與通知都提醒用範圍確認。
4. **曲線的內部形式**：直線；「c + u·cos t + v·sin t」的二次曲線（圓、圓弧、橢圓、凸度弧，經任何仿射變換仍是精確的同一形式）；NURBS。變換後：
   - u、v 等長且垂直 → 圓或圓弧（u × v < 0 表示被鏡射，起訖對調，草圖的圓弧一律逆時針）。整圈的 ARC 視為圓。
   - 否則完整的 → 橢圓（由 t = ½·atan2(2u·v, u·u − v·v) 求主軸）；部分的 → 三次貝茲近似。
   - 非有理 NURBS → 以 Boehm 插入節點到重數 p，拆成每段 p+1 個控制點的貝茲段，**精確**；有理的、或端點兩控制點重合（求解器要求端點切線存在）的段 → 近似。
   - 近似：端點與端點導數決定的三次貝茲，取 31 個內點量偏差，超過 `DXF_APPROXIMATION = 0.001 mm` 就二分（最多 14 層），做不到就說明不匯入。實際最大偏差寫在通知裡。
   - 只有擬合點、沒有控制點的樣條不匯入：它的形狀是原 CAD 自己的擬合，不能宣稱重現。
5. **轉成草圖**：端點在 `mergeTolerance`（預設圖面範圍的百萬分之一，至少 1e-9 mm）內的共用同一個點；**不加任何關係**，草圖保持未完全定義。圓心、橢圓的主軸點、貝茲內部控制點不合併。首尾合併成同一點的貝茲段以 de Casteljau 分成兩半（草圖的貝茲兩端必須不同）。
6. **文字**：TEXT 的 `%%c %%d %%p %%%` 轉成 Ø ° ± %；72／73 對齊（置中、靠右、中間、頂端）轉成草圖文字的對齊與基線；MTEXT 去掉格式碼，`\P` 分成多個文字，依附著點 71 放置，行距 5/3 字高。字高、方向跟著圖塊的變換。
7. **限制數量**：展開時拜訪的圖元與陣列格超過 `DXF_MAX_WORK = 200000`、或所選圖層的曲線超過 `DXF_MAX_CURVES = 5000`，整個檔案不匯入並說明數字；自我引用或巢狀超過 16 層的圖塊不展開並說明。
8. **不默默修改**（AGENTS §2.1）：非有限數值、半徑或字高 ≤ 0、長度 0、短長軸比不在 (0,1]、陣列行列不是正整數、節點與控制點數不合的圖元，不匯入，**逐一**記下「圖元種類與 handle、圖層、原因」；DIMENSION、HATCH、SOLID 等種類計數後略過。
9. **介面**：草圖的指令「匯入 DXF…」（`sketch-dxf`）→ 選檔 → 對話框列出單位、範圍、每個圖層會匯入的曲線與文字數（勾選要匯入的、可設為構造線）、略過的種類與有問題的數量 → 「匯入」以一個 `addSketchItems` 加入（一次復原），通知寫出匯入了什麼、近似幾條與最大偏差、略過的種類、第一個問題與總數。說明主題 `sketch-dxf`。

## 紅隊四問

1. **輸入破壞**：非數字、`1e400`、空字串、負半徑、0 半徑、0 長度、比值 > 1、非整數陣列、截斷檔、二進位檔、自我引用圖塊、百萬格陣列——全部有測試，皆以文字拒絕或略過，沒有一個被改成「合理」的值。容差非正或非有限直接拋錯。
2. **幾何相交**：匯入不做布林；輪廓自交與否交給既有的輪廓檢查（伸長時報錯），不在匯入時默默修改。近似的貝茲段有偏差上限，二分到上限仍做不到就拒絕。
3. **依賴鏈**：讀取（`readDxf`）→ 展開與轉換（`dxfImport.ts`）→ 指令（既有 `addSketchItems`，`sketchError` 檢查）→ 求解（PlaneGCS，貝茲端點切線檢查）→ 輪廓與核心（伸長）全鏈路以真實元件測試；介面 `actions.ts` → `store.importSketchDxf/readDxfData/applyDxfImport` → `DxfImportDialog`；說明字典與 `help-links.json`（`_untied`，手冊尚無此項）同步。
4. **真值**：測試的 DXF 依 DXF 參考手寫，期望值手算（凸度 ±1 的半圓中點、−Z 擠出的鏡射、圖塊旋轉陣列後的座標）；樣條以獨立寫的 Cox–de Boor 為真值；有理二次樣條（權重 √2/2）是精確的四分之一圓，用半徑量近似偏差；部分橢圓以黃金分割求最近點量偏差。實體體積對照手算面積（凸度半圓、圓孔、橢圓孔，相對 1e-9）與由 B 樣條本身以三點 Gauss 精確積分的面積（相對 1e-7）。

## 驗證

- `tests/phase5/dxf-import.test.ts`（24 項）：999 註解在檔頭與圖元中、`ACDSDATA` 形式的區段被略過、該區段沒有 ENDSEC 仍拒絕；單位（無、mm、in、cm、m）；端點合併與不合併；凸度三種；−Z 擠出與傾斜擠出；完整與部分橢圓；非有理樣條的貝茲段在節點與段中點與 Cox–de Boor 相差 ≤ 1e-9；有理四分之一圓近似偏差 > 0 且 ≤ 0.001；只有擬合點與節點不合的樣條；圖塊的縮放旋轉陣列、圖層 0 繼承、鏡射、不等比例縮放、自我引用與不存在的圖塊、超量陣列；TEXT／MTEXT；略過的種類、圖紙空間、構造線圖層、只匯入所選圖層；二進位、截斷、錯誤群組碼；逐一說明的問題；曲線上限；UTF-8 與 Big5；本程式輸出的展開圖 DXF（線、弧、圓、折彎線到 1e-6 mm，外形每個端點恰被兩條曲線共用）與工程圖 DXF（每段聚合線到 1e-6 mm，DIMENSION 與 SOLID 數量正確）；**200 組隨機檔案**（含壞數值與巢狀圖塊），0 崩潰、結果全部通過 `sketchError`、近似偏差 ≤ 0.001、共產生 500 條以上的曲線。
- `tests/phase5/dxf-import-solid.test.ts`（3 項）：真實 PlaneGCS 求解、OCCT 伸長，體積如上；第 3 項為外部檔 `issue21`。
- `tests/phase5/dxf-import-external.test.ts`（8 項）：其他 CAD 存出的檔案，見「外部檔案」。
- 瀏覽器 `tests/e2e/phase3-sketch-dxf.js`：二進位檔被拒絕且通知說要另存 ASCII；英吋檔的對話框列出 CENTER 1、OUT 5、單位 in = 25.4 mm、範圍、DIMENSION ×1；把 CENTER 設為構造線後匯入：4 條線、1 段圓弧、1 個圓，換算成 mm，外形四個點各被兩條曲線共用，中心線是構造線；草圖可解；一次復原全部撤回、重做回來；確認後伸長 10 mm 重建成功。

## 外部檔案（2026-10-29，使用者同意下載）

- 來源：開源 DXF 解析器 [bjnortier/dxf](https://github.com/bjnortier/dxf)（MIT）commit `cb571d1` 的 `test/resources`，67 個 DXF：AC1009（R12）、AC1014、AC1015（2000）、AC1018（2004）、AC1021（2007）、AC1024、AC1027、AC1032（2018）；寫出者有 AutoCAD 格式（無註解、2013 以後含 `ACDSDATA`）、LibreCAD（`999 dxfrw`）、QCAD（`999 dxflib`）。
- **第一輪 67 個裡有 39 個整個被拒絕**，是讀取器的兩個錯，不是檔案的錯：
  1. LibreCAD／QCAD 的檔案以 `999` 註解開頭，讀取器要求第一組就是 `SECTION`。DXF 參考允許 999 註解出現在任何地方；改為切成群組時略過。
  2. AutoCAD 2013 以後寫的 `ACDSDATA` 區段一開頭是群組 70、71，不是以 0 開始的記錄，讀取器拒絕。讀取器只讀它用得到的區段（HEADER、CLASSES、TABLES、BLOCKS、ENTITIES、OBJECTS），其他區段改為略過到它的 ENDSEC；沒有 ENDSEC 仍拒絕。
  修正後 67 個中 66 個匯入；剩下的 `Ceco.NET-Architecture-Tm-53.dxf`（2000，7413 條曲線）超過 5000 條的上限，以文字拒絕並請使用者少選圖層——設計如此。所有匯入結果通過 `sketchError`，近似偏差全部 ≤ 0.001 mm。被逐一說明的問題只有三種，都核對過原始檔：長度為 0 的 LINE（起訖點的群組值完全相同）、多邊形網格的 POLYLINE。
- 真值（都不經匯入器）：
  - 寫出程式記錄的範圍 `$EXTMIN`／`$EXTMAX`。只用記錄得準的檔案：LibreCAD 有些檔寫 1e+20 之類的佔位值，有些寫鬆的範圍（`arc15` 的 y 最小值記成 0，但 50° 到 155° 的弧最低 y ≈ 34.5），這些不拿來比；AutoCAD 的範圍含尺寸與文字，有尺寸的檔不拿來比。
  - 依 DXF 參考，直接從圖元自己的群組值算出曲線：3 個 ARC 與 14 個 ELLIPSE 檔，兩個方向（我們的點到真曲線、真曲線到我們）都量。圓弧與「其實是圓」的橢圓 ≤ 1e-12 mm；真的部分橢圓 ≤ 0.001 mm。量測時「到真曲線的距離」第一版取 2 萬個取樣點中最近的一個，在 8 m 長的曲線上取樣間距約 1 mm，量到 0.45 mm——是量測錯，改以黃金分割求最近點後 ≤ 0.001，門檻不放寬。
  - 由原始頂點與凸度手算面積（多邊形面積加上每段凸度的帶號弓形面積）。
- 納入版本庫的 11 個（`tests/fixtures/public-dxf/bjnortier-dxf`，README 有來源、授權、SHA-256，`.gitattributes` 保留原本的換行）與它們檢查的事：
  - `tests/phase5/dxf-import-external.test.ts`（8 項）：雜湊與版本、寫出者；全部是合法草圖、近似在上限內、問題只有 `testModelPaperSpace` 的兩條長度 0 的線；`testModelPaperSpace`（2018）只匯入模型空間的線、圖紙空間的圓與視埠不進來；`alu-profile`（2018 實際型材圖）略過的 DIMENSION、HATCH 數與檔案相同；R12、2004 樣條、2007 圖塊與英吋陣列、2018 的範圍與記錄相差 ≤ 1e-9 倍尺寸；`arc15` ≤ 1e-9 mm；`elliptical-arc7` 的貝茲段首尾相接、距真橢圓 ≤ 0.001 mm、起訖點 ≤ 1e-9 mm；`elliptical-arc11` 是精確的圓弧。
  - `tests/phase5/dxf-import-solid.test.ts` 新增 `issue21`（LibreCAD）：矩形內兩個正負凸度混合的封閉聚合線，真實求解並伸長，體積與原始頂點、凸度手算的面積相對差 ≤ 1e-9。
  - 反向對照：把讀取器的兩個修正拿掉，以上 9 項中 8 項轉紅（雜湊與版本那項不經讀取器）。

## 限制

- 外部檔案只有一個來源（bjnortier/dxf 的測試檔），不是使用者自己的圖；AutoCAD 格式的檔案無法確認是哪一版 AutoCAD 或相容軟體寫的。超過 5000 條曲線的大圖要分圖層匯入。
- 不支援二進位 DXF、DWG。
- 不匯入 DIMENSION、HATCH、LEADER、圖塊屬性（ATTRIB）、3D 圖元；尺寸不轉成草圖尺寸。
- 部分橢圓、有理樣條、被不等比例縮放的圓弧是近似（≤ 0.001 mm）。
- 文字字型、寬度係數、傾斜角不匯入；MTEXT 的段落格式只保留文字與換行。
- 曲線超過 5000 條的檔案不匯入；大量曲線的草圖求解效能未最佳化。
- 只能在編輯草圖時匯入；尚未提供「沒有草圖時選平面、自動建立草圖」的入口。

# ADR 0144：組合件設計樹展開零件——零件自己的原點、基準面與特徵，拿來做結合

- 狀態：**已完成（2026-10-15）**。純介面與命令驗證；組合件、零件檔案格式都不變（不升 Schema）。
- 需求追溯：`docs/decisions-2026-10-14b.html` 的 A1（建議選項「頂層零件加 ▸：原點、三基準面、零件參考基準面、唯讀特徵清單」）與 A2（建議選項「座標系統列出、但不能拿來結合」）；使用者截圖回報「組合件3 的零件下沒有可展開的基準面，無法用零件的基準面做結合」。比照藍圖外新增功能的慣例以 ADR 追溯（同 ADR 0123、0124）。
- 相關：[ADR 0013](0013-mate-ui.md)（結合的介面、圖面左上的浮出樹）。

## 背景

查 handoff、決策頁與 git log：A1／A2 是 10-14 晚提出的選擇題，**沒有任何實作提交**——提案停在「等裁定範圍」與「先確認別的工作階段的 verify:ui 跑完」。

現況逐層檢查（設計樹 → 選取 → 結合面板 → 模型參考 → 求解）：

| 層 | 對「零件的基準面與原點」 |
|---|---|
| 求解（`packages/regen/src/assembly.ts` `mateGeometry`） | 已支援：零件的預設基準面在零件座標、參考基準面以特徵 id 找 `frames`，原點是 (0,0,0)；`tests/phase2/mates.test.ts` 有兩例平行 |
| 模型（`MateRef`、`checkMate`） | 參考可以表達；但**命令層不擋**零組件端點的 `kind: 'body'`、未知種類、`plane:back` 這類不存在的預設基準面——要等求解時才報、或被當成「找不到基準面」 |
| 結合面板 | 只能從圖面左上的浮出樹選（ADR 0013）；不能先在設計樹選好再按「結合」 |
| 設計樹 | **缺口**：只有次組合件有 ▸；零件列不能展開，看不到原點、基準面與特徵 |
| 圖面 | 選取的組合件基準面會畫出；零件的基準面只有在結合面板裡才畫；**原點被選時什麼都不畫** |

## 決定

1. **零件列可展開**（`AssemblyTree.tsx`）：沒有抑制、已經重建好的零件列有 ▸。展開後依 SolidWorks 的樣子列出：原點、前／上／右基準面，然後是零件的特徵（歷史順序）。
   - 零件的**參考基準面**（`refPlane` 且有建出來）是可選的基準面列，和預設基準面一樣。
   - 其他特徵（含座標系統，依 A2 建議）**唯讀**：點了不選取，提示「唯讀：要修改請開啟零件」；在零件中重建失敗的特徵標紅並說明，被抑制的變淡。
   - 展開狀態放在 `AssemblyState.opened`（不是元件自己的 state），所以結合面板佔用左欄、關掉之後展開的列還在。
2. **特徵清單由 Worker 給**（`PartBuildPayload.features`，`apps/web/src/worker/partOutline.ts` `partFeatures`）：組合件的主執行緒只有零件的重建結果、沒有零件文件，所以由 Worker 依文件順序列出每個特徵的 id、名稱、種類與狀態（成功／失敗／抑制，取自重建結果，不自己判斷）。鏡射件沒有自己的特徵，給空清單。
3. **在樹上選基準面**（`AssemblyState.picks`、`pickDatum`）：點一下只選它，Ctrl／Shift＋點選加選（已選的再點一下取消）。組合件自己的原點與三基準面也走同一條（原點以前點了沒反應，現在可選）。選取的基準面畫在圖面上（零組件的位置與方向），原點畫成亮點。Esc 清掉選取。
4. **先選再結合**（`startMate`）：按「結合」時，樹上選的前兩個依序帶進結合面板，等同在浮出樹點了它們——同一個零組件的第二個會被既有規則擋下並說明；兩個平面預設「重合」、對正方向照既有規則。
5. **命令層拒絕不合法的參考**（`packages/model/src/assembly.ts` `checkMate`）：結合元素只能是面、邊線、頂點、基準面（`body` 或其他種類拒絕）；以 `plane:` 開頭但不是前／上／右的名稱拒絕。參考基準面的特徵 id 是否存在仍由求解器判斷（命令層不讀零件檔，與既有分工相同）。新增 i18n `mate.badRefKind`、`mate.badDatum`。

## 不做的（限制）

- 次組合件**裡面**的零件不從主樹展開基準面（A1 的第二選項）；要用請在結合時的浮出樹選（已支援）。
- 座標系統只列出、不能拿來結合（A2 建議選項）。
- 圖面上畫出來的基準面不能再用滑鼠在圖面點選（在樹上點）；SolidWorks 的「檢視→基準面」那種顯示全部基準面也沒有做。
- 唯讀特徵沒有右鍵選單（要編輯請「開啟零件」）。

## 驗證

- 單元（`tests/phase2/component-datums.test.ts`，真 OCCT、黃金零件定位板與削邊銷；定位板固定在偏離原點且轉過的位置，銷從傾斜的位置開始，先斷言開始時都不成立）：
  - 重合（同向、反向）、平行、垂直、距離 25（反轉尺寸到另一側）、原點對原點、銷的「基準面1」（偏移右基準面 3）對定位板右基準面、銷的上基準面對組合件的上基準面、三面重合完全定義且銷與定位板重合：**全部以求解後的姿態把平面原點與法向轉出來量**，誤差 1e-6；自由度 3／4／5／0 與預期相符；存檔再讀逐位相同。
  - 命令層：`body`、未知種類、`plane:back`（零組件與組合件）、組合件的面、空名稱、不存在的零組件都拋 `CommandError`，`setMate` 同樣檢查，文件不變；原點、三基準面、參考基準面 id 可接受。
  - `partFeatures`：與零件文件的特徵逐項相同；把「基準面2」改成建在不存在的面上 → 失敗、「導角1」抑制 → 抑制，且與重建結果逐項一致。
  - 反向對照：拿掉命令層兩道新檢查，「拒絕」測試即失敗。
- 瀏覽器（`tests/e2e/manual-asm-component-datums.js`）：零件列有 ▸、一開始收合；展開後銷的列＝原點、三基準面＋零件檔的特徵名（讀 OPFS 裡的零件檔對照）；參考基準面可選；點特徵列不選取；點定位板原點→圖面一個亮點在定位板的位置；Esc 清空；前／上／右各用「點銷的、Ctrl 點定位板的 → 結合」：兩列標示選取、圖面兩個平面、結合面板預填兩個元素並建議「重合」→ ✓；三個結合都成立、銷完全定義、狀態列「完全定義」、銷與定位板四個點的距離 < 1e-6；存檔重開姿態相同、三個結合都在樹上。反向對照：拿掉「預選帶入結合」，腳本在「結合面板預填」失敗。

# ADR 0239：STEP 特徵辨識與重建（F2.4）

日期：2026-11-06。狀態：已實作（核心、命令、屬性管理員入口、說明、瀏覽器腳本 `phase8-feature-recognition.js`）；使用者端手動試用未確認。設計見[特徵辨識方案](../design/feature-recognition/plan.md)。

## 背景

藍圖 F2.4「FeatureWorks 特徵辨識」原列 X（不做）。使用者 2026-11-06 決定要做，第一版範圍：伸長（凸台／除料）、孔（簡單、沉頭、錐坑）、圓角與倒角、旋轉。

## 決定

1. **不新增特徵種類、不升 Schema（仍為 91）**：辨識結果全部是既有特徵（草圖、伸長、旋轉、孔、圓角、倒角、參考點／軸／面）。檔案相容性不受影響。
2. **由外而內移除、反向重建**（`packages/regen/src/recognize`）：
   - `analyze.ts`：圓角（圓柱沿軸向直線、圓環沿同軸圓相切於兩個非圓角面；鏈狀圓角與角落補面一起移除）、倒角（比兩側支撐面都窄的平面條、凸的錐面倒角）→ `deleteFaces`；能一起移除就一起，否則逐一試、留下移除不掉的。孔（同軸凹圓柱／錐面＋垂直於軸的圓形平面，入口是垂直於軸的平面）→ `deleteFaces`。剩下的基體必須是共軸回轉體（半平面截面 → 旋轉）或沿單一方向的分層柱體（每層中間取截面 → 伸長）。
   - **其他方向的特徵**（2026-11-06 續，側面凸台／口袋）：沒有單一方向能解釋所有面時，取阻擋面最少的方向，把阻擋面與只被它們包住的面（凸台端面、口袋底）以 `deleteFaces` 拿掉得到主體（遞迴最多 3 層）；原件 − 主體的每一塊是凸台、主體 − 原件的每一塊是除料，各自依自己的方向做分層伸長（除料方向與凸台相同、`reverse` 依平面法向取反）。
   - 孔的修正（同日）：孔的「底面」平面必須每一圈都接著孔壁（凹的同軸圓柱／圓錐），所以凸台端面是入口而不是孔的一部分；入口面要朝外（法向與鑽孔方向相反）；貫穿孔的出口平面要朝前（法向與鑽孔方向相同），孔底朝上的盲孔（孔中有銷）因此不當貫穿孔。圓角的兩個支撐面若是平行平面（長槽的半圓端）不是圓角，留在輪廓裡。
   - **鑽尖錐底**（2026-11-06 續）：盲孔最後一段是收斂到軸上一點的凹圓錐（只有一圈邊，尖端由圓錐幾何算出），記為 `tip`（夾角）；孔深到肩部。重建為孔精靈的平底孔，再加一個旋轉除料（肩部到尖端的三角形，繞孔軸 360°）。孔精靈本身沒有鑽尖角，不升 Schema；若要讓孔精靈直接帶鑽尖角，需另立 ADR 並升版。
   - `loops.ts`：截面邊串成迴圈、共線直線與同圓圓弧合併、面積與巢狀深度，純 2D。
   - `reconstruct.ts`：產生特徵；圓角與倒角在重算後的模型上依還原尖角邊的幾何找邊、取持久名稱；倒角依「名稱排序較前的鄰面量第一距離」決定兩個距離。
   - 核心新增 `Kernel.sectionEdges`（實體與平面矩形的 common，回傳平面座標的直線／圓弧／圓）。
3. **全有或全無**：重建後與原件比體積、面積、對稱差（`Va + Vb − 2·V∩`），相對值都 ≤ `RECOGNIZE_TOLERANCE` = 1e-6 才回傳；同時要求所有新特徵及原本 ok 的特徵仍 ok。否則丟 `RecognizeError`，文件不動。面數只回報、不當條件（他牌 STEP 的分面方式可能不同）。
4. **草圖平面**：方向與預設平面法向一致 → 預設平面或其 `offset` 參考面；其他方向 → 兩個座標參考點 → 參考軸 → 垂直於軸的參考面。與重算引擎相同的 `planeFrame` 換算座標。
5. **產品入口**：設計樹右鍵輸入本體的「辨識特徵」（2026-11-06 續；只對未抑制、未在退回位置之後的輸入本體出現），或輸入本體的屬性管理員最下方「辨識特徵」按鈕 → `store.recognizeFeatures`（面板若正在編輯這個輸入本體，先依「確定」結束編輯、保留面板裡改過的值；正在編輯別的特徵則不動作） → Worker `recognizeFeatures`（**另建一個 Regenerator**，避免多次重算釋放畫面上零件的形狀）→ 回傳命令，以 `History.applyBatch` 一次套用、一次復原。等待期間文件若被改，結果不套用。
7. **MCP 工具 `recognize_features {feature}`**（2026-11-06 續）：`CadSession.recognize` 以獨立 Regenerator 算出命令，再交給既有的 `apply`（同一個交易、`broken` 檢查、`undo`，連線時經 app 的 gate 同步）。`RecognizeError` 轉成工具錯誤，零件不動。代理說明（`INSTRUCTIONS`）加第 7 點。代理取得輸入本體的途徑：`part_open` 含輸入本體的 .3dbx，或連線時 app 送來的零件。
6. **草圖完全定義**（2026-11-06 續）：圓與圓弧先加直徑／半徑；其餘依設計者的順序逐一試加候選（在原點則與原點重合 → 水平／垂直 → 每條直線長度 → 每點相對原點的 X／Y 距離，座標為 0 則改用與原點水平／垂直對齊），每加一個就求解，只保留讓自由度下降、又不多餘不衝突的。數值都等於草圖現有的值，所以幾何不動。求解器做不完時保持欠定義，絕不過定義。例：60×40 板的草圖為 4 個水平／垂直、長 60、寬 40、角點 X30 Y20；孔的草圖為 X5 Y3。`reconstructImported` 多一個選填的 `solver` 參數；Worker 傳入它的求解器。

## 不做（第一版）

自由曲面、拔模、變半徑圓角、薄殼、掃出／疊層、多實體、陣列與鏡射意圖、孔精靈以外的孔形（鑽尖從板底穿出的圓錐開口會拒絕）、錐面以外的孔入口倒角（入口錐面辨識為錐坑孔）。凹的平面倒角不辨識為倒角。

## 驗證

- `tests/phase8/feature-recognition.test.ts` **20/20**：以 kernel 原語自建實體 → STEP → 匯入 → 辨識 → 重建；測試自己對照原實體的體積、面積、對稱差（≤ 1e-6），並用全新 Regenerator（不帶 STEP 資料）重算。涵蓋方塊、分層、口袋、含圓弧 L 形、貫穿孔、兩個盲孔合為一個孔特徵、內含銷的盲孔（不當孔）、沉頭、錐坑、凸圓角、凹圓角＋不同半徑、不等距倒角、孔口倒角（＝錐坑）、凸台圓周倒角、階梯軸含錐、中空軸肩圓角、整件繞斜軸旋轉 30°；拒絕：自由曲面、兩個實體、斜切角（找不到伸長方向）。
- `tests/phase8/feature-recognition-fuzz.test.ts`：120 組隨機板（三種孔 × 隨機圓角 × 隨機不等距倒角），**120 重建、0 拒絕、0 崩潰、0 錯誤接受**，約 24 秒。Heap 以 `wasmMemory.buffer.byteLength` 量測（起點斷言 > 0）：128 → 661 MiB，約 4.4 MiB／次（布林與 Defeaturing，AGENTS §3.5），**不宣稱零洩漏**；產品側由 ADR 0126 的 Worker 高水位重啟處理。
- 突變（各自還原後重跑）：拿掉倒角窄條規則 → 轉紅；拿掉圓角「沿長度相切」規則 → 轉紅；倒角 flip 判斷忽略 → 轉紅；不產生孔並把容差放寬到 1 → 6 項轉紅。「盲孔底面檢查」改為任何底面都算 → 仍全綠；分析後確認多餘（孔內的銷形成第二個邊緣，已由貫穿分支拒絕），依 AGENTS §3.2 刪除。
- 全量測試（VM 逐檔分批，2026-11-06）：386 檔、4,561 項通過、25 項略過、0 失敗；詳見 DEV_LOG。`verify:ui` 未跑。

- 草圖完全定義後：`feature-recognition` 20/20 且每個草圖 `fully`、dof 0（測試斷言）；Fuzz 120 組全部重建、每個草圖 dof 0；瀏覽器腳本另斷言兩個草圖皆 `fully/0`，通過。

# 樣條截面：表示、積分與偏移隔離

日期：2026-11-05；基準 `343dbeb`。這是原生幾何探針，沒有新增產品命令、UI、Schema 或 ADR。原探針的三項拒絕保持原樣。

後續進展見[明示圓弧近似與包絡報告](bounded-offset.md)：已取得合成齒輪通過間隙／實體量測的候選；本檔保留第二階段的結果與限制，不將該候選概括為任意樣條偏移完成。

## 結論與採用邊界

體積偏差已縮到不經 STEP／截面的最小重現。可行的局部解法是將伸長結果以 `BRepBuilderAPI_NurbsConvert(shape, true)` **精確轉換表示**，再進行自適應積分；不是修改體積數字，也不是以折線重建幾何。原生 Green 邊界積分、解析控制組、有效實體及點分類提供交叉驗證。目前只在探針使用，未全域替換 `Kernel.massProps`。

截面應明確選擇 `Approximation(true)`，並在 `Build()` 前設定；這是 OCCT 的平滑近似，不能稱為精確保留來源曲線。需同時記錄來源誤差。它改善表示與面積，但**單獨使用不能修好積分或精確偏移**。

偏移尚無達到原訂精度的可交付方案。內建 `SetApprox(true)`／`ConvertFace` 可產生封閉線框，但量測超過原有 1e-5 mm 間隙門檻，必須拒絕。不能因為 `IsDone=true` 就採用，也不能默默降低精度。此階段不進入外圈／孔洞／多區域或介面開發。

## 可重現與真值

`npm test -- tests/phase6/section-spline-isolation.test.ts`；結果寫入 `out/section-clearance/spline-isolation.json`。原始拒絕案例仍由 `section-clearance-probe.test.ts` 重現。

- 最小模型：同一個面積 27 mm² 的梯形折線帽，分別表成「五控制點的一條一次 B-spline＋封底線」和「各段獨立直線」。曲線幾何本來就是折線，沒有把自由曲線降階；高度 3 mm 的解析體積為 81 mm³。前者暴露積分表示問題，後者為對照。
- Green 面積從 `BRepTools_WireExplorer` 的實際方向及 `BRepAdaptor_Curve.D1` 積分；按每個 B-spline 節點切段，一次段用精確端點叉積，平滑段用 Simpson 積分。獨立於 OCCT 面積／體積積分，並先以解析 27 mm² 與二次曲線驗證。不能在跨越 C0 節點時直接套單一積分區間。
- 24 齒來源實體及 STEP 往返先比對獨立解析面積。截面另比對 Green 與原生 `SurfaceProperties`；平滑路徑的原體與轉換體各驗有效、單一實體，並以含實體內／外點的 121 點分類比較，不能只看 `isValid`。密集一次截面在進入轉換前即拒絕，避免高成本的後續運算。
- 100 組固定種子二次 Bézier STEP：寬、曲高、厚度、截面高度隨機；獨立面積為寬×曲高÷3。全部要求 Green 面積與轉換後體積÷高度各小於 1e-6 mm² 誤差。此為小型樣條控制組，不冒充齒輪或間隙 fuzz。
- 偏移只接受唯一封閉外擴圈；每條實際輸出曲線取九個候選點，僅量測 ±π/24 的一齒角域到來源線框距離。這是離散反證探針，足以拒絕已超標結果，不是全域最大誤差證書。先前全齒量測逾三萬次距離，造成不必要的 Heap 成長；反證只需一個超標點，不須重複 24 份旋轉對稱的 extrema 運算。

## 分階段證據

| 階段 | 量測／判讀 |
|---|---|
| 五控制點最小模型 | 真值 81 mm³；一般積分 80.1954127573，自適應 81.3850327851（估計誤差約 2e-16），精確轉 NURBS 後 81.0000000000 |
| 齒輪來源／STEP | 體積÷5 約 443.8508235137 mm²，與解析來源吻合；不是 STEP 往返才出現偏差 |
| 預設截面 | 每條齒腹為 degree 1、814 poles、814 knots；截面本身已經是多段一次曲線，不是原來的 degree 17 Bézier |
| 平滑截面 | 齒腹變為 degree 7–8、多節點曲線；面積約 443.8508237686 mm²，與解析來源差約 2.55e-7 mm² |
| 平滑截面直接伸長 | 一般體積 1331.5655283796 mm³；eps=1e-9 為 1331.7866265192 mm³；自適應回報極小估計誤差仍不代表真值正確 |
| 同一伸長體精確轉 NURBS | 自適應體積 1331.5524713038 mm³；÷3 與原截面面積吻合，小於原 1e-6 mm² 門檻 |
| 內建圓弧／線段近似偏移 | gap 0.05、0.2 mm 的外擴結果須保留超標量測與拒絕；縮小角度不等於縮小距離容差 |

收斂後的一齒角域反證量到最大間隙誤差約 **8.20e-5 mm**（每個外擴結果 407–515 點），仍超過 1e-5 mm；先前全齒量測的最大值約 1.52e-4 mm，兩者取樣域不同，不能混稱同一最大值。100 組二次曲線最大面積誤差約 7.49e-8 mm²，體積÷高度誤差約 5.62e-8 mm²。

單獨完整執行本檔約 36.5 秒，6/6 通過，包含偏移預期拒絕。Heap 起點 128 MiB、終點 550.69 MiB，100 組二次曲線段由 382.38 MiB 到 550.69 MiB；不宣稱零洩漏。先前直接對密集一次截面做全體 NURBS 驗證並量測全部旋轉齒時，單檔約 88 秒、Heap 達 2544.31 MiB；這條高成本路徑不在建議流程內。最終數值以重跑 JSON 為準。

突變驗證：暫將 `converted()` 改成原形狀的副本，最小模型的體積誤差 0.3850327851 mm³ 立即使 1e-8 斷言轉紅，之後還原並重跑。這證明測試確實依賴表示轉換，沒有只量到退化的解析控制組。

## 根因與版本證據

本機 `libcascade 3.0.2` 的 provenance 指定 OCCT `b8f597c677811d1f9f4d8a97f5ae2825c0353a42`（V8_0_1），不是以其他 OCCT 版本的文件推斷：

1. [BRepAlgoAPI_Section 原始碼](https://github.com/Open-Cascade-SAS/OCCT/blob/b8f597c677811d1f9f4d8a97f5ae2825c0353a42/src/ModelingAlgorithms/TKBO/BRepAlgoAPI/BRepAlgoAPI_Section.cxx)：初始化 `myApprox=false`；本輪直接量到預設產生的一次曲線。
2. [BRepGProp_Face 原始碼](https://github.com/Open-Cascade-SAS/OCCT/blob/b8f597c677811d1f9f4d8a97f5ae2825c0353a42/src/ModelingAlgorithms/TKTopAlgo/BRepGProp/BRepGProp_Face.cxx)：積分階數、子區間與節點擷取對 BSplineSurface 有專門分支，SurfaceOfExtrusion 則走一般分支。結合不經截面的 C0 最小重現及精確表示轉換前後對照，將故障定位到此類曲面的積分表示路徑；未宣稱已修復 OCCT 的所有積分器。
3. [BRepAlgo::ConvertWire 原始碼](https://github.com/Open-Cascade-SAS/OCCT/blob/b8f597c677811d1f9f4d8a97f5ae2825c0353a42/src/ModelingAlgorithms/TKBool/BRepAlgo/BRepAlgo.cxx)：距離容差至少 0.0001 mm，角度參數不會取消此下限。這解釋為何縮小角度仍不能通過 0.00001 mm 間隙要求。

探索中的 Gauss–Kronrod（eps=1e-7）在原預設截面伸長得到約 1331.5575／1331.5526 mm³（span off/on），回報誤差約 1.40e-5／5.63e-6，未達要求，不採用。直接呼叫更小距離容差的 `Geom2dConvert_ApproxArcsSegments` 重建線框，遭遇空結果片段及 WASM `function signature mismatch`；未將此不穩定路徑放入驗收或產品。平滑截面直接精確偏移亦有長時間同步運算，被人工中止；不能在主 Worker 無防護重試。

## 後續解法與未解項目

1. 體積：保留精確 NURBS 轉換＋自適應積分作為已量測的局部解法。若要進產品，需限制在哪些表示上轉換、效能／Heap 量測、面名及顏色歷史對應；不能直接替換全 repo 的量測行為。
2. 間隙：要達現行精度，需可指定**距離誤差**且能驗證的曲線近似／偏移實作，或修正原生精確偏移。若採近似，須讓使用者明確選擇並顯示誤差；同時分開列「截面近似誤差」與「偏移近似誤差」，不能以縮小角度或提高取樣數冒充全域誤差界。
3. 一般外圈外擴、孔洞內縮、相撞／孔消失、自相交前置攔截、任意平面、持久參照與 UI 仍未完成。原三項預期拒絕不改成能力通過。
4. Heap 僅以 `wasmMemory.buffer.byteLength` 量測，先斷言起點 >0；共享同一 Heap 的階段數值不能作洩漏歸因。形狀持有歸零只驗專案的釋放責任，不宣稱零洩漏。

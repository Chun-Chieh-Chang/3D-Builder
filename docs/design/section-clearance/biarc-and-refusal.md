# 樣條間隙：偵測後拒絕、雙圓弧擬合與兩段式偏移

日期：2026-11-06；基準 `94a49c6`。研究階段，未接入產品命令或 UI，未新增 Schema、未占用 ADR。接續 [MakeOffset 違反間隙的原因](offset-violation-cause.md)。

## 結論

- **偵測後拒絕並標出位置**（`checkedOffset`）：
  - 違反時拋出 `OffsetClearanceError`，帶出每一處違反的最近點與距離。
  - 模數 3／0.3 mm 共 80 處，每個齒間左右兩個齒根凹角各一處，左右對稱。
  - 模數 1／0.8 mm 共 24 處，因為兩個凹角相距小於間隙，併成每個齒間一處。
  - 四個正常案例不會被拒絕。
  - 目前沒有產品入口，所以這只是研究用的輔助函式；產品化時接在偏移命令上。
- **雙圓弧（G1）擬合**（`sectionEnvelope` 的 `'biarc'` 模式）：
  - 同一條來源邊內，所有圓弧接點切線連續，實測最大折角 2.3e-8 rad。危險區間的接點從 292 個降到 0 個。
  - 模數 3／0.3 與模數 1／0.8 兩個違反案例都改為通過，而且逐邊證明的上限只比間隙多 1.9e-14 mm。
  - **但不能單獨取代三點圓弧**：模數 1 的間隙 ≤ 0.06 mm 時，`MakeOffset` 對雙圓弧形式直接算不出結果；三點圓弧在同樣的間隙都成功。
- **兩段式偏移**（`fallbackOffset`）：
  - 先用三點圓弧；被拒絕時才改用雙圓弧；兩種都不行就拒絕並帶出位置。
  - 六個案例都**不會交出違反間隙的結果**，而且每個交出的結果都通過逐邊間隙證明。

## 雙圓弧的做法

1. **切線**：每一小段 Bézier 取原曲線兩端的切線，以等切長雙圓弧連接兩端。相鄰小段共用原曲線在分割點的切線（de Casteljau 分割點的切線是精確的），所以不會像「逐段強制相切」那樣累積誤差；後者已在前一份報告中實測排除（0.71 mm）。
2. **誤差上限**：在雙圓弧接點對應的曲線參數 τ 把曲線切成兩半，各自對自己那段圓弧求上限。τ 用 33 點取樣後再做黃金分割求得。每一半取兩種上限中較小的那個：
   - **Bernstein 圓方程上限**：做法和三點圓弧相同，但要求那一半落在圓弧的角錐內。
   - **弦的路線**：該半到自己弦的控制凸包距離，加上弦到圓弧的弓高，再加上接點到曲線的距離。這條路線不受大半徑圓弧的 r² 捨入誤差影響。
   - 上限超過容差就二分。
3. **最短小段改直線**：長度短於 1e-4 mm、且弦在容差內的小段，直接用直線。
   - OCCT 的截面曲線在基圓處有一個極小的「勾」，例如最後一個控制點只離前一個 1.16e-7 mm。雙圓弧會照著它擬合，切出長 6e-6、半徑 3e-5 的微小圓弧；`MakeOffset` 處理這些微小圓弧也會出錯（6 處違反），小間隙時甚至直接算不出結果。
   - 改成直線之後，那裡會留下約 3.5e-4 至 6.5e-3 rad 的折角。合成幾何實測這個大小是安全的，但這是實測結果，不是證明。
4. **端點切線**：跳過離端點不到該段弦長 1e-3 的控制點，避免從近乎重合的控制點算出雜訊切線。
5. **接點改用原生邊的切線**：樣條和原生直線或圓弧相接、兩邊切線相差 < 1e-2 rad 時，樣條那一端改用原生邊的切線擬合。誤差上限仍對真實曲線計算，所以只會在接點附近多切幾段，不損精度。兩條樣條直接相接的接點不處理（測過的齒輪截面裡沒有）。

試過之後拿掉的：

- **接點共用切線、門檻 1e-3 rad**：當時拿掉它，突變測試沒有轉紅，就判定多餘而刪除。**這個結論錯了**：那次突變只涵蓋大間隙；真正需要它的是小間隙，而且 1e-3 的門檻管不到實際的 5.4e-3 折角。見下一節。
- **最短小段 3e-4、1e-3**：凹弧消失，但模數 1／0.05 仍然失敗，所以失敗原因不是凹弧。

## 小間隙算不出結果的原因

前一版記錄「模數 1 的間隙 ≤ 0.06 時，`MakeOffset` 對雙圓弧形式直接算不出結果」。逐步二分後定位：

- **位置**：把近似邊逐批換回三點圓弧，縮小到第 3 條來源邊（漸開線齒面，從齒頂 r = 13 到基圓 r = 11.2763），再縮小到它最後一小段 Bézier（長 6e-4 mm）。下一條邊是原生的徑向直線。
- **原因**：那個接點的折角。雙圓弧沿用樣條自己的端點切線，和直線差 −5.4e-3 rad，是**凹**折角；三點圓弧在同一處是 +2.8e-3 rad 的凸折角。三點圓弧形式所有樣條接直線的接點都是凸的（+0.003 至 +0.007）。
- **臨界掃描**：只改這一小段的端點切線，其他不動。

  | 接點折角（rad） | 算不出結果的間隙 |
  |---:|---|
  | −8e-3 | ≤ 0.02 |
  | −6.5e-3 | ≤ 0.04 |
  | −5.4e-3（實際） | ≤ 0.06 |
  | −4.5e-3、0、任何凸折角 | 無 |

  凹折角約 5e-3 以上才會失敗；出乎意料的是折角越大，失敗的間隙範圍反而越窄。這是實測，不是證明，原因沒有再往 OCCT 內部追。
- **對策**：上節第 5 點，接點改用原生邊的切線，折角變成 0。

改了之後單用雙圓弧：

| 模數／齒數 | 間隙 | 近似邊數 | 結果 |
|---|---|---:|---|
| 1／24 | 0.01、0.02、0.03、0.05、0.06、0.07、0.1、0.2、0.8 | 3,232 | 全部通過，最短距離 − 間隙 ≥ −4.3e-8 |
| 3／40 | 0.02、0.05、0.1、0.3 | 8,036 | 全部通過 |
| 0.5／18 | 0.01、0.05 | 2,120 | 全部通過 |

所有案例的誤差上限 ≤ 2e-6。兩段式偏移維持原順序（先三點圓弧、被拒絕才改雙圓弧），六個案例的結果不變；單用雙圓弧現在已經能處理所有測過的案例，產品要不要只用雙圓弧，留待接入產品時再定（雙圓弧近似約慢 3.5 倍，但省掉一次被拒絕的偏移）。

## 對抗驗證

- **`section-offset-refuse.test.ts`，7 項**：
  - 參數拒絕。
  - 兩個違反案例：拒絕的位置數量、全部落在齒根上方的禁止帶內、每個齒間都有、左右鏡像、第一處就是全域最近點。
  - 四個正常案例不被拒絕。
  - 突變：拿掉下限檢查 → 兩個違反案例轉紅；分群半徑改為 10 倍 → 轉紅。
- **`section-offset-biarc.test.ts`，18 項**：
  - 參數拒絕；單位四分之一圓精確擬合。
  - 100 組隨機有理 Bézier，在兩個方向和原生曲線比對：誤差上限成立，曲線到近似最大 1.0e-6、近似到曲線最大 6.9e-7；段內接點折角 < 1e-6 rad（實測最大 2.3e-8）。
  - 六個案例的兩段式偏移：都不交出違反；每個結果都通過逐邊證明；雙圓弧案例的危險折角為 0。
  - 模數 1／0.8 單用三點圓弧被拒絕、單用雙圓弧通過。
  - 八個小間隙案例單用雙圓弧（模數 1 的 0.01、0.02、0.05、0.06、0.2，模數 3 的 0.02、0.05，模數 0.5 的 0.01）全部通過。
  - 突變：拿掉「最短小段改直線」→ 模數 3／0.3 轉紅（回到 80 處），小間隙也轉紅。
  - 突變：接點門檻改回 1e-3、或整個拿掉 → 小間隙轉紅；原生邊在前、在後兩個方向各自改錯 → 各自轉紅。
  - 刪除兩段沒被任何測試觸發的分支（AGENTS §3.2）：兩條樣條相接時取平均切線（改成拋錯也全部通過）、最短小段遇到接點覆寫時不改直線（拿掉也全部通過）。
- **Heap**：只用 `wasmMemory.buffer.byteLength`，起點斷言 > 0，不宣稱洩漏結論；`liveShapes` 歸零。

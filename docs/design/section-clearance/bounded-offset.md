# 樣條間隙：明示圓弧近似與表示誤差包絡

日期：2026-11-05；基準 `2a1d707`。研究階段已取得能通過合成齒輪間隙／有效實體／體積檢查的候選路徑，沒有接入產品命令或 UI，沒有新增 Schema 或占用 ADR。原探針的拒絕案例保持原樣。

## 結論

採用**明示的圓弧／直線近似模式**，以正權重有理 Bézier 控制包絡及 Bernstein 隱式圓方程計算整段表示誤差上限；不能把它說成精確樣條偏移，也不能默默替換用戶曲線。

合成 24 齒 STEP 的平滑截面，2e-6 mm 表示容差產生 2,112 條近似邊，實際控制包絡最大 1.9689918039e-6 mm。0.05／0.2 mm 外擴都能建成有效的單一實體，體積÷3 與面積差 <1e-6 mm²；最短距離誤差 <1e-6 mm，原生曲線取樣間隙誤差 <1e-5 mm，沒有降低原門檻。

**已建立的是截面曲線到近似曲線的表示包絡。最終偏移的全域間隙上限尚未取得證書**；目前仍由原生最短距離及離散曲線探針驗證。多區域、孔洞、相撞、自相交、任意平面、持久參照與產品入口仍未完成。候選不應直接接進一般用途工具。

## 路徑與量測

1. 真實 OCCT 建齒輪 → STEP 輸出／輸入 → 水平平面截面。截面在 `Build()` 前明確 `Approximation(true)`，保留全部 144 條來源邊並接成唯一封閉圈。
2. 原生直線／圓弧保留；B-spline 依實際參數範圍精確拆為 Bézier 段，讀出原生控制點與權重。負／零／非有限權重明確拒絕，不降階或取絕對值。
3. 優先以控制凸包證明可用直線表示；否則用端點／中點構造候選圓，檢查整個控制凸包位於小於 90° 的同一角錐內，並以 Bernstein 圓方程計算徑向誤差界。不合格就做有理 de Casteljau 細分；深度或邊數預算超限明確拒絕。
4. 明確建立原生直線／圓弧線框。低於 OCCT 1e-7 mm 解析尺度的段直接拒絕，不能逐段略過後假設累積位移仍受控。原生 MakeWire／MakeFace 各階段均檢查成功及封閉。
5. `BRepOffsetAPI_MakeOffset` 以圓弧接角外擴，再 `MakePrism` 伸長 3 mm。必須唯一封閉線框、有效單一實體；體積與面積、最短距離及點到來源線框的距離全部獨立量測。

## 表示誤差界的推導與限制

正權重有理 Bézier 位於歐氏控制點的凸包中。到線段的距離是凸函數，因此各控制點到端點弦的最大距離，包住整段曲線到該弦的距離。曲線連續且連接弦的兩端，亦得到弦到曲線的同一距離界。

圓弧候選則使用齊次座標 `(X(t),Y(t),W(t))`，圓心 `(cx,cy)`、半徑 `r`。將

`F(t) = (X-cx W)² + (Y-cy W)² - r² W²`

精確寫成 2n 次 Bernstein 多項式；乘積係數使用 `C(n,i) C(n,j) / C(2n,i+j)`。Bernstein 凸包性給出 `|F(t)| ≤ max|係數|`，正權重給 `W(t) ≥ minWeight`。由 `|ρ-r| = |F| / (W²(ρ+r))` 且 `ρ+r ≥ r`，得到保守徑向界 `max|係數| / (minWeight² r)`，另加浮點運算餘量。控制凸包的角錐條件和端點連續性提供反方向的弧到曲線界。

這是浮點計算的幾何包絡，不是形式化的區間算術證明。原生圓弧建構與接線另預留 2e-7 mm 的解析尺度預算；JSON 的 `maxBound` 是控制包絡，`representationErrorBound` 是兩者相加。這筆預算不能取代對 OCCT 實際結果的量測，也不代表任意模型的最終間隙證書。

目前圓弧包絡只接受 XY 平面、正權重、有限尺度及至多 26 次曲線；非平面、非法容差、非法權重、未支援的曲線種類及細分預算超限均明確拒絕。沒有解決自相交或小於容差的局部特徵消失，必須先建立這些防禦才能產品化。

## 被量測淘汰的路徑

- 直接呼叫原生 `Geom2dConvert_ApproxArcsSegments`，經共享頂點重建後，錯誤可定位到長 7.669e-8 mm 的原生微段；先前的 WASM signature mismatch 不能概括成「所有回傳物件所有權都壞了」。檢查每個 MakeEdge 的 `IsDone` 後取得明確的 `DifferentPointsOnClosedCurve`。這輪修正前一報告對該探索路徑過於籠統的歸因。
- 用 2e-6 mm 原生近似容差，gap 0.05 可通過，但 gap 0.2 的取樣誤差為 1.0284386848e-5 mm，超過原 1e-5；改其他容差仍可能 `IsDone=false`。不能把「這組過了」當成可靠演算法，未採用。
- 具控制凸包界的明示折線近似，兩種間隙取樣誤差約 1.7423e-6 mm，確實通過，但有 16,256 條邊，單案例 Heap 到約 793 MiB，追加實體檢查耗時過長而人工中止。沒有延長測試期限。改圓弧包絡後為 2,112 條邊，含最短距離的兩案例整檔約 21.4 秒，Heap 各由 128 到約 184.4 MiB；不同案例各自 Kernel，不混用 Heap 做成長歸因。

## 可重現與對抗驗證

`npm test -- tests/phase6/section-offset-distance.test.ts tests/phase6/section-offset-envelope.test.ts --maxWorkers 1`

- `section-offset-envelope.ts` 是研究用純演算法／原生建線輔助，不是產品 API。
- 100 組正權重有理 Bézier 圓弧包絡：實際 OCCT 曲線點到候選、候選原生圓弧／線段點到原生來源曲線皆通過。最大取樣誤差約 1.495e-6／1.398e-6 mm，最大控制包絡 1.998e-6；最大 165 段，總計 9,333 段圓弧，確實觸發圓弧分支。另有 100 組折線包絡與獨立解析單位四分之一圓對照；這些不是一般 STEP 偏移 fuzz。
- 突變一：把整條曲線硬換成直線並假報零誤差，原生曲線第一組即量到 0.0052479 mm，斷言轉紅。
- 突變二：把實際偏移乘二，完整線框的最短距離誤差約 0.05 mm，原 1e-6 門檻轉紅。
- 兩項皆還原後重跑。所有暫存物件進 Arena；專案 shape 持有歸零只驗釋放責任。Heap 唯一路徑為 `wasmMemory.buffer.byteLength`，先斷言起點 >0，沒有零洩漏宣稱。100 組曲線測試的 Heap 未成長亦可能是餘裕吸收，不能據此宣稱無洩漏。

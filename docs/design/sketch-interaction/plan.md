## 結論與比較方式

本專案已具備相當完整的平面草圖求解與基本工具，優先問題是操作鏈不連續：精確輸入多在畫完後、選取只給單一命中、部分修改工具沒有結果預覽、輪廓選取仍以清單為主。建議依 **選取與工具狀態 → 繪製時輸入 → 修改預覽 → 區域選取 → 診斷與關係呈現 → 高階曲線** 改進。不要先換整套圖示或重寫求解器。

證據分級：**已核實**表示讀過現行原始碼／既有驗收紀錄；**待複核**表示產品常見操作基準，這輪沒有實機或可讀的官方文件；**待量測**表示有架構風險，不能當作已重現故障。這輪沒有操作三套 CAD 的桌面程式，也沒有重跑本專案 UI；外部倉庫測試是讀取實作證據，未在此執行，不代表本輪測試通過。

- SolidWorks：既有 [吸附研究](../../sketch-snapping-plan.md)保存官方推斷／抓取／快速抓取摘錄。本次官方2025說明連線403；直接輸入、Select Other、Power Trim、Selected Contours 等列為待實機複核的設計基準，不能冒稱已驗證版本／快捷鍵／全部曲線適用範圍。
- FreeCAD：讀取官方源碼 `6135077d5c2d7c93850db34f23cb0e70f015b747`，屬當時開發版本，不概括所有穩定版。核實畫布內參數、Tab切欄、Polyline模式切換、拘束／自由度訊息及B-spline工具。
- SolidCraft：使用使用者指定的 tangency-labs/solidcraft，源碼 `79214b6b49aed1b1809aca8612fdac9cfba02bf2`。核實輸入尺寸、草圖面板、拖曳修剪、參照槽與預覽、區域命中。與先前採用圖示時的版本未必相同；ROADMAP仍將草圖部分列為進行中，不視為全面成熟度標準。

## 互動規格與SSOT

1. 既有 `SketchFeature`／constraints與文件命令仍為真值；顯示欄位不得另存一份脫離模型的尺寸。建立時輸入必須產生模型拘束，草稿值只在控制器暫存。
2. 抽出一致工具階段：待選第一參照、待選下一參照、結果預覽、提交／取消。草圖層Esc保留現有「先退本步／鏈，再退工具」習慣；輸入框先攔截按鍵，IME組字不得觸發提交。
3. 數值優先序：明確鎖定值不可被吸附改寫。若鎖值與重合／推斷衝突，要提示可選的解除項，不偷偷捨棄已輸入尺寸。新段清除前一段暫存鎖值，已建立的尺寸保留。
4. 操作預覽與正式提交共用同一操作計畫；幾何求解結果附文件revision，過期回覆不可覆蓋新游標／新文件。預覽不產生Undo；確認一次提交、取消零變更。
5. 持久參照先保留既有ID與資料流；分割／裁剪造成一對多時需明訂繼承。新增持久資料才做Schema migration，單純互動狀態不升Schema。
6. 主工具保留圖示與名稱；草圖側欄把目前工具和選取資訊放前面，進階檢查折疊。保留滑鼠／鍵盤操作與中文說明，不因仿SolidCraft刪除文字。

- T09：數值輸入0、負半徑、NaN／Infinity、非法式、mm/in、中文IME、焦點離開與Enter／Tab／Esc，均有明確定義。
- T10：100／1000圖元指標移動，量選取＋吸附CPU p95及求解回覆延遲；暫定前者≤8ms為設計目標，P0固定硬體並公布基準，未達標先profile，不任意放寬門檻。

每批只跑新增／受影響案例；失敗只重跑相應案例，遵守使用者既有要求。參數化核心新增分支依AGENTS做100–200組原生幾何／求解組態，不用假solver；若涉及WASM記憶體，只用真實heap且先驗基準>0，不以物件數或少量操作宣稱零洩漏。型別、建置、文件與相關靜態守門依變更範圍執行。Windows/macOS/Web鍵盤與DPR驗收分開記錄，雲端通過不能代替桌面實測。

## 審核與交付門檻

**方案審核（已通過）**：確認P0–P4順序、G01輸入必須保留為驅動尺寸、G03選取消歧、既有延伸語意及以上驗收標準。審核未通過不開始開發；對部分項目通過則只執行核准範圍。P5維持候選，不因本計畫存在就自動開工。

**每階段開發驗收包**由開發者提供：

1. 案例編號→需求ID→變更程式→測試結果的對照表，狀態只有通過／失敗／未驗／不適用；後兩者說明原因。
2. 相同公開模型的修正前後截圖與短操作錄影，展示游標選點、輸入、取消與一次復原；不能只交最後成品圖。
3. 原生求解／幾何數值、模型拘束與存讀證據；UI成功不能替代幾何正確。
4. 相關回歸及既有失敗清單；不以全套重跑取代問題分析，也不能挑掉新失敗。若跨平台未驗，單獨列為待驗收。
5. 已知限制、操作說明、回退方式與DEV_LOG／handoff同步；沒有審核結果不得把計畫改為已交付。

**阻擋交付**：任何錯誤尺寸／錯參照、無聲幾何變更、取消仍修改文件、Undo無法完整復原、存讀遺失拘束、可重現崩潰，均不得通過。宣告支援的任務必須全部通過；純視覺缺點只有在記錄影響並經接受後才能留待下一階段。門檻或功能範圍若需改動，先更新方案取得同意，不在測試失敗後自行降低標準。

# 螺牙（真實螺紋實體）：計畫與驗證方案

- 狀態：**使用者 2026-10-10 確認 §9 三點（照建議）；T-1 核心已完成並已提交推送（`7f6c1ec`），下一步 T-2**。T-0 小驗證見 `spikes/occt-gaps/thread.mjs` 與 `spikes/occt-gaps/README.md`。T-1 與計畫的差異：螺旋每圈一條邊（面名多了圈號 `@helix<線>:<圈>`），掃出公差收緊為 1e-6；細節與根因見 `handoff.md` 最上方。
- 要的功能：能建出真的螺牙實體（可 3D 列印、輸出 STEP、做工程圖剖面），參數要夠彈性，不是只能畫一個零件。第一個驗收對象是 ISO 80369-7 的參考件（兩個零件：中間有中心孔的錐形體；外面有內螺紋的鎖緊環，右旋、雙線、自訂牙型）。
- 範圍外（日後另列）：螺旋曲線特徵本身（藍圖 C8.3，彈簧、渦捲線）、標準牙型庫（ISO 公制等）、外觀螺紋（只畫、不建幾何）、螺牙與異型孔 `tapped` 的連動。

## 1. 第一原理：螺牙是什麼

螺牙 = 一個**牙型**（軸向平面上的封閉輪廓）做**螺旋運動**（繞軸轉 θ，同時沿軸走 lead·θ/2π）所掃過的實體。由此導出幾個結論，也是 T-0 驗證過的事：

1. **圓柱螺紋與螺旋的半徑無關。** 牙型被剛體地繞軸轉動並平移，所以掃出路徑（螺旋）畫在哪個半徑都一樣，只要大於 0。半徑只在**錐形**時有意義：它決定牙型隨軸向位置往外漂多少（錐度）。
2. **導程 = 線數 × 螺距。** 使用者給螺距與線數，導程是算出來的（雙線、螺距 2.5 → 導程 5）。多線 = 同一個掃出繞軸轉 360°/N。
3. **長度靠修剪，不靠螺旋的終點。** 掃出比需要的長，再與一個圓柱取交集，牙就剛好切齊在起訖面上。這比處理螺旋兩端的收尾穩定。
4. **體積有解析式可對。** 螺旋掃出的每單位軸向長度的體積 = 牙型面積 × 2π × 重心半徑 / 導程（Guldin）；錐形再加上隨軸向變化的重心半徑。這是最強的自動驗收：不用目視，不用外部軟體。
5. **牙的相位要有定義。** 約定：牙在起始面、起始角的位置開始（T-0 的案例 E、F 驗過，沒有這個約定，部分長度與起始角的結果無法預測）。
6. **公差不屬於幾何。** 建模取名義尺寸；公差只存在工程圖的標註（現有資料結構已支援對稱、單向、不對稱：`DimensionTolerance` 的 `upper`、`lower` 各自帶正負號）。

## 3. 資料模型（零件 Schema 52 → 53，空轉遷移）

新特徵 `thread`（螺牙）。沿用掃出的做法：牙型是一張草圖，結果是工具體，再用現有的 `apply` 與本體做 boss／cut，命名與合併行為與掃出、伸長一致。

```ts
interface ThreadFeature extends FeatureBase {
  type: 'thread';
  /** 牙型草圖：封閉輪廓，所在平面必須包含螺紋的軸。輪廓畫在哪裡，牙就在哪裡開始。 */
  sketch: Id;
  /** 軸：直線邊、基準軸，或圓柱／圓錐面的軸（沿用基準軸的 Ref 解析）。 */
  axis: Ref;
  op: 'boss' | 'cut';
  merge?: boolean;                 // 同 ExtrudeFeature.merge
  contours?: Id[][];               // 同 ExtrudeFeature.contours
  pitch: Expr;                     // 螺距（長度）
  starts: Expr;                    // 線數（整數 ≥ 1）
  hand: 'right' | 'left';
  /** 長度：從牙型所在的垂直面起，沿軸（reverse 反向）走 length，或貫穿全部。 */
  end: { type: 'blind'; length: Expr } | { type: 'throughAll' };
  reverse?: boolean;
  /** 錐度：半角（度），0 或缺省為圓柱；正值往軸的走向變粗。 */
  taper?: Expr;
  /** 起始角偏移（度），缺省 0。 */
  phase?: Expr;
}
```

- 為什麼不把牙型寫成「ISO 牙型庫」：使用者要自訂牙型（非對稱角度、圓弧牙根）；牙型庫以後可以是「幫你畫好一張牙型草圖」的精靈，不影響特徵本身。
- 為什麼軸要用 `Ref`：這樣內螺紋可直接選孔的圓柱面，外螺紋選圓柱面，不必另外畫軸；重新生成時跟著模型走（沿用基準軸的解析）。
- `starts` 與 `taper` 用 `Expr`，可以接全域變數與方程式。
- 修改的地方（掃出特徵有的地方，螺牙都要有）：`schema.ts`、`commands.ts`（建立、修改、`onlyBossMerges` 等的白名單）、`params.ts`、`refs.ts`、`visibility.ts`（牙型草圖用過就隱藏）、`patterns.ts`（可當複製排列的種子）、`serialize.ts` 的遷移、`regen/dag.ts`、`regen/engine.ts`。

## 4. 核心（`@3db/kernel`）

新方法 `Kernel.threadTool(spec)`，回傳 `OpResult`（形狀與 `faceOrigins`）：

1. 取牙型區域，求出軸上的起點（牙型重心投影到軸）。
2. 螺旋：在圓柱或圓錐面上畫 2D 直線，補出 3D 曲線（T-0 驗過的 `Geom2d_Line` ＋ `BRepBuilderAPI_MakeEdge` ＋ `BRepLib.BuildCurves3d`）；螺旋半徑取牙型最靠近軸的點與軸的距離（必須 > 0）。
3. `BRepOffsetAPI_MakePipeShell`，`SetMode(gp_Dir)` 固定軸向副法線；方向反了（體積為負）要翻回來。
4. 多線：轉 360°/N 各一份；起始角偏移：整體再轉 `phase`。
5. 與外框圓柱 Common 修剪成 `[起點, 起點 + length]`；貫穿則延伸到本體在軸向的範圍外。
6. 命名：側面 `<特徵>:thread:<牙型邊>`，多線在後面加 `.<第幾線>`；兩端是 `cap`；沿用 `FaceOrigin` 的 `profileEdge` 與 `cap`。
7. 失敗要說原因，不只回「失敗」：軸與牙型不共面、牙型碰到軸（半徑 ≤ 0）、牙型的軸向寬度大於導程／線數（相鄰的牙重疊）、螺旋圈數太多、布林失敗、結果無效。

## 6. 階段與量化驗收

每個階段做完都跑 `npm run check`（全過）；T-3 起加跑 `npm run verify:ui`。

### T-1 核心：`Kernel.threadTool`（先寫測試）
測試檔 `tests/phase3/thread.test.ts`，把 T-0 的 6 個案例搬進來並加強：
- 圓柱／圓錐、單線／雙線／三線、右旋／左旋、起始角（用 60° 這種**不會因對稱而分不出正負號**的值）、部分長度、非對稱牙型。
- 驗收：結果有效（`BRepCheck`，不靠修復）；體積對解析式誤差 ≤ 0.5%（圓柱預期 ≤ 0.01%）；牙側位置用實體分類器探測在 0.003 mm 內；STEP 往返體積差 < 1e-6；網格 ≤ 20 萬個三角形；單一布林 ≤ 5 秒。
- 反向測試（必做）：故意把旋向、起始角符號、線數寫錯，對應的測試必須失敗。
- 錯誤路徑：每一種失敗各一個測試，確認訊息有原因。

### T-4 參考件（ISO 80369-7）與工程圖
- 兩個零件各自建模；用圖上的尺寸與方程式驅動。
- 數值驗收（自動，不靠目視）：
  - 錐形體：兩端直徑 Ø4.021、Ø4.315（名義值），高 7.5，錐度與圖相符；
  - 鎖緊環：通過軸線的截面上，量到小徑 Ø7.2、大徑 Ø8、相鄰牙側的軸向間距 = 螺距 2.5、導程 5.0、兩條牙相差 180°、牙側角 30°（誤差各 ≤ 0.005 mm 或 0.1°）；入口倒角與牙尾階梯面存在且布林有效；
  - 兩者都是有效實體，體積為正；STEP 往返誤差 < 1e-6。
- 工程圖：兩個零件的剖面視圖看得到牙；用現有的尺寸工具標 Ø8、Ø7.2、Ø4.021、Ø4.315、30°、7.5 等，**公差各自獨立**：對稱（±0.025）、單向（0 / −0.005）、不對稱（+0.001 / −0.004）都要能標出且輸出到 DXF／PDF 正確；若某種標法目前做不到，記為缺陷並修。
- 目視（使用者與我各一半）：用 eDrawings（使用者有）開輸出的 STEP；用 3D 視窗看牙；工程圖看剖面。
- 3D 列印：匯出 STL（`packages/io` 已有 STL）；驗收：網格是封閉的（每條邊剛好被兩個三角形共用）、體積為正、體積與實體差 ≤ 1%。

## 7. 各階段的模型選用建議

這是依各階段**可能出錯的方式**做的判斷，不是量測過的結果；實際用量與品質請以第一個階段的表現校正。

| 階段 | 難度與風險 | 建議模型 | 理由 |
|---|---|---|---|
| T-1 核心 | 最高：OCCT 的幾何與布林、數值驗收、判斷「測試失敗是核心的問題還是測試寫錯」 | **Opus 5.5**；若連續兩次無法收斂，換 **Fable 5.1** | T-0 就出現過兩次測試本身的錯（起點錨、對稱性）；這種判斷最需要嚴謹。 |
| T-2 特徵與再生 | 中高：跨很多檔案的一致性（Schema、指令、再生、命名、參考解析），錯一處會在別處爆 | **Opus 5.5**（命名與參考解析）；機械性的接線可用 **Sonnet 5.5** | 命名與遺失參考是已知難點；其餘照掃出特徵的樣子接。 |
| T-3 介面 | 中：面板、指令、說明、i18n，有現成樣板可抄 | **Sonnet 5.5** | 有明確樣板與測試擋著（說明測試、verify:ui）。 |
| T-4 參考件與工程圖 | 中：用既有功能建模與標註，真正難的是發現缺陷後的修正 | **Sonnet 5.5** 建模與驗證；發現工程圖或標註缺陷時換 **Opus 5.5** | 建模是操作；缺陷修正才需要深入推理。 |
| T-5 鞏固 | 高：效能、隨機測試找到的怪案例 | **Opus 5.5** | 要從失敗的幾何推出根因。 |
| 文件、i18n 字串、手冊、`handoff.md` | 低 | **Haiku 5.5** 或 **Sonnet 5.5** | 以現有文字為樣板。 |

使用原則：**驗收標準與測試先寫，並由較強的模型做最後的審查**；較弱的模型寫出來的程式，一律靠測試與審查把關，不靠它自己說「做完了」。

## 8. 風險與退路

| 風險 | 影響 | 對策 |
|---|---|---|
| 螺牙與倒角／圓角的布林（螺紋入口倒角、牙尾收在階梯面） | 圖上的鎖緊環就有這兩項 | T-2 就驗；順序上讓螺牙在倒角**之前**或**之後**都測；失敗就拒絕並說明，並記為限制 |
| 螺牙面的持久命名 | 後面的特徵找不到螺牙的邊 | 命名採「牙型邊＋第幾線」；一圈一圈的面不命名（面太多），後續特徵只能選牙型邊衍生的面；T-2 驗證，若不穩，限制為「螺牙是最後的特徵之一」並寫進說明 |
| 錐形螺紋 | 比圓柱複雜 | T-0 已過（體積差 0.074%）；錐度大（> 10°）未驗，面板限制並說明 |
| 掃出布林在瀏覽器 Worker 內太慢 | 每次改參數都等 | T-5 量；退路：螺牙預覽用簡化（只畫幾圈）或延後再生，並誠實告知 |
| 螺牙面太多，網格與工程圖隱藏線變慢 | 3D 視窗與圖面卡 | 單一螺牙面數在 T-0 約 2 千個三角形（網格），不是問題；工程圖隱藏線在 T-4 實測 |

## 9. 請使用者決定的（只有這三個，其餘都是參數）

1. 螺牙的**起始面**：目前定義為「牙型草圖所在的位置」（草圖畫在哪裡，牙從哪裡開始）。這樣可以嗎？
2. **兩端的收尾**：第一版只做「切齊」（牙在起訖面被平切）。需要漸縮收尾（runout）的話，列為第二版。
3. 先不做牙型庫與螺旋曲線特徵，等螺牙特徵穩定後再排。這樣可以嗎？

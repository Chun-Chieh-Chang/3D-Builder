# 工程圖：螺紋孔與錐形沉孔的標註、DXF 的 DIMENSION 圖元（計畫）

- 日期：2026-10-07。來源：handoff §8 Phase 5「還沒做」與手冊 K4；使用者 2026-10-07 選了「工程圖：螺紋孔標註＋DXF 尺寸圖元」為第一組。
- 狀態：**D-1 與 D-2 都已實作並驗證（2026-10-07）**，見 [ADR 0101](adr/0101-hole-callouts-thread-countersink.md)、[ADR 0102](adr/0102-dxf-dimension-entities.md)；D-2 沒有真正的 CAD 開過。實作時的差異：D-1 用「孔特徵表」（`holeFeatures`，含衍生本體的主模型）取代只有螺紋的表，因為定位銷孔入口的導角與錐孔同形，要由特徵分辨；自動尺寸的分組一併改成依註記分。

## 1. 現況（第一性原理：哪些資料已經在，哪些不在）

- 孔標註（C16.5）：`holeInfo(topology, face)`（`packages/regen/src/drawingDimensions.ts`）只看**幾何**：完整的凹圓柱、貫穿或盲、孔口的柱孔（環形平面＋更大的同軸圓柱）。結果 `HoleInfo` 隨 `ElementFacts` 與 `ViewFeature` 帶到繪圖端，`holeNote` 寫成「貫穿」「深 12」「沉頭 Ø15 深 8」。
- 錐孔（countersink）：孔口接的是兩個圓邊的圓錐，`holeInfo` 明確把它當「孔口開著」而沒有報出來，所以圖上看不到錐孔的尺寸。**幾何就足夠**（圓錐的兩個圓邊直徑、半角）→ 對匯入的零件也有用。
- 螺紋孔：模型只做到攻牙底孔（沒有螺紋，ADR 0057 限制），所以**幾何上它就是一個 Ø5 的孔**，圖上寫 Ø5 會誤導。「它是 M6」只存在於特徵（`HoleFeature.kind === 'tapped'`、`size: 'M6'`）。孔壁面的名字是 `<孔特徵>:side:<草圖>.<點>.wall`，名字隨編輯保留（持久命名），所以從面名可以回到特徵。
- DXF（ADR 0065）：場景 `Scene` 是平的折線與文字，尺寸也是；DXF 寫成 LWPOLYLINE／SOLID／TEXT。DIMSTYLE 表是空的，BLOCKS 只有兩個空的 `*Model_Space`／`*Paper_Space`。沒有真正的 CAD 開過（使用者待辦）。

## 2. D-1 螺紋孔與錐孔的標註

決定（可以改，改在 `holeNote` 一處）：

| # | 決定 | 理由 |
|---|---|---|
| 1 | `HoleInfo` 加 `countersink?: {diameter, angle}`（孔口直徑、夾角，幾何量得）與 `thread?: {size}`（螺紋規格，取自特徵） | 錐孔是幾何事實，螺紋是特徵的事實，兩者分開來源 |
| 2 | 錐孔的字：`沉錐 Ø12 90°`，接在「貫穿／深」之後，與沉頭並存時沉頭在前 | 與既有 `沉頭 Ø15 深 8` 同型 |
| 3 | 螺紋孔的標註**取代**直徑：`M6 貫穿（底孔 Ø5）`、`M6 深 12（底孔 Ø5）`；沒有 `callout` 的一般直徑尺寸仍寫 Ø5（尺寸就是量到的圓） | 圖上的主角是螺紋規格；底孔直徑是模型實際的圓，不能不寫 |
| 4 | 螺紋「深」寫模型的孔深（鑽孔深）；說明裡註明：模型沒有螺紋，螺紋深度＝鑽孔深度 | 誠實：不編造沒有模型的數字 |
| 5 | 孔表（`HoleRow.size`）同樣用這個字；A、B、C 的分組仍依直徑 | 一個來源 |
| 6 | 特徵的資料用在 worker：`drawingElements`／`drawingFeatures` 有 `built.result`，再把零件文件（特徵清單）帶上；`holeInfo` 本身仍只看幾何，另有 `holeThreads(doc, names)` 查 `thread` | 圖形層（`@3db/drawing`）不認識特徵 |
| 7 | 沒有規格名（`size` 空，自訂孔徑）的螺紋孔：寫 `螺紋底孔 Ø5 …`，不編造 M 數 | 同上 |

量化驗收（手算）：
- 錐孔：Ø6 孔、孔口 Ø12、夾角 90°、貫穿（板厚 20）→ `Ø6 貫穿 沉錐 Ø12 90°`；夾角 82° 與 100° 各一個，角度讀回與輸入差 < 0.01°。
- 螺紋孔：M6（底孔 Ø5）貫穿、盲孔深 12 → `M6 貫穿（底孔 Ø5）`、`M6 深 12（底孔 Ø5）`；孔表同字。
- 改規格 M6→M8（底孔 Ø6.8）後重算，圖上的字跟著變（不改圖）。
- 柱孔、直孔、定位銷孔的舊測試與輸出一字不差。
- 瀏覽器：新工程圖＋自動尺寸「孔標註」，看到 M6 的字。

## 3. D-2 DXF 的 DIMENSION 圖元

決定：

| # | 決定 | 理由 |
|---|---|---|
| 1 | 每個尺寸輸出一個 `DIMENSION` 圖元＋它的匿名圖塊 `*D<n>`（圖塊裡是現在畫的線、箭頭、字，圖層 DIMENSION／TEXT） | 看圖軟體只畫圖塊，CAD 讀 DIMENSION 的定義點；兩者一致，現有的畫面不變 |
| 2 | 文字用 `1` 蓋寫（override）成程式算好的字（含 Ø、公差、4×、括號） | 數字來源永遠是模型；不讓 CAD 重新量出不同格式的字 |
| 3 | 種類：線性（水平／垂直＝旋轉式 type 0，對齊 type 1）、直徑（3）、半徑（4）、角度（二線 type 2） | 對應程式的四種尺寸 |
| 4 | 定義點取自**繪圖時已算出的紙面座標**（延伸線起點、尺寸線上一點、圓心與圓上的點、角的兩條線與弧上的點），文字位置明確指定（type + 128） | 不重算第二次，圖塊與定義點同源 |
| 5 | 加 DIMSTYLE 表的 `STANDARD`（箭頭、延伸線、文字高度取自 `ARROW`、`GAP`、`OVERSHOOT`、`DIM_TEXT`）與 `$DIMSTYLE` | DIMENSION 要指向一個存在的樣式 |
| 6 | `Scene` 多一個 `dimensions`（每個尺寸的種類、字、定義點、圖塊的圖元）；SVG／PDF 仍畫 `items`，**同一份場景**的規則不變 | 保住「三種輸出不會互相矛盾」 |
| 7 | `readDxf` 加檢查：DIMENSION 的圖塊存在且在 BLOCK_RECORD、DIMSTYLE 存在、定義點量出的數字等於字 | 沒有 CAD 可驗時，自己的讀取器是第一道關 |

量化驗收：
- 手算：板 120 × 80 的水平尺寸 120：兩個延伸線點 `13`、`14` 的距離 = 120 × 圖比例換算後的紙面距離；DXF 讀回後，由定義點算出的數值（除以比例）= 120 ± 1e-9，與文字相同；Ø9 的直徑：`10` 與 `15` 的距離 = 9 × 比例；R、角度同理（45°、90°、135°）。
- 每種尺寸至少一個測試；4×Ø9 與帶公差的字原樣出現在 `1`。
- 輸出的 DXF 通過 `readDxf`（結構、控制代碼、圖塊、樣式）；有 DIMENSION 的檔案與沒有的檔案，實體數差 = 尺寸的圖元數。
- 瀏覽器：輸出 DXF，用 `readDxf` 讀回，DIMENSION 數 = 圖上尺寸數。
- **限制（誠實寫）**：沒有真正的 CAD 開過。手冊 F6 加一步，請使用者用 AutoCAD／DraftSight／eDrawings 開，檢查尺寸可選取、數字可改、字相同。DXF 的 `STANDARD` 樣式是最小版本，別的 CAD 可能顯示成略不同的箭頭（圖塊內的箭頭仍是原樣）。

## 4. 順序與提交

1. D-1：模型（`HoleInfo`）→ regen（`holeInfo` 錐孔、`holeThreads`）→ worker → 繪圖（`holeNote`、孔表）→ i18n（zh/en）→ 測試 → 瀏覽器 → ADR 0101 → 手冊 F4 與說明 → 提交推送。
2. D-2：場景（`dimensions`）→ `dimension.ts` 回報定義點 → `dxf.ts`（DIMSTYLE、BLOCKS、DIMENSION）→ `dxfRead.ts` 檢查 → 測試 → ADR 0102 → 手冊 F6 → 提交推送。

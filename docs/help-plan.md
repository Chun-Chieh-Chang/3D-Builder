## 1. SW 的說明有哪些入口（要複製的）

- 功能表「說明」：SolidWorks 說明、線上教學、**這是什麼？**（游標變問號，點任一按鈕或面板跳到它的說明）。
- **F1**：依目前正在做的事（工具、PropertyManager）開對應主題。
- 滑鼠停留在按鈕上：一行說明（工具提示），多半帶「按 F1 看更多」。
- 說明視窗：目錄、搜尋、主題內文、相關主題。

## 2. 單一來源怎麼定（第一性原理）

資料只有一份：**i18n 目錄裡的 `help.<主題>.*`**。四個入口（工具提示、F1／說明窗、這是什麼？、驗證手冊的連結）都只讀 `helpOf(主題)`，不各存一份文字。

- **主題 id 就是已有的穩定 id**：`ACTIONS` 的 `id`（`extrude`、`fillet`…）、草圖工具的 `ToolId`（`tool.line`…）；沒有對應按鈕的概念（草圖吸附、選取、設計樹）用 `concept.*`。
- **標題不另存**：動作主題的標題就是按鈕的 `label`（UI 與說明永遠同名）；概念主題才有 `help.<id>.title`。
- 每個主題：`summary`（一句話，工具提示用，必有）、`body`（內文，段落以空行分隔，`- ` 開頭是清單，選用）、`keywords`（搜尋用，選用）、`see`（相關主題 id，空白分隔，選用）。
- **防漏**：`ACTIONS` 每個 id 與每個草圖工具都必須有 `summary`，沒有就 `npm run check` 失敗；`see` 指到不存在的主題也失敗；說明用到的 id 在程式裡不存在（動作被改名或刪掉）也失敗。**加指令而忘了寫說明，編不過。**
- **驗證後同步**：[manual-verification.html](manual-verification.html) 的每一項在 `docs/help-links.json` 列出它驗證的主題 id；檢查會確認 id 存在；手冊的項目標為「有問題」並修好後，工作約定要求對照這份清單改相應主題（handoff §7）。手冊在項目下方顯示這些主題的標題（之後做）。

## 4. 風險與預設假設

- 內文是我依程式行為與驗證手冊寫的；**驗證者（使用者）看過才算定稿**，所以內文放在目錄裡，改一行就好。
- 一句話與內文只描述行為與步驟，不放會隨版本變的數字（驗證過的預期數字例外，並在 H-C 與手冊連結）。
- 這是什麼？模式只攔截有 `data-help` 的元素（功能列按鈕、設計樹、PropertyManager、狀態列、圖形區）；其餘點下去照常（不攔）。
- 英文：既有規則要求 `en` 目錄翻譯 zh-TW 的每一個字串，所以新增說明時中英文一起寫（主題 key 的詞用駝峰：`extrude-cut` → `help.extrudeCut.summary`，因為 key 規則不允許連字號）。
